## 二、路由方案

### 2.1 目标路由表

| 路径 | 行为 | 套工作台壳 |
|---|---|---|
| `/` | 营销首页 HomePage（保留现状） | 否 |
| `/t/:slug` | ToolPage 工具页（URL 不变） | **是** |
| `/tools` | 全部工具目录页（重设计）；`?cat=<菜单大类>` 聚焦单类（第七轮：顶栏/首页/页脚/面包屑的大类入口统一去向） | **是** |
| `/tools/:id` | 分类目录页（重设计，`id=all` 同） | **是** |
| `/image-tools` … `/studios` 12 个分类路径 | 分类目录页（**SEO 兼容页**：URL/sitemap 保留，主导航不再指向，页内改链 6 大类口径） | **是** |
| `/saved` | 收藏页 | **是** |
| `/guides`、`/guides/:slug` | 指南（融入新风格） | 否 |
| `/about`、`/contact`、`/privacy`、`/terms` | 内容页（融入新风格） | 否 |
| `/studio/:id` | 既有重定向（不变） | — |
| `/:pathMatch(.*)*` | 404（不变） | — |

### 2.2 嵌套路由结构

```ts
// src/router.ts 结构示意
routes: [
  { path: '/', name: 'home', component: HomePage },
  /* 指南/关于/法务等独立页 … */
  {
    path: '/workbench', // 占位父路径（无入口链接指向它，children 全部用绝对路径）
    component: () => import('@/components/layout/WorkbenchLayout.vue'),
    children: [
      { path: '/t/:slug', name: 'tool', component: () => import('@/pages/ToolPage.vue') },
      { path: '/tools', name: 'all-tools', … },
      { path: '/tools/:id', name: 'category-all', … },
      { path: '/:id(image-tools|…|studios)', name: 'category', … },
      { path: '/saved', name: 'saved', … },
      { path: '', redirect: '/' }, // 父路径兜底
    ],
  },
]
```

- Vue Router 4 支持 children 绝对路径：URL 形态完全不变，仅渲染层级变化；`/workbench` 自身无 child 匹配时兜底重定向。
- **壳不重挂载**：工具间切换是兄弟 children 间导航，`WorkbenchLayout` 与 `ToolMenu` 不卸载，展开态/滚动位置保持；`ToolPage` 现有 `watch(slug)` 懒加载逻辑不动。
- `scrollBehavior`、`afterEach` 的 title/meta/og 同步逻辑全部沿用，不需改动。

### 2.3 菜单与分类页的分工（关键交互口径；2026-11-16 第七轮修订）

- **菜单大类头点击** = `router.push('/t/' + 该类首位工具 slug)` 并展开该类——即「子工具默认路由是第一个工具」；类内**领域族小标题**主体点击 = 族内第一个工具（次级导航，不改变层级）。
- **顶栏大类与菜单联动（第七轮新增）**：顶栏 6 大类链接 = `/tools?cat=<大类>` + `useMenuSync.solo(catId)`（菜单独占展开该类、折叠其他）；顶栏「全部工具」= `/tools` + `expandAll()`（全部大类展开）。菜单当前大类判定覆盖 `/tools?cat=`（目录页同样强制展开当前类）。
- **大类浏览入口统一为 `/tools?cat=`**（第七轮修订）：顶栏、首页胶囊「查看全部」、页脚工具目录、工具页面包屑分类层全部指向该口径；**12 个数据分类页降级为 SEO 兼容页**——URL/sitemap/页面内容保留（外链与收录不受损），但主导航不再指向，页内「按大类浏览」链到新口径。
- 外部入口（首页卡片 `ToolCard`、搜索弹窗、指南内链）本来就是 `/t/:slug` 直链，套壳后自动获得菜单定位，无需改链接。

## 三、菜单数据层（`src/data/menuGroups.ts`）

### 3.1 数据结构

```ts
/** 菜单大类（6 个，显示层归并；≠ 数据分类 CategoryId 12 个） */
export interface MenuCategoryDef { id: string; name: string; icon: string }
export const menuCategories: MenuCategoryDef[] = [/* image / av / docdata / utility / dev / ai */]

export interface MenuGroupDef {
  id: string          // 如 'json'
  name: string        // 如 'JSON'
  icon: string        // AppIcon 名称
  category: CategoryId // 所属数据分类（组成员必须一致，脚本断言）
  menuCategory: string // 所属菜单大类（6 值之一，显示层归并）
}
/** 数组顺序 = 菜单组级顺序（R2-c 已随蓝图定稿） */
export const menuGroups: MenuGroupDef[] = [...]
/** slug → 组 id，511 项全覆盖 */
export const groupOf: Record<string, string> = {...}
```

- **单一事实源**：组只定义「归属与顺序」，工具名/简介/URL 一律实时取自 `toolMap`/注册表序，不复制第二份名录；`ToolDef` 契约（`src/types.ts`）与数据分类体系（`CategoryId` 12 个）**不加不改**——菜单大类是纯显示层。
- 派生 `menuTree`（**菜单大类 → 组 → `ToolDef[]`**；组的 `menuCategory` 给出归并归属，组内序 = 注册表数组序）在模块内 computed 一次生成，直接映射为 `el-menu` 的嵌套结构（`el-sub-menu` = 菜单大类、`el-menu-item-group` = 族小标题、`el-menu-item` = 工具）。
- 侧栏底部固定区放「★ 我的收藏」「全部工具」入口（非组项）。

### 3.2 断言哨兵（进 `npm run test`）

1. `groupOf` 覆盖 `allTools` 全部 slug，无遗漏、无多余、无重复；
2. 每组成员的 `category ===` 组定义 `category`（领域族不跨**数据分类**）；
3. 每组 ≥2 项（单项组并入相邻组合并，避免菜单碎片化）；
4. 每组的 `menuCategory` ∈ 6 个菜单大类 id（显示层归并映射完整）；
5. 重排脚本断言沿用：条目数 / slug 集合不变。

### 3.3 领域族与菜单大类定稿（6 菜单大类 · 77 领域族，2026-11-15 评审定稿）

**唯一权威载体：`docs/V1.1/工具清单-V1.1.md`（分组排序蓝图）**——**6 菜单大类 → 77 领域族**的完整成员、组内与组间排序、各菜单大类默认落地工具均已在该文件定稿，并经脚本校验（511 项按 6 大类与注册表并集逐类一致、无重复、无遗漏、每组 ≥2）。归并关系：图片=image；音视频=video+audio；文档与数据=pdf+data；实用工具=utility+editors+finance+business+seo；开发=developer；AI=ai。本文件不再重复组表；`menuGroups.ts`（含 menuCategory 映射）与 reorder FULL 全序表直接从该清单机械转写。

### 3.4 菜单交互形态与实现（2026-11-15 六轮拍板定稿）

三轮形态演进：领域族一级（初稿）→ 领域族一级铺开+过滤（第二轮）→ **大类两级折叠 + 类内族小标题 + 总体折叠**（第三轮，现行）——用户明确「511 项在一个菜单里太多、体验不好」；第四轮拍板实现方式：**用成熟组件库 Element Plus，不自研折叠树**；**第五轮把菜单一级从 12 个数据分类收敛为 6 个菜单大类**（图片/音视频/文档与数据/实用工具/开发/AI，显示层归并，数据分类不动），折叠加放在菜单大类层；**第六轮补快捷操作语义**：6 个大类头 = 快速入口（点击独占展开该类 + 路由首位工具），族小标题固定展开不可折叠并配三层快速定位（族索引弹层/吸顶链/过滤匹配族名）。曾评估「6 入口分开展示」（每类独立菜单）被否：跨类切换要退回入口层、与分类页职责重叠、工具页内链只剩本类，仅保留其入口语义并入大类头。

**组件映射（Element Plus `el-menu` 体系，按需引入）**：

| 菜单元素 | EP 组件 | 关键配置 |
|---|---|---|
| 菜单容器 | `el-menu` | `router` 模式（`index`=路径，真实 `<a>` 保 SEO/中键新标签）、`unique-opened=false`（多开）、`default-active`=当前路径、`collapse=false`（我们的侧栏收起是布局层，不用 EP 的 collapse 模式） |
| 菜单大类（6 个） | `el-sub-menu` | title 插槽 = 大类名 + 工具数徽章 + RouterLink + 族索引图标（弹层触发，仅展开态显示）；链接点击冒泡 = 导航 + **独占展开**（其余大类全部折叠，「6 入口=快速路由」）；EP 自带箭头点击仅普通折叠——两种语义天然分离；`unique-opened=false` 保持（solo 在自绘 title 点击 handler 里实现，不用 EP 的 `unique-opened=true`——否则 chevron 普通切换也被连带 solo） |
| 族小标题（77 组） | `el-menu-item-group` | title 插槽加点击导航到族内第一工具；非折叠分隔且**固定展开不可折叠**；title 挂锚点 id 供 scrollIntoView 定位 |
| 工具项（511 个） | `el-menu-item` | `index=/t/:slug`，title/keywords 渲染 + 收藏星标（可选） |

**交互规格**：

- **默认折叠策略与入口独占**：仅当前大类展开，其余折叠；折叠集合存 localStorage（`toolhub.menuCollapsed`，菜单大类 id 数组，EP 受控 `opened` 状态）；当前工具所在大类强制展开（优先于记忆）——**外部直达/路由切换只强制展开当前类，不折叠其他类**（独占是入口点击的显式动作）；大类头主体点击 = `opened` 置为仅该类 + 路由该类首位工具 + 清空过滤态；chevron = 普通折叠/展开切换（多开浏览仅经此路径）；「全部折叠/展开」一键按钮（全折 = 6 行大类索引，行点击同入口语义）。
- **过滤框置顶**：侧栏顶部 sticky；输入按 title + keywords + **领域族名** 三口径就地 includes 匹配（工具口径与 SearchModal 一致；族名命中显示整族工具）；**过滤态自动展开有匹配的大类**（覆盖折叠态），无匹配大类整类隐藏；清空恢复；入口点击导航时清空过滤态。
- **方向感补偿**：当前工具高亮（`default-active` + 路由 watch 同步）；路由切换/首入对活动项 `scrollIntoView`（EP 不内置，壳层补，仅导航触发不劫持滚动）；**吸顶链**：大类标题与当前族小标题在侧栏滚动容器内分层 sticky 吸顶（族标题 `top` 紧贴大类头下方），滚到哪族当前族标题始终可见；若与 EP 内部结构冲突，降级为仅大类头吸顶（实现期验证）。
- **族索引弹层（族快速定位主路径，仅桌面）**：已展开大类头右端「列表/锚点」图标 → `el-popover` 弹出该类全部领域族目录（族名 + 工具数，列表 `max-height` 内滚）；弹层顶部即时过滤框（输入缩族列表）；点击族项 = 关弹层 + 菜单滚动容器内对该族小标题 `scrollIntoView({ block: 'start' })` + 闪烁高亮约 0.8s（CSS 动画，滚动结束后触发）；点外部/Esc 关闭。零常驻占用，顺带提供该类族结构总览。**移动端不启用**（弹层在抽屉内定位复杂），移动端快速定位只走过滤框族名匹配。否决备选：通讯录式右缘首字索引条——中文族名首字歧义大且常驻占宽 240px 侧栏，不采用。
- **总体折叠**：① 侧栏整体收起/展开——顶栏按钮 + 折叠后内容区左缘悬浮把手，收起后工具面板占满全宽（呼应 R4），状态 `toolhub.sidebarCollapsed`；**收起态 rail 常驻 6 个大类图标 = 入口**（点击 = 展开侧栏 + 独占展开该类 + 路由首位工具）；仅桌面提供（移动端本就是抽屉）。
- **移动端抽屉**：默认仅当前大类展开；过滤框同样置顶（含族名匹配，是移动端唯一的族快速定位手段）；桌面/移动共用 ToolMenu，断点 860px 沿用现网。
- **性能**：511 个 `el-menu-item` 静态渲染（EP 虚拟化菜单对受控 opened/过滤场景反而复杂，不启用）；折叠只挂起渲染仍一次性——如实现期实测卡顿，退化为「折叠大类延迟渲染 children」（备选方案，预期用不上）。

### 3.5 顶栏联动与菜单布局（2026-11-16 第七轮验收追加）

**联动总线 `useMenuSync`**：模块级 `request = ref<{kind:'solo'|'all', catId?, nonce}>` + `consumedNonce`。顶栏点击 → `solo(catId)`/`expandAll()`（nonce 单调递增，重复点同一类也再触发）；`WorkbenchLayout` watch 请求先把收起态侧栏展开；`ToolMenu` watch 请求施加开合态。两个实现细节（坑位）：

1. **过滤恢复 watcher 的时序竞争**：联动若在过滤态触发，先 `query=''` 后须 `nextTick` 再施加 solo/all 开合——「过滤恢复」watcher 会在同轮 flush 里按 `preFilterOpened` 双向对齐，直接施加会被其覆盖/回滚。
2. **晚于请求挂载的实例**：从首页等非壳页点顶栏大类时工作台才挂载，watcher 已错过请求——`ToolMenu.onMounted` 末尾按 `nonce > consumedNonce` 补消费一次（桌面侧栏/移动抽屉两实例共用 `consumedNonce`，先到先得；抽屉实例打开时按 localStorage 记忆初始化，不依赖补消费）。

**菜单 100% 高度布局**：滚动容器从壳层（`wb-menu-scroll`/`drawer-body` 原为 overflow 容器）**移入 ToolMenu 内部** `.menu-scroll`（flex:1 + overflow-y:auto + overscroll contain），壳层只做高度透传（flex 列）。收益：ToolMenu 根节点得以自持 `flex:1` 撑满，`.menu-foot`（我的收藏/全部工具）作为 flex 列尾**吸附侧栏/抽屉底缘**，不随菜单滚动；抽屉内 menu-foot 恰好落在 drawer-foot 站点导航条上方。吸顶链不变（过滤框 sticky top:0、大类头 top:50px 都在 `.menu-scroll` 内）。

**族小标题样式（居左分组头）**：`group-link` = 强调色小竖标（3×11px tick）+ 11px/700/字距 0.6px 族名 + 淡化计数；左缘 padding 12px（介于大类头 8px 与工具项 20px 之间）；hover 只提亮 tick 与族名色。与工具项（13px 常规、无标记）拉开「分组标签 vs 菜单项」的层级，不再像可点子菜单。族首工具路由、锚点定位与闪烁高亮保留。

## 五、布局与响应式规格（R4 + R5）

### 5.1 断点体系（收敛约定）

全站现存 **14 种散乱断点**（520/560/600/640/680/720/760/800/860/900/960/1000/1099/1100），同一组件族行为不一致。本次收敛为 4 档口径、**2 个权威断点**：

| 档位 | 范围 | 形态 |
|---|---|---|
| 桌面宽 | ≥1200px | 侧栏展开（240px）+ fluid 内容区 |
| 桌面紧凑 | 861–1199px | 同上；侧栏可整体收起让宽 |
| 平板/手机 | 481–860px | 抽屉菜单、单列、工具面板全宽 |
| 手机小屏 | ≤480px | 同上 + 更紧凑（16px 边距、执行按钮全宽、面包屑极简） |

- **权威断点只有 `860` 与 `480`**：壳层、共享组件、本期新写代码一律使用；`860` 与现网 SiteHeader 断点一致，不引入第三套。
- 存量旧断点（760/720/640…）**不强求本期清零**：组件被本期改造触碰时就近归并，其余随 R5-f（qa 轮）治理——防止「断点统一」膨胀成全站回归工程。

### 5.2 桌面规格（≥861px，承 R4）

- 壳为 `grid: 240px 1fr`（侧栏整体收起时 `56px 1fr` rail）；侧栏 `position: sticky; top: 60px`（页头高度）+ `height: calc(100dvh - 60px)`，独立滚动发生在菜单组件内部 `.menu-scroll`（§3.5，壳层高度透传），过滤框与大类标题在滚动容器内二级吸顶（§3.4）；侧栏可整体收起（内容区占满全宽，左缘悬浮把手恢复）。

### 5.7 下载兼容（R5-d，国内重点）

微信内置浏览器（iOS WKWebView / Android X5）对 `blob:` URL + `download` 属性经常静默失效——国内工具站最高频移动端投诉。方案：

1. `lib/download.ts` 保存逻辑不变；下载类工具增加环境检测（UA 含 `MicroMessenger`）。
2. 微信环境显示固定提示条：「当前在微信内打开，文件可能无法直接保存——点右上角 ··· 选『在浏览器打开』后再下载」。
3. 图片类结果额外提供「长按图片保存」路径：结果同时渲染为 `<img>`（blob src）而非仅 canvas。
4. 不接任何分享/SDK（成本考量，与隐私承诺无关）。

### 5.8 编辑器工作室移动降级（R5-e，P1）

四工作台（pdf/video/photo/data-studio）多面板布局在 ≤860 降级为「分区垂直堆叠 + 吸顶锚点导航」精简模式；摄像头/麦克风能力移动端可用但操作受限，UI 诚实标注「移动端精简模式，复杂剪辑建议在桌面使用」。

### 5.9 移动端验收与哨兵

- **真机矩阵**：iOS Safari / 微信内置 / Android Chrome / 华为浏览器 × 4 档断点（480/860 邻界必测）；每档抽代表工具（每实现模式 2–3 个）过「打开→输入/上传→执行→下载/复制」全链路。
- **哨兵**（进 `scripts/tests/verify-defects.mjs`）：① base.css 含 ≤860 输入 16px 规则（字符串断言）；② `src/` 白名单外禁新增 `100vh`；③ flex 横排中文胶囊 `flex:none + white-space:nowrap` 沿用既有哨兵思路。

### 落地实施要点与坑位沉淀

1. **EP 子菜单卸载会漂移 open 状态**：过滤最初用 v-for 卸载无匹配大类，实测 EP `openedMenus`/组件注册表在大量卸载重挂后与本地 openedIds 漂移（`menu.open()` 调用不生效）。修复：大类 el-sub-menu 永不因过滤卸载，改 `v-show` 隐藏整类、只过滤族/工具项；过滤恢复用「双向对齐」（既关多余的也补回缺失的，EP 的 active-item 自动展开会引入计划外 open）。
2. **当前族三级吸顶与 EP 冲突（已按 §3.4 预授权降级）**：子菜单内联 ul 由 ElCollapseTransition 接管，过渡期 overflow:hidden 捕获 sticky 上下文；强置 overflow:visible 会卡死 transitionend 回调。降级为仅大类头+过滤框两级吸顶，`cur-group` 类保留。
3. **EP 静态入口泄漏路径**：App.vue 若静态 import 移动端抽屉（内含 ToolMenu→EP），会把 EP 打进主入口。修复：`defineAsyncComponent` + `v-if="drawerOpen || isMobile"`（桌面永不加载，移动端常挂载）。
4. **default-openeds 仅挂载时读取**：el-menu 的 default-openeds 不响应后续变化，初始展开集必须在子组件挂载后用 `menu.open()` 撑开（EP 也会按 active item 的 indexPath 自动展开当前类，与该机制叠加无冲突）。
5. **首页前 8 露出变化**：全序重排后首页各分类区块前 8 = FULL 前 8（FRONT 语义被覆盖，属设计内联动）。
6. **联动与过滤恢复的时序竞争（第七轮）**：联动开合态必须在 `query=''` 触发的「过滤恢复」watcher（按 preFilterOpened 双向对齐）跑完之后施加，否则被其覆盖——实现为先清过滤、`nextTick` 后再 solo/all（详见 §3.5）。
7. **目录页标题拼接去重（第七轮）**：`/tools?cat=` 标题模板「大类名+工具」遇以「工具」结尾的大类名（实用工具/开发工具）会拼出「实用工具工具」——按后缀判断不再追加。

## 八、已知边界

- 菜单为**大类两级折叠 + 类内族小标题 + 总体折叠 + 过滤**形态（§3.4，2026-11-15 第三/四轮拍板；§3.5 第七轮追加联动/布局/样式）；折叠只发生在大类层（族小标题不再折叠，避免两级折叠状态机）；当前大类强制展开优先于折叠记忆；过滤仅做就地 includes 匹配，不做拼音/模糊/服务端检索。
- **12 个数据分类页为 SEO 兼容页**（第七轮定稿）：URL/sitemap/页面内容保留，主导航与站内标识位一律 6 菜单大类口径（`/tools?cat=`）；数据分类 12 个仍是注册表/路由/reorder 的实现层，不在用户可见导航出现。
- 领域组成员不跨分类（§3.2 断言锁死）；若未来出现真跨类工具族（如「OCR」分属 image/ai），以菜单组就近归类、分类页保持各自注册为准。
- 首页与工作台两种形态并存一个版本期（首页为营销落地页、工具区为工作台），属已拍板的设计分工，不视为不一致缺陷。
- 纯文字段落限行宽（≈900px）是刻意的可读性处理，不是「没改干净」。
