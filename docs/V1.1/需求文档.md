# V1.1 需求文档 —— 工作台菜单路由改版

> 提出日期：2026-11-15 ｜ 状态：**需求已确认，待实施**（代码未动工，当前构建产物仍为 V1.0 形态）
> 基线：V1.0 全站 **511 项**（11 内容分类 507 + 编辑器工作室 4，slug 全站唯一）；本期**不增减工具**，只改导航结构与排序。
> 本期主题：**菜单路由**——工具区从「卡片目录 → 独立工具页」改为「左侧两级菜单 + 右侧全宽工作区」的工作台模式。
> 硬约束不变：纯浏览器端、无后端、文件不上传；history 路由 + slug 即 URL 不改；文案与视觉资产原创。

## 一、需求原文（路线图原始记录，2026-11-15）

> 1. 首页>（子工具）页，修改路由方式，不再是卡片-页面的方式，而是类似菜单路由的方式，左侧二级菜单，首先按照工具大类拆分（比如 json/Markdown/音频处理）等，每个子工具类下分成二级菜单；
> 2. 菜单重排序，使用率-技术含量等多因素考虑，重排各个工具顺序，子工具默认路由是第一个工具，如果外侧（首页/全部工具）点进去就是该工具的路由；
> 3. 首页和全部工具/指南/关于等可以不做，也可以设计成更符合整体风格的感觉；
> 4. 原先工具只占中间那一点，页面两边其实是空白的，在我看来是浪费的，尤其是 json 这类需要展开看内容的场景，这期统一改成左侧菜单+右侧占用的左右布局，不要留空了。
>
> 本期主要需求则是菜单路由的修改。

## 四、需求结构化

### R1 工作台壳与菜单路由（本期核心，P0）

工具区（`/t/:slug`、`/tools`、12 个分类页、`/saved`）套用统一的工作台壳：**左侧可折叠菜单 + 右侧内容区**，替代「卡片页 → 工具页」的孤岛模式。

- R1.1 菜单层级：**按菜单大类（图片 / 音视频 / 文档与数据 / 实用工具 / 开发 / AI，共 6 个，由 12 个数据分类显示层归并）收放的两级菜单**——一级 = 菜单大类（可折叠，默认仅当前大类展开）；二级 = 该类工具，类内用**领域族小标题**（共 77 组，分组与排序已定稿于 `工具清单-V1.1.md`）聚拢分隔，避免大类展开后一片散卡。数据分类 12 个保持不变（分类页/注册表/路由不动）。
- R1.2 大类头双语义（6 入口 = 快速路由）：标题主体点击 = **独占展开该类（折叠其余大类）+ 进入该类第一个工具的路由**（「子工具默认路由是第一个工具」，类内第一个 = 注册表排序首位，R2 重排后即综合分最高），同时清空过滤态；chevron/空白区 = 折叠/展开切换（不导航、不折叠其他类），**浏览类内容不触发导航**；多开浏览仅经 chevron（localStorage 记忆，`toolhub` 前缀 key）；当前工具所在大类强制展开（优先于记忆），但外部直达/路由切换不折叠其他类——独占只发生在入口点击。
- R1.3 类内领域族小标题：非折叠的分隔标题（带工具数徽章），主体点击 = 族内第一个工具；**固定展开不可折叠**；成员不跨大类（脚本断言）。族快速定位三层：① **族索引弹层**（桌面主路径）——大类头右端图标弹出该类全部族目录（族名 + 工具数、弹层内即时过滤），点击族项滚动定位 + 闪烁高亮；② **吸顶链**——大类头与当前族小标题在侧栏滚动容器内分层吸顶，滚到哪族当前族标题始终可见（只做上下文）；③ **过滤框匹配族名**——命中族名显示整族，是移动端唯一快速定位路径（弹层不进抽屉）。
- R1.4 菜单内过滤框（核心件）：菜单顶部常驻，输入即按工具名/关键词/领域族名就地缩小列表（工具口径复用 SearchModal，族名命中显示整族）；过滤态自动展开有匹配的大类（覆盖折叠态），清空恢复。
- R1.5 当前工具在菜单中高亮，路由切换/首入自动滚动定位到当前项；大类标题与当前族小标题在侧栏滚动容器内分层吸顶（吸顶链）。外部入口（首页卡片/搜索弹窗/指南内链/分类页）点进即直达该工具路由——URL 始终是 `/t/:slug`，可分享、可回退、可刷新。
- R1.6 菜单总体可折叠：① **侧栏整体收起/展开切换**（顶栏按钮 + 折叠后内容区左缘悬浮把手），收起后工具面板占满全宽（呼应 R4 不留空），收起态 rail 常驻 6 个大类图标入口（点击 = 展开侧栏 + 独占展开该类 + 路由首位工具）；② **「全部折叠/展开」一键**，全部折叠时菜单成为 6 行大类索引，行点击同入口语义（独占展开 + 路由）。状态 localStorage 记忆。
- R1.7 壳在工具间切换时不重挂载（嵌套路由），菜单滚动位置/过滤/折叠状态天然保持。
- R1.8 移动端（≤860px）菜单收进抽屉，默认仅当前大类展开；工具面板占满全宽。
- R1.9 菜单数据与注册表单一事实源：大类来自 `categories.ts`，族定义 + slug 归属独立成数据文件，工具名/序直接取自注册表，不产生第二份工具名录。
- R1.10 实现方式：菜单折叠树**不自研**，基于成熟组件库 **Element Plus** 的 `el-menu` 体系按需引入（`el-sub-menu`/`el-menu-item`/`el-menu-item-group` 映射菜单大类/工具/族小标题；`router` 模式真实 `<a>` 链接保 SEO；`unique-opened=false` 多开；`default-active` 当前高亮）；随工作台壳 chunk 懒加载，不进静态入口。过滤框、侧栏整体收起、滚动定位为壳层配套实现（组件库不覆盖）。

**验收标准**：任一 `/t/:slug` 页面左侧菜单默认仅当前大类展开、当前工具高亮且自动滚动定位；菜单项与注册表 511 项一一对应（脚本断言）；大类头主体点击落在该类首位工具 URL 且其余大类折叠（独占展开），chevron 折叠不触发导航且刷新后记忆保持；外部直达只展开当前类不清掉其他类折叠记忆；族索引弹层可按族名过滤并滚动定位到对应族（闪烁高亮）；过滤命中族名显示整族；侧栏整体收起后工具占满全宽、rail 图标入口可恢复定位；「全部折叠」后菜单为 6 行索引且行点击可达首位工具；直链刷新/回退前进正常；移动端抽屉可用且族定位走过滤框。**（第七轮追加）** 顶栏大类与菜单联动（点大类=独占展开、全部工具=全展开，直链 `/tools?cat=` 亦强制展开当前类）；菜单列撑满 100% 高且底部「我的收藏/全部工具」吸附底缘（侧栏与移动抽屉两处）；族小标题为居左分组头样式。

### R2 全量重排序（P0）

按「使用率 × 技术含量」等多因素重排全部工具顺序，两级落地：

- R2.1 **组内工具序**：各分类注册表全量重排（`reorder-registry.mjs` 从 FRONT 前置白名单升级为 FULL 全序表），排序即菜单二级顺序，也同步改善首页分类区块露出与「同类工具」推荐。
- R2.2 **组级顺序**：领域族的菜单排布同口径评估（高频刚需族在前，长尾专业族靠后）。
- R2.3 排序评分口径（0–5 分 × 权重）：**使用频率 40%**（日常刚需/办公高频）+ **技术含量与差异化 25%**（独家引擎、端侧 AI、付费平替）+ **人群广度 20%**（非专业用户也能上手）+ **传播引流价值 15%**（互动娱乐/爆款属性）。
- R2.4 机制保障：重排前后条目数/slug 集合断言不变；脚本幂等；重排后重生成工具清单。

**验收标准**：12 张全序表经评审写入脚本并执行成功；`npm run test` 哨兵全绿；工具清单与注册表一致。

### R3 辅助页重设计（P1）

- R3.1 `/tools`（全部工具）与 12 个分类页：保留为真实目录页，重做成与工作台一致的视觉（去卡片孤岛感、全宽分组网格、与菜单同源的排序）。
- R3.2 指南/关于/联系/隐私/条款：保留（SEO 内容 + 备案合规），样式融入新风格。
- R3.3 首页保持营销形态；顶栏/页脚/首页胶囊与目录区块/面包屑**统一 6 菜单大类口径**（第七轮决策），大类入口统一指向 `/tools?cat=`；12 个数据分类页保留为 SEO 兼容页（URL/sitemap 不变，主导航不再指向）。

**验收标准**：全站无 404 死链；新旧页面风格统一；sitemap 集合不变。

### R4 全宽布局（P0，随 R1 落地）

- R4.1 工作区去掉 1200px 居中限制：桌面端右侧内容区占满视口减侧栏的剩余宽度（fluid），JSON 展开、代码 diff、表格、时间线等宽内容直接受益。
- R4.2 可读性例外：纯说明文字段落（如工具简介）保留合理行宽上限，面板与交互区全宽。
- R4.3 侧栏规格：约 240px、sticky 跟随、独立滚动。

**验收标准**：≥1440px 视口下工具面板无两侧空白；侧栏与内容区各自滚动互不牵扯。

### R5 移动端兼容（P0）

现状欠账较多（见「现状与问题」末行），借工作台重布局一并还清。范围：

- R5.1 断点体系收敛：壳层与共享组件统一 **860 / 480** 两档权威断点（与现网顶栏断点兼容）；存量散乱断点不强求一次清零，组件被本期触碰时就近归并，其余随 qa 轮治理。
- R5.2 全局基座（base.css/tokens.css）：移动端输入控件 font-size ≥16px（禁 iOS 聚焦缩放）；新代码一律 `dvh` 并替换存量 100vh；safe-area 变量并应用到抽屉/吸底/页脚；`-webkit-text-size-adjust: 100%` 与 tap-highlight 重置；交互元素触控目标 ≥44×44。

**验收标准**：真机矩阵（iOS Safari / 微信内置 / Android Chrome / 华为浏览器）× 4 档断点，代表性工具（每实现模式抽 2–3 个）完成「打开 → 输入/上传 → 执行 → 下载/复制」全链路；全程无 iOS 聚焦缩放、无 100vh 跳动；抽屉/全屏弹层含 safe-area；表格类横滑可用；微信内下载有明确降级提示；触控目标 ≥44px。
