## 结论与优先级

**交互优化 + 需拓展** · P1

判据：检索式引用是真可用（页码可溯源），但与 ChatPDF 生成式综合存在代差且"对话"承诺虚位——需诚实标注 + 检索质量修复。

## 扣分点明细

1. 【灵魂-规约红线】"对话"名不副实：无多轮上下文、无改写式回答，实为"单问→3 条引用句"；面板 notice 有诚实说明但标题/desc（registry.ts:84"上传 PDF 后用自然语言提问"）未告知"非生成式、不支持总结/跨句推理/追问"
2. 【实用价值-疑似问题】疑问词规则正则缺陷：`/[先生|女士|博士|教授|总|经理|作者|创始人]/`（nlpEngine.ts:286）是字符类而非alternation——问句含"谁"时，句中出现"先""生""士"任一单字即 +2 分；`:289` `(位于|位于|在.+市|省|国|路|街)` 松散alternation使句含"省"字即 +2，含"省"的无关句可被顶成答案
3. 【实用价值】匹配无语义容错：similarity 基于中文 2-gram 集合（textEngine.ts:606-614）+仅 30 个英文停用词（:616-620），提问改写一个同义词即失配；0.02 阈值（ChatWithPdf.vue:66）过低，弱相关句也会凑满 Top3
4. 【交互】无问答历史：asked 只存最后一问（:23），上一轮引用被覆盖，无法对比多问结果
5. 【性能】句子 token 无缓存：sents 存原文（:39-41），每次提问 map 全量重算 similarity（:63-65），长文档卡顿且 ask 无 loading/busy 态
6. 【功能】引用不落地：无"跳转到该页"（PDF 本身未渲染，无法定位上下文），引用句只有孤句无前后文
7. 【功能】无导出：问答对无法复制/导出 Markdown（引用+页码本可一键成稿）
8. 【实用价值】长句切分依赖标点：splitSentences 仅按"。！？!?；;"与". 大写"切分（`nlpEngine.ts:11-17`），标点稀疏的 PDF（合同/条款示密集排版、英文小写句点无空格）会产出整段超长"句子"，引用卡变成整段糊墙
9. 【共性】提问行与引用卡受 266px 装饰层前缀挤压（共性-根因 1）

## 行业对标与差距

- **ChatPDF / Humata**（云生成式，架构天花板）：LLM 综合多段生成回答、多轮追问、按引用溯源跳页。差距：生成式综合属模型能力；纯前端可逼近 = 端侧 embedding 检索（transformers.js 模型向量相似度，替代 2-gram）+ 端侧小模型 QA（已预留 question-answering 家族同款引擎）。
- 借鉴优先级：**面板内"检索式非生成式"标注 > 提问 token 缓存+同义容错 > 问答历史 > 正则规则修复 > 导出**。

## 可拓展性

- 短期（1 周）：notice 升级为能力边界卡（"非生成式：只摘原句，不支持总结与追问"）；ask 加 busy 态；句子 token 一次性预计算缓存
- 中期（1 月）：问答历史列表（最近 10 问，localStorage）；引用句带前后句展开；复制为 Markdown 引用块
- 远期：transformers.js embedding 检索双引擎（2-gram 快/向量准）；扫描件走站内 OCR 工具分流提示

## 优化处方（验收标准）

1. **能力边界卡**：结果区头部加"检索式问答——直接引用原文，非 AI 生成；不支持总结与追问"。→ **验收：面板首屏内可见，与 ChatPDF 类产品的差异点说清**
2. **正则修复**：:286 改 `(先生|女士|博士|教授|总经理|作者|创始人)` 真alternation，:289 同步收紧。→ **验收：问"作者是谁"时含"先"字无关句不再加分（构造对照文档验证）**
3. **提问缓存**：索引时预 tokenize 存 Map。→ **验收：300 页 PDF 提问响应 <100ms 且结果与现版一致**
4. **问答历史**：保留每次问答对（问题+Top3 引用+页码），可回看。→ **验收：连续 3 问后历史区可展开每问引用**
5. **引用上下文**：引用卡加"±1 句"展开按钮。→ **验收：展开后能看到该句前后文且标注页码不变**
