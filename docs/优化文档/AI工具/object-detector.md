## 扣分点明细

1. 【实用价值-核心，疑似问题】入口 desc 虚标：registry desc"检测并标注照片中的常见物体（端侧模型，首次需下载）"（registry.ts:104）+ needModel: true 触发 ToolPage.vue:67 下载徽章——实际实现是显著性检测零下载（ObjectDetector.vue:34-131），面板诚实说明（:193-196）直接推翻入口承诺，与 image-caption 的 needModel 问题同根但性质更重（desc 明确承诺"常见物体"）
2. 【实用价值】显著性算法语义盲：能量=梯度+通道方差（:63-78），阈值=均值+0.55σ（:83-85）——纯色背景上一朵云、一张纹理地毯都能触发成框；结果对"找物体"问题无回答能力
3. 【功能】框标签只有"#1"（:147-153）无任何语义信息，用户无法区分"框=主体还是噪声"
4. 【可用性】标注图 460px 钉死（:254，共性-根因 2 家族自建舞台版）：4000px 宽图缩到 460px 后框位置无法逐像素核对，无点击放大
5. 【交互】无框编辑：显著性天然误框，却不能删框/拖框/合并，唯一出路是换图
6. 【功能】无置信度：能量分被丢弃（:130 只留几何），连"框的显著强度"都不展示，排序依据不可见
7. 【灵魂】口径魔术数未披露：16×16 网格、阈值 0.55σ、过滤 cells<3（ObjectDetector.vue:39,:85,:120）三参数无说明，用户无法预期"什么图会出几个框"
8. 【灵魂】DETR"需下载约 100MB"提示（:194）给了模型体积预告却无升级路径入口，承诺悬空（同 image-caption 扣分 5）

## 行业对标与差距

- **HF Spaces YOLOS/DETR demo**（transformers.js 同源天花板）：真类别标签+置信度+多目标，Xenova/yolos-tiny 可端侧跑。差距：语义识别属模型能力（架构天花板），纯前端可逼近 = transformers.js 检测管线（懒加载+needModel 下载纪律）；框编辑/放大属 UI 硬件应先行。
- **Canva/稿定的"主体识别"**（云）：一键抠主体。差距：无主体分割。
- 借鉴优先级：**desc 口径对齐 > 框增删/放大核对 > yolos-tiny 端侧真模型 > 显著强度排序展示**。

## 可拓展性

- 短期（1 周）：desc/needModel 口径修正；标注图点击 1:1 放大查看；框点击删除
- 中期（1 月）：显著强度数值与排序开关；标注样式（线宽/颜色/编号开关）；批量目录出框数据 CSV
- 远期：transformers.js 目标检测真模型双引擎（显著性档即时 / YOLOS 档带类别）

## 优化处方（验收标准）

1. **口径对齐**：desc 改"框出画面中最抓眼的显著区域（非物体识别）"，needModel 改 false。→ **验收：搜索卡/工具页/面板三处文案一致承诺"显著区域"**
2. **标注图放大**：点击标注图弹 1:1 覆盖层可平移。→ **验收：4000px 图上单框边缘在放大视图内可核对**
3. **框编辑**：列表行加"移除"按钮同步重绘。→ **验收：删除 #2 后标注图与列表编号即时重排**
4. **显著强度**：每框显示能量分并按强度排序。→ **验收：能量分与 detect() 返回顺序一致**
5. **YOLOS 端侧**：transformers.js 检测管线双引擎。→ **验收：模型档对猫/车图输出类别名+置信度，下载有预告与进度条**
