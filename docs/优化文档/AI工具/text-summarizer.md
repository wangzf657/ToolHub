## 结论与优先级

**交互优化 + 需拓展** · P1（无 P0 硬伤——M-17 证实按钮可达；核心问题是质量诚实度与中文效果）

## 扣分点明细

1. 【实用价值-核心】中文停用词缺失：`STOPWORDS` 仅 30 个英文虚词（`textEngine.ts:616-620`），`summarize` 的词频统计（`nlpEngine.ts:29-33`）对中文直接喂 2-gram——"的了""的是""一个"等高频虚词组合主导词频，得分句未必是关键句，中文摘要质量不可靠
2. 【灵魂-规约红线】诚实标注未进面板：引擎确为抽取式规则法（词频+位置+首段×1.25 权重，`nlpEngine.ts:38-46`），desc 有诚实说明（registry.ts:8"抽取式摘要引擎在本地运行"）但该文案渲染在面板下方 `.tool-about`（`ToolPage.vue:99`）视口外——**用户在面板内看不到"这是规则抽取、非大模型生成"**，易产生"AI 幻觉式改写"的错误预期（抽取法只搬原句，不改写）
3. 【功能】无压缩比控制：仅句数（1~N），无法表达"压到 30%"或"300 字以内"——摘要场景最自然的输入是目标长度（registry.ts:11 单 number 选项）
4. 【功能】无原文高亮联动：QuillBot 在原文中高亮被选中的句子，让用户秒懂"摘了哪几句"；本工具输出纯文本，用户无法回溯选句依据
5. 【交互】手动执行：`count` 是 number 选项 → `auto=false` → 显示"立即转换"按钮（`TextTool.vue:47,:131`），粘贴后不自动出结果；改句数也要手动重跑
6. 【交互】无压缩比展示：输出仅摘要文本，"3000 字压成 187 字"的价值信息缺失（输出区字符计数 TextTool.vue:124 需用户自己心算）
7. 【灵魂】无示例长文预填（空态 textarea 只有 placeholder"粘贴长文章、报告或段落…"）、无"要点式/段落式"输出切换

## 行业对标与差距

- **QuillBot / TLDRthis**（云，架构天花板）：生模型改写式摘要、关键句/段落双模式、长度滑杆、原文高亮联动。差距：**生成质量属架构天花板**——规则抽取法达不到改写式摘要，需在 UI 诚实标注；但"原文高亮 + 长度滑杆"是纯前端可完全实现的交互，属真差距。
- **HF transformers.js 摘要模型**（纯前端天花板参照）：-distilbart 等量化后可跑浏览器，是本项目提升生成质量的合理路径（注意 needModel 下载提示纪律）。
- 借鉴优先级：**面板内能力标注 > 压缩比参数 > 原文高亮联动 > 中文停用词修复 > 要点式输出**。

## 可拓展性

- 短期（1 周）：输出区顶部加"抽取式 · 本地规则引擎"徽章与"只摘原句不改写"说明；显示压缩比行；预填示例长文
- 中期（1 月）：中文停用词表（的/了/是/在/与/及…）+ 中文分词优化（复用 word-frequency 场景的口径）；目标字数/百分比模式；要点式（每句一条）输出开关
- 远期：transformers.js 摘要模型（懒加载 + needModel 下载提示），提供"规则（快）/模型（准）"双引擎切换

## 优化处方（验收标准）

1. **面板内诚实标注**：输出区头部加徽章"抽取式摘要（本地规则）—只挑原句、不改写原文"。→ **验收：工作面板首屏内可见该标注，与 tool-about 文案口径一致**
2. **中文停用词修复**：STOPWORDS 增补中文虚词表（≥80 词），summarize 分词对中文停用 1-gram 虚词。→ **验收："……的""……是一个"高频虚词 2-gram 不再进入 top 词频，同一篇议论文摘要句含主题词的句子占比提升（人工比对 3 篇测试文）**
3. **压缩比展示**：结果区加"原文 X 字 → 摘要 Y 字（压缩 Z%）"行。→ **验收：数字与输入/输出字符计数一致，Z 计算正确**
4. **原文高亮联动**：输出区加"定位原文"模式，被选句在输入窗内高亮。→ **验收：摘要中任一句子可在输入区找到并带高亮底纹**
5. **目标长度模式**：参数加"按句数 | 按目标字数"切换。→ **验收：目标 200 字时摘要字数落在 150~260 区间**
