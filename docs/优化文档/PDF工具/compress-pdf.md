## 结论与优先级

**交互优化** · P1

判据：功能骨架（双模式+量化结果）已优于家族平均，短板集中在"压缩结果不可见"的确认闭环与进度/达标提示两个交互点。

## 扣分点明细

1. 【可用性】压缩结果只有三个数字，无画质预览——用户无法在下载前确认"低档是否糊、中档是否够"，iLovePDF 压缩后直接给前后页对比；本工具下载后才发现画质不可接受只能凭记忆换档重压
2. 【功能/疑似 Bug】目标体积达不成时无任何提示：二分固定 5 轮后无条件返回 best（`pdfEngine.ts:976-977`），1GB 扫描件压不到 500KB 也照常报"压缩完成，体积减少约 X%"，用户不知道目标未达成
3. 【性能/疑似 Bug】预设档位进度归一化按"10 页"硬编码：`onProgress?.(i / 10)`（`pdfEngine.ts:984`）——20 页文档进度冲到 200%，5 页文档走不满 50%，进度条失真
4. 【功能】压缩策略只有栅格化一条路（`pdfEngine.ts:927-947`）：纯文字 PDF 压完变大、文字不可选只剩 notice 一句劝告（CompressPdf.vue:102），无"先试无损结构压缩（去重复对象/重压内嵌图）再栅格化"的分级策略，也无自定义 DPI
5. 【交互】输出名固定"压缩后.pdf"（`CompressPdf.vue:51`），多轮压缩同名互覆
6. 【灵魂】空态无"压缩率预估"：载入后已知页数与大小，可粗估"扫描件约可压至 X%"引导选档，现在只能盲选

## 行业对标与差距

- **iLovePDF**：压缩档位（低/中/高/极致）+ 压缩完成页展示前后体积对比与画质缩略预览。差距：**结果可确认性**——对方"看得见"，本工具"只报数"。
- **Smallpdf**：压缩率环形展示 + 强压缩（Pro）分级；失败时明确告知原因。差距：目标未达成的诚实反馈。
- **PDF24**：压缩可选 DPI 与 JPG 质量自定义参数。差距：参数自由度。
- 借鉴优先级：**画质对比预览 > 目标未达成提示 > 修进度归一化 > 自定义 DPI**。

## 可拓展性

- 短期（1 周）：修进度 `i / 10` → `i / totalPages`；目标未达成时结果卡变警示色并写"目标 500KB 未达成，实际 X KB，请降低目标或选低档"
- 中期（1 月）：压缩完成后展示首/中/尾三页 JPG 预览图（复用 pdfToImages 的渲染回调，几乎零新依赖）；自定义"倍数+质量"高级档
- 远期：无损先行策略——先 pdf-lib 结构重存 + 内嵌 JPEG 重压缩（embedJpg 直通），不达标再落栅格化；与 split-pdf-by-size 共享"目标体积"引擎

## 优化处方（验收标准）

1. **画质预览**：压缩完成后结果区显示 2~3 页"压缩前|压缩后"并排缩略图（≤200px 高）。→ **验收：同一文档低档与高档各压一次，预览图可见清晰度差异**
2. **目标未达成提示**：`resultKB > targetKB` 时结果区第三卡替换为警示样式"未达到目标 500KB"。→ **验收：构造小目标（如原图 10% 体积）压缩后出现警示文案且不再显示"-X%"成功率**
3. **进度修复**：进度条按实际页数推进并覆盖嵌入阶段。→ **验收：10 页文档压缩中进度从 0 连续走到 100%；3 页文档可走满 100%**
4. **压缩率预估**：载入后按页数/大小显示一行"预计可压缩 30%~70%（扫描件）"。→ **验收：载入任意 PDF 后提示行出现且不晚于首屏**
5. **输出文件名**：默认"压缩后"，加输入框可改。→ **验收：改名"标书-压缩版"后下载文件名为"标书-压缩版.pdf"**
