## 结论与优先级

**交互优化 + 需拓展** · P1（就地字段定位是交互主修，批量导入填写与中文外观流验证是拓展）

判据：60 分；可用性扣分集中在"字段名↔纸面位置"映射缺失——这是填写工具区别于普通表单的核心可用性；另有一项疑似功能缺陷待实测（扣分 2）。

## 扣分点明细

1. 【可用性】字段无页面定位：表单网格平铺（FillForm.vue:73-96），标签直接显示 AcroForm 内部名（:76），用户无法把 "f1_01[0]" 对应到页面上的具体框；fillpdf.com/Sejda 在页面渲染图上就地高亮字段（点击缩略图字段跳转），本工具完全没有页面视图
2. 【功能-疑似缺陷】中文值写入风险：fillForm 对文本字段 setText 后强制 form.flatten()（pdfEngine.ts:842、:851），pdf-lib 外观流默认 Helvetica（WinAnsi）无法编码中文，flatten 抛错被空 catch 吞掉（pdfEngine.ts:852-854）——中文表单可能"界面填了、下载后是空"；office-to-pdf 已确认同类 helvetica 无 CJK 缺陷，此工具疑似同坑，**需实测验证**（构造含中文字段的 AcroForm 填写下载检查）
3. 【可用性】填写结果零预览：点"填写并下载"直接存盘（:56-57），扁平化是否成功、字段外观是否画出全凭运气（与扣分 2 叠加放大风险；模式 F 共性）
4. 【功能】字段多时无搜索、无按页分组、无必填标记（:73-96 单层网格）；复选框只有"勾选"文案没有字段语义（:83-85）
5. 【功能】无批量填写：不能导入 CSV/JSON 把一份模板填出 N 份（fillpdf.com 支持 import data）；站内 pdf-form-data 只做反向汇总，正反双向没打通
6. 【交互】强制扁平化无开关（:102 文案写死），需要保留可编辑字段回单位系统流转的用户没得选
7. 【灵魂】初值回填后无"清空全部重填"快捷（换人填同一模板时要逐字段删）

## 行业对标与差距

- **fillpdf.com**：渲染页面原图就地高亮可填字段、点击字段在图上定位输入、支持从 CSV 导入批量生成。差距：**"看见字段在纸上哪里"是代差**。
- **Sejda Fill & Sign**：字段按页分组+缩略图导航，填写后可选保留字段可编辑性。差距：分组导航与扁平化开关。
- 借鉴优先级：**字段定位预览（页面图＋高亮）> 中文外观流修复/验证 > 字段搜索与分组 > CSV 批量填写 > 扁平化开关**。

## 可拓展性

- 短期（1 周）：flatten 失败改为显式告警（toast+结果预览页）；表单网格加搜索框与"仅看未填"过滤
- 中期（1 月）：右侧页面预览（renderPageToCanvas 现成）＋字段 hover 高亮（pdfjs annotation 层可取字段矩形）；CSV 导入批量填写多副本
- 远期：与 pdf-form-data 组成"表单双向工作台"：汇总出表 → 改表 → 批量回填，覆盖 HR/财务整条链路

## 优化处方（验收标准）

1. **中文写入验证与兜底**：先实测含中文字段的 AcroForm；若外观流乱码/为空，改用「更新 DA 字体＋中文贴图外观」或提示用户改用 add-text-to-pdf。→ **验收：含中文姓名字段的 W-9 式表单填写下载后，打开可见中文字样非空白**
2. **flatten 告警**：flatten catch 非 silent，提示"该表单无法扁平化，已保留字段（阅读器需支持表单）"。→ **验收：构造不可扁平化表单下载时出现明确提示而非静默**
3. **字段定位**：列表项 hover 时右侧页面预览对应字段矩形闪烁。→ **验收：hover "f1_01[0]" 能看到页面上对应输入框高亮**
4. **结果预览**：填写完成先渲染首页预览再提供下载按钮。→ **验收：下载前可见已填值出现在页面图上**
5. **批量填写**：支持上传「模板 PDF＋CSV」，每行生成一份副本打 zip。→ **验收：3 行 CSV 输出 3 个 PDF，各行字段值与 CSV 一致**
