## 结论与优先级

**交互优化** · P1（ghost 覆盖层是第一优先，单点微调与语义口径其次）

判据：61 分；交互骨架（翻页/清单/素材切换）家族最佳，但放置结果在生成前完全不可视，确认成本与误放风险高。

## 扣分点明细

1. 【可用性-硬伤边缘】已放置项在预览上零可视化：renderPreview 只替换 canvas（InsertImagePdf.vue:35-57），placements 不渲染 ghost 缩略图/边框——连续放 5 个图后"第几个放歪了"只能靠清单文字（页码+百分比）脑内还原；Sejda 放置即所见
2. 【可用性】生成即 saveBlob 自动下载（:99），无成品首页预览：图片压缩比/透明度效果/是否压到正文都要打开下载文件回看（模式 F 共性叠加 ghost 缺失，确认链路全断）
3. 【交互】已放置项不可调整：清单只能整条删除重放（:88-90），不能拖动改位、不能改单条尺寸；scalePct 输入只影响之后的放置（:84 快照），改数值对已放置项无效且 UI 未说明
4. 【交互】点击点=图片中心（pdfEngine.ts:547 注释）但界面文案只说"点击页面放置"（:151），对照 add-text-to-pdf 的"点击点≈文字左上角"（AddTextPdf.vue:151）——同一家族两种锚点口径，跨工具使用必错位
5. 【功能】无透明度/旋转：做"已阅"斜章或半透明水印图时无能为力（engine drawImage 支持 opacity 参数却未透出）
6. 【功能】素材区 FileDrop 占位大（:126），图片行只有文件名 chip（:128-135）无缩略图——素材多时全靠文件名辨认
7. 【契约】insertImagesAt 走 savePdf 正常盖章（pdfEngine.ts:552），此项合格；但生成无进度回调，多页多图静默
8. 【交互】下载名固定"插入图片.pdf"（:99）

## 行业对标与差距

- **Sejda**：插入图片后立即可拖动、四角手柄缩放、双击替换；画布上所有元素持续可见。差距：**放置后元素生命周期**（放置→可视→可调）整条链路。
- **PDF24**：插入图片支持每图独立尺寸输入与对齐辅助线。差距：单元素参数化。
- 借鉴优先级：**ghost 覆盖层（廉价高收益）> 成品回读预览 > 单条拖动/缩放 > 透明度/旋转 > 素材缩略图**。

## 可拓展性

- 短期（1 周）：在预览 canvas 上叠绝对定位 ghost（图片名+半透明轮廓，坐标已有 xRatio/yRatio）；文案补"点击点=图片中心"
- 中期（1 月）：ghost 可拖动改位、滚轮/滑杆改尺寸；生成后回读首页预览；素材行缩略图（URL.createObjectURL 即可）
- 远期：并入"PDF 标注工作台"（与 add-text/sign-pdf 共享放置项模型、撤销栈与翻页器）

## 优化处方（验收标准）

1. **ghost 可视化**：每次放置在预览上按比例叠加半透明图片轮廓＋序号角标。→ **验收：连放 3 处后预览上可见 3 个轮廓，位置/相对大小与导出成品一致**
2. **成品回读**：生成后先渲染输出首页预览再提供下载。→ **验收：下载前能看到图片已落在页面上，透明 PNG 无白底**
3. **拖动微调**：ghost 支持拖拽改位（更新 xRatio/yRatio）。→ **验收：拖动第 2 个 ghost 后导出，图片位置随拖动更新**
4. **口径统一**：文案改为"点击点=图片中心"，并给 add-text/sign-pdf/insert-image 三工具统一锚点说明。→ **验收：三个工具的提示文案锚点口径一致且与实际渲染相符**
5. **透明度滑杆**：素材区加 opacity 0~100% 开关透传 engine。→ **验收：50% 透明度放置后成品中底图文字可透过图片辨认**
