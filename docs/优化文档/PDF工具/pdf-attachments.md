## 结论与优先级

**交互优化** · P2

判据：62 分；核心闭环完整，短板在能力边界披露（Rendition/Portfolio）、同名附件移除风险与"保存后要重来"的流程摩擦。

## 扣分点明细

1. 【功能】附件类型覆盖边界未披露：仅走 doc.getAttachments 高层 API（:41），Rendition（多媒体屏幕附件）与 Portfolio/Collection 集合式附件静默不显示——用户拿 Acrobat 能看到 5 个附件、本工具显示 0 个时会以为文件"没有附件"
2. 【功能-疑似问题】同名附件误伤风险：移除按名字匹配 detach(name)（:86-90），两个同名附件会被一起移除且无法只删其一；列表 key 也用 a.name（:135）重复名渲染复用
3. 【交互】保存副本后全量重置：atts 清空 + base.clear()（:107-112），连续操作（先删 2 个再补 1 个说明文件）被迫重新拖入重新扫描
4. 【可用性】附件列表 320px 钉高内部滚动（:176），大列表浏览憋屈（共性-根因 2 家族值随机取值的又一例）
5. 【交互】双保存按钮语义重叠："保存副本"与"移除所选（N）并保存"调用同一个 saveCopy（:150-155），勾选后出现两个都能完成同一动作的按钮
6. 【功能】无附件内容预览：图片/PDF 附件不能先看后下，判断"哪个是要的"只能逐个下载（Acrobat 附件面板支持打开预览）
7. 【诚信】对已签名 PDF 做增删附件会破坏数字签名，工具无任何警示——重存副本即签章失效，合规场景用户无从知晓
8. 【灵魂】无合计行（共 N 个 · 合计 X MB）；添加侧无已选文件大小汇总（:146 FileDrop 只显文件名）

## 行业对标与差距

- **Adobe Acrobat 附件面板**：树状列表（含 Portfolio）、双击打开预览、按附件类型图标区分、可"从所有页面删除附件"。差距：Portfolio 支持与预览能力。
- **PDF24 提取附件**：免费提取+打包，流程一致但同样不做 Portfolio。差距不大，本工具的"增/删"能力反而更全。
- 借鉴优先级：**合计行与已选汇总 > 附件预览（图片/PDF blob URL）> 同名去重提示 > Rendition/Portfolio 边界提示**。

## 可拓展性

- 短期（1 周）：列表底部合计行；保存副本后保留文件与列表（只增量刷新 atts）；同名附件行标注"同名 n 个"
- 中期（1 月）：图片/PDF 附件点击预览（URL.createObjectURL）；检测 doc.catalog 的 Collection/Renditions 键并提示"含 Portfolio/多媒体附件，此处不可见"
- 远期：与 batch-pdf 联动"批量移除附件"动作；输出"附件清单.txt"随 ZIP 供归档对账

## 优化处方（验收标准）

1. **合计行**：列表底部显示"共 N 个附件 · X MB"。→ **验收：3 个附件的 PDF 合计值与逐项大小之和一致**
2. **保留上下文**：保存副本成功后不 clear 文件，刷新列表为新副本状态。→ **验收：移除 1 个附件保存后，列表仍在且计数减 1，可直接继续操作**
3. **同名提示**：检测到重名附件时行内标注并禁用按名移除。→ **验收：构造两个同名附件，出现警示且保存前提示将同时移除**
4. **边界披露**：扫描完成 toast 追加"仅支持标准内嵌附件，Portfolio 不显示"。→ **验收：含 Portfolio 的 PDF 扫描后出现该提示**
5. **签名警示**：load 后检测 AcroForm/Sig 字段存在时提示"该文件含数字签名，修改附件将使签名失效"。→ **验收：签过名的 PDF 载入后出现警示条**
