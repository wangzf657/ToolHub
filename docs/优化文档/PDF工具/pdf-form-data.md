## 结论与优先级

**交互优化** · P1（预览表补文件名列＋基础排序搜索是第一步，批量进度第二步）

判据：60 分；汇总链路可靠且导出超出同类，但"结果表格体验"这一任务书点名的场景在屏上不可辨识（无文件名列），确认成本高。

## 扣分点明细

1. 【可用性-硬伤边缘】预览表无文件名列：rows 渲染只有序号＋字段（FormSpreadsheet.vue:109-121），fileNames 仅在 exportXlsx 拼入首列（:48）——屏上无法核对"哪一行对应哪份 PDF"，HR 场景核对是主流程；列头也无来源文件排序
2. 【可用性】结果区 table-wrap 钉死 520px（base.css:362-367 共性-根因 2），且位于拖放区＋执行按钮之下，与 M-16（csv-viewer 表格 top=648 首屏外）同构：填完表要滚动才能看到汇总
3. 【功能】表格无排序/搜索/列显隐：找"某个人填的表"只能肉眼扫；50 行预览截断后无法翻页查看（:116 slice 固定）
4. 【功能】复选框值导出为中文"是/否"（pdfEngine.ts:816 isChecked ? '是':'否'）——下游 Excel 数据透视/脚本处理需要的是 TRUE/FALSE 或 1/0，口径未提供选项
5. 【性能】100 份表单串行整册解析且 busy 期间无逐份进度（:24-39 仅 spinner）；XFDF/FDF 导出又把每份文件重新完整解析一遍（:67-68），浪费一半时间
6. 【交互】同一文件重复添加不警告（FileDrop 共性，见 merge-pdf.md 扣分 8）——重复份会在表里出两行，汇总口径悄悄失真
7. 【灵魂】无"空字段高亮"（哪些人漏填了某字段一眼看不出）；导出后无"已导出"状态标记，容易重复点击

## 行业对标与差距

- **Adobe Acrobat**：多表单"合并数据文件到电子表格"出标准 CSV，字段可映射改名。差距：字段名映射/改名能力（AcroForm 内部名直出对下游不友好）。
- **convertcsv.com**：结果表即时排序、过滤、每列统计。差距：屏上数据加工能力。
- 借鉴优先级：**文件名列＋行排序 > 漏填高亮 > 字段名映射 > 逐份进度 > TRUE/FALSE 口径开关**。

## 可拓展性

- 短期（1 周）：预览表首列加文件名；列头点击排序；结果区高度改弹性（calc(100vh - 330px)）
- 中期（1 月）：逐份进度条（files.length 已知）；XFDF/FDF 复用 process 的解析结果不再二次 load；布尔口径选项
- 远期：与 fill-pdf-form 组成"表单双向工作台"：汇总出表 → 表内改数 → 批量回填生成 N 份已填 PDF（闭环 HR 场景）

## 优化处方（验收标准）

1. **文件名列**：预览表首列显示来源文件名（截断+title 全名）。→ **验收：拖入 3 份不同名的 PDF，每行首列文件名与实际一一对应**
2. **排序/搜索**：列头点击排序＋表上方搜索框过滤行。→ **验收：点"姓名"列头按拼音/字母序重排；搜索关键词后仅剩匹配行**
3. **弹性结果区**：结果表格高度 calc(100vh - 330px) 下限 420px。→ **验收：1366×768 下无需滚动页面即可见 ≥20 行汇总**
4. **逐份进度**：解析循环回调进度"N/总数"。→ **验收：100 份文件解析时进度数字递增而非只有 spinner**
5. **漏填高亮**：空单元格浅黄底色。→ **验收：1 份漏填"日期"字段的表单在表中该格黄底可见，导出 xlsx 同步底色**
