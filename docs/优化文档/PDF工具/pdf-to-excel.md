## 结论与优先级

**交互优化 + 需拓展** · P1

判据：52 分；"盲盒转换 + 数值不可计算"是双重硬伤；表格检测从空白启发式升级到坐标聚类（pdfjs transform 可达）属纯前端可及的功能拓展，与 iLovePDF 的差距应如实标注为架构天花板但给出可达路径。

## 扣分点明细

1. 【功能-硬伤】数值全部以文本写入单元格：pageToRows 返回字符串数组直接 aoa_to_sheet（`PdfToExcel.vue:22,:46`），未调用 officeEngine.smartCell（`officeEngine.ts:45-50`），转出的 Excel 不能直接 SUM/排序——"转 Excel"的核心价值（可计算）落空，疑似功能缺陷
2. 【可用性-硬伤边缘】无检测预览：用户看不到哪些行被判定为表格、切出了几列，调 minCols 全凭下载后盲试（`PdfToExcel.vue:56` 直接下载，模式 F 家族共性）
3. 【功能】切列规则对真实 PDF 失效率高：pdfjs 拼接文本时列间距未必保留为"2+ 连续空格"（`pdfEngine.ts:676-678` 仅按 y 换行、按 item.str 原样拼接），版式规整的财务表常整页变单列；无坐标聚类兜底
4. 【功能】无框线表格与多表同页无区分：一页两个表被压进同一 sheet 连续拼接（:40-49 每页一个 sheet，无表间隔断），表头行也不加粗
5. 【可用性】有表格行时单列文本行被整行丢弃：`tableRows.length ? tableRows : ...`（`PdfToExcel.vue:43-44`）分支下，夹在表格间的标题/注释行静默消失，无任何提示
6. 【交互】"至少列数（判定为表格行）"文案是开发者视角（:72），无解释示例（如"设为 3 = 至少 3 列才算表格"）；minCols 允许手输超出 2~6（input min/max 不拦手动键入）
7. 【灵魂】扫描件仅 toast 一句（:52），未像 pdf-to-word 那样给出"请先使用扫描件 OCR"的站内引导话术——同家族不一致
8. 【交互】输出名固定"表格.xlsx"（:56）——家族共性（merge-pdf.md 扣分 7）

## 行业对标与差距

- **iLovePDF（云）**：几何+字体特征识别表格边界与单元格合并，数值以数字类型写入。差距：识别质量是云端天花板；但**数值类型转换（smartCell 一行代码）与检测预览**是本仓库一天内可补的。
- **Tabula（开源）**：用户框选区域→按标尺线聚类出表，"所见即所得"式选择是对抗启发式失准的正解。启示：pdfjs 的 text item transform 含 x/y 坐标，按 x 间距聚类即可显著优于空白切列。
- 借鉴优先级：**检测预览（命中行高亮+列数展示）> 数值类型写入 > x 坐标聚类切列 > 多表/表头识别**。

## 可拓展性

- 短期（1 周）：smartCell 接入（数字/负数/千分位转数值）；转换前预览 sheet 前 10 行；扫描件引导话术对齐 pdf-to-word
- 中期（1 月）：基于 text item x 坐标聚类切列（间距 > 2 倍中位字宽判列界）；同页多表按空行+列数变化断表；表头行加粗
- 远期：与 pdf-to-markdown 共享"表格检测层"；接入 SheetJS 社区版公式无关的列宽/样式写入提升开箱观感

## 优化处方（验收标准）

1. **数值可计算**：写入前逐格过 smartCell（含千分位"1,234.5"清理）→ **验收：含金额列的表格 PDF 转出后，对金额列 SUM 返回正确数值而非 0**
2. **检测预览**：执行后先展示"第 X 页：命中 N 行表格行（示例前 5 行切列结果）"+确认下载 → **验收：拖入规整表格 PDF，预览可见切开的列；单列页标注"未检测到表格"**
3. **坐标聚类切列**：列界判定改用 x 坐标间距聚类，空格切列为兜底 → **验收：一份无连续空格的框线财务表，转出后列数 ≥3 且与视觉列一致**
4. **丢行提示**：存在表格行且单列行被丢弃时，stat 显示"已忽略 N 行非表格文本" → **验收：夹标题的表格页提示数字正确**
5. **文案与边界**：minCols 输入框失焦时钳制到 2~6；标签改为"表格最少列数"并带悬浮解释 → **验收：手动键入 9 失焦后自动回 6**
