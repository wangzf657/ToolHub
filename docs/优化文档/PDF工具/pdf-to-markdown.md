## 结论与优先级

**交互优化 + 需拓展** · P1

判据：59 分；规则透明诚实，但标题判级靠正则猜（章节号/全大写）而 pdfjs 每行的字号信息（transform）现成未用——字体大小判级是纯前端可达的结构化跃迁，属明确需拓展；渲染预览缺失属交互补课。

## 扣分点明细

1. 【功能】标题判级不用字号用正则：仅"第 X 章/节/篇"（`PdfToMarkdown.vue:71`）与全大写西文（:77）两种猜测判 ##；pdfjs text item 的 transform 自带字号（`pdfEngine.ts:673` 已取 transform 却只用 y），1.5 倍正文字号判 H1/H2 的通用方案未做——大多数无章节编号的现代文档标题全部漏判
2. 【可用性】无渲染预览：markdown 源码直出（:128），表格对齐是否正确、标题层级是否合理要复制到别处才知道；站内已有 markdown 预览能力（开发工具 MarkdownPreview）却未联动
3. 【功能】表格判定与 pdf-to-excel 同源同病：2+ 空格切列（:63）对无空格间距的真实 PDF 常失效，且无列坐标聚类兜底；表格内标题/列表规则互相干扰（表格行优先级高于标题，:63-68 先判表格）
4. 【功能】图片零处理：PDF 内插图既不转 base64 嵌入也不生成 `![](图-n.png)` 占位——marker/pdf2md.cc 均输出图片引用
5. 【交互】零选项：标题识别规则、表格开关、分页注释均不可调（:101 硬编码多页才加注释）；AI 语料场景常需要"去分页注释"的一键开关
6. 【灵魂】无空态示例：不知道转换效果的首次用户没有样例 PDF 一键体验入口
7. 【可用性】列表嵌套拍平：多级列表（缩进）统一转一级 `- `（:56-61 无缩进解析），大纲结构丢失
8. 【交互】大文档无进度且失败静默：catch toast.err 有（:109）但提取阶段无逐页进度；300 页文档 spinner 独转

## 行业对标与差距

- **pdf2md.cc（云）**：基于版面分析输出标题层级/列表/表格/图片引用，转换后在线双栏预览。差距：**预览环节 + 结构推断深度**双代差；版面模型是云端天花板，但字号判级可达其 60% 水平。
- **Microsoft markitdown（开源）**：PDF 走 pdfminer 结构推断，图片转 base64/引用，支持公式。差距：图片引用与公式能力。
- **marker（开源）**：版面检测模型（OCR + 布局）输出高质量 md，学术 PDF 标杆。差距：模型级能力属天花板；其"标题层级置信度"思路可用字号规则近似。
- 借鉴优先级：**字号标题判级 > 渲染预览（复用站内能力）> 图片占位/嵌入 > 列表嵌套解析**。

## 可拓展性

- 短期（1 周）：选项区三开关（分页注释/表格识别/标题规则）；空态样例入口；进度文案
- 中期（1 月）：字号判级（正文众数字号归一化，≥1.5x→H1、1.2~1.5x→H2）；结果区加"源码 | 渲染"Tab（复用站内 markdown 渲染器）；列坐标聚类表格兜底
- 远期：图片抽取按页面位置生成引用清单（复用 extractImages）；与 pdf-to-text/excel 共享版面解析层三输出

## 优化处方（验收标准）

1. **字号判级**：正文众数字号基准，≥1.5 倍判 H1、1.2~1.5 倍判 H2，正则仅作兜底 → **验收：无章节编号的商务 PDF（视觉大标题）转出后含 `#`/`##` 且位置与原视觉标题一致**
2. **渲染预览 Tab**：结果区上方加"源码 | 预览"切换 → **验收：GFM 表格与标题在预览 Tab 正确渲染**
3. **选项三开关**：分页注释/表格识别/全大写标题识别均可开关 → **验收：关表格识别后原表格以段落文本输出**
4. **图片占位**：检测到内嵌图片的页面在 md 中生成 `<!-- 图：本页含 n 张图片 -->` 注释 → **验收：含图 PDF 转出后对应页注释数字与 extractImages 提取数一致**
5. **列表嵌套**：按 text item x 缩进判定层级，转多级列表 → **验收：两级缩进列表转出后含二级 `- ` 缩进结构**
