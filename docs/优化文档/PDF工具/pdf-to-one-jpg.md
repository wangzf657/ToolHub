## 结论与优先级

**交互优化 + 需拓展** · P1

判据：核心链路在小文档可用，但"页数×清晰度"的硬上限既不预防也不解释，属于可用性红线边缘；与 iLovePDF 类工具比缺页选择与分段能力。

## 扣分点明细

1. 【可用性-硬伤边缘】超长图撞 canvas 上限无预警：输出 canvas 总高无上限（`pdfEngine.ts:647-653`），Chrome 单边 ~16384px、面积 ~268MP、iOS 更小——30 页 A4 @1.5x（每页 ~1263px 高）即出界，结果为空白图或报错，用户只收到一句"生成失败，页数过多时请降低清晰度"（`PdfToOneImage.vue:29`）
2. 【可用性】无进度反馈：引擎无 onProgress 回调，组件只有 spinner（`PdfToOneImage.vue:23-33`），50 页文档渲染数十秒内按钮假死，与家族内 pdfToImages/compressPdf（均有进度条）形成落差
3. 【性能】全页 canvas 同时驻内存再拼接（`pdfEngine.ts:627-647`）：内存峰值 ≈ 全部页位图 + 输出大图 ≈ 双倍位图总量，无分批"渲染→写入输出→释放"管线
4. 【功能】无页范围选择与分段导出：超出上限的唯一出路是降倍数，iLovePDF 类产品至少可选页；"每 20 页一张分 5 张"这种分段模式完全没有
5. 【灵魂】成功后无尺寸汇报：长图多少 px×多少 px、多少 MB 只有文件管理器里才知道；"建议倍数≤1.5x"提示（:62）与实际页数无关，是一刀切静态文案
6. 【交互】输出名固定"长图.jpg/png"（`PdfToOneImage.vue:26`），多次生成同名互覆

## 行业对标与差距

- **iLovePDF（同类转换家族）**：页选择网格 + 转换后逐图预览下载。差距：**失败预防与结果确认**。
- **ezgif**（gif/图拼接）：拼接前显示各段尺寸与预估输出大小，超限时明确报"超出行数上限"。差距：超限的量化提示。
- **手机端实践**（iOS 长截图/微信收藏长图）：分段显示或按上限自动分段是通行做法。差距：分段导出能力。
- 借鉴优先级：**载入时超限预警（按页数×倍数即时计算）> 进度条 > 分段导出 > 成功后尺寸汇报**。

## 可拓展性

- 短期（1 周）：引擎加 onProgress；载入后按"页数×当前倍数"即时计算总高并显示"约 N px，超出浏览器上限（~16000px）"，同步建议倍数上限
- 中期（1 月）：分批渲染管线（渲染 N 页→drawImage 到输出→释放 canvas，内存峰值降一个量级）；超限自动改问"是否分段导出"
- 远期：页范围选择（复用 PagePickerTool）；与 pdf-to-jpg 共享"倍数↔DPI"口径与预览组件

## 优化处方（验收标准）

1. **超限预警前置**：载入文档与调整倍数时实时显示"预计长图约 {{宽}}×{{高}} px"；超 16000px 时按钮禁用并提示"页数过多，当前倍数最大 {{maxScale}}x"。→ **验收：30 页 A4 文档默认 1.5x 出现预警且按钮禁用；降到 1x 后按钮恢复可用**
2. **进度反馈**：进度条按"第 X / N 页"推进。→ **验收：20 页文档生成中进度单调递增且文案随页数变化**
3. **成功后汇报**：完成 toast 与结果行显示"{{宽}}×{{高}} px · X MB"。→ **验收：生成 5 页长图后提示数字与实际文件属性一致（±5%）**
4. **分段导出（中期）**：超限时提供"每 20 页一张"分段选项，产出多张图打 ZIP。→ **验收：90 页文档分段导出 5 张图，每张 ≤16000px 高且顺序正确**
5. **输出命名**：默认名改含页数与倍数（如"长图-20页-1.5x.jpg"）。→ **验收：改倍数重新生成后文件名随参数变化**
