## 扣分点明细

1. 【可用性-硬伤边缘】结果区钉死 260px：`PdfToText.vue:39` 传 minHeight 260px，ResultBox 双重钉高（`ResultBox.vue:69` `height: minHeight`），提取 10 万字在 260px 窗口内滚、大屏不放大（共性-根因 2，M-01/M-02 机制同源）
2. 【功能】无页码范围提取：parsePageSpec 现成（`pdfEngine.ts:9-25`）未接入，只要第 3~10 页文本必须全册提取后手动删
3. 【功能】无提取模式切换：阅读顺序直接沿用内容流顺序（`pdfEngine.ts:673-679` 只按 y 换行、无列聚类），双栏论文/杂志提出来左右栏交错串行——pdftotext 的 -layout 模式对应能力缺失且无乱序预警
4. 【功能】无页眉页脚噪声过滤：每页页码/页眉重复进入结果（无"过滤与首末 N 行重复的行"开关），50 页文档结果里 100 行噪声
5. 【交互】大文档无进度：pdfText 无 onProgress（`pdfEngine.ts:663-687` 循环内未回调），300 页 PDF 提取期间仅 spinner，与 pdf-to-word 同病灶
6. 【灵魂】无页分隔标记：页间仅空行（:690 join '\n\n'），处理多页提取结果无法定位页界——pdf-to-markdown 有 `<!-- 第 n 页 -->` 注释（PdfToMarkdown.vue:101）本工具却不提供选项，家族内不一致
7. 【灵魂】无分页诊断：每页字符数为 0 的页（扫描页）不在结果中标注，用户要知道"哪几页是图"只能逐页翻原文档
8. 【交互】catch 后静默清空（`PdfToText.vue:20-22` catch 只置空不 toast），加密/损坏文件失败时无错误原因提示——与家族其他工具的 toast.err 不一致

## 行业对标与差距

- **Poppler pdftotext（CLI）**：-layout（保持版面空隙）/ -raw（内容流原序）/ -f -l（页范围）/ -nopgbrk 四个开关覆盖了本工具缺的全部模式。差距：**模式开关面**——四项均为纯前端可及（pdfjs item 坐标足以实现 layout 模式）。
- **Adobe Acrobat 导出**：可选"纯文本/保留版式"，导出前可预览选中页。差距：页范围与预览。
- 借鉴优先级：**页范围 > layout 模式（列聚类）> 页分隔符选项 > 页眉页脚过滤**。

## 可拓展性

## 优化处方（验收标准）

1. **结果区弹性高度**：min-height 260px 但 height 改 auto/弹性，提供全屏切换 → **验收：1366×768 下 1000 行提取结果同屏可见 ≥28 行；点全屏覆盖整页**
2. **页范围输入**：按钮旁输入"1-5,8"仅提取对应页 → **验收：10 页文档输入 2-3，结果恰为第 2、3 页文本且含页分隔标记**
3. **页分隔符选项**：提供"空行 / 标记行"切换 → **验收：选标记行后结果中每页前出现 `--- 第 n 页 ---`**
4. **失败原因提示**：catch 分支 toast.err 显示引擎错误信息 → **验收：拖入加密 PDF 提取时出现明确错误 toast 而非静默清空**
5. **提取进度**：pdfPageTexts 增加 onProgress，UI 显示"已提取 n/N 页" → **验收：300 页文档提取中文案随页数推进更新**
