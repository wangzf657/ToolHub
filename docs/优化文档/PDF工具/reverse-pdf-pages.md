## 扣分点明细

1. 【功能】双面扫描另一态未覆盖：长边装订双面扫描产出 2,1,4,3 序（成对倒序），全档倒转后变 N,N-1…依然乱——缺"成对倒转"档位
2. 【功能】无区间倒转：300 页文档只需倒转前 50 页（扫描仪卡纸后补扫衔接）时做不到，需提取→倒转→合并三跳
3. 【可用性】产物零反馈：不显示"产物共 N 页"与首页缩略图确认（模式 F 共性；本工具语义简单，降级为摩擦而非硬伤）
4. 【灵魂】预期提示缺失：载入后可免费显示"倒转后第 1 页 = 原第 N 页"（N 已知），建立正确预期只差一行字
5. 【交互】输出名固定"倒序后.pdf"（ReversePdf.vue:23）不可命名——家族共性（同 merge-pdf.md 扣分 7，不重复展开）
6. 【功能】单文件限制：批量倒转一摞扫描件（该场景最常见形态就是成批）需逐个重走全流程（PdfToolBase multiple 默认 false，PdfToolBase.vue:19）
7. 【灵魂】无"再点一次即还原"提示：倒转是对合操作（执行两次=复原），这一零成本彩蛋文案未做，误操作用户不知道怎么安全回头

## 行业对标与差距

- **PDF24 反转页序**：同为全档倒转，附结果页数与预览确认。差距：确认环节。
- **iLovePDF 组织页面**：倒序是缩略图墙工具条上的一键动作，效果即时可视。差距：可视确认（组织器化后的自然形态）。
- 借鉴优先级：产物页数+首页缩略图确认条 > 区间倒转 > 成对倒转 > 预期提示行。

## 可拓展性

- 短期（1 周）：按钮旁回显"倒转后第 1 页 = 原第 N 页"；产物页数反馈
- 中期（1 月）：区间倒转输入框（复用 parsePageSpec）；成对倒转开关
- 远期：并入组织器工具条（作为"倒序"一键动作，与 reorder 的重置/区间操作同屏）
- 站内联动：reorder-pdf 可达成同效果（全手动），本页是其零参数快捷方式；两者的产物确认条应统一实现

## 优化处方（验收标准）

1. **预期提示行** → **验收：载入 30 页文档显示"倒转后第 1 页 = 原第 30 页"，产物首页页码恰为 30**
2. **区间倒转**：输入框复用 parsePageSpec，留空=全部 → **验收：10 页文档输入"1-4"，产物序为 4,3,2,1,5,6,…,10**
3. **成对倒转开关** → **验收：1,2,3,4 测试档产出 2,1,4,3**
4. **产物确认条**（可与家族统一方案共改）→ **验收：完成后显示"共 N 页"+首页缩略图，缩略图与原最后一页内容一致**
5. **批量模式（中期）**：多文件列表逐个倒转 → **验收：3 个文件批量倒转产出 3 个 PDF，zip 内文件名与原名一一对应**
