## 结论与优先级

**交互优化 + 需拓展** · P1

判据：57 分；可用性（静默吞页码+零预览+性能陷阱）触发硬伤边缘；与 iLovePDF 的可视化选页差距属需拓展——而解药（PageThumbs rotatable）就在自家组件库里。

## 扣分点明细

1. 【可用性-硬伤边缘】页码静默容错：parsePageSpec 把 "5-999" 钳成 "5-末页"（pdfEngine.ts:16-17）、把 "0,abc,300"（300>总页数）等无效 token 静默丢弃（:20-21），仅当结果为空才提示（RotatePdf.vue:31-33）——用户以为转了 300 页实际只转了少数几页，且产物方向不可见
2. 【性能-个性缺陷】选定页旋转逐页全档往返：`for (const i of idx) blob = await rotatePage(blob, i, deg)`（RotatePdf.vue:35-36），rotatePage 每次重新 load+save 整个文档（pdfEngine.ts:135,139）——对比 rotatePdf 全档一次成型，是明显的引擎层反模式
3. 【可用性】零预览：转对没有只能下载打开确认；"顺时针 270°（= 逆时针 90°）"（:58）靠文字区分方向，无 ↻/↺ 图标直观示意
4. 【功能/架构】无缩略图点选页——自家 PageThumbs 的 rotatable 能力（PageThumbs.vue:140-145 + 旋转角标 :192）已实现且 PdfStudio 在用，本工具却走纯文本框路线，工具间体验割裂
5. 【灵魂】范围输入旁不回显"共 N 页"（PdfToolBase.pageCount 现成可取），用户构造"1-N"范围只能靠猜
6. 【交互】输出名固定"旋转后.pdf"（:38）——家族共性（同 merge-pdf.md 扣分 7，不重复展开）
7. 【功能】无"恢复原始方向/旋转归零"档位——当前旋转角本可读（pdfEngine.ts:127 getRotation），读出即可归零，属零成本缺失
8. 【灵魂】选项不记忆：deg/pages 每次进入默认 90°/空（RotatePdf.vue:12-13），常转 180° 的用户每次重选；无 localStorage 偏好（家族普遍现状，本页表单短尚可容忍）

## 行业对标与差距

- **iLovePDF 旋转**：缩略图网格逐页点转+全选，页面方向所见即所得。差距：**可视化选择代差，且补齐成本极低（组件已存在）**。
- **PDF24 旋转**：仅奇数页/仅偶数页分组旋转（修复合扫描的错向）、旋转预览。差距：分组策略与预览。
- 借鉴优先级：接入 PageThumbs 可视化选页 > 引擎批量旋转（单次 load/save）> ↻↺ 图标按钮 > 越界明确警告。

## 可拓展性

- 短期（1 周）：范围输入旁回显"共 N 页"；越界输入改为明确警告（"第 300 页不存在，文档共 120 页"）
- 中期（1 月）：PageThumbs 可视化选页模式（selectable+rotatable 组合）；引擎新增 rotatePages(file, indices[], deg) 单次 load/save 批量写
- 远期：与 delete/extract 合并组织器（旋转作为组织器工具条动作）
- 站内联动：PdfStudio 工作台已实现缩略图逐页点转，rotate-pdf 应直接复用该交互而非另造文本框路线

## 优化处方（验收标准）

1. **越界警告替代静默钳制** → **验收：120 页文档输入"5-999"出现"范围已截断至 5-120"提示且可继续执行**
2. **引擎批量旋转**：新增 rotatePages 单次 load/save → **验收：120 页文档选 60 页旋转耗时 ≤ 全档旋转的 2 倍（现状约 60 次整档往返）**
3. **PageThumbs 可视化选页**：缩略图点选+每页旋转按钮，角标实时显示累计角度 → **验收：点转第 3 页两次显示 180°，产物仅第 3 页方向改变**
4. **方向图标按钮组**（↻90°/↺90°/180°）替代 select → **验收：点"↺"一次与点"↻"三次产物方向一致**
5. **旋转归零档位**：新增"清除旋转（归零）"选项 → **验收：对已带 90° 旋转角的页面执行归零，产物旋转角为 0**
