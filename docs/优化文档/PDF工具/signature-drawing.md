## 结论与优先级

**交互优化** · P1（导出纯度/裁边是功能级修正，衔接与性能其次）

判据：66 分；无可用性硬伤，核心书写体验扎实，但"透明 PNG 带淡框"这一输出缺陷直接影响它唯一的存在价值（做图章）。

## 扣分点明细

1. 【功能-疑似缺陷】导出"透明 PNG"不纯：画布初始化与每次重绘都把 3.5% 透明度的基线和边框画进同一画布（SignatureDrawing.vue:31-34、:69-72），produce() 原样 toBlob（:110-113）——下载/复制的 PNG 自带一圈极淡灰框与横线，盖到 PDF 纸面上会留下淡淡的框印
2. 【功能】无墨迹裁边：导出保留整幅 720×300 含空白边，对比同站 PdfStudio 签名板会扫描非空边界裁剪（studio/SignaturePad.vue:63-87）——同站两套标准；空白边还让 insert-image-pdf 的"占页宽%"换算失真（签名看起来只有设定尺寸的一半）
3. 【灵魂】与盖章工具只有文案级衔接（:171"可到「给 PDF 添加图片」盖章"），无"直接送去盖章"按钮、无签名素材本地保存，下次使用全部重写
4. 【功能】笔色仅黑/蓝/红三选（:140-144），无自定义色与笔型（荧光/马克笔）；对比 Excalidraw 的笔迹生态差距明显
5. 【性能】pointermove 每次全量重绘全部笔画（:66-99），O(总点数) 随书写增长；可改增量绘制＋仅撤销/清空时全量重绘
6. 【交互】导出无分辨率/尺寸选项，内部固定 720×300；笔画少的签名导出后大片留白（与扣分 2 叠加）

## 行业对标与差距

- **Excalidraw / tldraw**：perfect-freehand 轮廓笔迹、压感+倾斜双参数、笔画可选中再编辑。差距：我们的压感变宽已有 70 分水准，输出端（裁剪/纯透明/导出选项）是短板。
- **Smallpdf eSign**：画/打字/上传三来源采集，签名保存为账号模板跨文档复用。差距：来源单一、零复用。
- 借鉴优先级：**导出裁边＋纯透明 > 与 sign-pdf/insert-image-pdf 一键衔接 > 打字/上传来源 > 增量绘制**。

## 可拓展性

- 短期（1 周）：导出前按墨迹包围盒在离屏 canvas 重绘（天然剥离基线/边框，逻辑参照 studio/SignaturePad.vue:63-87）；move 改增量绘制
- 中期（1 月）：签名素材 localStorage（key 前缀 toolhub，存最近 5 个），sign-pdf/insert-image-pdf 提供签名选择器；打字签名（系统手写体）
- 远期：signature-drawing + sign-pdf + insert-image-pdf 合并为"签署工作台"（模式 E），签名资产一处管理多端放置
- 短期补强：笔色 select 改为"黑/蓝/红色板＋自定义取色"，与笔宽滑杆同行收纳

## 优化处方（验收标准）

1. **纯透明导出**：produce() 按墨迹包围盒离屏重绘（不含基线/边框）。→ **验收：只写一个"王"字导出，PNG 四角与四边 alpha=0（取色器检查），图中无水平横线**
2. **裁边生效**：导出尺寸=墨迹包围盒＋6px 边距。→ **验收：在画布角落写小签名，导出 PNG 宽高 < 400px（而非 720×300）**
3. **一键衔接**：下载行加"送到 PDF 签名"按钮，携带签名跳转 sign-pdf 并自动载入签名板。→ **验收：点击后落地 /t/sign-pdf 且无需重画即可放置**
4. **增量绘制**：pointermove 只绘最新线段，undo/clear 时全量重绘。→ **验收：连续书写 2000 点过程中无卡顿（与修改前对比）**
5. **移动端画布**：≤560px 视口画布高度提升。→ **验收：390×844 下画布可视高度 ≥220px（当前约 160px）**
