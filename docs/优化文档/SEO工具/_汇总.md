- **均分 58.8 / 100**（13 项），区间 50~66，是全站分差最小但整体中位偏低的分类：无高分标杆，也无崩塌项。

## 二、schema 六件套 Tab 路由化杠杆（一处改惠及 6 项）

- 证据：六件套共用 `SchemaGenerators.vue`（220 行），`const tab = ref<Tab>('article')` 硬编码（**SchemaGenerators.vue:7**，无 useRoute 读路由）；注册 6 个 slug（registry.ts:28,52-60）。
- 后果：除 article 外 **5 个 URL 首屏表单与工具名不符**（faq/product/event/localbusiness/breadcrumb 落地即 Article 的 headline/作者表单），SEO 落地页与内容错位，breadcrumb 档案称其为"六 slug 中语义落差最明显的一个"。
- 修法：tab 初始化按 slug 映射（route→Tab 一张表），一处改惠及 6 项，是本分类杠杆最大的单点。
- 字段完整性对照表（vs Google 富结果文档 / technicalseo 口径）：

| 类型 | 现有骨架 | 缺什么（按影响排序） |
|---|---|---|
| article | headline/author/publisher/description/image/datePublished+Modified/url@id | publisher.logo、author.url/sameAs（E-E-A-T）、datetime（现仅 date）、字段必填分级 |
| product | name/brand/description/image/offers(price+currency+availability)/rating | sku/gtin/mpn 标识符、评分配对提示（:53 `&&` 单填静默消失）、shippingDetails/hasMerchantReturnPolicy、priceValidUntil、ISO 4217 币种校验 |
| localbusiness | name/image/phone/address 五段/hours/geo/priceRange/url | 逐日营业时间构建器（现手写 `Mo-Sa 09:00-19:00` 无校验）、address 空壳修复（:65-68 无条件展开）、aggregateRating、@type 子类型、国家 ISO 下拉、坐标拾取指引 |
| event | name/status 四态/起止时间/venue/price/URL | eventAttendanceMode 三态（缺它线上活动富结果验证不过）、location PostalAddress（现逗号字符串 :76）、offers availability/validFrom、时区标注、performer/image |
| breadcrumb | name+url 行编辑 | 从 URL 推导层级（SerpPreview.vue:25-34 同款算法可复用）、中间层 URL 校验、"与页面可见导航一致"提示 |
| faq | q/a 行编辑 | Google 2023-08 政策披露（富结果已收缩至政府/健康站）、批量粘贴导入、验证直达 |

- 家族共享病（各档案已编号）：家族-1 落地 Tab 错位（上文杠杆）；家族-2 无 Rich Results Test 直达（:195 仅文字提示，"生成＋验证"闭环缺后半环）；家族-3 双 ResultBox 钉 190px 内滚＋字段级校验缺失。

## 三、SEO 家族零联动问题

- 现状：13 项两两零互链，站内天然搭档全部断开——
  1. **robots ↔ sitemap 协议成对**：robots-txt-generator（开发分类）处方 6 已承诺带域名互跳，sitemap 页无任何回链，用户两页各填一次域名；
  2. **heading → breadcrumb**：heading 刚解析出页面层级大纲，breadcrumb 要逐层重敲（markdown-toc 导出桥也缺）；
  3. **文本分析三件互不导流**：keyword-density/readability/heading 与 word-counter、word-frequency-counter 同源 nlpEngine 却零互链；
  4. **跨分类字段双标准**：serp-preview ↔ meta-tag-generator（开发分类）title/description 重复录入互不感知（meta 档案已裁定以 serp 口径收敛）；utm → serp 只差一条"预览这条链接的 SERP 展示"互链；
  5. **hreflang ↔ sitemap**：多语言站第二官方形态 `xhtml:link` 无处衔接。
- 整合愿景：DEV-5b「SEO 工作台」（meta-tag-generator.md 已立）——一次录入 title/desc → SERP 预览＋meta 标签＋OG 社交卡片三份产出，字段走 localStorage 共享；远期贴域名 → sitemap＋robots 一次产出。
- 成本判断：互链是全分类性价比最高的一档——13 份档案"短期（1 周）"清单里互链类动作出现 8 次，全部是结果区挂链接级改动。

## 四、P0 与疑似缺陷清单

**P0（1 项，疑似功能缺陷，交用户决定，本轮不改码）**
1. readability 中文评分塌陷：`avgWordLen = en ? enChars/en : cjk`（nlpEngine.ts:355）把全文汉字总数当词长，纯中文 ≥20 字得分恒 0 且标"很难（专业）"；keywords 标注 flesch（registry.ts:32）实为自造线性公式——名实不符＋对主要受众整体失效，修复后回收约 4~6 分需重评。

**疑似缺陷 / 口径矛盾（P1 内的硬伤级扣分）**
2. serp 像素口径自相矛盾：估算按中文 12px 字宽（SerpPreview.vue:15），渲染字号实为 20px（:127-129），px 数值系统性低估约 40%——effLen≤60 判级兜住了结论，但展示的像素不可信。
3. hreflang 拒绝中文子标签：`LANG_RE ^[a-z]{2,3}(-[A-Z]{2})?$`（:29）拒收 zh-Hans/zh-Hant，简繁互指恰是中文多语言站最高频场景，且 UI 下拉无法表达校验器本允许的 2-3 位码。
4. keyword-density desc 超售：注册表 desc 写"可选过滤停用词"（registry.ts:11），textDef `options: []` 无任何选项，停用词过滤是引擎硬编码且不可关。
5. utm 参数静默覆盖：URL 自带 utm_source 时 `sp.set()` 直接顶掉（:33-37）无警示；示例默认值（wechat/social/spring-sale）与真实值无视觉区分，无"清空示例"。
6. schema-product 评分黑洞：rating 与 reviews 须双填才输出 aggregateRating（:53 `&&`），单填静默消失——用户以为带了评分实际没带。
7. schema-event 线上矛盾：eventStatus 可选"改为线上"（:168）却无 eventAttendanceMode 字段，富结果验证不通过。
8. sitemap 误导性输出：Google 已声明忽略 changefreq/priority，工具照常提供六档频率选择不披露（并入第五节声明规范）。
- 横向结论：13 项中 4 项存在"描述/口径与实现不符"级信任问题（readability/keyword-density/serp/sitemap）——本分类的专业性短板不在能不能算，在敢不敢说。

## 五、纯前端能力边界专项（诚实声明规范）

- **sitemap 无爬站**：xml-sitemaps.com 输入域名即爬全站（云端架构），本工具实现路径是"手动贴 URL 列表→XML"，受 CORS 架构天花板必墙；现状 notice 只讲行内语法（:81-84），连"这是列表编译器不是爬虫"的边界声明都没有。
- 同病：heading-structure-checker 不支持贴 URL 只本地解析，notice 未解释 CORS 边界，用户疑惑"为什么不能直接查网址"（其扣分 5）。
- 站内已有正向样板可循：serp-preview 的估算口径自白（:98-101）、word-frequency-counter 的"简化分词"披露。建议形成**固定三行式声明**：能做什么／不能做什么及原因（CORS/官方口径）／替代路径（下载 HTML 后贴入、搜索控制台提交、外链直达 Rich Results Test）。
- 其余天花板按"标注＋可逼近"处理：utm.io 的云端批量/历史（纯前端用 localStorage 历史＋CSV 导出逼近）、technicalseo 的云验证（用验证器外链直达逼近）。

## 六、与行业 Top 差距地图

| 工具组 | 行业 Top | 核心差距 | 纯前端可及性 |
|---|---|---|---|
| sitemap | xml-sitemaps.com | 爬站、sitemap index、URL 去重 | 爬站为云天花板；index/去重/披露可及 |
| schema 六件套 | technicalseo.com（Merkle） | 12+ 类型、字段说明与分级、生成＋验证闭环 | 字段补全/分级/验证外链均可及 |
| readability | readable.com ＋ Hemingway | 多公式体系、逐句五级标色定位到句 | splitSentences 已有（nlpEngine.ts:11-17），完全可及 |
| serp-preview | portent ＋ metatags.io | canvas 像素实测、关键词加粗、多引擎 | canvas measureText 可及；多引擎含百度视图可及 |
| hreflang | ahrefs generator | BCP47 文字子标签、组合去重校验、URL 推导 | 正则级修复，全部可及 |
| utm | Google Builder ＋ utm.io | 历史记录、批量矩阵、参数冲突检测 | localStorage 历史/批量可及；云同步为天花板 |
| keyword-density | wordcounter.net | 目标词双模式、表格化＋条形图 | 全部可及 |

- 分档结论：无一工具达到对标 Top 的完整形态；差距集中在三类——口径诚实（1 处声明规范）、字段完整（schema 系 6 项）、交互闭环（验证直达/复制/互链）；**没有任何差距属于"纯前端做不到"**，天花板只存在于爬站与云同步两处，且都可由声明规范兜住。

## 七、分类优化路线图

- **第一批（1 周，修疑点＋杠杆）**：readability 中文评分修复（P0，先修后重评）；SchemaGenerators tab 路由化（一处改 6 项受益）；hreflang 正则放行 zh-Hans/zh-Hant；serp 一键复制＋清空示例＋站点名可编辑；keyword-density desc 改口径或兑现停用词开关。
