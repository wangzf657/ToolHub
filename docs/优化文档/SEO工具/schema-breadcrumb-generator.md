## 结论与优先级

**交互优化** · P2

判据：六件套中产出质量最完整、门槛最低的一员，扣分集中在家族共享问题（落地 Tab/钉高/验证直达）与"URL 推导"级的锦上添花，无域专业缺口。

## Schema 六件套家族共性（六 slug 共用本组件，证据一致）

- **家族-1**：六 slug 共用组件且 `tab` 恒为 `'article'`（:7，无 useRoute）——本 slug 首屏错位；
- **家族-2**：校验只有层级名非空的行过滤（:80），无 URL 格式校验、无 Rich Results Test 直达（:195）；
- **家族-3**：双 ResultBox 钉高（:193-194）；空字段省略（:31-35）＋转义防注入（:89）为共同加分项。

## 扣分点明细

1. 【可用性】落地 Tab 错位（家族-1）：URL 说面包屑，第一屏是 Article 表单——六 slug 中语义落差最明显的一个
2. 【功能】无"从 URL 推导"：粘贴 `https://site.com/blog/2026/post` 应可自动拆出 首页/博客/2026/文章 四层（站内 serp-preview crumbs 逻辑 SerpPreview.vue:25-34 已实现同款算法，复用即可），现要求逐层手填
3. 【灵魂】缺"与页面可见导航一致"提示：Google 明确要求 schema 面包屑须与页面实际显示的面包屑一致，工具无此提醒，产出可能与真实页面脱节
4. 【功能-轻】URL 校验缺失：任意字符串填入照常输出（:80 只滤 name 空），非 http(s) 的 item 会导致验证告警；中间层 URL 留空时输出无 item 的 ListItem（:82 条件仅"末级可留空"语义，中间层留空静默产生 item 缺失）——与 placeholder 承诺不符
5. 【交互】无验证直达（家族-2）；六 Tab 横排 chips 在窄屏挤压（:94-96）
6. 【交互-轻】与 heading-structure-checker 零打通：那边刚解析出页面层级大纲，这边要逐层重敲
7. 【可用性-轻】双 ResultBox 钉高（家族-3）：Breadcrumb JSON 短（5 层约 20 行），190px 略紧但伤害全家族最小

## 行业对标与差距

- **technicalseo.com**：Breadcrumb 生成器逐层 URL＋即时预览面包屑视觉效果。差距：**可视化预览**（层间分隔符渲染）＋字段校验；纯前端 CSS 模拟即可。
- **Google 面包屑文档**：要求与页面可见导航一致、末项可省 URL、position 从 1 起。差距：一致性与中间层留空的处理逻辑。
- 借鉴优先级：**从 URL 自动推导 > 可见导航一致性提示 > 中间层 URL 校验 > 面包屑视觉预览 > 落地 Tab 路由化**。

## 可拓展性

- 短期（1 周）：路由化初始 Tab；URL 非空行校验 http(s) 并黄条；"与页面可见导航一致"notice；hint 挂验证器外链
- 中期（1 月）："从 URL 推导"按钮（复用 crumbs 拆解）；中间层 URL 留空时黄条说明"将输出无 item 的层级"；面包屑视觉预览条
- 远期：与 heading-structure-checker 互链（大纲一键转面包屑层级）；六件套合并"结构化数据工作台"

## 优化处方（验收标准）

1. **落地 Tab 路由化**（家族-1）。→ **验收：直达 /t/schema-breadcrumb-generator 首屏即面包屑层级行**
2. **从 URL 推导**：加"粘贴 URL 自动分层"输入，按路径段拆层（末层名可用文本改写）。→ **验收：粘贴 `https://a.com/blog/2026/post` 生成 4 行层级且首层为域名、position 正确**
3. **URL 校验**：item 非 http(s) 开头黄条警告。→ **验收：填 `blog` 触发警告；补全 URL 后消失**
4. **一致性提示**：Tab 顶部常驻 notice"schema 面包屑必须与页面实际显示的面包屑一致"。→ **验收：文案常驻不随输入变化**
5. **中间层留空说明**：中间层 URL 留空时黄条"该层将输出无 item 的 ListItem（Google 允许但建议补充）"。→ **验收：第二层留空触发黄条，末层留空不触发**
