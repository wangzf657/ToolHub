## 一、五条全局根因（共性-根因 1~5）

### 共性-根因 1：竖向预算被装饰层吃掉
工具页 DOM 堆叠（桌面 1440px 宽估算）：
- sticky 站头 60px（`src/components/layout/SiteHeader.vue:104-109`，常驻）
- 页面顶部留白 30px（`src/pages/ToolPage.vue:53`，inline `padding-top: 30px`）
- 面包屑 ~39px（13px 字号 + margin-bottom 18px，`src/components/common/Breadcrumbs.vue:29-30`）
- H1 ~60px（clamp(28px,4vw,40px)，`ToolPage.vue:119-121`）
- 隐私徽章 ~33px（`ToolPage.vue:123-132`）
- tool-head 下间距 22px（`ToolPage.vue:116`）
- `.tool-panel` padding 22px（`ToolPage.vue:169-172`）

**→ 工具第一个控件出现在视口顶下 ~266px；768px 高笔记本首屏被页头装饰消耗约 35%。所有 520 个工具共享此前缀。**

### 共性-根因 2：高度策略"固定值 + 内部滚动"，结果区无法变大
- `ResultBox.vue`（开发者工具主输出组件）：`:style="{ minHeight, height: minHeight }"`（`src/components/common/ResultBox.vue:69`）——**height 被同时钉死**，默认 180px（:18），只能靠用户手动 resize:vertical 拖大。调用方最多传 320px。
- 全局 `.textarea { min-height:180px }`（`src/styles/base.css:164-168`）——TextTool 输入/输出各钉 180px。
- 全局 `.table-wrap { max-height: 520px }`（`base.css:362-367`）。
- 全站 60+ 处固定 `max-height`/钉高清单见下表。
- **除 4 个工作室（52~74vh）外，没有任何一处结果区用 `flex-1`/`calc(100vh - …)` 弹性高度。**

代表性收紧点（file:line：px）——同一"结果区"家族从 96px 到 560px 随机取值，全站无一致性：
- developer：RegexTester.vue:144=220｜JwtDecoder.vue:130、RsaKeyGenerator.vue:111、EncodingConverter.vue:191=260｜SvgOptimizer.vue:151=300｜JsonPathTester.vue:93、TextDiff.vue:92、MarkdownToImage.vue:109、UnicodeLookup.vue:103=420｜JsonVisualizer.vue:155=480｜MarkdownPreview.vue:91=520｜UaParser.vue:105=120
- pdf：DeepRedact.vue:180=180｜FindReplacePdf.vue:159=220｜ComparePdf.vue:143=260｜SplitPdf.vue:92=320
- data：SqlQuery.vue:303=96｜ParquetViewer.vue:132=160｜CsvToExcel.vue:100=260｜CsvDedupe.vue:78=300｜SqliteViewer.vue:220=380｜ExcelViewer.vue:122=460
- image：IcoToPng.vue:176=96｜ColorBlindness.vue:103=160｜FontConverter.vue:192=240｜GifEditor.vue:238、GifCompressor.vue:220=380
- utility：CountdownTimer.vue:238=200｜BannedWordsChecker.vue:124=240｜TextSetOps.vue:83=300
- video/editors：FfBase.vue:217（预览 video）=340｜VideoStudio.vue:404=52vh｜PhotoStudio.vue:510=68vh｜PdfStudio.vue:441=74vh

### 共性-根因 3：右侧常驻 300px TrustSidebar 压窄面板
- `.tool-layout { grid-template-columns: minmax(0,1fr) 300px }`，≤900px 才收单列（`ToolPage.vue:158-168`）。
- 1200px 容器下工具面板实际宽 ~880px；工作室三栏布局（PhotoStudio `132px 1fr 250px`）中栏画布被压到 ~400~500px。
- TrustSidebar 内容（信任盾+快速指南，`TrustSidebar.vue:14-40`）价值低却常驻首屏黄金位置。

### 共性-根因 4：全站无 sticky 操作条，执行按钮在内容流底部
- App.vue 无全局操作条机制；`DownloadButton.vue:35`、`FfmpegCompress`（FfBase.vue:199）、`MergePdf.vue:39` 等按钮全在流内底部。
- 叠加共性-根因 1，"填完表单往下找按钮""先下滑才能点执行"是结构性现象。

### 共性-根因 5：响应式断点碎片化
520/560/760/860/900/960/1100 七种断点并存（base.css:329=560、TextTool.vue:156=760、SiteHeader.vue:244=860、ToolPage.vue:164=900、PhotoStudio.vue:472=960、CategorySection.vue:73-87=1100/800/520）。同一设备在不同工具上布局切换时机不一致；`.grid-2` 到 ≤560px 才叠单列（base.css:329-335），平板上双栏过挤。

### 附：其他共性事实
- 隐私徽章/H1/面包屑位于工具面板上方（无法折叠），`.tool-about` 与"同类工具"卡片在主视口之外（`ToolPage.vue:99-106,188-196`）。
- CookieBanner fixed bottom 首访遮挡页面底部（与 toast 同区域）。
- 首页 popularTools 16 个白名单 + 编辑器区曾重复登记 4 组卡（BUG-30，df29be8 已修，需验证）。

## 二、六种布局模式与各自典型风险

| 模式 | 载体/数量 | 典型体验风险（证据） |
|---|---|---|
| **A：TextTool 双栏**（输入\|输出 textarea + 底部按钮） | textDef，42 个 | 两窗各钉 180px（`base.css:164-168`），长文本内滚憋屈；异步转换无 loading UI（`TextTool.vue:15` 有 pending 但模板从未渲染）；按钮在最底部（`TextTool.vue:130-133`）；≤760px 单列后更矮。多数 textDef 工具自动执行（watch input+opts，`TextTool.vue:47-48`）是加分项 |
| **B：CalcTool 表单 + 结果行** | calcDef，67 个 | 无执行按钮（watch 自动重算 `CalcTool.vue:39-40`）；长表单+多结果行把主结果推到折叠线以下；字段 auto-fill `minmax(220px,1fr)`（:45）窄屏一列还好、宽屏表单被拉得过散；无输入记忆、无结果一键复制单值 |
| **C：单列堆叠文件流**（FileDrop→选项→按钮→进度） | ImageConvertTool/PdfToolBase/FfBase/AudioToolBase 及多数文件工具 | 拖放区 130px+（`FileDrop.vue:117-129`）+ 选项盒 + 文件列表把执行按钮推出首屏；预览区若有也是固定上限（FfBase 预览 340px）；**结果常为"自动下载 zip"，无预览**（`ImageConvertTool.vue:55`）；进度条 6px 细条 |
| **D：grid-2 双栏 + ResultBox** | JsonFormatter/CodeFormatter/GraphqlFormatter 等开发/文本工具 | **"结果窗口太小"主案发现场**：ResultBox 双重钉高（`ResultBox.vue:69`），默认 180px、调用方普遍 220~420px；≤560px 才转单列 |
| **E：三栏工作室** | 4 个 studio | 全站体验最好（Tab 化选项、vh 级画布 52~74vh），但被 ToolPage 300px 侧栏挤压（共性-根因 3）；≤900-960px 塌成单列长页 |
| **F：notice 条即结果** | CompressToSize、MergePdf 等一批文件工具 | 无结果预览（`CompressToSize.vue:139-145` 仅一条成功横幅+下载按钮），成败只靠横幅+toast；用户无法确认输出质量（压缩后画质？合并后顺序？） |

## 三、组件级已知事实（评估对应家族工具时直接引用）

- **TextTool.vue**（42 工具共用）：选项条不折叠（`.text-opts`）；互换/清空为两窗之间小图标（:116-119）；复制有 toast；**无键盘快捷键**。
- **CalcTool.vue**（67 工具共用）：主结果行 `.primary` 高亮（:91-94）；空态"请先完整填写上方数值"（:25-28）；错误 toast（:35）。
- **ImageConvertTool.vue**（15 个 imgcvt）：完成即自动 saveMany 打 zip 下载（:55）；按钮 spinner 即 loading（:92）；无前后对比预览。
- **FileDrop.vue**：虚线拖放区 padding 36px 20px（:117-129）；文件列表 ↑↓ 移动/删除（:96-112）；**无缩略图、无文件大小展示**（大文件前无判断）。
- **ResultBox.vue**：标题行含字符数+复制/下载/清空 mini 按钮（:49-62）；复制带 1.5s 对勾反馈（:28-31）；height 钉死（:69）。
- **DownloadButton.vue**：仅主按钮+spinner（:35-43），无进度条。
- **FfBase.vue**（视频系基座）：预览 video max 560×340（:212-221）；进度带百分比/状态文案（:189-197,239-262）是全站最完善的大文件反馈；但按钮在流内最底部（:199-206）；ffmpeg 首用 30MB 有 notice（:184-187）。
- **ToolPage.vue**：steps 快速指南在 TrustSidebar；`.tool-about` 文案区块在面板下方视口外（:99-106）。
- **SearchModal.vue**：结果区 max-height:70vh（:112-121,149-152）。
