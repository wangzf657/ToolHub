## 二、指标口径统一工程

**LTV 三套口径分裂现状（同站三个工具，三个互相矛盾的结论）：**

| 工具 | LTV 口径 | 证据 | 问题 |
|---|---|---|---|
| ltv-calculator | ARPU×毛利率÷churn（生命周期 1/churn） | registry.ts:170-171 | churn=0 按 999 月上限出 ¥79,920；负值照算出 −33.3 月 |
| cac-calculator | 36 个月硬编码近似 | registry.ts:208 | 月流失 5% 真实生命周期仅 20 个月，高估 80%；死代码（:202-203）暴露口径决策未完成 |
| churn-rate-calculator | 无周期声明 | registry.ts:229-232 | note 按"月流失"解读，输入期是月/季/年全凭用户自觉 |
| mrr-calculator（旁证） | NRR=(start+netNew)/start 含新客 | MrrCalculator.vue:37-41 | 真口径应剔除新客，默认值报 105.0%、真值 100.0%，违反行业铁律 |

**收敛目标**：全站统一"月流失率 → 1/churn"主口径；cac 新增可选 churn 字段复活真口径（验收：churn 3% 时与 ltv 同输入误差 ≤0.1）；churn 补周期选择器与年化换算（1−(1−m)^12）；36 月近似若保留必须在 note 披露高估风险。

**SaaS 指标互链图（应为一条链，现状五个孤岛）：**

`MRR(mrr) → 月流失率(churn) → LTV(ltv) → LTV:CAC 与回收期(cac) → 投放决策(roi)`；旁路：rule-of-40 的增长率应取自 mrr 变动、利润率语境应链 burn-rate。

现状六工具零透传零互链：ltv 缺 CAC 字段致"健康线 ≥3×CAC"自证不能（registry.ts:178）；churn 恰是 LTV 最难填的输入却无带入；cac 用假 LTV 算比值；roi 与 cac 的 spend 不互通；rule-of-40 与 burn-rate/mrr 数据源不联。互链 = 结果区底部链接 + URL 参数透传两件事，站内 hint 内链写法可直接复用。

## 三、空态误导专项

错误财务结论比 ¥0 更危险——分级清单（共同根因：CalcTool.vue:25-28 NaN 守卫不拦 0，BIZ 家族集中爆发）：

- **一级·输出明确且错误的结论（4 例，最恶劣）**：burn-rate 空态"盈利，无限跑道"（registry.ts:267-273，空表单直接宣判盈利）；rule-of-40 空态宣判"得分 0.0 / ✗ 未达标 / 还差 40%"（:294-299）；churn-rate 空态"流失率 0.00%、留存率 100%"（:229-232，像一条真实测量结论）；ltv churn=0 出 ¥79,920 荒谬主值、负值出 −33.3 月（:168-170）。
- **二级·∞/负值/自相矛盾行（3 例）**：profit-margin"¥∞"（守卫正则漏拦本地化符号）；saas-pricing target≥100 出"建议定价 ¥−2,500"（:323）；roi cost=0 时"净利润 +¥18000 / ROI 0.00%"同屏矛盾（:53-54）。
- **三级·¥0 无引导（6 例）**：cac、take-home、freelance-rate、saas-pricing 空态 ¥0 主行；mrr 空档位行 ¥0 与合计并列干扰读数；ltv 空态"¥0 主值+极长文案"护栏误报互相打架。
- **四级·守卫存在但失准（3 例）**：break-even cm≤0 定向守卫把"未填写"当"无法盈利"误报（:107-110）；profit-margin 有空态提示行（:152）但 ¥∞ 从眼皮底下漏过；cohort 量纲失配零守卫（填绝对人数 5000 时热力全钳最深，输出完全失义）。
- **正确守卫样板对照**：break-even 的 cm≤0 行动式文案"售价不高于变动成本，无法盈利，请先调整定价或成本"（registry.ts:108-110，全批最佳实践，只需分流空值/真 0 两种触发）；profit-margin 空态提示行（:152，本批少数有提示成员）。两例证明守卫意识已在，缺的是**系统性机制**：CalcTool 增加"空态引导行"契约 + 渲染层拦截 Infinity/负值主结果。
- **可复用的判定/着色实践**：mrr 流失率三态着色 + NRR≥100 绿色（MrrCalculator.vue:131-136）；burn-rate 三态判定阈值入文案（registry.ts:278）；cash-flow 负现金红/最低点琥珀；cohort 空态 notice+示例一键载入+loading+错误 toast 可恢复。

## 四、P0 与疑似缺陷清单

1. **P0｜resume-builder**：导出按钮 top=1673、页面总高 2402，终点动作藏 2.2 屏外（M-19，全站唯一）；附带 workPoints `slice(0,3)` 静默丢内容无警告（ResumeBuilder.vue:39，疑似功能问题）。
2. **疑似｜profit-margin ¥∞**：targetMargin≥100 → Infinity → toLocaleString 渲染"∞"，CalcTool.vue:25 `/NaN|Infinity/` 守卫漏拦本地化符号（registry.ts:145）。
3. **疑似｜cac 死代码**：`const ltv = ...churnPct ?? 3...; void ltv`（registry.ts:202-203），churnPct 不在字段列表——真口径写了又整体废弃，被 36 月硬编码顶替。
4. **疑似｜mrr NRR 口径**：netNew 含 newMrr 进 NRR 分子（MrrCalculator.vue:37-41），高估留存恰好"新客÷期初"个百分点，:137 解释文案随之失真。
5. **疑似｜burn growth 死字段**：字段收集后 compute 从未读取（registry.ts:264 vs :266-280），填 10% 跑道纹丝不动——活输入被静默忽略，比 void 死代码更恶劣。
6. **疑似｜saas-pricing 折扣语义**：label"折扣（%）"（:317）+公式 `price×(1−discount/100)`（:324）+文案"打 X 折后价格"（:330）三方错位；填 8 实际只减 8%，填 20 出现中文不存在的"打 20 折"——报价场景直接算错。
7. **口径硬伤｜take-home 精度倒退**：税=全额毛薪×有效税率、五险一金税后才扣（registry.ts:25/:20），系统性高估个税；同站 income-tax-calculator 用 2026 现行七级累进表（utility/registry.ts:197-240）。另 freelance-rate 税负系数缺席同列硬伤。

## 五、阉割与合并建议

- **阉割（唯一判例）**：take-home-pay（52，分类最低）并入 income-tax-calculator——用途重叠且精度倒退，独立存在价值低；若保留必须换 chinaPayroll.annualIncomeTax 累进引擎（chinaPayroll.ts:49-74），以 13/14 薪发放月数为差异化。
- **分工而非合并**：saas-pricing 与 profit-margin 双向定价能力完全重叠（registry.ts:144-151 vs :322-341）——建议 profit-margin 管毛利/加价互转+价格阶梯表，saas-pricing 管折扣与盈亏平衡折扣线，双方 note 写明分工并互链透传成本字段。
- **工作台愿景（远期四合）**：①**SaaS 指标工作台** = mrr+churn+ltv+cac+cohort-retention+rule-of-40 六件 tabs 合一（baremetrics 式，口径收敛为前提）；②**现金跑道工作台** = burn-rate+cash-flow（判定行+逐月编辑互补，透传 cash/收支）；③**定价工作台** = break-even+profit-margin+saas-pricing（正反定价+平衡点+阶梯表一页）；④**薪酬工作台** = income-tax 吸收 take-home 后与五险一金、税后一条龙。

## 六、与行业 Top 差距地图

- **第一档·指标联动代差（baremetrics，7 项对标：ltv/cac/churn/mrr/burn/cash-flow/cohort）**：对方指标同屏互算+健康着色+月度序列，"指标会说话"；我们是"孤立乘法+单点快算"，数字靠用户读。结构性差距决定"指标工作台"是唯一正解。
- **第二档·口径与场景纵深（Omnicalculator，8 项对标；ProfitWell 4 项；Bessemer 参照）**：对方每参数附口径出处、场景分流（投资 vs 投放）、目标利润反推、上市 SaaS 基准参照 vs 我们连 note 都缺（saas-pricing 全分类唯一无口径披露）。
- **第三档·功能资产差距（纯前端可追赶）**：HubSpot/WiseStamp（签名：10+ 模板+社交图标行 vs 我们"一张名片的三种边框"）；超级简历/FlowCV（简历：分步向导+模板库+示例填充 vs 我们 2402px 长表单）；51 个税管家（专项附加+累计预扣）；Amplitude（cohort 逐群组曲线叠加+颜色图例）；Upwork（freelance 市场费率区间锚点）。
- **架构天花板（诚实标注不硬追）**：ResumeWorded 云 AI ATS → 以启发式检查替代（量化词占比/动词开头/长度警告）；baremetrics 订阅数据源自动化 → 手填/粘贴 + 诚实披露能力边界（email-signature"头像建议在客户端内添加"是此姿态的正面示范）。

## 七、分类优化路线图

- **第一步（1 周，止血）**：resume-builder 导出栏 sticky（P0，最小改动）；CalcTool 空态引导行契约 + 一级 4 例定向提示；profit-margin ¥∞ 拦截；saas-pricing 折扣语义修正+补 note；burn growth 字段生效或下线；cac 死代码清理。
