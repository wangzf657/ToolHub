## 结论与优先级

**交互优化** · P1（家族级整改 + 本工具个性补丁）

判据：可用性扣分=家族共性（结果不可见）叠加个性风险（无浏览器能力检测）；改造随家族处方走，个性补丁成本低。

整改优先序：浏览器能力诊断（P1）→ 家族结果列表 → 体积膨胀预警 → 双目标输出（P2）。

## 扣分点明细

1. 【可用性-硬伤（家族级）】自动 zip 下载、无结果预览（`ImageConvertTool.vue:55`；M-12）——透明区是否完整保留只能下载后打开验证
2. 【功能-个性】AVIF 解码直接走 `<img>` 原生路径（`imageEngine.ts:41-43`），**无浏览器能力检测**：Safari 15/旧 Chrome 必然失败，用户只见"图片解码失败"，无"请换 Chrome/Edge/Firefox 93+"指引，也无 wasm 解码兜底
3. 【功能-个性】体积反向膨胀零提示：AVIF 高压缩→PNG 无损输出，体积常涨数倍至二十倍，UI 与 desc 均未预警（png-to-jpg 有"体积更小"叙事，本工具方向相反却静默）
4. 【灵魂】无格式说明位：AVIF 是什么、为何打不开、PNG 何时选，页面零科普
5. 【家族共性】文件列表无缩略图（FileDrop.vue:97-108）、进度条 6px 无百分比、无逐张重转——见 `png-to-jpg.md` 扣分点 5/6/7
6. 【功能】EXIF/方向元数据丢失：canvas 重编码（imageConvert.ts:16-49）不保留 AVIF 内嵌 EXIF 与 orientation 标记，手机竖拍照片转出后可能横竖颠倒且无任何提示

## 行业对标与差距

- **Squoosh**：单张解码+对比滑块+实时看输出体积；AVIF 兼容性有 wasm 兜底。差距：结果可见性代差＋兼容性策略（全押原生 vs 双保险）。
- **CloudConvert**：AVIF→PNG/JPG/WebP 全目标矩阵，失败给明确原因回执。差距：本工具目标仅 PNG 一种、失败无诊断。
- 借鉴优先级：**能力检测+失败诊断 > 结果列表（家族级）> 体积膨胀预警 > WebP 双目标**。

## 优化处方（验收标准）

1. **浏览器能力诊断**：解码失败时用 AVIF 探针（`new Image()` 载入 1×1 avif dataURL）区分"格式不支持"与"文件损坏"，前者提示"当前浏览器不支持 AVIF，建议 Chrome 85+/Edge/Firefox 93+"。→ **验收：不支持 AVIF 的环境拖入文件，2 秒内出现指引文案而非通用失败**
2. **体积预警**：选项区固定显示"PNG 为无损格式，输出体积可能显著大于源文件"。→ **验收：页面加载即见该提示**
3. **家族处方 1~7**（结果列表/自动下载开关/进度升级/缩略图等）同步落地。→ **验收：同 `png-to-jpg.md` 处方 1~6**
4. **双目标输出**：允许 PNG+WebP 同时输出。→ **验收：勾选后结果列表分两组、行数各等于输入张数**
5. **方向修正**：检测源图 orientation 标记并在解码后应用旋转。→ **验收：EXIF 带 90° 旋转标记的 AVIF 转出 PNG 方向与手机相册预览一致**
