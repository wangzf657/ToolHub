## 结论与优先级

**交互优化 + 需拓展** · P1（附分类归位建议）

判据：实时预览与诚实披露是及格底盘；但碰撞静默覆盖属数据丢失级隐患必须先堵，正则/过滤/排序基准缺失与 PowerRename 差距明确。

## 扣分点明细

1. 【功能-疑似缺陷】重名静默覆盖：两条规则产出同名文件时（如序号关闭+查找替换撞名），`zip.file(r.newPath, r.file)`（:90）后写覆盖先写——zip 里悄悄少文件，无检测、无警告、无阻断。改名工具的"数据丢失"红线
2. 【功能-个性】序号顺序不可控：序号按 webkitdirectory 遍历顺序编号（:56 index），浏览器目录遍历序≠名称字典序，"第 001 张"可能不是用户心中的第一张；无按名称/时间/大小排序基准选项
3. 【功能】无类型过滤：规则作用于全部文件（含子目录里任何类型），图片分类场景下却没有"仅图片"开关——非图片文件被迫陪跑改名
4. 【功能】无正则与日期变量：PowerRename 支持正则捕获组、枚举、日期时间插入；本工具查找替换仅字面量 split/join（:51）
5. 【可用性】预览 300 条截断+360px 钉高（:154,160,184-189）：千文件目录翻找困难，且无"只看改动项"过滤——changedCount 有数（:73）却不能筛
6. 【交互】文件夹入口单一：仅 hidden-input webkitdirectory 点击选择（:113-114），不支持拖拽文件夹入窗口（DataTransfer items 可做）
7. 【共性】列表钉高属家族高度策略（共性-根因 2 自建版）；无 File System Access API 的目录句柄复用（换规则需重新选目录）

## 行业对标与差距

- **PowerToys PowerRename**：正则+捕获组、序号枚举、日期变量、仅改扩展名开关、实时预览+只看改动项+碰撞高亮。差距：预览体验本工具已达标，差的是规则表达力（正则/日期）与安全网（碰撞检测）。
- **Everything**（检索参照）：本工具无搜索/过滤能力，千文件目录里核对目标靠肉眼滚动。差距：过滤器是清单类工具的基本功。
- 借鉴优先级：**碰撞检测（P0 安全网）> 序号排序基准 > 只看改动项 > 正则查找替换 > 类型过滤**。

## 可拓展性

- 短期（1 周）：碰撞检测（newPath 去重标红+禁用导出）；序号排序基准下拉（名称/修改时间/大小）；"只看改动项"开关
- 中期（1 月）：正则查找替换（含捕获组 $1）；类型过滤 chips（仅图片/仅视频/全部）；拖拽文件夹入口（DataTransferItem.webkitGetAsEntry）
- 远期：File System Access API（showDirectoryPicker）目录句柄记忆+增量重跑；分类归位为文件管理类工具，与 folder-content-lister 组成"文件整理"分组

## 优化处方（验收标准）

1. **碰撞检测（P0）**：预览中对重复 newPath 行标红并禁用导出。→ **验收：构造两文件改后同名，预览行标红、"确认并导出"按钮禁用并 toast 说明冲突数**
2. **序号排序基准**：新增"排序依据"下拉（选择顺序/名称/修改时间），序号按所选基准编号。→ **验收：乱序目录按名称排序后，001 号与字典序首项一致**
3. **只看改动项**：预览头加开关，仅显示 newPath≠path 行。→ **验收：千文件目录开启后列表仅剩 changedCount 行**
4. **类型过滤**：规则区加"全部｜仅图片｜仅视频"chips。→ **验收：选"仅图片"后非图片文件预览行灰显且导出不改名**
5. **正则查找替换**：查找框支持正则开关+捕获组 $1 引用。→ **验收：`IMG_(\d+)` 替换为 `照片_$1` 后预览与 PowerRename 结果一致**
