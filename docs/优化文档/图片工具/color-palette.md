## 结论与优先级

**需拓展 + 交互优化** · P1（从"取色器"补成"方案生成器"）

判据：相比 Coolors 的锁定/微调/导出全链路子功能缺失悬殊，触发需拓展；可用性无硬伤但功能面差距是主要矛盾。

整改优先序：算法升级与 desc 纠偏（快赢）→ 复制格式/导出 → 方案编辑（锁定+和谐规则）。

## 扣分点明细

1. 【功能-desc 名实不符】注册表宣称"中位切分算法"（registry.ts:53），imageEngine.ts:566 注释也写"中位切分"，实现实为 4bit/通道（4096 桶）计数+均值（:577-592）——无任何切分/迭代，桶均值必然产生偏灰主色；这是算法水准与自我描述的双重问题
2. 【功能-需拓展】零方案能力：无色数控制（:33 写死 8）、无锁定、无微调、无互补/三角/类比和谐规则、无从单色生成方案——Coolors 的核心循环"提取→锁定保留→微调替换→导出"一环都缺
3. 【功能】复制格式单一：copy(hex)（:38-41）仅 HEX，无 RGB/HSL/CSS 变量，无"复制全部"，无 PNG/JSON/URL 导出
4. 【可用性】鲜艳组无占比展示（:55-62 色块只有 HEX），与主色组信息不对等——"鲜艳但用了多少"恰恰是点缀色决策依据
5. 【可用性-家族共性】竖图预览无高度上限（ImageToolBase.vue:61-64），看色板需滚过整张大图；无"隐藏原图只看色板"开关
6. 【灵魂】与站内 image-color-picker、screen-color-picker 零互链——"图上某处这个颜色"的自然需求被留给用户自己找工具

## 行业对标与差距

- **Coolors.co**：色块锁定（锁定后重摇不覆盖）、HSL 轮微调、和谐规则、导出 PNG/JSON/PDF/URL 分享、历史。差距：本工具停在"提取"第一格，后续四格全空。
- **Adobe Color**：从图提取主题可逐色拖动重取、可指定提取规则（彩色/亮色/暗色）、给出辅助色与对比度检查。差距：提取结果不可修正，误提的杂色无法剔除。
- 借鉴优先级：色数控制+去杂色 > 复制格式扩展 > 锁定/微调 > 和谐规则生成 > 导出。

## 可拓展性

- 短期（1 周）：色数 chips（4/6/8/12）；鲜艳组补占比；desc 与注释如实改为"色桶聚合（降采样统计）"
- 中期（1 月）：复制格式菜单 + 复制全部为 CSS 变量/JSON；对桶结果跑 3~4 轮 k-means 精化主色（纯前端可行）；隐藏原图开关
- 远期：色板编辑条（锁定/替换/和谐规则）+ URL 分享方案 + 与 image-color-picker 组成"取色工作台"

## 优化处方（验收标准）

1. **算法精化与纠偏**：paletteFrom 桶结果上叠加 k-means 迭代（k=色数，3~5 轮），desc 同步改为实际算法。→ **验收：同一张高饱和渐变图，主色饱和度较现算法提升且 desc 与实现一致；单张 4000px 图提取耗时 <500ms**
2. **色数与占比**：主色组加 4/6/8/12 色切换；鲜艳组补占比标签。→ **验收：切 12 色后主色组渲染 12 块，占比合计 95%~100%；鲜艳组每块显示百分比**
3. **复制格式菜单**：色块 hover 出现 HEX/RGB/HSL 三格式 + 色板右上"全部复制为 CSS 变量"。→ **验收：点 RGB 复制出 `rgb(51, 102, 153)`；全部复制得到 :root 变量块**
4. **方案编辑最小闭环**：色块点击弹层含锁定开关 + HSL 微调滑杆；主色旁"和谐方案"按钮按互补/三角/类比各生成 5 色。→ **验收：对 #336699 生成互补 5 色方案；锁定 2 色后点"重新提取"其余色刷新、锁定色不变**
5. **隐藏原图**：预览与色板之间加"收起原图"开关。→ **验收：开启后 1366×768 视口内色板完整可见且无需滚动**
