## 结论与优先级

## 扣分点明细

1. 【灵魂-硬伤级】needModel 误标：registry 标 `needModel: true`（registry.ts:65），但组件无任何模型加载逻辑（纯 Canvas 循环，:28-62），导致 ToolPage.vue:67 隐私徽章显示"（部分能力首次使用需下载模型）"——向用户承诺一个不存在的 28MB 下载，疑似功能问题，交用户确认后修正注册项
2. 【灵魂-硬伤级】desc 与实现不符：registry 描述"天空偏蓝、植被偏绿"（registry.ts:65），代码中不存在任何植被/绿色通道（ColorizePhoto.vue:35-57 仅 暗部→棕、中灰→暖肤色、高光→冷白、:52-57 天空蓝渐变）——"植被偏绿"是无中生有的能力宣传
3. 【功能】上色结果与亮度强绑定（:33-50）：同亮度的草地、人脸、砖墙得到完全相同颜色；只有天空（按位置）有空间先验。结果接近三层渐变叠加的怀旧滤镜，"上色"名不副实
4. 【功能】无任何局部控制：Palette.fm 可用文字指定"天空蓝、草地绿"；本工具连"人脸别那么黄"的饱和度/色温微调都没有
5. 【可用性】无按住对比：黑白原图与上色结果的差异靠记忆（共性家族缺口，ImageToolBase.vue:61-64 无对比机制）
6. 【交互】强度滑杆 step=5（:86）、min=10 起步无"0=不上色"基线，不能与原图二分对比
7. 【灵魂】诚实 notice 之后没有下一步指引（"想要更真实上色目前需云端工具"未说明），诚实只做了一半
8. 【交互】无参数记忆：单滑杆本可零成本 localStorage 记忆（家族走 composposables 惯例），每次进入固定回 65

## 行业对标与差距

- **MyHeritage colorization**（云）：GNN 上色，人脸/衣物/背景分对象着色，肤色有先验。差距：代差。天花板标注：云端模型；纯前端可逼近 = DeOldify onnx（HF 有公开权重）走本仓库已验证的 onnxruntime-web 管线（inpaintEngine.ts:122-150 同款下载/缓存/进度机制），标 needModel 即名副其实。
- **Palette.fm**（云）：文本提示词引导分区上色。差距：无任何引导输入，空间先验仅"上部=天空"。
- 借鉴优先级：修 needModel/desc（零成本，立即）> DeOldify 端侧真上色 > 区域画笔指定色调 > 强度 0 基线 + 对比。

## 可拓展性

- 短期（1 周）：registry 修正 needModel=false 或改为 needModel=false + desc 删"植被偏绿"；notice 补"当前为基调渲染"边界句；滑杆 step=1
- 中期（1 月）：DeOldify onnx 端侧上色（复用 inpaintEngine 基建，28→约 100-300MB 需下载提示）；强度滑杆保留作为"AI 结果混合比"

## 优化处方（验收标准）

1. **注册项整改**：needModel 改 false（或落地真模型后保持 true）；desc 改为"按亮度分区映射怀旧色调"。→ **验收：/t/colorize-photo 隐私徽章不再出现"需下载模型"；desc 中无代码未实现的能力表述**
2. **按住看原图**：预览左上角对比按钮。→ **验收：按住显示黑白原图，松开恢复上色态**
3. **色调微调**：新增暖↔冷、饱和度两滑杆作用于映射输出。→ **验收：肤色区域可被调至不偏黄且草地不受影响有限（可解释为全局调整）**
4. **强度 0 基线 + step=1**：min=0。→ **验收：0 时输出与原图逐像素一致**
5. **端侧真上色（中期）**：DeOldify onnx 接入，needModel=true 恢复真实。→ **验收：人脸呈现肤色、草地偏绿、天空偏蓝且区域间颜色不同；模型下载有进度条**
