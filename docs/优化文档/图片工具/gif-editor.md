## 结论与优先级

**交互优化 + 需拓展** · P1（可视裁剪与帧时间轴是两根主梁）

判据：源图零预览+数字盲填裁剪触发可用性硬伤；与 ezgif 的帧级能力差距悬殊触发需拓展——两者共同决定该工具必须先"看得见"再谈"编辑"。

整改优先序：源帧预览+框选裁剪（P0）→ 帧时间轴（删帧/起止）→ 解码缓存 → 预览放大。

## 扣分点明细

1. 【可用性-硬伤】源 GIF 零呈现：open() 仅保存 file（GifEditor.vue:43-52），加载后页面只有参数表单——用户看不见要编辑的是什么，裁剪 X/Y/W/H 全凭想象盲填，错了就完整重编码一遍再验
2. 【功能-需拓展】无帧级操作：不支持删除/复制帧、起止帧裁剪（cut）、帧重排、加文字——ezgif 编辑器的核心能力全缺；对比站内 gif-frame-extractor 已能浏览全部帧（其 :98-111），本工具反而不展示帧
3. 【交互-个性】每轮试错全量重算：decodeGifFrames 在 run() 内（:81），改一个速度倍率也重新解码全部帧；解码段无独立进度（stage 文案 :80 有但无百分比）
4. 【可用性（家族共性）】结果预览钉 380px（:234-239，审计底稿 GifEditor.vue:238），无放大无前后对比（Squoosh 滑杆式对照缺失）
5. 【功能】变速静默钳制：delay 下限 20ms（:116 Math.max(20)）——低速 GIF 高倍加速时帧延迟被钳到 20ms 不提示，实际速度与滑杆标称不符
6. 【交互】裁剪参数无联动约束（cropX+cropW 可超 100% 边界靠 :58-59 clamp 兜底但 UI 不反馈），无比例锁定（如 1:1 表情包）
7. 【灵魂】无参数预设（"表情包 240px 1.5 倍速"类一键档）、无试算输出体积（要生成完才知道变大变小）

## 行业对标与差距

- **ezgif 全能编辑器**：帧缩略图时间轴（逐帧删/复制/移动/逆转区间）、可视化裁剪框、字幕逐帧叠加、每帧独立延迟、效果实时预览。差距：**帧时间轴是代差**——本工具连"看到帧"都没有。
- **Squoosh**：压缩前后分屏滑杆对比。差距：编辑结果与原 GIF 无法对照播放，变速/倒放效果只能凭记忆比较。
- 借鉴优先级：源帧预览+框选裁剪 > 帧时间轴（删帧/起止）> 解码缓存 > 前后对比播放 > 参数预设。

## 可拓展性

- 短期（1 周）：加载后渲染首帧（可左右切帧），裁剪数值改动即时在预览上画半透明遮罩示意选区
- 中期（1 月）：拖拽框选裁剪（同步数值）；帧时间轴（复用 gif-frame-extractor 网格）支持勾选删除与起止裁剪；解码缓存；delay 钳制提示
- 远期：与 maker/compressor 合并"GIF 工作台"（共享帧时间轴与解码层，模式 E）；逐帧字幕（canvas 文字+时间区间）

## 优化处方（验收标准）

1. **源帧预览+框选裁剪**：加载后显示帧画布（可切帧），在画布上拖出裁剪框并同步 4 个数值，数值手改也实时画遮罩。→ **验收：拖框后点"应用并生成"，输出尺寸与框选区域一致（±2px）；cropX+cropW>100% 时框自动贴边且 UI 即时纠正**
2. **帧时间轴**：缩略图条支持勾选删除帧与"保留第 N~M 帧"。→ **验收：10 帧删第 3 帧后输出 9 帧顺序不变；保留 3~7 输出 5 帧、总时长相应缩短**
3. **解码缓存**：文件不变时解码帧缓存复用。→ **验收：首次生成后仅改速度再生成，耗时减少 ≥60%**
4. **预览放大与对比**：结果预览点击全屏；全屏内可切换"原图/结果"同尺寸对照播放。→ **验收：1366×768 全屏可核画质；对照模式切换即时（两者均已解码）**
5. **钳制与预设**：delay 触及 20ms 下限时提示"已达 GIF 最小帧延迟"；参数区加 2 个预设 chips（表情包 240px/1.5x、论坛签名 468px/原速）。→ **验收：以 400% 速度处理 20ms 帧 GIF 时提示可见；点击预设后宽度/速度联动填入**
