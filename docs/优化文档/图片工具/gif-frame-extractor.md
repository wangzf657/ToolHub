## 结论与优先级

**交互优化** · P1（缩略图缓存是必修，播放预览是灵魂件）

判据：功能与结果区质量在 GIF 家族领先（63 分），但模板内 toDataURL 的重渲染风暴是可复现的性能硬点，播放预览缺失使核心场景不闭环。

整改优先序：缩略图缓存（性能快赢）→ 播放预览 → 多选/范围导出 → 解码进度。

## 扣分点明细

1. 【性能-个性】模板内 toDataURL 风暴：`f.canvas.toDataURL('image/webp', 0.7)` 直接写进 v-for 模板（GifFrameExtractor.vue:107）——Vue 重渲染（点选一帧、toast 状态变化）即对**全部帧**重新同步编码 WebP，百帧 GIF 每次点击卡顿数百毫秒；应解码后一次性生成 dataURL 数组缓存
2. 【功能】选择是摆设：pickFrame 仅切换高亮（:61-63），selectedIndex 不参与任何下载——无多选、无"导出所选帧"、无范围提取（如只取第 5~10 帧）
3. 【可用性】无播放预览：帧条不能按原延迟连播，用户要逐格脑补动画节奏；ezgif 逐帧页内置帧播放器
4. 【性能】解码主线程同步无进度（:27-59 仅文案切换），300 帧 GIF 期间 UI 冻结；同族 gif-compressor 已有阶段文案+进度条（其 :136-139），本工具反而没有——同源管线反馈不一致
5. 【美观】帧格白底硬编码（:128）：暗色主题下每帧强制亮白，且透明帧在深色页面无法辨识边界（无棋盘格）
6. 【交互】单帧下载 hover 才见的按钮（:152-168）触屏端不可达（无 hover 态），移动端只能逐帧点开再找

## 行业对标与差距

- **ezgif GIF frame extractor**：帧缩略图列表+播放预览器、帧范围输入（from/to）、按延迟排序查看、导出为雪碧图。差距：**播放预览**与**范围导出**两块直接决定工具从"查看器"升级为"素材截取器"。
- **站内 gif-maker（整改后）**：帧条+预览组件与本案处方同构，应抽成共享组件。差距：目前两工具互不复用，帧网格只在提取侧存在。
- 借鉴优先级：缩略图缓存 > 播放预览 > 多选/范围导出 > 解码进度 > 雪碧图导出。

## 可拓展性

- 短期（1 周）：解码完成时生成 thumbs: string[]（dataURL 数组）替换模板内编码；帧格底色改棋盘格 token
- 中期（1 月）：帧多选（shift 连选）+"导出所选帧 ZIP"；范围输入（起止帧号）；decodeGifFrames 加 onProgress 回调；移动端帧号跳转
- 远期：抽出 GifFrameStrip 共享组件供 maker/editor 复用（家族处方）；雪碧图/横条导出；大 GIF 虚拟滚动

## 优化处方（验收标准）

1. **缩略图缓存**：解码完成后一次性生成 dataURL 数组存 ref，模板仅引用。→ **验收：100 帧 GIF 加载后点击选择帧，Performance 面板无 >50ms 长任务；重复点击不再触发 toDataURL**
2. **播放预览**：网格上方加播放小窗，按各帧 delay 轮播，可暂停/逐帧步进。→ **验收：播放节奏与原 GIF 一致（同屏对比目视无差）；步进按钮可逐帧停驻**
3. **多选/范围导出**：支持点击多选与"第 N~M 帧"输入，新增"导出所选帧 ZIP"。→ **验收：选第 2/5/8 帧导出 zip 恰含 3 个 PNG 且命名沿用原序号；范围 5~10 导出 6 帧**
4. **解码进度**：decodeGifFrames 增 onProgress，进度条按已合成帧数刷新。→ **验收：300 帧 GIF 解码期间进度条刷新 ≥10 次，UI 不冻结（分片 yield）**
5. **主题化帧格**：帧格背景改棋盘格+主题 token，暗色模式对照检查。→ **验收：暗色模式下透明帧边界清晰，无整格纯白突兀**
