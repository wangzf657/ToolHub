## 结论与优先级

**交互优化** · P1（含一项疑似功能缺陷需回归验证）

判据：63 分无结构性硬伤；但"JPG 白底"实际黑底疑似缺陷 + ZIP 不跟随格式选择，需按测试纪律先记录交用户修复。

整改优先序：白底缺陷修复（P1）→ ZIP 跟随格式 → 点击放大 → 帧科普（P2）。

## 扣分点明细

1. 【功能-疑似缺陷】**"JPG（白底）"实为黑底**：选项文案称白底（`IcoToPng.vue:118`），但 downloadOne 直接 `canvasToBlob(canvas,'image/jpeg',0.92)`（:87-92），从未铺白底——透明帧的 canvas 转 JPEG 时 alpha 被弃、背景变**黑**。对照 imageConvert.ts:31-40 对 JPG 目标显式 `fillRect('#ffffff')`，代码库已知此坑却在此漏做。测试纪律：仅记录，待用户确认修复
2. 【功能】ZIP 不跟随格式选择：downloadAll 硬编码 `canvasToBlob(e.canvas,'image/png')`（:99,101），格式下拉选 JPG 后单帧是 JPG、ZIP 仍是 PNG，行为不一致且 UI 无说明
3. 【可用性】帧缩略图钉 96px：`.thumb max-width/max-height 96px`（:174-178，审计底稿 IcoToPng.vue:176=96 入清单），256px 帧在网格里无法看大图细节，无点击放大
4. 【功能】无重采样导出：ICO 内最大帧 256px，想得到 512px 得去别的工具放大——竞品常提供"最大帧放大导出"
5. 【灵魂】bpp（色深）直接甩给用户（:135）无解释；无"主图=最大帧"之类的引导；主图下载按钮是唯一 primary 样式（:127）但主图与最大帧往往重复，易困惑
6. 【交互】解析失败态薄：全帧失败时仅 toast（:77-81），页面上不留诊断信息（浏览器、文件头信息等）

## 行业对标与差距

- **favicon.io**（ico 转 png 等反查向）：上传即见各帧列表、可下载任意帧、附"该 ico 含哪些尺寸"说明卡。差距：帧信息科普卡。
- **ezgif**：ICO→PNG 逐帧拆分+帧预览点击放大+输出尺寸可调。差距：放大预览与重采样。
- 借鉴优先级：**JPG 白底修复（缺陷级）> ZIP 跟随格式 > 点击放大 > bpp 科普**。

## 可拓展性

- 短期（1 周）：修复白底缺陷（downloadOne 里 JPG 分支先 fillRect 白）；ZIP 按 format 选择编码
- 中期（1 月）：帧点击放大（lightbox 或侧栏大图）；"导出最大帧"快捷按钮；帧信息 tooltip 解释 bpp
- 远期：与 png-to-ico 合成"ICO 工作台"：互转+预览+favicon 套件一处完成

## 优化处方（验收标准）

1. **修复白底（缺陷级）**：downloadOne JPG 分支先在副本 canvas 铺 `#ffffff` 再导出。→ **验收：含透明的 ico 转 JPG，输出背景为白色非黑色**
2. **ZIP 跟随格式**：downloadAll 按 format.value 编码（JPG 时统一白底）。→ **验收：选 JPG 后 ZIP 内全部为 .jpg 且白底**
3. **点击放大**：帧缩略图点击弹出原图尺寸 lightbox。→ **验收：256 帧点击后按 1:1 显示，可关闭返回**
4. **帧科普**：网格上方加一行"bpp=色深，32bpp 含透明通道；主图通常为最大帧"。→ **验收：页面静态文案可见**
5. **导出最大帧**：主图区加"最大帧 512/256px 导出"说明或按钮。→ **验收：点击后文件名含尺寸标注**
6. **站内互链**：结果区提示"想把 PNG 做回 ICO？→ PNG 转 ICO"并带链接。→ **验收：提示可见，点击跳转 /t/png-to-ico**
