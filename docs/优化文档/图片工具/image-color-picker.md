## 结论与优先级

**交互优化** · P1

判据：桌面 hover 取色体验流畅，但精度手段（缩放/loupe/键盘）缺位与触屏路径缺失是明确交互硬摩擦。

## 扣分点明细

1. 【可用性-个性】无放大镜/缩放：画布仅 maxWidth:100%（:29-30），4000px 宽图在 ~500px 舞台上每屏幕像素对应原图 ~8×8 像素块——瞄准具体像素无辅助手段（无滚轮缩放、无 1:1 模式、无 loupe 浮窗）
2. 【移动端-个性】取色预览依赖 @mousemove（:100），触屏无 hover——移动端点击直接 commit 入历史（:64-66）且无预览确认，核心交互退化
3. 【灵魂-个性】历史不持久化（:14 仅内存，刷新即丢）——同站 screen-color-picker 却有 localStorage（ScreenColorPicker.vue:14-19），姊妹工具行为不一致
4. 【功能】仅 HEX/RGB 双格式（:112-113），无 HSL/CMYK——imagecolorpicker.com 四格式并行
5. 【功能】无键盘方向键 ±1px 微调——像素级对齐设计稿的精选取色无辅助
6. 【交互】无粘贴剪贴板图片/URL 载入（仅 FileDrop 文件 :80-87）——"截图后直接 Ctrl+V 取色"高频路径断裂
7. 【可用性-共性】stage 自绘无高度上限（:100，家族共性变体），竖图把历史列表推到两屏外
8. 【灵魂】与 color-palette（主色提取）零互链——取完单色想看整图调色板的路径断裂，两工具无相互引导

## 行业对标与差距

- **imagecolorpicker.com**：放大镜精确取色、HEX/RGB/HSL/CMYK 四格式、URL/上传双载入、主色提取联动。差距：**精度工具链**——对方放大后逐像素点选，本工具全屏目测。
- **RedKetchup Color Picker**：zoom 预览窗、sampler 吸管、多格式同步换算。差距：同上，且无采样器。
- 借鉴优先级：滚轮缩放+loupe > 触屏取色路径 > 粘贴载入 > HSL 格式 > 历史持久化 > color-palette 互链。

## 可拓展性

- 短期（1 周）：滚轮缩放（0.5~8x）+拖拽平移；hover 放大镜 loupe（9×9 邻域）；历史 localStorage 持久化
- 中期（1 月）：touchmove/长按预览松手固定的触屏路径；HSL 格式与粘贴剪贴板图片载入；方向键微调
- 远期：与 color-palette/color-converter 组成"取色→调色板→转换"工作台；取色历史导出 JSON

## 优化处方（验收标准）

1. **缩放取色**：滚轮缩放 0.5~8x + 拖拽平移，取色映射始终按原图坐标（现有映射逻辑 :54-56 不变）。→ **验收：4000px 宽图 8x 放大后可瞄准单个原图像素且读数正确**
2. **放大镜 loupe**：hover 显示 9×9 邻域放大浮窗（中心十字标示当前像素）。→ **验收：浮窗中心色与读数 HEX 一致，浮窗不遮挡鼠标指针**
3. **触屏路径**：touchmove 实时预览、长按 300ms 松手固定。→ **验收：iOS Safari 手指拖动实时显示色值，长按固定不入误点**
4. **历史持久化**：对齐 screen-color-picker 写 localStorage。→ **验收：固定 3 色后刷新页面历史保留且可复制**
5. **粘贴载入**：监听 paste 事件读取剪贴板图片。→ **验收：微信截图后 Ctrl+V 直接进入取色舞台，无需拖文件**
