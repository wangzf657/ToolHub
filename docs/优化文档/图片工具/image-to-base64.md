## 结论与优先级

**交互优化** · P1

判据：功能正确、体积对比是亮点，但"文本输出工具的输出区只有 160px"是共性-根因 2 在本工具的最痛实例，64 分卡在输出区可用性。

## 扣分点明细

1. 【可用性-共性】输出区双重钉高 160px：min-height 传 160px 且 ResultBox 内部 height 同值钉死（ImageToBase64.vue:84；ResultBox.vue:69），1MB 图产出约 137 万字符在 160px 窗口同屏仅 ~6 行——复制靠按钮尚可，人工核对前缀（data:image/png;base64,）全靠想象
2. 【可用性-个性】多文件静默丢弃：FileDrop 未传 `:multiple="false"`（默认 true，FileDrop.vue:15）可多选多拖，但 load() 只编码 files[0]（ImageToBase64.vue:33）——拖 3 张时列表显示 3 行却只编码第 1 张，无任何提示
3. 【可用性-个性】无图片预览：载入后只有文件名+大小（:27-36），无法确认"编码的是不是这张图"；base64-image.de 载入即显示图片预览
4. 【灵魂-个性】体积告警无阈值分档：只有静态一句"小图标划算大图不划算"（:90），10MB 大图编码后无红色警示"建议先压缩"——本站就有 compress-image-to-size 却不做联动引导
5. 【功能】无批量：一次一图（受缺陷 2 连累还多拖无效），图标集场景要重复拖 20 次；Base64.im 支持多图列表逐个复制
6. 【功能】模板缺 srcset/`image-set()` 场景：响应式内联是 data URI 进阶用法，三 Tab 未覆盖；无 SVG 专责处理（原样编码含脚本可能，无安全提示，"强制 PNG"才重编码 :42-44）
7. 【交互】无精确字符数：b64Size 只显示 KB/MB（:25,88），核对编辑器字符上限时无用
8. 【可用性-共性】Cookie 横幅首访遮挡底部体积徽章行（M-01 同款）

## 行业对标与差距

- **base64-image.de**：载入即预览+字符数+大小对比+HTML/CSS 双模板。差距：**预览与批量双缺**。
- **Base64.im**：多文件列表+逐个复制+体积徽章。差距：批量工作流。
- 借鉴优先级：输出区弹性高度 > 多文件行为修正 > 载入预览 > 阈值告警+压缩联动 > 批量 > srcset 模板。

## 可拓展性

- 短期（1 周）：ResultBox expand 模式（弹性高度+全屏切换）；图片预览缩略图（48px 即可）+精确字符数徽章；multiple 改 false 或补全批量逻辑
- 中期（1 月）：>100KB 红色告警+"先压缩"跳转 compress-image-to-size；批量多图列表逐个复制；srcset/image-set 模板 Tab
- 远期：与 compress-image-to-size 组成"内联工作台"（压到目标体积→转 base64→复制模板），覆盖图标管线全流程

## 优化处方（验收标准）

1. **输出区弹性高度**：expand 模式默认 calc(100vh - 330px)、下限 480px、可全屏。→ **验收：1366×768 下 1MB 图的 base64 输出可浏览 ≥30 行，一键全屏覆盖整页**
2. **多文件行为修正**：multiple=false（拖第二张即替换）或真批量。→ **验收：拖 3 张文件不再出现"列表 3 行只编码 1 张"的静默丢弃**
3. **载入预览**：列表行加 48px 缩略图。→ **验收：拖入图片后列表行可见图片内容**
4. **阈值告警**：原始 >100KB 时徽章变红显示"内联成本高，建议先压缩"链接。→ **验收：200KB JPG 触发红色告警，点击跳转 compress-image-to-size**
5. **字符数徽章**：显示精确字符数（≈原始字节×1.37）。→ **验收：与浏览器 dataUri.length 完全一致**
