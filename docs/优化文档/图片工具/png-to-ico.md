## 结论与优先级

**交互优化 + 需拓展** · P1

判据：核心可用（61 分无硬伤），但对照 favicon 双标杆缺"尺寸勾选/体积优化/使用指引"三块，拓展空间明确；裁剪无确认环节属交互摩擦。

整改优先序：逐尺寸预览网格（P1 快赢）→ 裁剪确认 → 使用指引 → 尺寸勾选与 PNG 帧压缩（P2）。

## 扣分点明细

1. 【功能】**尺寸档固定不可选**：encodeIco 硬编码六档（`PngToIco.vue:23`→`imageEngine.ts:485`），用户无法只要 16+48 或追加 20/24 等特殊档——realfavicongenerator 支持逐尺寸勾选
2. 【功能】**ICO 体积偏大**：encodeIco 每帧存未压缩 BGRA（imageEngine.ts:497-502，约 256²×4 累计 ≈350KB），而标杆做法是 PNG 帧内嵌（realfavicongenerator 的 ico 通常 <50KB）——功能正确但产物质量有优化空间
3. 【交互】居中裁方无确认：onLoaded 直接裁（:10-17），裁掉的两侧内容不可见不可调，仅靠文案提醒"建议方形"；无裁剪预览或手动框选入口
4. 【可用性】无逐尺寸预览：六档里 16px/32px 的实际观感（缩小后是否可辨）是用户最关心的，预览区只有原图大图（ImageToolBase stage），要靠下载后打开验证
5. 【灵魂】缺 favicon 落地指引：下载后"放根目录+`<link rel="icon">`写法"零说明，favicon.io 生成完直接给出 HTML 片段
6. 【功能】源格式限制弱：accept `image/png,image/*`（:35）什么图都收，非方形自动裁切OK，但 JPG 带 JPG 噪点缩到 16px 效果差，无"建议透明背景"的事前拦截或提醒（仅静态文案）

## 行业对标与差距

- **favicon.io**：一张图出 ico+apple-touch-icon+android-chrome+site.webmanifest 全套，附 HTML 使用片段、浏览器标签页实时预览。差距：**生态完整度**——本工具只有单文件 .ico。
- **realfavicongenerator.net**：逐尺寸预览网格（模拟真实显示尺寸）、尺寸可选、PNG 帧压缩。差距：逐尺寸预览与体积优化。
- 借鉴优先级：**逐尺寸预览网格 > 使用指引片段 > 尺寸勾选 > PNG 帧压缩**。

## 可拓展性

- 短期（1 周）：结果区加六档实际尺寸预览网格（16/32/48/64/128/256 各画一帧并列）；下载后展开"如何使用"折叠块（`<link rel="icon" href="/favicon.ico">` 片段+复制按钮）

## 优化处方（验收标准）

1. **逐尺寸预览网格**：载入后预览区下方渲染 6 格（各按真实 px 显示+标注"16×16"）。→ **验收：拖入非方形图后，网格中每格为裁方后对应尺寸的实际观感，16px 格与下载后资源管理器缩略图一致**
2. **裁剪确认**：自动裁方前给出"居中裁切预览"（原图+裁切框叠加），提供"换一张/微调"入口。→ **验收：拖入 800×600 图出现裁切框示意，确认后才进入结果态**
3. **体积优化**：encodeIco 改为 PNG 帧内嵌。→ **验收：同一 1024 源图产物从 ~350KB 降至 <80KB，Windows 资源管理器可正常显示**
4. **尺寸勾选**：六档复选框默认全选。→ **验收：仅勾 16/32/48 后导出 ico 目录头恰含 3 帧**
5. **使用指引**：下载按钮下方折叠"部署指引"，含 `<link>` 片段与一键复制。→ **验收：展开可见完整 HTML 片段，复制后剪贴板含 `<link rel="icon"`**
6. **站内互链**：结果区提示"需要 iOS/Android 全套图标？→ App 图标生成"并带链接。→ **验收：提示可见，点击跳转 /t/app-icon-generator**
