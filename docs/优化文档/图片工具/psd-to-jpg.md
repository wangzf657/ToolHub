## 结论与优先级

**交互优化 + 需拓展** · P1

判据：64 分无硬伤但大 PSD 冻结 UI 触近可用性红线；对照 Photopea 的图层工作流（缩略图/开合并/选层导出）缺一整块功能面。

## 扣分点明细

1. 【可用性】**解析全程无进度**：ag-psd readPsd 主线程同步执行（`PsdToJpg.vue:59`），大文件期间"正在解析 PSD…"一行后 UI 冻结，无百分比/阶段提示/Worker——对照 FfBase 的百分比进度（全站最佳实践）与审计底稿"大文件处理：异步+进度条"纪律，属家族外最需补的一块
2. 【功能】图层树无缩略图：列表仅图层名+导出按钮（:147-151），"哪一层是哪块"全靠命名习惯；Photopea 图层行带缩略图+可见性眼珠
3. 【功能】隐藏图层不标注：walk 未读 `n.hidden`（:64-68），隐藏层照常列出，导出"全部图层 ZIP"时会把设计稿里已弃用的层一并打包
4. 【功能】图层截断无提示：`acc.slice(0,200)`（:74）静默丢弃第 201 层起，无"已截断"文案——疑似缺陷（信息丢失无告知）
5. 【功能-边界】JPG（白底）同源风险：选 JPG 导出时直接 canvasToBlob（:88），若 PSD 合成图带 alpha，透明区转黑（对照 imageConvert.ts:31-40 正确做法）；PSD 多数有底，低频但存在
6. 【交互】图层列表 280px 钉高（:198-203，共性-根因 2）内滚；无搜索/无折叠组层，百层文件找层吃力
7. 【功能】全层 ZIP 不含合成图：downloadAllLayers 只打包有画布的层（:102-110），想要"合成图+全部层"一份包得点两次
8. 【性能】预览图 toDataURL('image/jpeg',0.6)（:137）二次压缩后展示，预览画质与实际导出有差，无说明

## 行业对标与差距

- **Photopea**（纯前端可达，属对齐目标非架构天花板）：图层缩略图+可见性开关+选层导出+开合组；大文件后台解析带进度。差距：**图层工作流代差**——本工具是"导出器"，Photopea 是"工作台"。
- **ezgif/CloudConvert**（PSD 转换向）：解析进度条+失败原因回执+多目标（JPG/PNG/PDF）。差距：进度反馈与失败诊断。
- 借鉴优先级：**解析进度（Worker/分阶段）> 图层缩略图 > 隐藏层标注 > 选层导出 > 200 层截断提示**。

## 可拓展性

- 短期（1 周）：readPsd 移入 Web Worker（ag-psd 支持 offscreen canvas 注入）或至少分阶段文案（"读取结构→解码图层→合成"）；补 slice 截断提示
- 中期（1 月）：图层行缩略图（canvas.toDataURL 48px）；隐藏层灰显+眼珠标注；图层复选后导出所选 ZIP
- 远期：与 photo-editor 工作台打通——PSD 解析结果直接进 PhotoStudio 编辑，形成"打开 PSD→修图→导出"闭环

## 优化处方（验收标准）

1. **解析进度**：解析前显示阶段文案并保持 UI 响应（Worker 化或 setTimeout 分片）；>50MB 文件解析期间页面不冻结。→ **验收：拖入 100MB PSD，解析期间可滚动页面，阶段文案至少切换 2 次**
2. **图层缩略图**：图层行左侧 48px 缩略图。→ **验收：10 层 PSD 每行可见对应画面缩略，与 Photopea 目测一致**
3. **隐藏层标注**：hidden 层灰显+"隐藏"角标，"全部图层 ZIP"默认排除并可勾选包含。→ **验收：含 3 隐藏层的文件 ZIP 默认不含它们，勾选后包含**
4. **截断提示**：>200 层时列表顶部显示"共 N 层，仅显示前 200 层"。→ **验收：构造 210 层 PSD 出现提示文案**
5. **JPG 白底兜底**：合成图导出 JPG 时检测 alpha 通道并铺白。→ **验收：透明底 PSD 导 JPG 背景为白**
6. **图层搜索**：列表顶部搜索框按名称过滤。→ **验收：输入关键字后列表仅剩匹配层，清空恢复**
