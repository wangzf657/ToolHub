## 结论与优先级

**交互优化** · P1

判据：免模型定位诚实、动线完整，是 AI 图片家族中"说到做到"的工具；但无缩放涂抹与无 1:1 验收让"填得自然不自然"不可判断，交互短板明显。

## 扣分点明细

1. 【可用性-个性】无画布缩放/平移：大图上小目标涂抹是核心场景，蒙版画布被 maxWidth:100% 钉死（:43-45），笔刷坐标虽经 rect 换算无偏差（:69-76）但屏幕像素精度不够，抹 30px 杂物如同穿针
2. 【可用性】填补结果不可验收：onion peeling 的模糊补丁要 100% 才能判断，无局部放大/无按住原图对比（同 ImageToolBase 家族缺口，本组件自建舞台亦未做）
3. 【功能】撤销仅 5 步（:106 slice(-4)+push）：多物件逐个抹除的典型流程很快耗尽；且快照存全图 ImageData，内存代价高——应存增量（蒙版+前值）
4. 【功能】无蒙版羽化/软边笔刷：硬边均值填补在蒙版边界易留色带；:150 alpha>40 硬阈值与 0.55 笔刷透明度叠加，轻涂两遍才足量，新手易漏
5. 【交互】无笔刷大小光标预览（只有滑杆数字 :225），涂抹时不知道实际覆盖范围；填补后蒙版自动清除（:197），想补一刀需重涂
6. 【性能】填补主线程同步执行，无进度无分片；大蒙版 + guard 600 圈（:173）在低端机上界面冻结
7. 【实用价值-边界】对"物体+强纹理背景"（沙滩人物、树叶间）效果差且无降级提示，仅 :242 一句通用建议
8. 【共性】下载锁死 PNG（:207-208）；按钮行随内容下移（共性-根因 4）

## 行业对标与差距

- **cleanup.pictures**（纯前端画笔修复标杆）：可缩放画布、笔刷光标实时预览、模型级 inpainting（浏览器端推理）涂抹即自动填。差距：缩放与自动填补双缺——它是"涂完即走"，本工具涂完还要再点按钮；它有模型本工具是均值生长。**天花板标注：纯前端完全可做到模型级（本仓库 remove-watermark 已用 MI-GAN 跑通），本工具是产品上有意的免模型档位（被 remove-watermark.vue:215 正面引用为轻量备选），定位成立但体验件须补齐。**
- **Google Magic Eraser**（云）：自动检测并圈选干扰物、一键消除、阴影一起处理。差距：无任何智能圈选；架构天花板（云端检测），纯前端可逼近 = 显著性显著图（saliency）圈选候选。
- 借鉴优先级：画布缩放平移 > 笔刷光标预览 > 蒙版羽化 > 增量撤销（内存）> Web Worker 填补。

## 可拓展性

- 短期（1 周）：滚轮/双指缩放画布 + 空格拖移；笔刷圆形光标跟随；撤销改增量存储（扩到 20 步）
- 中期（1 月）：蒙版羽化（蒙版高斯 1-2px 再阈值）；填补迁 Web Worker + 进度条；可选"接入 AI 修复"按钮复用 inpaintEngine（与 remove-watermark 共享 28MB 缓存）
- 远期：与 remove-watermark 合并"涂抹修复工作台"（一个画布两档引擎：均值/MI-GAN），注册表二选一保留入口

## 优化处方（验收标准）

1. **画布缩放**：滚轮/捏合 100%~800% 缩放 + 拖移，笔刷大小按画布实际像素不变。→ **验收：4000px 图放大至 200% 后可精确涂中 20px 杂物，蒙版坐标无偏移**
2. **笔刷光标预览**：跟随鼠标的圆圈指示实际半径。→ **验收：调滑杆时光标圈直径同步变化，与涂抹痕迹直径一致**
3. **按住看原图**：舞台左上角对比按钮。→ **验收：按住显示未填补原图，松开恢复填补态**
4. **增量撤销**：仅记录蒙版变化区域的前值。→ **验收：12MP 图撤销 20 步内存增量 < 100MB；撤销深度 20**
5. **填补进度**：Worker 化 + 环形进度。→ **验收：500×500 蒙版填补期间滑杆与撤销按钮仍可点击，完成后 toast 提示**
