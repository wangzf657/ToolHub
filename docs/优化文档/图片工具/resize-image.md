## 结论与优先级

**交互优化 + 需拓展** · P1

判据：可用性无绝对硬伤，但"导出 PNG 抵消缩图价值"属实用性漏洞；预设/百分比缺失与 birme 差距明确。

整改优先序：导出格式/质量（P1）→ 预览高度约束（P1）→ 预设与体积徽章（P2）→ 阶梯降采样（P2）。

## 扣分点明细

1. 【实用-个性】导出格式锁死 PNG：基座默认 `mime: 'image/png'`（ImageToolBase.vue:34），本组件未覆盖也无格式 UI——2MB JPG 缩到 800px 导出仍是 1.5MB+ PNG（canvasToBlob 本身支持 JPEG/WebP quality，imageEngine.ts:103-115，能力在而 UI 缺）
2. 【可用性-个性】预览舞台无高度上限：canvas 仅 `maxWidth:100%; height:auto`（ImageToolBase.vue:61-64，.bt-stage 无 max-height :157-165）——9:16 竖图预览高约 1400px，宽高输入与下载按钮沉到二屏外
3. 【功能】无尺寸预设与百分比：birme.net 有常用档位与滑杆式缩放；无"缩小到 50%"、无社交尺寸（1080×1080 等）
4. 【交互】宽/高输入 0/负数靠 render 守卫静默跳过（:44），无"最小 1px"提示
5. 【性能】大比例降采样单步完成（imageEngine.ts:163-177），边缘发糊；Squoosh 有重采样器可选
6. 【灵魂】无输入/输出体积对比徽章，用户只能下载后自己看省了多少
7. 【共性】拖放区 165px@top≈273、首控件≈266px（共性-根因 1；实测锚点 M-11 为 image 家族空态几何）
8. 【功能】仅支持单文件（ImageToolBase.vue:135 `:multiple="false"`），多张统一尺寸需去 batch-image-process，两边参数互不相通

## 行业对标与差距

- **Squoosh**：缩放+压缩一体、重采样算法可选、前后对比滑块、输出体积实时显示。差距：**缩放质量与"结果可量化"代差**。
- **birme.net**：拖拽即改尺寸、常用预设、批量多张。差距：预设与批量。
- 借鉴优先级：导出格式/质量选择 > 预设与百分比 > 体积对比 > 阶梯降采样。

## 可拓展性

- 短期（1 周）：下载行加 PNG/JPG/WebP chips+质量滑杆；预览舞台 max-height 约束
- 中期（1 月）：预设 chips 与百分比档；输出体积徽章；批量入口转 batch-image-process 预填
- 远期：与 compress-image-to-size、batch-image-process 合并为"图片尺寸/压缩工作台"，共享重采样与格式管线

## 优化处方（验收标准）

1. **导出格式与质量**：下载行新增"PNG｜JPG｜WebP"chips（localStorage 记忆，toolhub 前缀）+ JPG/WebP 质量滑杆。→ **验收：2MB JPG 缩至 800px 选 JPG 0.85，导出 <500KB 且页面显示体积**
2. **预览高度约束**：.bt-stage 内 canvas 增加 `max-height:min(60vh,640px)` 并保持宽高比。→ **验收：载入 1170×2532 竖图，预览高 ≤640px，宽高输入与下载按钮在 1366×768 首屏可见**
3. **预设与百分比**：输入区加"50%｜25%｜1920 宽｜1080 宽｜1080×1080"chips，点击即填并联动锁比例。→ **验收：点击"50%"后宽高各为原图一半且预览刷新**
4. **体积对比徽章**：预览下方显示"原 W×H · X KB → 新 W×H · Y KB（±Z%）"。→ **验收：改尺寸 300ms 内徽章数字更新**
5. **阶梯降采样**：缩小比例 >2 倍时逐半降采样并叠加轻度锐化。→ **验收：8000px→500px 缩图边缘清晰度不低于逐级手动缩放结果**
