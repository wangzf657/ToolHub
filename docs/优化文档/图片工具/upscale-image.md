## 结论与优先级

**交互优化 + 需拓展** · P1（含文案整改前置项）

判据：H1"AI 图片放大"与实现（浏览器插值重采样）不符，属"文案与能力不符"疑点；且预览机制使核心效果不可核对。

## 扣分点明细

1. 【灵魂-硬伤级】文案与能力不符：H1/工具名"AI 图片放大"、keywords 含"超分"（registry.ts:63），实际算法是 `imageSmoothingQuality:'high'` 的分步 drawImage 插值（UpscaleImage.vue:19-44）——同页 :76 又自述"非神经网络超分"，页面自相矛盾，先入为主的"AI"预期放大了失望
2. 【可用性】结果不可核对：放大效果必须 100% 像素级判断，预览 maxWidth:100% 缩放（ImageToolBase.vue:61-64）+ 无局部放大/无按住原图对比，4× 与 2× 的差异在预览里几乎不可辨
3. 【功能】仅 2×/4× 固定档（:66-67），不能指定目标宽度（"放大到宽 4000px"是高频真实诉求）；锐化固定 25 强度（:50）不可调也不可关观察
4. 【功能】无前置尺寸拦截：40MP 警示在渲染完成后才出现（:70-75 v-if="outSize"），192MP 画布先吃满内存再警告
5. 【性能】主线程同步执行，切换 2×↔4× 或开关锐化全量重跑（:56-59 仅 100ms 防抖），大图 UI 冻结无进度
6. 【可用性-共性】竖图预览无高度上限、下载按钮流内底部（ImageToolBase.vue:143-151，共性-根因 4）；导出锁死 PNG（:19 默认 mime）
7. 【灵魂】无"什么时候重采样够用/什么时候需要真超分"的场景指引，诚实声明只做了免责没做教育
8. 【功能】无批量：一次只能处理一张，Upscayl/ezgif 均支持队列放大，证件照套图等场景需反复拖放

## 行业对标与差距

- **Upscayl**（开源桌面，Real-ESRGAN）：GAN 超分重建纹理（发丝、文字笔画），多种模型（通用/动漫/人脸）。差距：本工具 4× 只是平滑插值+锐化假清晰，文字与线条放大会糊。**架构天花板标注：并非不可逾越——本仓库去水印已跑通 onnxruntime-web 推理管线（inpaintEngine.ts:122-150），Real-ESRGAN x2/x4 onnx 模型（HF 有公开权重）可复用同一管线端侧推理**，属可落地中期项而非空想。
- **Bigjpg**（云，waifu2x）：动漫图降噪+放大是标杆。差距：云架构，但端侧 onnx 可逼近其 2× 档。
- 借鉴优先级：H1 去掉"AI"或换真模型（二选一，必须做其一）> 100% 局部核对 > 自定义目标尺寸 > 进度反馈。

## 可拓展性

- 短期（1 周）：H1 改"图片放大"或面板首行即澄清；100% 局部查看窗；锐化强度滑杆化；40MP 前置估算拦截
- 中期（1 月）：onnxruntime-web + Real-ESRGAN x4 onnx（复用 inpaintEngine 的下载/缓存/进度机制，标 needModel）；按目标宽度输入换算倍率
- 远期：与 enhance-image、resize-image 合并为"图片尺寸与清晰度工作台"，一条管线覆盖 缩放→超分→锐化

## 优化处方（验收标准）

1. **文案整改**：registry title 去掉"AI"（或落地真超分后再用）。→ **验收：H1 与面板 :76 声明不再互相矛盾；关键词不再含"超分"**
2. **100% 局部核对**：预览点击弹出 1:1 局部窗（200×200 可拖取样点），支持原图/结果双窗并排。→ **验收：4000px 原图 4× 后可看清文字笔画边缘有无插值糊化**
3. **自定义目标尺寸**：新增"按目标宽度放大"输入，内部换算为 ≤4× 的分步重采样。→ **验收：输入 4000px，3000px 宽原图输出恰为 4000px 且尺寸徽章数字正确**
4. **锐化强度滑杆**（0-100，默认 25）。→ **验收：0 时与纯重采样输出逐像素一致**
5. **前置尺寸拦截**：载入时按 4× 估算输出像素，>100MP 直接提示并禁用 4× 档。→ **验收：6000×6000 图载入后 4× chip 置灰并给出原因文案**
