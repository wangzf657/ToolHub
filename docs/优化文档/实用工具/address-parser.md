## 结论与优先级

**交互优化 + 需拓展** · P1

判据：可用性 11/20——静默截断属"错误不可理解"级问题（数据丢了但用户不知道）；对快递鸟的姓名/电话/街道分离是明确功能差距。

## 扣分点明细

1. 【可用性-硬伤】批量静默截断：超过 200 行的输入被 `slice(0, 200)` 无声丢弃（textExt.ts:189），无"仅解析前 200 条"提示——打单用户贴 500 条地址后 300 条凭空消失，比对行数才能发现
2. 【功能】收件人姓名不分离：placeholder 承诺"…博云路2号 13800000000 王小明"式输入（registry.ts:1870），stripNoise 剥掉电话（textExt.ts:142）但"王小明"原样留在详址尾部（:182）——对标快递鸟 API 返回 name/mobile 独立字段，本工具只兑现一半
3. 【功能】无街道/乡镇第四级：只加载 provinces/cities/areas 三表（textExt.ts:129-133），china-division 自带 streets.json 未用，"杭州市西湖区文三街道"拆不到街道
4. 【可用性】未匹配只给"?"（引擎 :198 `${r.province || '?'}`）：不区分"省不认识/市缺失/区缺失"，无法快速定位是哪条地址的哪一级出了问题
5. 【可用性-家族】首用词库加载无反馈：china-division 三 json 首次动态加载（textExt.ts:127-140）期间 pending 置位但模板不渲染（TextTool.vue:15，pinyin-converter.md 扣分 2 同源），areas.json 数百 KB 时粘贴后空窗数秒
6. 【功能】电话识别后直接进垃圾堆：stripNoise 把手机号/长数字替换为空格（:142）既不回显也不入 CSV 列——用户想校对"号码抄对没"必须回原文肉眼找
7. 【交互】无逐条复制：lines 模式整块复制后还得手动分；CSV 模式无"仅下载 CSV 文件"（只能复制粘贴进 Excel）
8. 【灵魂】识别结果无置信标注：完全未匹配（:183 原样保留）与精确匹配在输出上只有"?"之差，打单前无法批量筛出可疑条目人工复核

## 行业对标与差距

- **快递鸟地址解析 API**：省/市/区/街道四级＋收件人/电话/地址三分离＋智能补全（乱序、缺省自动推断）＋置信度。差距：**字段完整性代差**——对方返回结构化五元组，本工具三级＋半详址。（对方为云 API，纯前端可用 china-division 四级＋启发式姓名/电话分离逼近。）
- **快递 100 地址解析**：同场景标杆，地址补全与纠错（错别字容错）是亮点。差距：本工具前缀匹配遇错别字（"浙江省杭洲市"）整条失败。
- 借鉴优先级：**截断提示 > 姓名/电话分离列 > 街道四级 > 失败原因标注 > CSV 文件下载**。

## 可拓展性

- 短期（1 周）：截断时输出区首行提示"已解析前 200 条（共 N 条）"；未匹配项标"【未识别】"前缀；TextTool 渲染 pending 态（一处改动惠及全家族）
- 中期（1 月）：姓名/电话分离（stripNoise 捕获组回填为独立列）；streets.json 四级；CSV 文件下载按钮
- 远期：错别字容错（拼音近似匹配市级名）；与站内快递相关工具（如有）打通"解析→打单"链路；批量进度条（分片 yield 渲染）

## 优化处方（验收标准）

1. **截断提示**：输入超 200 行时输出首行显示"共 N 条，仅解析前 200 条，其余未处理"。→ **验收：贴 250 条后首行计数正确、第 201 条状态可见**
2. **姓名/电话分离**：解析结果增加"姓名/电话"两列（CSV）或两行（lines 格式），从原文捕获回填。→ **验收：示例地址解析后电话 13800000000、姓名王小明独立呈现且详址不含二者**
3. **失败标注**：未识别字段以"[?省]/[?市]/[?区]"标注缺失级别。→ **验收："浙江省杭洲市"输出省=浙江省、市=[?市] 并整行标黄**
4. **四级街道**：加载 streets.json 支持街道级拆分。→ **验收："文三街道"从详址中拆出为独立字段**
5. **CSV 下载**：加"下载 CSV"按钮（lib/download.ts saveText）。→ **验收：下载文件 Excel 打开表头省/市/区县/详细地址（+姓名/电话）四~六列无乱码**
