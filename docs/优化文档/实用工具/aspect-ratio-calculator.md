## 结论与优先级

**交互优化 + 需拓展** · P1

判据：可用性无硬伤；但小数像素不取整、无常用预设，与 Calculator.net/calculateaspectratio.com 的"即用尺寸"体验存在明确差距。

## 扣分点明细

1. 【可用性】小数像素无取整策略：按新宽求高输出 853.33（registry.ts:837 fmtN 两位小数），像素必须整数，用户要自己决定 853/854 谁更接近原比例——对标产品给出"取整后实际比例偏差"（如 854 → 1.7799 vs 1.7778）
2. 【功能】无常用预设：16:9/4:3/21:9/1:1/9:16（竖屏视频）无一键填入（registry.ts:823-827 仅四个数字字段），最高频入口靠手填 1920×1080 起步
3. 【功能】双向同填无校验：nw 与 nh 都填时两行结果各自输出（registry.ts:837-838），不提示"你填的新尺寸是否符合原比例"——这正是该工具最该回答的问题
4. 【灵魂-口径缺失】无 note：最简比取整策略（Math.round 后 gcd，registry.ts:833）、非整数输入如何处理均未说明；AGENTS.md 口径要求未满足
5. 【可用性】最简比/换算值不可复制（registry.ts:835-838 纯展示；CalcTool.vue:55-66 无复制按钮），设计协作场景需手抄
6. 【交互】只能"先有原尺寸再换算"：想直接"按 16:9 和高 1080 求宽"必须先填原宽高 1920×1080 再求，字段语义绕（ Calculator.net 支持直接锁比例输入单边）
7. 【灵魂】非整数静默取整：原宽 1279.6 按 1280 参与化简（registry.ts:833），无任何提示，结果与用户预期可能差一档

## 行业对标与差距

- **Calculator.net Aspect Ratio Calculator**：预设比例下拉 + 旧/新双行四格 + 任意三格求第四格 + 比例小数值显示。差距：**预设与"三格求一格"的自由度**。
- **calculateaspectratio.com**：预设条（16:9 等）+ 取整选项（floor/round/ceil）+ 取整后偏差百分比。差距：取整策略与偏差披露。
- 借鉴优先级：像素取整 + 偏差显示 > 预设按钮组 > 双向同填校验 > 结果复制。

## 可拓展性

- 短期（1 周）：换算行加"取整"开关（默认 round）并显示偏差；最简比可复制
- 中期（1 月）：16:9/4:3/21:9/1:1/9:16 预设 chip；nw+nh 同填时输出"符合/偏离原比例"判定行
- 远期：与 image 系裁剪工具互链，"先算比例再去裁剪"路径打通

## 优化处方（验收标准）

1. **像素取整**：换算结果默认取整并附偏差（"854（偏差 0.12%）"）。→ **验收：1920×1080、新宽 1520 时显示"855（偏差 ≤0.15%）"而非 853.33**
2. **预设 chip**：16:9/4:3/21:9/1:1/9:16 五个预设，点击填入原宽高（如 1920×1080）。→ **验收：点击"16:9"后原宽/原高字段变为 1920/1080 且最简比显示 16:9**
3. **同填校验**：nw 与 nh 同时填写时输出"新尺寸比例 xx:yy，符合原比例"或"偏离原比例（建议高为 xxx）"。→ **验收：原 16:9、新 1280×720 时显示"符合"；1280×760 时给出建议值 720**
4. **补口径 note**：注明"最简比按整数 gcd 化简，非整数输入四舍五入；换算按比例线性缩放"。→ **验收：页面底部出现口径行**
5. **结果复制**：最简比与换算尺寸行 hover 复制。→ **验收：复制最简比行后剪贴板内容为 16:9**
6. **锁比例直算**：选预设比例后可只填新宽（免填原宽高）直接求解。→ **验收：选 16:9、仅填新宽 1280 时直接输出"对应高 720"**
