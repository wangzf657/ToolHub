## 扣分点明细

1. 【可用性-疑似文案缺陷】空集文案与标签矛盾：impossible 为空时"子女不可能血型"行显示"四种都有可能"（registry.ts:1820 `r.impossible.length ? fmt(...) : '四种都有可能'`）——标签+值连读成"不可能血型：四种都有可能"，语义拧巴（应为"无，四种血型都可能出现"）；默认开屏 A×B 恰好触发此分支，第一屏即见矛盾表述
2. 【功能】Rh 未参与计算：Rh 行是写死的科普句"父母均 Rh− 时子女必为 Rh−；其余组合以血检为准"（registry.ts:1821），输入区只有 ABO 两下拉（:1808-1813），引擎亦无 Rh 基因（utilLife.ts:92-112 仅 ABO）——Rh+ 显性/rr 隐性的父母组合推导（Rh+×Rh− 可出 Rh+/Rh−，Rh−×Rh− 必 Rh−）没做，Omnicalculator/Calculator.net 均为 ABO+Rh 双输入双输出
3. 【可用性】Rh 行观感像结论：三行同样式并列（registry.ts:1819-1822），Rh 行实际与输入无关却被视觉默认为"本次计算的第三项结果"，应显式限定"与本次输入无关的通用说明"
4. 【功能】无反推模式：只有父母→子女单向（registry.ts:1816），"孩子是 O 型，父母可能是哪些组合"的亲子向核对缺失——Calculator.net 标配双向
5. 【灵魂-科普】不给原理与速查表：A/B 显性、O 隐性的基因型解释（utilLife.ts:96-97 A=AA/AO 等枚举本可直译成科普）不上页面，16 组合完整速查表也无折叠提供——科普工具只给结果不给"为什么"，用户只能选择相信
6. 【功能】无概率区间：A×B 在 AO×BO 下四型各 25%，AA×BB 下 AB 100%——表型组合相同而概率分布不同，工具只给可能集不给概率层（标杆有基因型概率分配）；属进阶但科普价值高
7. 【交互-亮点备案】默认 A×B 开屏即出完整结果（registry.ts:1808-1813），是 calcDef 家族里少见的零输入成本开局（多数工具空字段+引导行）——该实践值得家族推广

## 行业对标与差距

- **Calculator.net Blood Type Calculator**：父母→子女与子女→父母双向、ABO+Rh 全组合 16 格速查表。差距：反向模式与完整表格。
- **Omnicalculator Blood Type Child Calculator**：ABO+Rh 双输入、父母基因型概率分配、孟买血型例外说明。差距：Rh 计算与概率层。
- **丁香医生/宝宝树等孕育平台血型科普**：ABO/Rh 遗传表+Rh 阴性母亲新生儿溶血警示的孕育场景延伸。差距：场景纵深（延伸须医学审校+强免责，可远期再议）。
- 借鉴优先级：修空集文案 > Rh 输入参与计算 > 16 组合速查表折叠 > 反推模式 > 基因型科普一句 > 概率区间。

## 可拓展性

- 短期（1 周）：修空集文案；Rh 行加"通用说明，与本次输入无关"限定前缀
- 中期（1 月）：父母 Rh± 输入→子女 Rh 可能组合推导（Rh+ 按可能杂合处理）；16 组合速查表折叠区；子女血型反推父母组合模式
- 远期：孕期 Rh 阴性母亲注意事项科普扩展（须医学审校+强免责声明），或明确止步于基础科普不扩展

## 优化处方（验收标准）

1. **文案修复**：impossible 为空时改输出"无（四种血型都可能出现）"。→ **验收：A×B 时该行标签+值连读无矛盾；任意 16 组合下不存在"不可能：…都有可能"式表述**
2. **Rh 计算**：增加父/母 Rh 下拉参与推导。→ **验收：父 Rh− 母 Rh− 时输出"子女必为 Rh−"；父 Rh+ 母 Rh− 时输出"Rh+ / Rh− 均有可能（Rh+ 者基因型无法由表型确定）"，行文案随输入变化**
3. **速查表**：折叠区提供 16 组合速查表。→ **验收：展开后抽查 A×B、O×AB、AB×AB 三组与计算器实时输出一致**
4. **反推模式**：新增"由子女血型推父母可能组合"。→ **验收：选子女 AB 型时列出 A×B、A×AB、B×AB、AB×AB 四组可能且不含 O×O 等不可能组合**
5. **原理一句**：页面附显隐规则科普。→ **验收：可见"A/B 抗原为显性、O 为隐性，故 O 型父母不可能生下 AB 型子女"类解释文案，且与 note 医学免责并存**
