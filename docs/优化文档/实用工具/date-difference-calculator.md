## 结论与优先级

**交互优化** · P1（补 note 口径 + 与 business-day-calculator 互链/合并是必做项）

判据：无可用性硬伤；但"工作日"指标无口径披露（规约硬要求）且与站内同指标工具口径分裂，属明确的交互/口径优化。

## 扣分点明细

1. 【口径-规约】无 note：本工具 calcDef 没有计算口径说明（registry.ts:170-191 无 note 字段，对照规约"金融/单位换算需附口径"），"工作日（周一至周五）"仅靠 label 半披露——含不含法定节假日、区间含不含首尾日全部未说明
2. 【功能】工作日仅排周末：dateEngine.ts:66-72 只排除周六日，元旦/春节/国庆与调休补班一概不计；而站内 business-day-calculator desc 明确"含法定节假日与调休补班"（registry.ts:1172）——同一站点两个"工作日"答案可能差一周，且两工具零互链零提示
3. 【功能】无"含结束日"开关：合同期/租期场景"算头算尾"差一天，Calculator.net/timeanddate 均有 include end date 选项
4. 【功能】只有独立月数/年数行，无"2 个月零 5 天"式组合拆解（人读日历的方式）；也无"距今/从今天起"快捷
5. 【交互】日期无快捷填充（今天/明天/下周一）、无历史记忆（家族共性）
6. 【美观】6 行结果平铺，"总小时"这类弱信息与"总天数"同权重（CalcTool.vue:55-66 结果行无层级机制，仅 primary 一档）
7. 【口径】端点日边界：1/31→2/28 判"0 个月零 28 天"（dateEngine.ts:63-64 `e.getDate() < s.getDate()` 即减月），与"1 个月"的人类直觉冲突且无 note 可澄清
8. 【交互】起止颠倒仅静默换序（dateEngine.ts:59），无"已按时间先后自动交换"提示——用户不知道自己填反了

## 行业对标与差距

- **timeanddate.com Date Duration**：可勾选排除节假日（内置各国假日表）、include end day、按周/月拆分。差距：**工作日口径代差**——对方答"真实要上班多少天"，本工具只答"周一到周五有几天"。
- **Calculator.net Date to Date**：含尾日开关、business days 单独 Tab、结果可读化（"or 6 months, 5 days"）。差距：可读拆解与口径开关。
- 借鉴优先级：**note 口径披露 > 节假日口径（互链或内置）> 含尾日开关 > 组合拆解行 > 今天快捷**。

## 可拓展性

- 短期（1 周）：补 note；工作日行加 hint 互链 business-day-calculator；"今天/明天"快捷按钮
- 中期（1 月）：复用 business-day-calculator 的节假日数据源统一口径（加"排除法定节假日"开关）；含尾日开关；组合拆解行
- 远期：与 event-countdown/business-day-calculator 整合"日期工作台"（间隔/加减/倒计时/工作日四 Tab）

## 优化处方（验收标准）

1. **补 note**：注明"工作日仅排除周六日，未计法定节假日与调休；区间不含结束日"。→ **验收：页面底部可见该口径行**
2. **口径互链**：工作日行加 hint"需含节假日？→ 工作日计算器"链接。→ **验收：点击跳转 /t/business-day-calculator 且透传起止日期**
3. **统一节假日口径**：内置开关"排除法定节假日（含调休）"，默认关。→ **验收：2025-10-01~2025-10-07 开启后工作日为 0 天（国庆假期），关闭时为 4 天（仅排周末）**——若复用 business-day-calculator 数据源，两工具同区间结果必须一致
4. **含尾日开关**：勾选后总天数与工作日 +1。→ **验收：2024-01-01~2024-01-31 勾选后显示 31 天（默认 30 天）**
5. **组合拆解**：新增"X 年 Y 个月零 Z 天"可读行。→ **验收：2024-01-15→2024-03-20 显示"2 个月零 5 天"**
