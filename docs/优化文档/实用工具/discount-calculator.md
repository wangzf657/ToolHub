## 结论与优先级

**交互优化 + 需拓展** · P1

判据：可用性无硬伤（M-07 同族几何），但空态静默零值、口径缺失，且对照标杆缺"折上折/满减"主场景，功能面差距明显。

## 扣分点明细

1. 【可用性】部分填写即出零值：只填折扣 20、原价留空时 compute 照常执行，主结果"打 80 折后价格 ¥0.00"（registry.ts:671-675 仅判断 `if (Number(v.off))`、原价未守卫；对照 loan-calculator 的守卫 registry.ts:52）——NaN 守卫（CalcTool.vue:25-28）拦不住合法的 0
2. 【功能】无折扣链：不支持"满 300 减 50 + 9 折"叠加与先后顺序口径（顺序相乘 vs 直接相加结果不同），Omnicalculator/Calculator.net 均支持连续折扣
3. 【灵魂-口径缺失】无 note 字段：折数与百分比混用（20% = 8 折）恰是本品类最易误解处，AGENTS.md 要求金融类附计算口径，registry.ts:662-682 无 note（同文件 loan-calculator :62、compound-interest :655 均有）
4. 【灵魂-文案】"打 80 折后价格""真实折扣 80 折"标签非标准表述（registry.ts:673,678）：中文规范为"8 折"，"80 折"会被误读为 80% off
5. 【可用性】反推方向无异常校验：现价 > 原价时得"打 110 折（省 -10%）"照常输出（registry.ts:676-679），无"现价应低于原价"提示
6. 【功能】折扣率只能正算不能反求：已知"想省 200 元求折扣率"需用户心算后再填，Calculator.net 支持原价/现价/折扣率任意两求一
7. 【交互】比价场景无多商品清单：不同店铺到手价需来回手改同三个框，无历史对比（家族共性无记忆）

## 行业对标与差距

- **Calculator.net Discount Calculator**：原价/折扣率/现价任意两求一 + 第二重折扣按顺序相乘 + 总节省百分比。差距：折扣链与"反求折扣率"。
- **Omnicalculator**：满减门槛条件式（满 X 减 Y、满 X 件 Y 折）与叠加顺序可视化。差距：促销组合建模为零。
- 借鉴优先级：折上折/满减叠加 > 折数文案修正 > 空态守卫 > 结果单值复制。

## 可拓展性

- 短期（1 周）：空态守卫引导行；"打 X 折"改标准折数；补 note 口径说明
- 中期（1 月）：第二重折扣 + 满减字段，输出"到手价/总节省/合计折扣率"三行
- 远期：与 percentage-calculator（registry.ts:117）互链成"价格优惠计算组"，支持多商品比价清单

## 优化处方（验收标准）

1. **空态守卫**：折扣已填但原价为空时返回引导行。→ **验收：仅输入 20 时首行为"请先填写原价"，不出现 ¥0.00 主结果**
2. **折数文案**：主结果改为"8 折价 ¥80.00（省 20%）"。→ **验收：off=20 时标签含"8 折"字样而非"80 折"**
3. **补口径 note**：注明"到手价 = 原价 × (1 − 折扣%)；真实折扣% = (1 − 现价/原价) × 100"。→ **验收：页面底部出现口径说明行**
4. **折扣链**：新增"第二重折扣（%，可选）"字段，两折扣按顺序相乘并给出合计折扣。→ **验收：原价 100、off=10 再 off=20 时到手价 72、合计显示"7.2 折"**
5. **反推校验**：现价 ≥ 原价时返回提示行。→ **验收：原价 1000、现价 1200 时无"负折扣"行，显示"现价应低于原价"**
6. **结果单值复制**：到手价/节省/真实折扣行 hover 显示复制按钮。→ **验收：复制"节省"行后剪贴板为形如 200.00 的纯数字（无 ¥ 前缀）**
