## 结论与优先级

**交互优化 + 需拓展** · P1

判据：删表毁线属疑似功能缺陷（可用性扣分触发），保存/导入/撤销属与 dbdiagram.io 的子功能悬殊（需拓展），二者组合定级。

## 扣分点明细

1. 【可用性-疑似 Bug·核心】删表破坏连线：removeTable 用"id 大于被删 id 则减 1"重映射（:34），但 id 由 nextId 单调递增、tableOf 按 id 查找（:52），删除中间表后其余连线被重映射到不存在的 id——如删 id=2 后 link{to:3} 被改成 to:2，而 id=2 的表已不存在，linkPath 返回空串（:77）连线消失、exportSql 静默跳过（:102）；**同时所有连线 fIdx/tIdx 被强改为 0（:34），字段对位关系全部错乱**，导出的外键指向错误字段
2. 【可用性】连线画布裁剪：SVG 绝对定位 inset:0（:171）尺寸只等于画布视口，表拖到滚动区深处后其连线在首屏矩形之外的部分被裁剪——用户看到"断头线"或整条消失
3. 【功能-核心】无工程保存：tables/links 纯内存（:16-17），精心设计的 10 表 schema 刷新即蒸发——建模工具的内容是典型"高价值资产"，dbdiagram 的 DBML 常驻编辑器是第一体验
4. 【功能-核心】连线不可删除：link 无任何点击/右键处理（:136 仅渲染），连错字段后唯一出路是删除整张表（连带触发扣 1 的毁线 Bug）
5. 【功能】无反向导入：只有图→SQL 单向；dbdiagram.io 的核心是"贴 DDL/DBML→秒出图"双向编辑，已有 schema 的团队因此无法用本工具
6. 【交互】无撤销：删表/删字段/删连线全部不可恢复（全文无 undo 栈）；对照白板同门都有撤销，建模工具误删代价更高
7. 【灵魂】无示例引导：空态只有一句"点新建表开始设计"（:160），不放「用户-订单」示例 schema 一键载入；新用户面对空白画布+两步连线玩法有理解成本
8. 【交互/文档】hint 误导：「双击字段名可改名」（:131）但字段名是单击即编辑的 input（:152）；连线无橡皮筋拖拽预览（点起点后无视觉跟随鼠标的虚线），完成前无法预判连线走向；PK 判定靠字段名叫"id"的字符串匹配（:92），叫 uid/user_id 的主键无法标记

## 行业对标与差距

- **dbdiagram.io**：DBML 文本编辑器与图双栏联动（改代码即改图）、导入 MySQL/PostgreSQL/SQL Server DDL 反向生成、导出 PDF/PNG/SQL 多方言、工程保存与分享链接。差距：**双向编辑与持久化代差**；纯前端可先补 localStorage 保存+DDL 导入解析（CREATE TABLE 正则级解析即可用）。
- **drawSQL**：字段类型/约束图形化勾选、列宽自适应、团队协作（云端天花板）。差距：约束（NOT NULL/UNIQUE/默认值）字段缺失。
- 借鉴优先级：localStorage 自动保存 > 删表连线修复 > 连线点选删除 > DDL 导入反向生成 > 撤销栈 > 示例 schema。

## 可拓展性

- 短期（1 周）：removeTable 改为按 id 精确过滤+保留连线字段索引（不重置 fIdx/tIdx、不重映射 id）；连线 hover 高亮+点击删除（带确认）；tables/links 防抖存 localStorage+进页恢复；修正 hint 文案
- 中期（1 月）：撤销/重做快照栈；DDL 导入（正则解析 CREATE TABLE 生成表卡）；连线端点箭头+基数标注（1:1/1:N 选择）；画布缩放（Ctrl+滚轮）
- 远期：DBML 双栏编辑模式（左代码右图联动）；多方言导出（PostgreSQL/SQLite）；与 whiteboard 共享画布引擎（缩放/框选）；示例模板库（电商/博客/权限系统三套）

## 优化处方（验收标准）

1. 删表可靠性：删除任意表后，与其无关的连线保持原字段对位不变且正常渲染/导出；与被删表相连的连线自动移除。→ **验收：建 A/B/C 三表互连，删除 B 后 A→C 连线图形与 SQL 外键字段均与删除前一致**
2. 工程保存：tables/links 变更防抖 800ms 写 localStorage，进页自动恢复并显示「已恢复上次设计（N 表 M 连线）」+「清空重来」按钮。→ **验收：设计 3 表 2 线后刷新，结构与坐标原样恢复**
3. 连线删除：hover 连线变实线加粗，点击弹确认后删除该连线（不影响表）。→ **验收：删除 1 条连线后导出 SQL 中对应 ALTER TABLE 语句消失，其余保留**
4. 示例引导：空态画布中央放「载入示例：用户-订单-商品」按钮，一键生成 3 表 3 线含 FK 的完整示例。→ **验收：首次进入点击示例后立即可导出可执行的 schema.sql（含 3 条 CREATE TABLE + 2 条 FK）**
5. DDL 导入：新增「导入 SQL」入口，粘贴含 CREATE TABLE 的脚本后按表生成卡片（字段名/类型映射 9 类，不识别的类型落 TEXT）。→ **验收：导入 2 张含外键注释的建表语句后生成 2 卡，字段数与原文一致**
