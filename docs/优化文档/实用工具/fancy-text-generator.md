## 扣分点明细

1. 【功能-疑似功能 Bug（阻断级）】星体平面字符按 UTF-16 码元索引：`fancyText` 用 `map.upper[c.charCodeAt(0) - 65]` 取字符（textEngine.ts:497-508），而 bold/italic/script/fraktur/mono/double 六种映射表是 U+1D400 区的星体字符（每字符占 2 码元），码元下标取出来是孤立代理项+错位字形——**实测码点**：'HELLO' bold 输出 `U+DC03, U+1D405, U+DC05, U+DC05, U+D835`（首尾为渲染成 � 的孤立代理、E 变成 𝐅）；'HELLO' mono 输出含 U+DE7F/U+DE81 乱码。仅 circled（ⒽⒺⓁⓁⓄ）与 smallcaps（ʜᴇʟʟᴏ）因在 BMP 内幸存。小写与数字同样中招
2. 【功能-数据】mono 大写表本身还右移 12 位：'𝙼𝙽…𝚉𝙰𝙱…𝙻'（textEngine.ts:491，A 应为 U+1D670 实为 U+1D67C）——修好索引后该表仍错，需一并修正
3. 【功能】风格数量：8 种 vs CoolSymbol 80+；缺 Zalgo、删除线/下划线、上标/下标、emoji 装饰包裹等流量款；全角有站内 fullwidth-converter 但零互链
4. 【功能】无逐风格平台兼容标注：部分变体在 Instagram/微博渲染豆腐块，notice :44 只有一句整页提示，复制前不可避坑
5. 【口径】circled 数字 0 映射为实心 ⓿（textEngine.ts:492）与 ①-⑨ 空心系不一致；italic 无数字映射（Unicode 客观限制）但 UI 未说明
6. 【灵魂】smallcaps 中 Q/X 无小型大写字形回退为普通字母（textEngine.ts:494），风格突变无提示
7. 【交互】无批量出口：逐行复制，无"复制全部 8 行"；输入含中文时映射跳过（中文原样保留）但提示远离列表区

## 行业对标与差距

- **LingoJam**：风格家族矩阵+实时预览+平台兼容经验沉淀为页面文案。差距：对方产出可用，本工具 6/8 风格产出损坏——正确性先于丰富度。
- **CoolSymbol**：80+ 风格分类、点击复制、多语言界面。差距：数量级差距。
- 借鉴优先级：修复星体索引（`[...map.upper][idx]`）> 修正 mono 数据表 > 逐风格兼容标注 > 风格扩充（Zalgo/删除线）> 复制全部。

## 优化处方（验收标准）

1. **修复索引 Bug**：`map.upper`/`lower`/`digits` 索引前先 `[...]` 展开为码点数组。→ **验收：fancyText('HELLO','bold') 输出 𝐇𝐄𝐋𝐋𝐎（U+1D407 U+1D404 U+1D40B U+1D40B U+1D40E），8 风格任意大小写数字输出均无 U+D800~DFFF 孤立代理**
2. **修正 mono 数据**：mono 大写表改为 U+1D670~U+1D689 顺排。→ **验收：fancyText('HELLO','mono') 等于 U+1D677 U+1D674 U+1D67B U+1D67B U+1D67E（𝙷𝙴𝙻𝙻𝙾）**
3. **引擎哨兵测试**：scripts/tests 增加 fancyText 码点合法性用例（8 风格×Aa0 输出不含 U+D800~DFFF 且与 FANCY 表展开后第 idx 项一致）。→ **验收：npm run test 包含该用例并通过**
4. **逐风格兼容标注**：每行风格名后加"IG ✓ / 微博 ⚠"徽标。→ **验收：8 行各有徽标，点击出现 1 句说明**
5. **复制全部**：列表头加"复制全部风格"。→ **验收：剪贴板为 8 行"风格名：变换结果"文本且 circled/smallcaps 行内容正确**
6. **输入历史**：localStorage 记最近 5 次输入，输入框下方以 chips 呈现。→ **验收：输入 3 个昵称后刷新页面，历史区可见 3 个 chips，点击即恢复输入并实时重算 8 行**
