## 扣分点明细

1. 【可用性-安全】加密前无密码二次确认/可见性切换：`type="password"` 单输入（FileEncryptor.vue:72-77），看不清输错什么就是什么——AES-GCM 下错误密码不报错而是产出"可成功解密成乱码"的新文件，用户发现时原文可能已删。Hat.sh 用"密码输入两次一致才允许加密"解决
2. 【功能-大文件】整文件读入内存：`encryptFile`/`decryptFile` 均一次性 `arrayBuffer()`（cryptoFile.ts:36-37,46），500MB 视频即内存溢出；无分块流式、无进度回调、无 50MB 拦截提示
3. 【功能】无密码强度提示：PBKDF2 31 万次迭代挡不住弱口令离线爆破，加密强度实际取决于密码熵，UI 却无任何强度反馈（对照站内 password-strength-checker 有现成引擎未复用）
4. 【口径】自定义 .wzf 格式不与任何标准工具互通：魔数 WZF1 + salt+iv+密文（cryptoFile.ts:4-8），notice 只说算法（:93）不说"其他工具打不开本格式"——跨设备解密必须再回到本站，未披露
5. 【交互】单文件限制（:64 `:multiple="false"`），多文件场景要逐个加密 5 次
6. 【灵魂】无加密后自检：可在加密后立即用输入的密码做一次内存内解密比对，通过才交付下载——低成本高安心，未做
7. 【交互】解密产出 Blob 直接 saveBlob（:51），解密照片/文档前无预览确认

## 行业对标与差距

- **Hat.sh**：拖入即估时、密码二次输入、拖放输出、Argon2id 抗 GPU 爆破、大文件分块流式。差距：**危险操作防护与流式处理**两处代差。
- **Cryptomator**：密码强度实时评估、密钥文件双因子、保险库概念。差距：密码强度反馈缺失。
- 借鉴优先级：密码二次确认 > 密码可见切换 > 流式分块+进度 > 强度评估 > 格式互通披露。

## 可拓展性

- 短期（1 周）：密码输入二次确认+小眼睛切换；加密成功后自动回读解密校验再交付
- 中期（1 月）：分块流式加密（每 4MB 一块、manifest 记录），配进度百分比；复用 password-strength 引擎做强度条
- 远期：多文件打包加密（.wzf 档案格式 v2）；接入 Web File System Access API 做原地加密

## 优化处方（验收标准）

1. **密码二次确认**：加密模式显示"再次输入密码"框，两次不一致禁用加密按钮。→ **验收：两次输入不同时按钮 disabled 且给出红色不一致提示；一致后可加密**
2. **密码可见切换**：输入框右侧加眼睛图标切换明文。→ **验收：切换后 input.type 在 password/text 间变化且焦点不丢失**
3. **加密后自检**：交付下载前用同密码在内存中解密并比对字节数。→ **验收：加密 1MB 文件时 Network 无新请求、控制台无报错、下载文件可被本工具解密回原字节**
4. **大文件进度**：>10MB 文件显示百分比进度条（分块加密后按块上报）。→ **验收：加密 200MB 文件可见进度推进，且页面不冻结（每块之间让出主线程）**
5. **格式披露**：notice 补一句"输出为本站自定义 .wzf 格式，解密需回到本工具"。→ **验收：notice 文案含该句**
6. **密码强度提示**：复用站内 password-strength 引擎，密码框下显示强度条。→ **验收：输入 123456 显示红色"弱"警示条，输入 16 位混合密码显示绿色"强"，加密模式下弱密码时按钮旁出现风险提示文案**
