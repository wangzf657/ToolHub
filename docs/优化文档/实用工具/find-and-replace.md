## 结论与优先级

**交互优化 + 需拓展** · P1

判据：计数反馈缺失与"替换为换行做不到"是明显交互摩擦；对比 textmechanic/CyberChef 的替换闭环存在可追功能缺口。

## 扣分点明细

1. 【可用性-硬伤·家族】双 textarea 各钉 180px、无同步滚动（`base.css:164-168`；M-06），详见 `pinyin-converter.md` 扣分 1
2. 【交互】替换计数被丢弃：引擎明确返回 `{result, count}`（`textEngine.ts:194`）但注册表只 `return r.result`（`registry.ts:413`）——替换了几处用户永远不知道，也不敢确认成功
3. 【功能】替换为换行做不到：find/replace 均为单行 text 输入（`TextTool.vue:87-94`）无法输入换行符，替换串的字面 `\n` 在 JS replace 语义下也不会被解释——"逗号→换行"这一最高频诉求无法完成
4. 【功能·未接线】整词匹配引擎已实现（opts.whole → `\b...\b`，`textEngine.ts:186`）但注册表选项未暴露（`registry.ts:405-410` 无该 toggle）——现成能力躺在代码里
5. 【交互】非法正则的 toast 直接透出英文原始报错（"Invalid regular expression: …"），TextTool 仅对 JSON 错误做了本地化（`TextTool.vue:41`）
6. 【可用性】"用输出替换输入"（swap）不可逆覆盖原文（`TextTool.vue:56-58`），替换错了无法回到原文再试，无快照撤销
7. 【功能】无"仅替换第一处"粒度开关（textmechanic Replace Text 标配）——只想替换首个命中时被迫全量再手工改回
8. 【灵魂】无命中高亮：替换前看不出哪些会被命中；空查找时输出=输入且无"未填写查找内容"提示

## 行业对标与差距

- **textmechanic.com（Replace Text）**：大小写敏感、"仅替换第一处"等粒度开关一排——替换范围可控。差距：替换计数与粒度开关。
- **CyberChef（Find/Replace）**：正则/大小写开关齐，且多操作可串成流水线（替换→去空行→转格式一气呵成）。差距：流水线编排；单点能力上我们只差计数、整词与转义。
- 借鉴优先级：替换计数 > `\n`/`\t` 转义支持 > 整词开关 > 正则报错中文化。

## 可拓展性

- 短期（1 周）：输出标题行显示"替换 N 处"（count 现成，接线即可）；正则报错中文化映射
- 中期（1 月）：替换串支持 `\n` `\t` 转义；暴露整词与"仅第一处"开关；swap 前快照一键撤销
- 远期：命中高亮预览模式（替换前染色）；与 remove-duplicate-lines/sort-lines 组成"文本批处理管道"

## 优化处方（验收标准）

1. **计数反馈**：输出 io-head 显示"替换 N 处"；0 匹配显示"无匹配"徽标 → **验收：aaa 替换 a→b 显示"替换 3 处"；查找不存在的串显示"无匹配"**
2. **转义支持**：替换串解释 `\n` `\t`（非正则模式同样生效） → **验收：非正则模式把逗号替换为 `\n`，输出逐行分行**
3. **整词开关**：暴露 whole 选项为 toggle → **验收：开启后查找 cat 不命中 category**
4. **正则报错中文化**：捕获 SyntaxError 并翻译常见三类（未闭合分组/无效转义/量词错误） → **验收：输入 `(a` 时 toast 显示中文提示**
5. **撤销保护**：swap 前自动快照原文，提供"撤销替换"入口 → **验收：替换→swap→撤销后输入区恢复替换前原文**
