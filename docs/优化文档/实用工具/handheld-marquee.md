## 结论与优先级

**交互优化** · P1

判据：核心动效可用，但 Esc 失效与假全屏属可感知的交互缺陷（P1）；场景模板与常亮属拓展加分。

## 扣分点明细

1. 【可用性-Bug】Esc 退出形同虚设：keydown 监听挂在覆盖层 div 上（@keydown :63）且依赖 tabindex=0 获焦，但 start() 后焦点仍留在面板的启动按钮上、覆盖层从未主动 focus（:25-29 无 focus 调用）——按 Esc 无任何反应，与 hint「全屏后：Esc 退出」（:60）承诺不符，退出只能点右上角小圆钮
2. 【可用性】假全屏：未调用 `requestFullscreen`（全文件无该 API，对照站内 Teleprompter.vue:54-56 已正确使用）——移动端浏览器工具栏不消失，举牌时上下各损失一截可视区；也无 Wake Lock，手机息屏后弹幕中断
3. 【交互】默认速度劝退：滚动时长默认 80s（:8），一句「接机 · 请往 3 号口」约 21px/s 龟速爬行，首次使用者大概率判定"没动/坏了"；且参数模型是"恒定时长"而非 px/s，同参数在手机与 4K 屏上视觉速度完全不同
4. 【灵魂】无启动前预览：面板内不放一行迷你滚动预览（缩小的 track），字号/颜色/速度的全部调整都要「启动→退出→再启动」循环
5. 【功能】无场景模板：接机牌/生日快乐/演唱会应援各配一句默认文案+应援配色（如红底白字）的一键预设；最近记忆只存文字不存配色组合
6. 【功能】动效模式单一：只有匀速平移——LED 牌经典的闪烁/呼吸/逐字亮起均无；无多行（两行大字并排）能力
7. 【美观】颜色操作原始：两个原生 color input（:46-48）无预设色板、无对比度提示（深底深字白举牌看不清）；字号/时长数字输入框在手机上要唤起键盘
8. 【交互】方向语义反直觉：默认左→右（:10），而 LED 牌/机场屏惯例是从右向左滚入；镜像开启时方向语义再次翻转，无即时说明

## 行业对标与差距

- **LED 弹幕大师（iOS/Android）**：真全屏+屏幕常亮、速度像素级滑杆、闪烁/扫描多动效、多行与 emoji、场景模板库（接机/表白/招聘）、横屏一键锁定。差距：**沉浸可靠性（全屏+常亮）是硬差距**，模板库是软差距；Fullscreen API 与 Wake Lock 均为纯浏览器标准能力，天花板内可补齐。
- **演唱会应援字牌类小程序**：明星色系一键套用（红/蓝/紫阵营色）、双面镜像（舞台反光板）。差距：色板与镜像已有（:54）但缺色系预设。
- 借鉴优先级：requestFullscreen+Wake Lock > 面板内预览 > 场景模板 > 速度滑杆(px/s) > Esc 修复。

## 可拓展性

- 短期（1 周）：start() 时 `overlay.focus()` 修活 Esc + 同步调用 requestFullscreen（失败降级 fixed）；接入 `navigator.wakeLock`（不可用时 hint 注明）；面板内加 0.3 缩放迷你预览条
- 中期（1 月）：接机/生日/应援三套模板卡（文案+配色+速度组合）；速度改 px/s 滑杆并按视口宽度换算时长；预设色板（8 组高对比组合）；闪烁/呼吸动效模式
- 远期：多行双拼大字（上下两行反向滚动）；「双屏镜像」模式（手机+平板通过 URL 同步显示同款弹幕）；最近记忆存完整配置组合

## 优化处方（验收标准）

1. 真·全屏与常亮：start() 内调用 `overlay.requestFullscreen()`，并 `navigator.wakeLock.request('screen')`（不支持的浏览器在 hint 说明）。→ **验收：Android Chrome 启动后地址栏消失、举牌 5 分钟不息屏；Esc/退出按钮均恢复正常面板**
2. Esc 修复：start() 末尾对覆盖层调用 `overlay.focus()`，Esc 与右上角按钮行为一致。→ **验收：启动后不点击任何位置直接按 Esc，覆盖层关闭**
3. 面板预览：选项条下方常驻一条 120px 高的迷你滚动条，实时反映文字/颜色/字号比例/速度/方向/镜像。→ **验收：改背景色为蓝色，预览条即时变色且无需点启动**
4. 默认体验：默认时长改为按视口宽换算的等效 12s 全程（或速度默认 150px/s 滑杆），短文案 5s 内完成一次穿屏。→ **验收：默认参数下「生日快乐」从屏右到屏左 ≤10s**
5. 场景模板：空态区放 3 张模板卡（接机红底白字 / 生日金底红字 / 应援蓝底白字），点击填充全部参数。→ **验收：点击「接机」模板后直接启动即为红底白字横滚效果**
