## 结论与优先级

**交互优化 + 需拓展** · P1（信息层补齐 + CDN 韧性，属辅导场景的完整性缺口）

判据：可用性 12/20 无硬伤；功能面 10/20——对标笔顺网缺笔画数/笔顺名称这类"课本必备"信息，家长仍需开第二网页。

## 扣分点明细

1. 【功能】无笔画数与笔顺名称展示：数据里 `strokes` 数组长度即笔画数、每笔序号即名称可映射（横竖撇捺折），均未渲染——小学作业场景"这个字几笔、先写哪笔"是第一问（`HanziStrokeOrder.vue` 全文无对应 UI）
2. 【环境-弱网】charDataLoader 走 `cdn.jsdelivr.net/npm/hanzi-writer-data@latest/`（:44）——jsDelivr 境内可用性波动大，失败仅有 toast 无"重试/换源（unpkg/npmmirror）"按钮；`@latest` 未锁版本，库更新可能改数据格式
3. 【交互】画布固定 240px（:31-37）不可缩放，投影/大屏教学与低年级大字描红两场景都不适配；无田字格/米字格底格选项
4. 【功能】无部首/部件分解（radStrokes 数据在但未标）、无拼音/组词，与站内 pinyin-converter 无联动——"字"维度的学习闭环断裂
5. 【交互】连播模式播放中无当前第几字高亮指示（仅输入框文字被动变化，:76），中途不可暂停跳字（busy 锁全按钮，:89-90）
6. 【灵魂】无最近练习记录、无"今日一练"随机常用字推荐，复练动机未建立
7. 【交互】生僻字/非汉字字符无前置校验：输入字母或符号后走完加载流程才报"不在笔顺库中"（:45 依赖 CDN 404），本地可先行字符类判断即时拦截

## 行业对标与差距

- **HanziWriter 官方 Demo**：完整 char 数据展示（笔画分解列表、部件着色开关、quiz 参数可调）、离线数据包示例。差距：**信息层暴露**——同款引擎对方把数据用满，本工具只用了动画+quiz。
- **笔顺网（bihua.chazidian 类）**：笔画数+笔顺名称图文（"横折钩"逐笔标注）、田字格描红字帖打印、组词造句。差距：课本合规性信息与打印输出（站内 CopybookGenerator 已有字帖能力却未互链）。
- 借鉴优先级：**笔画数+笔顺名称 > CDN 换源重试 > 田字格 > 拼音组词联动 > 字帖互链**。

## 可拓展性

- 短期（1 周）：画布下方渲染"共 X 画"+ 逐笔名称 chips（strokes.length 就地可算）；CDN 失败按钮化重试
- 中期（1 月）：数据源容灾（jsDelivr→unpkg→npmmirror 依次 fallback + 版本锁定）；田字格/米字格开关；画布 160/240/320px 三档
- 远期：与 pinyin-converter（读音）、CopybookGenerator（字帖打印）、poem-search（例句）组成"语文学习工作台"；本地打包一级常用 3500 字数据（约 35MB 按需分片）

## 优化处方（验收标准）

1. **信息层**：画布下方常显"X 画"与逐笔名称 chips（1横 2竖 3撇…按序高亮当前动画笔）。→ **验收：输入"永"显示"5 画"，播放时第 N 笔 chip 同步高亮，名称与通用笔顺名称表一致**
2. **CDN 韧性**：charDataLoader 失败后画布区显示"加载失败 [重试]"按钮，重试依次切换 unpkg/npmmirror 源；URL 锁定具体版本号。→ **验收：断网点重试显示明确失败文案而非静默；hosts 屏蔽 jsdelivr 后 npmmirror 源可成功加载**
3. **底格与尺寸**：选项行加"田字格/米字格/无"切换与 160/240/320 三档尺寸。→ **验收：切米字格后画布出现对角虚线且笔顺动画在其上层正常播放，320px 下描红触点精度不降级**
4. **连播控制**：连播时显示"2/4 · 好"进度指示，支持暂停/跳过当前字。→ **验收：输入"你好世界"连播中出现进度文案，点暂停后动画停帧、点播放继续当前字**
5. **非汉字即时拦截**：输入非 CJK 字符点播放时直接 toast"请输入汉字"且不发网络请求。→ **验收：输入"abc"点播放 100ms 内提示、DevTools Network 无 CDN 请求**

> 跨工具协同：站内 CopybookGenerator（字帖生成）与本工具同属"练字"场景，处方 3 落地后两工具应互挂入口，补齐"屏上描红 ↔ 纸上字帖"的闭环。
