## 结论与优先级

**交互优化** · P2

判据：无硬伤，核心闭环（填→存→出示）完整流畅；扣分集中在防错校验与数据备份，属打磨级改造。

## 扣分点明细

1. 【灵魂-核心】无税号校验：纳税人识别号应为 18 位统一社会信用代码（placeholder 自己都写了 :87），但任意输入照单全收——前台开票时才发现税号错一位被退回，正是本工具最该防的错误；缺长度/字符集实时校验与 Luhn 类校验位提示
2. 【交互】二维码滞后：`@change` 事件只在失焦触发（:86-89），边打字右侧码不变，用户可能截屏/出示了旧码；应 input 防抖刷新或出示前二次确认
3. 【交互】空名可复制：doCopy 未检查 form.name（:60-63），空表单点「复制抬头」复制空串且 toast「已复制抬头信息」，误导
4. 【功能】无备份通路：8 条抬头只存 localStorage（:15,:28），换设备/清缓存即全丢——抬头信息恰恰是低频重填高价值数据；缺「导出 JSON/导出图片码集」与对应导入
5. 【灵魂】无示例引导：空态不提供「XX科技有限公司」示例一键填充试玩，新用户不知道填完会发生什么；无「个人抬头（免税号）」快捷预设按钮
6. 【交互】覆盖保存无预告：save 按同名去重即覆盖（:27），改了已存抬头再点保存会静默覆盖原条目，无确认或「另存为新抬头」选项
7. 【美观】`.sr-icon { display:none }` 死样式（:127）；模板无对应元素，属清理项
8. 【功能】二维码 payload 为中文纯文本行（:45-46）——相机扫码可读，但部分开票录入 App 期望特定结构（如 JSON 或 vCard 变体），未提供格式切换或说明，跨 App 兼容性靠运气

## 行业对标与差距

- **草料发票抬头码**：扫码即出结构化抬头（录入 App 直接解析）、支持批量员工抬头管理、活码可后台更新、数据云端同步。差距：**结构化编码与多设备同步**；纯前端天花板内可做「导出图片码集+JSON 备份」逼近。
- **微信发票抬头管家**：与聊天/卡包打通、开票时直接选择推送商户。差距：场景嵌入无法企及（架构天花板），但「复制文本」通路本工具已等价覆盖。
- 借鉴优先级：税号实时校验 > input 防抖刷新码 > 备份导出/导入 > 示例与个人抬头预设 > 覆盖确认。

## 可拓展性

- 短期（1 周）：税号 18 位校验（长度+字符集，错位标红）；doCopy/doDownload 空名守卫；「个人抬头」预设按钮（名称=个人，税号留空）
- 中期（1 月）：导出/导入 JSON 备份；保存前同名确认弹层；input 防抖 300ms 刷新二维码；抬头卡片长图（码+文本一体）分享下载
- 远期：与 vcard-generator 统一「我的卡片」入口（个人名片+发票抬头+WiFi 一处管理）；payload 可切换纯文本/结构化 JSON 两种编码

## 优化处方（验收标准）

1. 税号校验：输入非 18 位或含非法字符时字段下出现红色提示「统一社会信用代码应为 18 位」，且不阻断保存但标黄警示。→ **验收：输入 17 位数字即见提示；完整 18 位数字+字母通过**
2. 二码同步：input 事件防抖 300ms 后重渲染二维码。→ **验收：连续输入公司名，停手 0.5s 内右侧码内容与表单一致**
3. 空态守卫：form.name 为空时「复制抬头」置灰或 toast「请先填写公司名称」。→ **验收：清空名称后点击复制，无空串写入剪贴板**
4. 备份通路：新增「导出抬头（JSON）」与「导入」按钮，导入合并去重（按名称）。→ **验收：A 浏览器导出 8 条，B 浏览器导入后 chips 数量一致且重名不重复**
5. 个人抬头预设：空态区放「公司抬头/个人抬头」两个快捷卡，点个人即预填名称「个人」并聚焦税号提示可留空。→ **验收：首次进入点击「个人抬头」后二维码立即生成**
