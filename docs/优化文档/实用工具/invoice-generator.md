## 扣分点明细

1. 【可用性-硬伤·疑似功能缺陷】`printInvoice` 中 `rowsHtml` 的 map 回调在第 56-66 行同步调用 `esc()`，而 `const esc` 在第 67 行才声明——TDZ 导致每次点击「打印 / 另存 PDF」抛 `ReferenceError: Cannot access 'esc' before initialization`，空白弹窗残留且无任何错误提示（已用同构代码在 Node 印证必现）
2. 【功能】无中文增值税发票模板：购销双方税号、地址电话/开户行账号、价税合计（大写）、收款人/复核/开票人等要素全部缺失，中文商务场景只能输出英文 invoice 变体
3. 【交互】无草稿持久化：meta/items 全部 reactive 无 localStorage（:8-23），填了 10 行明细误刷新即归零——发票是典型「填一半停一停」场景
4. 【功能】无 Logo 上传与模板配色：invoice-generator.com 的核心差异化即「左侧 Logo + 模板库 + 币种/语言本地化」，本工具输出是素面 HTML
5. 【可用性】打印失败零反馈：window.open 被拦截有 toast（:52-55），但 write 阶段崩溃静默；成功也无「已打开打印窗」确认
6. 【功能】合计无大写金额、无行折扣、税率只有百分比手输无免税/含税价切换——财务口径粗放（AGENTS.md 金融口径要求应附计算说明，此处无口径注）
7. 【交互】明细行不支持拖拽排序与复制行（只有删除 :155-157），换客户复用需逐行重填
8. 【实用价值】与站内 invoice-assistant（发票抬头助手，已评估 61 分）零互链——开票抬头场景两工具各管一段，页面互相找不到对方

## 行业对标与差距

- **invoice-generator.com**：实时右侧预览、模板/Logo/币种/语言切换、每行折扣、备注与付款条款预设、PDF 直下（非打印对话框）、草稿保存。差距：**「预览所见即所得」代差**——对方编辑区右侧永远长着发票成品，本工具填完还要靠一个坏掉的打印窗口。
- **中文增值税发票模板惯例**：价税合计大写、购销双方八要素、清单附件——本工具字段模型（desc/qty/price/taxRate）可复用，缺的是模板渲染层。
- 借鉴优先级：修复打印 TDZ > 右侧实时发票预览 > 草稿 localStorage > 增值税模板 > 大写金额。

## 可拓展性

- 短期（1 周）：esc 提到 map 之前（一行修复）；打印成功 toast；meta+items 存 localStorage 草稿（key 前缀 toolhub）
- 中期（1 月）：右侧实时发票预览（HTML 模板直接渲染进面板，替代新窗口）；价税合计大写转换（站内 number-to-words 引擎可复用）；与 invoice-assistant 互链
- 远期：模板系统（通用 invoice / 增值税发票 / 收据三套 JSON 模板）；Logo 上传 base64 嵌入；导出真 PDF（pdfEngine 已有 imagesToPdf/textToPdf 能力）
