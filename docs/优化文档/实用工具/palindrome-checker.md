## 扣分点明细

1. 【交互】无示例一键填充：placeholder 写着"上海自来水来自海上 / A man, a plan..."（:41）却要用户手动打字——新用户想验证工具只能自己想回文；一键示例是本工具成本最低的灵魂升级
2. 【交互-死代码】回文输入框 `@keydown.enter.prevent`（:41）阻止了回车却无事发生——既无提交语义也无焦点跳转，行为不可预期
3. 【功能】变位词无词典推荐：dcode.fr 输入 listen 可反查 silent/enlist/tinsel 全部变位词（需词典数据，纯前端可内嵌 5 万常用英文词表）；本工具只能验证已知对
4. 【功能】无最长回文子串/回文切割：编辑器场景常问"这句话里最长的回文是什么"，引擎只做整串判定
5. 【口径】中文变位词语义弱：字符排序比较对英文 word anagram 成立，对中文"上海/海上"也会判为变位词（isAnagram :628-630 不区分词边界）——结果正确但用户可能误解语义，无口径说明
6. 【可用性】清洗规则把全角数字/带声调拼音字母（á é）全部剥除（:7 正则只留 a-z0-9+汉字），"Ánana"类外文回文误判为空——口径未披露
7. 【灵魂】判定为"不是回文"时不给"差一步"提示（如"翻转后差 2 个字符，前 6 位一致"）——趣味场景下"差多少"比"不是"更有传播价值

## 行业对标与差距

- **dcode.fr**：回文/变位词/最长回文子串全家桶+词典反查+批量处理。差距：**词典能力代差**——对方能"发现"变位词，本工具只能"验证"变位词。
- **站内 word-counter 家族**：实时统计+口径注释的惯例一致 ✓；无额外重复。
- 借鉴优先级：示例一键填充 > 变位词典反查 > 移除死 Enter 处理 > 差一步提示 > 口径披露。

## 可拓展性

- 短期（1 周）：双 pane 各加 3 个示例 chip（上海自来水来自海上 / A man, a plan, a canal: Panama / listen↔silent）点击填充；删除 :41 的死 Enter 处理
- 中期（1 月）：变位词词典反查（内嵌英文常用词表 ~200KB 懒加载，输入 listen 列出全部词级变位）；"差一步"提示（最长公共前后缀长度）
- 远期：最长回文子串高亮（Manacher 算法）；回文日期/回文数生成器（数字趣味场景）；与 word-frequency 组成"文字游戏工具组"互链

## 优化处方（验收标准）

1. **示例 chips**：回文 pane 下方 3 个示例按钮，点击即填充并出判定。→ **验收：首次进入首屏可见示例区，点击"上海自来水来自海上"后 verdict 显示绿色"是回文"**
2. **移除死交互**：回文输入框 Enter 转为"聚焦变位词第一输入框"或移除 prevent。→ **验收：回文框内按 Enter 焦点移动（或行为与普通 input 一致），无卡顿感**
3. **差一步提示**：非回文时显示"前 N 位对称一致，差异在：清洗后第 k 位『x』vs『y』"。→ **验收：输入"上海自来水来自海上"改 1 字后提示指出首个不对称位置与两侧字符**
4. **口径披露**：pane 底部说明补"全角数字与带声调字母不参与判定"。→ **验收：说明句可见且与 :7 清洗正则行为一致**
5. **中文变位词口径**：变位词 pane 结果下方注明"中文按单字比较（上海↔海上 会判定为互为变位词）"。→ **验收：说明句可见，输入 上海/海上 显示绿色判定与该注释**
6. **判定历史**：localStorage 记最近 5 条检测结果（原文截断+结论），双 pane 各自呈现。→ **验收：检测 3 条后刷新页面历史区可见 3 条带绿/红色点的记录，点击回填输入并重出判定**
