## 结论与优先级

判据：可用性无硬伤；功能面与 zxcvbn 的差距是"会不会判断字典/键盘/日期模式"的代差，属纯前端可补的真差距。

## 扣分点明细

1. 【功能-核心差距】无字典攻击识别："password123!"、"qwertyuiop1" 等高频弱密码因"字符类别多"被评中等以上（entropyBits :19-28 按字符池盲算）——zxcvbn 的核心即字典+模式（键盘序/重复/日期）匹配，这是安全工具的立身之本
2. 【功能】无本地常见密码表兜底：前 1000 弱密码表（<20KB）即可识别绝大多数撞库密码，未内置；haveibeenpwned k-匿名 API 需网络，与"纯前端契约"冲突，至少应 UI 诚实标注"不含泄漏库比对"
3. 【灵魂】只诊断不开药：无"改进建议"区（zxcvbn demo 会给出 feedback.suggestions），用户知道"中等"却不知道下一步
4. 【交互】无清空按钮、无生成替代密码入口——与 password-generator 无任何互链（两文件均无引用），相关工具靠注册表顺序前 3（ToolPage.vue:44-46）不保证配对；"检测出弱密码→一键生成强密码"的闭环缺失
5. 【口径】破解速率 1e11 次/秒的假设对 GPU 集群偏保守（现代破解可达 1e12+），虽有披露但无档位可选（离线哈希/在线限速两种场景差别巨大，:109 仅一句话）
6. 【功能】无批量检测（导入密码列表逐条评级），测试数据/审计场景不可用
7. 【功能】熵模型把重复字符当独立熵："aaaa"按池 26 算 4×4.7=18.8 bits 尚可，但"abababab"类模式无惩罚，与 zxcvbn 的模式压缩熵差距明显
8. 【交互】无"新旧密码对比"模式：改密码场景需要确认"新密码确实比旧的强"，当前只能先后输入靠记忆比较

## 行业对标与差距

- **zxcvbn（Dropbox）**：字典+键盘序+重复+日期四级模式识别、按匹配片段压缩熵、给出 suggestions 与 crack time（多种攻击场景档位）。差距：评估智能的代差，库本身 MIT 协议可懒加载（注意 zxcvbn-ts 体积与懒加载纪律）。
- **How Secure Is My Password**：即时"X 秒/X 年被破解"+常改建议+泄漏库提示。差距：结论的情感化表达与行动指引。
- 借鉴优先级：字典/模式识别引擎 > 改进建议区 > 生成器互链闭环 > 攻击场景档位 > 批量检测。

## 可拓展性

- 短期（1 周）：底部加"弱密码？去生成一个强密码 →"互链卡片；加清空按钮；给出 2-3 条文字建议（长度/类别/避免重复规则引擎即可）
- 中期（1 月）：懒加载 zxcvbn-ts（needModel 类似的首用提示）替换/叠加现有启发式；内置 top-1000 弱密码表；破解速率三档（在线限速 1e4 / 单机 GPU 1e11 / 集群 1e12）
- 远期：与 password-generator 合并"密码工作台"（左生成右检测实时互证）；可选 HIBP k-匿名查询并明示"此步需要联网"

## 优化处方（验收标准）

1. 字典识别：内置 top-1000 弱密码表，命中即评级"非常弱"并显示"命中常见密码榜"。→ **验收：输入 password123! 结果为"非常弱"，不再显示"中等"**
2. 改进建议区：评级下方输出具体建议（如"增加长度至 14+""加入符号"）。→ **验收：输入 8 位纯小写密码时出现至少 2 条针对性建议**
3. 互链闭环：评级≤"弱"时展示"一键生成强密码"入口（跳转或内嵌 generator）。→ **验收：检测弱密码后一次点击可达生成器并预填长度 16**
4. 破解速率档位：三选一（在线/单机 GPU/集群），结论随档位联动。→ **验收：同一密码切"集群"档时破解时间比"在线"档至少缩短 5 个数量级**
5. 诚实标注：说明区补一句"未比对泄漏库，纯本地计算"。→ **验收：计算口径说明含此句，无网络请求发出**
