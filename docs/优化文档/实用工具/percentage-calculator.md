## 结论与优先级

**交互优化 + 需拓展** · P1（文案缺陷与空态零值必须修；三问分立是拓展方向）

判据：硬编码"30%"label 与空态零结果属可直接检验的实现缺陷；与 Calculator.net 的分立式三问存在交互范式差距。

## 扣分点明细

1. 【疑似文案缺陷】label 硬编码示例"30%"：第一行结果 label 固定为 `X 的 Y%（${x} 的 30% 类问题）`（registry.ts:129），y 填 15 时仍写"30% 类问题"，30 像上一版残留，直接误导
2. 【可用性】空态零值误导：两字段全空时第一行显示"（0 的 30% 类问题）0"（registry.ts:125-129 无守卫，Number('')=0 直接运算；CalcTool.vue:25 只拦 NaN）；第三行增减幅缺席导致初始结果区残缺
3. 【功能】问法覆盖不全：只有"求积/求占比/求变化率"三问，缺"基数×(1±r%)"求变化后值（打折/涨价/加薪场景第一问）、缺百分点与百分比语义区分（利率上调 0.5 个百分点 ≠ 0.5%）
4. 【交互】一对输入硬答三问：用户的问题形态（我知哪两个数）未作为输入，三行结果里有 1~2 行是用户不需要的（Calculator.net 三问分立三框，问题即输入）
5. 【口径】note（registry.ts:136）未写增减幅方向定义（(X−Y)/Y、X 为新值），X<Y 与 X>Y 用户对符号无感知（仅 hint 一个词）
6. 【家族共性】无输入记忆、结果不可单值复制（CalcTool.vue:55-66）
7. 【可用性】负数百分比无拦截：y 填 -10 时"X 的 -10%"照算无提示（registry.ts:129 直接运算，CalcFieldInput.vue:44-46 的 min/max 未配置）
8. 【口径】X=Y 时增减幅显示"0% + 增长"（registry.ts:132 `x >= y` 即判"增长"），相等应为"持平"，文案与数值打架

## 行业对标与差距

- **Calculator.net Percentage Calculator**：三问分立（X% of Y / X is what % of Y / % change）+ 每问独立示例与公式注释。差距：**问题对位**——对方用户零歧义，本工具要用户自己认领答案行。
- **Omnicalculator**：每类百分比问题单设计算器并附教学式步骤解释（"先除后乘"过程可见）。差距：无中间步骤展示，结果只有终值无"怎么算的"。
- 借鉴优先级：**修 30% 硬编码 > 三问分立或问题类型下拉 > 中间步骤展示 > 方向口径 note > 示例空态**。

## 可拓展性

- 短期（1 周）：修 registry.ts:129 label 模板；空态守卫；note 补方向口径
- 中期（1 月）：问题类型下拉（求占比/求数值/求变化率/求变化后值），按类型切换字段组；中间步骤行
- 远期：与 discount-calculator（registry.ts:659）整合"比例与折扣"家族入口，共享增减幅口径

## 优化处方（验收标准）

1. **修硬编码 label**：改为 `（${x} 的 ${y}% 类问题）`。→ **验收：x=200、y=15 时 label 显示"200 的 15% 类问题"**
2. **空态守卫**：x、y 任一为空时仅返回一行引导。→ **验收：清空两字段后 300ms 内结果区只剩"请填写数值"引导行**
3. **三问分立**：三组输入各答一问（可折叠），未填组不产生结果行。→ **验收：只填"求占比"组时其余两组无 0 值行出现**
4. **求变化后值**：新增"基数 + 变化率"两字段问题。→ **验收：基数 200、变化率 -15% 显示 170，且 hint 标注"下降"**
5. **note 口径**：注明"增减幅 = (X−Y)÷Y，X 为新值、Y 为旧值；百分点变化请直接相减"。→ **验收：页面 note 含该句**
