## 扣分点明细

1. 【可用性-数据正确性】携号转网零提示：validators.ts:154-166 为纯号段前缀查表，2019-11 全国携号转网正式实施后号段不再代表实际在网运营商（186 号码可能早已转网电信）；note 仅写"新号段可能未收录，不联网查询"（registry.ts:1269），全文无"携号转网"四字——按号段报"中国联通"可静默失真，离线架构无法解决转网数据，但 UI 诚实标注是唯一且必须的补救（README 口径规则 3）
2. 【灵魂-数据治理】号段表无版本承诺：CARRIER_RANGES（validators.ts:136-142）已含广电 192 与虚商 162/165/167/170/171，2026 年现状覆盖尚可；但无"号段数据更新至 YYYY-MM"标注，新号段发放后用户无从判断结果时效——数据型工具的信任底线
3. 【可用性】批量无汇总首行：逐行输出最多 200 行（registry.ts:1262-1266），无"有效 N / 无效 M / 虚商 K"统计行，客服核单场景需肉眼扫到底
4. 【功能】批量结果不可导出：核验完要回填 CRM/风控系统，结果区无一键复制/CSV 导出（CalcTool.vue:55-66 家族共性）——批量工具丢导出等于白测一半
5. 【交互】超量静默截断：slice(0,200)（registry.ts:1262）截掉第 201 个起全部号码且无任何"已截断"提示行，风控批量场景悄悄漏判
6. 【功能】归属地缺失无引导：note 诚实声明"不提供归属地" ✓（registry.ts:1269），属架构选择；但页面无"如需归属地/在网运营商请用 XX"的替代路径提示，用户预期落空无处可去
7. 【灵魂】未知号段结果无后续动作：validators.ts:165 的"运营商未知（新号段或未收录）"处理诚实 ✓，但不附数据版本/反馈入口，用户卡在"不知道该不该信这个'未知'"
8. 【交互】批量去重静默：`[...new Set(...)]`（registry.ts:1262）把重复号码无声合并，粘贴 210 个含重复的号码行数变少且无"已去重 N 个"提示——风控对账场景会疑惑"粘了 210 个怎么只剩 198 行"

## 行业对标与差距

- **站长工具（tool.chinaz.com）手机号归属地查询**：号段+归属地+卡类型一次出、批量带统计与导出。差距：批量汇总与导出闭环（归属地为更大时效维护面，本工具选择不做属合理取舍，但应互链指引）。
- **运营商官方携号转网查询**（短信 CXXZ#姓名#证件号至 10001 等）：给出"当前实际在网运营商"的权威答案。差距：权威性——对方回答"现在是谁的"，本工具只回答"号段原本是谁的"，且不说破这层差别。
- 借鉴优先级：携号转网警示 > 号段表版本标注 > 批量统计行 > 结果导出 > 截断提示。

## 可拓展性

- 短期（1 周）：note 与结果行补携号转网失真提示；号段表版本日期；批量统计首行
- 中期（1 月）：结果一键复制/CSV 导出；截断提示行与分批处理；头部虚商转售品牌识别（更细号段子段，静态可维护）
- 远期：归属地静态区号库（按年维护）或明确放弃并互链外部权威查询；号段表抽为独立数据文件便于年度更新

## 优化处方（验收标准）

1. **携号转网警示**：note 增补转网说明，单号查询时结果行下加 hint。→ **验收：页面口径行含"携号转网"字样；单号查询时可见"该结果基于号段归属，携号转网用户实际运营商可能不同"提示行**
2. **版本承诺**：号段表附带数据版本日期并在 note 展示。→ **验收：口径行可见"号段数据更新至 20XX-XX"，日后更新号段表同步改日期**
3. **批量统计首行**：多号查询时结果区第一行输出统计。→ **验收：粘贴 3 个合法号+1 个非法号，首行显示"有效 3 / 无效 1"**
4. **结果导出**：结果区右上角"复制结果"按钮。→ **验收：点击后剪贴板为逐行"号码,运营商"对，贴入 Excel 即成两列**
5. **截断提示**：超 200 个时输出提示行。→ **验收：粘贴 210 个号码时结果区出现"去重后仅处理前 200 个，其余 N 个未处理"**
