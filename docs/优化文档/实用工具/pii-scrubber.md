## 扣分点明细

1. 【可用性】遮盖处零标记：输出是纯文本墙（:80 pre），无高亮/下划线标出被遮盖片段——脱敏工具的用户核心疑问"哪些地方被改了"无法快速确认，长文本只能肉眼对照原文逐字找
2. 【功能-误报】银行卡正则 `\d{16,19}` 无 Luhn 校验（textEngine.ts:640）：16~19 位订单号/快递单号/IMEI 补零会被当银行卡打星——对照站内 text-extractor 对身份证做校验位过滤防误报（其加分项），同族工具质量落差
3. 【口径-误报】IP 正则无 0-255 段校验（textEngine.ts:641）：版本号"1.2.3.4"、章节编号"3.13.2.1"都会被整段打星，且 IP 先于 URL 规则执行（:645-658 顺序），URL 内的 IP 先被打星导致 URL 残段再被打星——遮盖串与统计口径不完全一致且无披露
4. 【交互】无类型开关：六类强制全开（textEngine.ts:637-644 无 skip 通路），"只要脱手机号、保留 IP"的合法诉求做不到；保留位数（前 2/末 4）写死不可调
5. 【功能】类型覆盖缺口：无座机、无中文姓名/地址（NER 需模型，可标注架构边界）、无微信/QQ 号、无自定义正则——Presidio 支持全部
6. 【交互】手动按钮非实时：粘贴后需点"立即脱敏"（:66-74），对照 TextTool 家族粘贴即处理（watch input）是退步；且无输入变化后"结果已过期"提示
7. 【灵魂-互链】与 text-extractor（提取）同正则家族反向场景零互链：先提取再脱敏、或脱敏前想看"到底有哪些敏感项"，两页要靠搜索二次触达
8. 【可用性】"未发现敏感信息"仅 notice-ok 横幅（:99），不提示"可尝试放宽口径"（如身份证日期范围限制导致误漏时无诊断线索）

## 行业对标与差距

- **Microsoft Presidio**：NER+正则双引擎、逐实体可配置遮盖策略（hash/encrypt/redact/mask 保留位数）、置信度阈值。差距：**可配置性代差**——对方是策略引擎，本工具是固定套餐。
- **CyberChef**：Mask/Regex 操作可自定遮盖字符与保留组，配合提取操作形成闭环。差距：无自定义通路。
- 借鉴优先级：遮盖处高亮 > 类型开关（保留哪类可勾）> 银行卡 Luhn 校验 > 与 text-extractor 互链 > 保留位数可调。

## 可拓展性

- 短期（1 周）：结果 pre 用 <mark> 包裹被遮盖段（piiScrub 返回带位置的 spans）；银行卡加 Luhn 校验开关（默认开）；脱敏前自动提取统计（复用 textExt）
- 中期（1 月）：六类 checkbox 开关+保留位数下拉（末 2/末 4/全遮）；粘贴实时脱敏（防抖 300ms）；结果区"转提取工具查看原文敏感项"互链
- 远期：自定义正则行（用户输入 pattern+遮盖策略，本地 eval 于沙箱）；NER 中文姓名地址（transformers.js，needModel 标注+诚实能力边界）；批量文件脱敏（txt/csv 下载）

## 优化处方（验收标准）

1. **遮盖高亮**：piiScrub 返回遮盖片段位置，结果区用黄色高亮底渲染。→ **验收：粘贴含 1 邮箱 1 手机号的文本，结果区恰见 2 处高亮且高亮内容与统计表计数一致**
2. **类型开关**：六类 checkbox（默认全开），取消某类后该类原样保留。→ **验收：取消"IP 地址"后文本中 IP 原样可见且统计表不再出现该行**
3. **银行卡 Luhn**：开启校验后仅 Luhn 通过的 16~19 位数字被打星，未通过的计为"疑似银行卡（未过校验）"单独行。→ **验收：粘贴合法信用卡号（Luhn 通过）被打星；粘贴 16 位递增订单号不打星且出现在疑似行**
4. **实时脱敏**：输入防抖 300ms 自动执行，保留手动按钮。→ **验收：粘贴文本后 0.5s 内结果区自动出现，无需点击**
5. **互链**：统计表下方加"查看/导出这些敏感项 → 文本提取器"。→ **验收：点击携带原文跳转 text-extractor 并自动执行全部类型提取**
