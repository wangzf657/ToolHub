## 扣分点明细

1. 【灵魂-诚实度】能力边界未前置："修复"实为"识别成功→按所选纠错等级重出干净码"，**识别失败的残码（重度模糊/大面积残缺）无能为力**（QrCodeRepair.vue:22-33 失败仅报错）——hint（:84）说明了用途但没说明"识别不出就修不了"，用户带着"坏码能救"的预期来会落空；desc（registry.ts:1717"识别模糊、带 Logo 的旧二维码，重新生成高纠错的干净新码"）与实现一致、无虚假承诺，问题在 UI 表达而非文案造假
2. 【功能】输出锁死 240px（:43 size: 240 + :94 qr-box 固定）：重打印/印贴纸场景分辨率不足，无 512/1024 档
3. 【功能】无解码增强：无放大重试/二值化/多尺度（同 qr-code-scanner 家族短板，qrEngine.ts:41-43 单次 getImageData）——"模糊码"恰是本工具的目标输入，解码成功率却是裸 jsQR 水平，目标场景与能力错位
4. 【功能】无前后对照：原图与修复码不同屏（原图上传后即弃），用户无法并排确认"这就是我那张码"；也无修复参数摘要（纠错等级/版本）
5. 【交互】无复制图片/SVG：仅 PNG 下载（:48-57），贴文档场景缺一步复制
6. 【交互】下载文件名固定"二维码-修复版.png"（:53）：多张修复同名覆盖
7. 【功能】重生成不保留版本信息：新码不显示二维码版本/模块数，用户无从判断与原码规格是否一致（同内容同纠错时模块布局可能不同——重编码引擎差异）
8. 【环境】家族共性：兄弟工具互链靠 ToolPage 注册表前 3 不可达（ToolPage.vue:44-46）；Cookie 横幅遮挡底部 hint（M-01 同款）

## 行业对标与差距

- **草料二维码**：解码容错强（多引擎+容错率自适应）、扫码后自动给"内容预览+重新生成美化码"路径。差距：**解码成功率代差**——对方模糊码常能识别，本站裸 jsQR 单次尝试；多引擎解码纯前端可实现（zxing-wasm+jsQR 竞速）。
- 能力边界的天花板说明：真正"修复"已残缺的码需要利用 RS 纠错冗余做部分恢复，业界在线工具也无此能力——本工具"重生成"路线是合理选择，问题只是要把边界讲清楚（见处方 1）。
- 借鉴优先级：**边界诚实前置 > 解码重试链 > 输出尺寸选项 > 前后对照 > 复制/SVG**。

## 可拓展性

- 短期（1 周）：上传区明示"仅能修复仍可被识别的码"；输出尺寸 240/512/1024 三档；下载名含内容摘要
- 中期（1 月）：解码重试链（1.5x/2x 放大+二值化 3 档）复用 scanQr 增强；修复前/后并排对照+参数摘要卡；复制图片按钮
- 远期：zxing-wasm 多引擎竞速解码；批修复（多张图→逐张重出 ZIP）；与 qr-code-generator/styled 打通"修复后直接转美化"流水线

## 优化处方（验收标准）

1. **边界诚实前置**：FileDrop hint 改为"仅能修复仍可被识别的码（换纠错等级/去 Logo 重出干净码）；完全无法识别时请手动输入内容"。→ **验收：首屏可见边界说明；模拟一张识别失败图，错误引导与说明文案一致**
2. **解码重试链**：失败后自动放大 1.5x/2x 与二值化阈值 3 档重试 ≤5 次。→ **验收：同一张轻度模糊样张，现版识别失败、改版识别成功（用 qa 夹具留存样张）**
3. **输出尺寸选项**：240/512/1024 三档，qr-box 随之缩放。→ **验收：选 1024 导出 PNG 实际 1024×1024 像素**
4. **前后对照**：识别成功后左栏显示原图缩略与"原码→新码（H 级）"摘要。→ **验收：对照区显示上传原图与重生成码，参数摘要与实际渲染一致**
5. **复制图片**：重生成码旁加复制按钮。→ **验收：点击后微信聊天框可直接粘贴出二维码**
6. **修复后转美化**：结果区加"转艺术码"按钮携带内容跳转 /t/qr-code-styled。→ **验收：点击后艺术二维码页内容框已预填修复出的内容**
