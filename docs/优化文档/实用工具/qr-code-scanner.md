## 结论与优先级

**需拓展 + 交互优化** · P1

判据：可用性 12/20 无硬伤；摄像头实时扫码是扫码工具的标配功能（草料/WebQR 均有，纯前端 BarcodeDetector/jsQR+MediaStream 可实现），属功能代差需拓展。

## 扣分点明细

1. 【功能】无摄像头实时扫码：全文无 getUserMedia/BarcodeDetector（QrScanner.vue:15-47 仅 onFiles 单路）——草料扫码、WebQR 标配；纯前端可实现（BarcodeDetector API 优先+jsQR 回退，HTTPS 依赖需 note），真差距
2. 【功能】只认 QR 不认条码：jsQR 仅 QR 系列（qrEngine.ts:38），EAN-13/Code128 扫不了；站内 barcode-generator 只生成不能反扫验证，两工具互为缺口
3. 【性能】解码无预处理：原尺寸 getImageData 后单次 jsQR（qrEngine.ts:41-43），无降采样、无放大重试、无二值化——小尺寸截图（如 200px 缩略图）与超尺寸照片（12MP）两个极端成功率都受损
4. 【灵魂】结果不结构化：WiFi 码扫出 `WIFI:T:WPA;S:Home-5G;P:xx;;` 原文（:67），SSID/密码要用户肉眼拆；vCard 一大坨转义串同理；草料扫码自动识别类型分字段展示
5. 【交互】无会话内历史：连续扫多张截图时前一条被覆盖（result 单值 :11），无法回看对比
6. 【交互】失败兜底弱：toast 报错后仅文字建议（qrEngine.ts:44），无"裁剪局部重试/放大重试"一键操作
7. 【交互】大图无压缩预览：识别成功后只给文本结果（:63-79），不显示所扫图片缩略，用户无法确认"扫的是哪张图"（多图连扫时尤其困惑）
8. 【环境】家族共性：面板 top≈250px（共性-根因 1）、断点碎片化（共性-根因 5）

## 行业对标与差距

- **草料扫码**：摄像头即扫+相册上传双路、自动识别类型（网址/WiFi/名片分字段）、扫码历史、批量扫描。差距：**输入通道代差**（摄像头缺位）+结果结构化代差；扫码历史云端同步属天花板，会话内历史纯前端可做。
- **WebQR**：getUserMedia 逐帧解码+手电筒补光+焦距提示。差距：实时取景反馈层（扫描框动画/成功震动）全缺。
- 借鉴优先级：**摄像头实时扫码 > WIFI:/vCard 结构化卡片 > 解码重试链 > 会话历史 > 条码支持**。

## 可拓展性

- 短期（1 周）：解码重试链（原图→放大 1.5/2x→降采样 3 档）；WIFI:/URL/vCard 三类结构化卡片展示
- 中期（1 月）：摄像头实时扫码（BarcodeDetector 优先，jsQR+requestAnimationFrame 回退，HTTPS/权限失败 notice 提示）；会话内历史列表（最近 10 条可复制）
- 远期：条码识别（zxing-wasm 懒加载，覆盖 EAN/Code128 等）；与 barcode-generator 打通"生成↔反扫验证"闭环；批量多图上传逐张解码出 ZIP/文本列表

## 优化处方（验收标准）

1. **摄像头实时扫码**：新增"摄像头"Tab，BarcodeDetector API 优先+jsQR 回退，HTTPS 非安全上下文显示提示。→ **验收：摄像头对准屏幕上的二维码 2 秒内出结果；http 环境（非 localhost）显示"摄像头需 HTTPS"提示而非白屏**
2. **结构化结果卡片**：URL 显示可点链接+域名、WIFI: 拆 SSID/加密/密码三字段（各自可复制）、vCard 显示姓名/电话/邮箱。→ **验收：扫工具自身 wifi-qr-code 生成的码，SSID 与密码正确拆分显示**
3. **解码重试链**：失败后自动按 1.5x/2x 放大与 25%/50%/75% 降采样重试 ≤5 次。→ **验收：240px 小截图与 4032×3024 手机照片均可成功解码，主线程无 >300ms 长任务（Performance 面板验证）**
4. **会话历史**：最近 10 条解码记录列表可点击复制。→ **验收：连续扫 3 张截图后历史区有 3 条且均可复制**
5. **条码识别**：接入 zxing-wasm 支持条码格式并在结果标注码制。→ **验收：EAN-13 商品码扫出 13 位数字且标注"EAN-13"**
6. **原图回显**：识别成功后结果卡顶部显示所扫图片 80px 缩略图。→ **验收：多张截图连续识别时每条历史可对应到具体图片**
