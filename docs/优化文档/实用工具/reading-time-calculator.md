## 结论与优先级

**交互优化 + 需拓展** · P1

判据：可用性无硬伤；但 desc 宣称"由字数或原文"实际只支持数字（registry.ts:720 vs :722），对标 wordcounter.net 的"粘贴即得时长"存在一步之遥的代差。

## 扣分点明细

1. 【功能-主短板】无原文粘贴直算：字段只有 number 型字数（registry.ts:722），而 desc 写"由字数或原文估算阅读时间"（registry.ts:720）——能力与宣传不符，最自然的用法（贴稿子看时长）要绕道
2. 【交互】字数需用户自备：空态 hint 让用户"先用字数统计工具"（registry.ts:728）但只是纯文字，无 /t/word-counter 跳转链接，接力成本全在用户
3. 【灵魂-口径】中英混排无口径：label 声称"中文按字、英文按词"（registry.ts:722），混排文本（如技术博客）按什么计未说明；Medium 对中英分语言计速（265 wpm/500 cpm），本工具单一 wpm 一刀切
4. 【灵魂-默认值】wpm 默认 300 取自身 note 区间（200–300，registry.ts:723 vs :736）上限，普通读者默读中位约 250–300，默认偏快导致时长系统性偏短
5. 【功能】无场景预设组：默读/演讲/慢读只有一行固定 240 朗读参考（registry.ts:733），不能像对标那样按" TED 演讲 130、播客 150、审阅 100"多行对比
6. 【交互】结果不可复制：排期表场景需把"约 12 分钟"贴进文档，结果行无复制按钮（家族共性，CalcTool.vue:55-66）
7. 【实用价值】与 word-counter（registry.ts:40，组件内已含阅读时长字段）功能重叠：WordCounter.vue 已展示阅读时长，本工具未互链也未说明差异

## 行业对标与差距

- **wordcounter.net**：粘贴文本同屏得字数 + 阅读时长 + 阅读等级，零手填。差距：**粘贴即得的一体化闭环**——本工具要用户带数上门。
- **Medium 阅读时长**：分语言速率（英文 265 词/分、中文 500 字/分）+ 首图衰减计入，公开口径可信。差距：分语言速率与口径透明度。
- 借鉴优先级：原文粘贴直算（合并 word-counter 能力）> 口径 note 补混排规则 > 多场景速率对比行 > 结果复制。

## 可拓展性

- 短期（1 周）：新增可选"粘贴原文"文本框自动统计字数（复用 textEngine.textStats）；hint 加 /t/word-counter 链接
- 中期（1 月）：默读/演讲/审阅三档速率对比行；中英混排分语言计数
- 远期：与 word-counter 合并为"稿件的统计与时长工作台"，输入一次出全套指标

## 优化处方（验收标准）

1. **原文直算**：新增可选 textarea，粘贴后自动计数（中文按字、英文按词）并覆盖 words 字段。→ **验收：粘贴 600 字文章后无需手填，主结果显示"2 分钟"**
2. **hint 加链接**：空态提示中的「字数统计」为可点击链接跳 /t/word-counter。→ **验收：点击后 URL 变为 /t/word-counter**
3. **wpm 默认值下调**：默认 250（note 区间中位）。→ **验收：打开页面 wpm 输入框显示 250**
4. **多场景对比行**：结果区加"演讲（240 字/分）/ 审阅（100 字/分）"两行。→ **验收：600 字输入时三档时长并排可见**
5. **口径 note 补混排**：注明"混排文本按字词混合计数，估算仅供参考"。→ **验收：页面底部口径行出现该说明**
6. **结果单值复制**："预计阅读时长"行 hover 显示复制按钮。→ **验收：复制后剪贴板为"12 分钟"或纯分钟数，可直接贴进排期表**
