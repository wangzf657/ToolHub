## 结论与优先级

**交互优化** · P1

判据：去重效果无法量化（removed 计数已算出却被丢弃）属明显交互摩擦；统计视图对比标杆是可追缺口。

## 扣分点明细

1. 【可用性-硬伤·家族】双 textarea 各钉 180px、无同步滚动（`base.css:164-168`；M-06），详见 `pinyin-converter.md` 扣分 1
2. 【交互】"已删除 N 行"被丢弃：引擎明确返回 `{result, removed}`（`textEngine.ts:147`），注册表只取 `.result`（`registry.ts:428`）——现成的统计信息没有出口，用户无法确认"删得对不对"
3. 【功能】无出现次数统计视图：哪些行重复、各重复几次看不到，排查"为什么这行被删"只能自己肉眼数
4. 【功能】空行参与去重：多段文本的连续空行被压成一行（`textEngine.ts:133-148` 无空行豁免逻辑）且无开关，段落感被静默破坏
5. 【功能】无反向筛选（只保留重复行/只保留唯一行）——清洗数据时"先看有哪些重复"是常见前置动作
6. 【可用性】"用输出替换输入"（swap）不可逆覆盖原文（`TextTool.vue:56-58`），去重错了想回到原列表只能重新粘贴
7. 【功能】无列级去重口径（按分隔符取某列判断重复、其余列取首条）——数据清洗里"按邮箱列去重"比整行去重更常见
8. 【灵魂】无前后行数对比徽标、无示例空态（placeholder 只有一句话）

## 行业对标与差距

- **textmechanic.com（Remove Duplicate Lines）**：同款保序口径外加"显示被删行/导出被删行"双输出——去重结果可审计。差距：可审计性（我们只有单输出、零统计）。
- **Excel/WPS"删除重复项"（桌面参照）**：按列去重+保留首条是表格软件的常规口径，佐证列级去重（扣分 7）属行业常规而非小众。
- 借鉴优先级：删除计数 > 重复统计视图 > 空行豁免 > 反向筛选。

## 可拓展性

- 短期（1 周）：io-head 显示"原 N 行 → M 行（删 K 行）"（removed 现成，接线即可）；空行豁免开关
- 中期（1 月）：重复统计 Tab（行内容+次数）；反向筛选模式；swap 前快照撤销
- 远期：与 sort-lines、find-and-replace 组成文本批处理管道（去重→排序→替换一键链）

## 优化处方（验收标准）

1. **计数反馈**：输出 io-head 常显"原 N 行 → M 行，删除 K 行" → **验收：粘贴 10 行含 4 条重复，显示"10 → 6，删除 4"；无重复时显示"无重复"**
2. **空行豁免开关**：新增"忽略空行"toggle（默认开） → **验收：三段文本间的空行在去重后完整保留**
3. **重复统计视图**：输出区加"去重结果｜重复统计"切换 → **验收：重复行按次数降序列出，行尾标注 ×N**
4. **反向筛选**：新增"只保留重复行"模式 → **验收：开启后输出仅含出现 ≥2 次的原行（保序）**
5. **撤销保护**：swap 前快照原文并提供撤销 → **验收：去重→swap→撤销后输入区恢复原列表**
