## 扣分点明细

1. 【可用性-硬伤·家族】双 textarea 各钉 180px、无同步滚动（`base.css:164-168`；M-06），详见 `pinyin-converter.md` 扣分 1
2. 【功能·疑似问题】"全部移除"模式把英文单词粘连："hello\nworld"→"helloworld"（`textEngine.ts:151` `\s*\n\s*` 连同两侧空白一并删除且不补空格）——中文无损但英文文本破坏词界，输出不可读
3. 【功能】无自定义替换符："合并为单行"写死空格（`textEngine.ts:158`）——"换行→逗号"拼接列表/SQL in 条件是高频衍生需求，textmechanic 同类工具支持任意替换字符
4. 【功能】缺"仅压缩连续空行"口径：keepParagraph 会把段内单换行合并为空格，用户只想删多余空行时被过度处理
5. 【可用性】swap 覆盖原文无撤销（`TextTool.vue:56-58`），清洗错了想回到原文本只能重新粘贴
6. 【灵魂】无换行移除数统计、无处理前后对比徽标，效果不直观
7. 【交互】处理模式选择不记忆（TextTool.vue:19-24 initOpts 无持久化），"保段落"以外口径的用户每次重选

## 行业对标与差距

- **textmechanic.com（Remove Line Breaks）**：替换为自定义字符（逗号/分号任意）、保留段落同款开关——拼接粒度可控。差距：自定义替换符与英文空格处理。
- **Word/记事本"替换 ^p"（桌面参照）**：换行作为可替换字符的一般化口径，佐证"自定义替换符"（处方 2）是行业常规能力而非锦上添花。
- 借鉴优先级：all 模式补空格 > 自定义替换符 > 仅压缩空行 > 统计反馈。

## 可拓展性

- 短期（1 周）：all 模式补"换行处插入空格"开关；输出统计"移除 N 个换行"
- 中期（1 月）：自定义替换符输入框；"仅压缩连续空行"第四口径；swap 快照撤销
- 远期：与 find-and-replace 通用化合并（换行本就是一种"替换"目标）

## 优化处方（验收标准）

1. **英文词界保护**：all 模式新增"换行处补空格"toggle（默认开，中文场景可关） → **验收："hello\nworld" 输出 "hello world"；纯中文文本仍无缝合并**
2. **自定义替换符**：新增 text 类型"替换为"选项（默认空格） → **验收：填"，"后所有换行替换为中文逗号**
3. **统计反馈**：输出 io-head 显示"移除 N 个换行" → **验收：5 行文本显示"移除 4 个换行"**
4. **仅压缩空行**：第四种口径"压缩连续空行为单个空行，段内单换行保留" → **验收：段间 3 空行变 1，段内换行不动**
5. **swap 撤销**：swap 前快照原文 → **验收：清洗→swap→撤销后输入区恢复原文本**
6. **空态示例**：placeholder 给出"从 PDF 复制的带硬换行文本"示例 → **验收：空态时输入区有可理解的典型输入提示**
