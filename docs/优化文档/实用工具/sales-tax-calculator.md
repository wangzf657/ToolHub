## 结论与优先级

**交互优化 + 需拓展** · P1

判据：可用性无硬伤（有守卫、结果首屏可见）；相比 Calculator.net 缺税档预设与数量乘数，口径披露缺失直接违反规约。

## 扣分点明细

1. 【灵魂-口径缺失】无 note：提取方向用 amt/(1+rate)（registry.ts:707）价内税口径，但页面未披露"含税价 = 净价 × (1+税率)"，AGENTS.md 金融类口径要求未满足（同文件 loan-calculator :62、compound-interest :655 均有 note）
2. 【功能】无增值税档位预设：13%（默认）/9%/6%/0% 四档国内常见税率只能手填（registry.ts:690-694 仅一个 rate 数字字段），不知税率的用户无从下手
3. 【功能】无数量×单价与金额单位切换：发票场景常需"单价 × 数量"，本工具只有单一金额字段；输出固定两位小数（moneyCn，registry.ts:26-27）不能切万元
4. 【交互】方向切换靠 select 下拉（registry.ts:692-694），两方向切换后主结果 label 变化不够醒目；分段按钮更直观
5. 【交互】无输入记忆、无单值复制（家族共性，CalcTool.vue 全文无 localStorage、:55-66 仅展示）
6. 【灵魂】标题"税费计算器"与站内"个税计算器"（registry.ts:197）概念易混：增值税价税分离 ≠ 个人所得税，页面无互链引导，搜索词"税"两个工具抢流量
7. 【可用性】税率为空或 0 时静默按 0 处理（registry.ts:698 `Number(v.rate) || 0`），用户漏填税率会得到"含税价 = 净价"的无税结果且无提示

## 行业对标与差距

- **Calculator.net Sales Tax Calculator**：税前/税后双向 + 数量乘数 + 按件税率拆分，输出税额与含税/净价对照。差距：数量维度与档位。
- **Omnicalculator（VAT/GST）**：按国家预置标准税率并解释价内/价外税概念。差距：教育与预设维度为零。
- 借鉴优先级：税率档快捷按钮（13/9/6/0）> 口径 note > 数量字段 > 与个税计算器互链。

## 可拓展性

- 短期（1 周）：13/9/6/0 四档快捷 chip；补 note 价内/价外税口径；与个税计算器底部互链
- 中期（1 月）：单价×数量字段；"元/万元"切换；多税目行（增值税 + 附加）
- 远期：与 invoice-generator/invoice-assistant（registry.ts:365,1679）打通成"开票工作台"

## 优化处方（验收标准）

1. **税档快捷按钮**：税率字段上方加 13%/9%/6%/0% 四个 chip，点击回填输入框。→ **验收：点击"9%"后 rate 值变为 9 且结果行同步刷新为 9% 口径**
2. **补口径 note**：注明"含税价 = 净价 × (1 + 税率)；净价 = 含税价 ÷ (1 + 税率)，即增值税价税分离"。→ **验收：页面底部可见口径行**
3. **税率漏填提示**：rate 为空时显示"税率已按 0% 处理"提示行。→ **验收：清空税率后结果区出现提示行，不再静默输出无税结果**
4. **数量字段**：新增"数量"默认 1，金额按单价语义计算。→ **验收：单价 100、数量 3、税率 13% 时含税总价 ¥339.00**
5. **单值复制**：结果行 hover 出现复制按钮复制纯数字。→ **验收：复制"含税总价"行后剪贴板为形如 339.00 的数字（无 ¥ 前缀）**
6. **输入记忆**：CalcTool 增加 localStorage 持久化（key 前缀 toolhub）。→ **验收：填入金额与税率后刷新页面，字段值保留且结果自动重算**
