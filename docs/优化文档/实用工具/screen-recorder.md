## 结论与优先级

**交互优化 + 需拓展** · P1

判据：主链路（选屏→录→停→预览→下载）完整可靠；缺暂停/倒计时/中途掌控是明确交互摩擦，摄像头气泡与声源分离属拓展。

## 扣分点明细

1. 【功能-核心】无暂停/续录：`MediaRecorder.pause()/resume()` 是原生 API（:58 创建 recorder 后未封装），录到一半接电话只能停录重来——Loom/Screencastify 的第一排功能
2. 【功能-疑似 Bug】"同时录制麦克风"声源语义错位：`getDisplayMedia({ audio: withMic })`（:34-37）请求的是**屏幕流音轨**（Chrome 共享标签页时=网页声音），仅当屏幕流无声轨才回退真麦克风（:42-50）——勾了麦克风、共享了带声音的标签页时，录到的是 B 站视频声而非人声，标签与实际声源不符
3. 【可用性】不支持系统声/麦克风/无声三选：勾选框是布尔（:9），"录屏+人声+游戏声"混录做不到（getDisplayMedia audio 与 getUserMedia 音轨可叠加 :43-50，UI 未暴露）
4. 【交互】无起录倒计时：点开始→选择器→立即录，用户手指还没离开鼠标已被录进去（Loom 默认 3 秒倒计时）
5. 【交互】录制中无任何源预览小窗：不知道自己录的是不是选对的窗口（舞台只有图标+计时 :113-120）
6. 【灵魂-口径】"无时长限制"（:144）与内存现实冲突：chunks 数组不落盘（:59-61），长录内存告警前无任何提示；Loom 云端无此约束属架构天花板，但"约 30 分钟内存上限"这类诚实披露纯前端可做
7. 【功能】无格式选择（仅 WebM :57）：需 MP4 的用户要再跑一趟站内 convert-video（零互链引导）
8. 【交互】下载文件名 `screen-时间戳.webm`（:89-93）不可自定义

## 行业对标与差距

- **Loom**：暂停续录、摄像头气泡、即时裁剪、一键分享链接（云架构，标注天花板——纯前端可对齐的是前三者中前两个）。差距：**中途掌控力代差**。
- **Screencastify**：标签页/窗口/全屏+系统声/麦克风/双声源矩阵、绘制工具、倒计时。差距：声源矩阵与倒计时。
- 借鉴优先级：暂停续录 > 声源三选矩阵 > 起录倒计时 > 录制中源小窗 > MP4 出口引导。

## 可拓展性

- 短期（1 周）：pause/resume 按钮（录制态三按钮：暂停/停止/取消）；3-2-1 倒计时；notice 补内存口径
- 中期（1 月）：声源矩阵（系统声/麦克风/双录，叠轨混流）；录制中源画面小窗（captureStream 自绘）；结束后引导"需 MP4？→ 视频格式转换"互链
- 远期：摄像头画中画合成（canvas 叠加后 captureStream 重编码）；分段落盘（File System Access API 流式写盘破内存上限）

## 优化处方（验收标准）

1. **暂停续录**：录制中提供"暂停"按钮，暂停后计时停走、点击续录计时接续。→ **验收：录 10s→暂停 5s→续录 10s，产出文件时长≈20s 且无 5s 空洞帧**
2. **声源矩阵**：勾选区改为"麦克风/系统声音"两独立勾选；勾麦克风时不向 getDisplayMedia 传 audio:true。→ **验收：仅勾麦克风、共享带声音的标签页，回放文件音轨为麦克风人声而非网页声音**
3. **倒计时**：选择共享源后弹出 3-2-1 全屏倒计时再开始录制。→ **验收：倒计时期间 recorder.state 仍为 inactive，计时结束才 recording=true**
4. **内存口径**：notice 改为"录制在内存中缓存，建议单段 ≤30 分钟；超长请分段录制"。→ **验收：文案可见且不再出现"无时长限制"字样**
5. **互链**：回放态下方加"转 MP4 → 视频格式转换"入口。→ **验收：点击携带当前 blob 跳转 convert-video 并自动装载**
