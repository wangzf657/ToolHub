## 结论与优先级

## 扣分点明细

1. 【功能】无童码：仅男鞋/女鞋两档（registry.ts:1402），儿童鞋（EU 22~35 段、US 儿童码 Infant/Toddler 分段）完全缺位——亲子海淘是尺码换算高频刚需，Zappos/Omnicalculator 均为男女童三册
2. 【可用性】两行重复信息：primary"脚长参考 约 260 mm"（registry.ts:1425）与"中国码（脚长制）260 mm"（:1426）是同一个数——中国码即脚长制，两行毫无信息差，主结果区的"第一个高亮"被浪费了一半
3. 【功能】无品牌偏码提示：note 只说"各品牌 ±半码"（registry.ts:1433），Nike/Adidas/Asics 等常见偏码方向无静态提示——海淘差评最高频的"按通表买回来小半码"没有缓解手段
4. 【灵魂】无量脚方法引导：换算的前提是脚长量对（下午站立量、预留 5~10mm 活动空间、量最长脚），页面零引导——模型再准，输入错则全错
5. 【功能】半码差异被抹平：脚长结果按 5mm 取整（registry.ts:1419），EU 42.5 与 43 的脚长差异（约 3.3mm）被同一数值吞掉——换算回来"反查"场景会糊
6. 【交互】无尺码档案记忆：鞋码准稳态、录一次用三年，刷新即清空（家族共性，CalcTool.vue:10 无 localStorage）
7. 【实用价值-站内边界】与 clothing-size-chart（registry.ts:1828-1852）同属海淘尺码家族零互链：买鞋顺手买衣的用户要在两页间自己找路，家族内无"尺码中心"叙事
8. 【可用性】换算值可落在市场不存在的码上：EU/US/UK 输出按一位小数原样展示（registry.ts:1423、:1427-1429），输入中国码 268mm 时 EU 显示 42.2——市场只有整数/半码，无"就近按 42 或 42.5 选购"吸附提示，用户拿 42.2 搜商品一无所获

## 行业对标与差距

- **Zappos Size Guide**：男女童三册、脚长测量图解（站/坐、双脚取大）、宽度 N/M/W 双维、品牌偏码备注列。差距：童码+测量指引+宽度三维。
- **Omnicalculator Shoe Size Chart**：按品牌出建议码（Nike/Adidas 等偏差库）、cm/inch 双单位、半码精确保留。差距：品牌级精度（离线可先做头部 5~8 个品牌的静态偏码表）。
- 借鉴优先级：删重复行 > 量脚三步引导 > 童码模式 > 头部品牌偏码提示 > 尺码档案记忆。

## 可拓展性

- 短期（1 周）：合并重复行（脚长只留 primary 一行）；输入区加量脚三步文案；与 clothing-size-chart 页底互链
- 中期（1 月）：童鞋模式（男女童双轨，脚长 110~180mm 段）；Nike/Adidas/Asics/新百伦等头部品牌静态偏码提示；脚长 localStorage 档案（key 前缀 toolhub）
- 远期："海淘尺码中心"（鞋+服装+手围领围+儿童分册），尺码档案一次录入全家族复用
