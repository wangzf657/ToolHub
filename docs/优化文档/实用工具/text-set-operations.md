## 结论与优先级

**交互优化** · P1（差集丢重复属正确性问题，修复后可升 P2 基调）

## 扣分点明细

1. 【功能-正确性】差集/交集丢重复行：setOperations 对结果先 new Set 去重（textExt.ts:109-112），A=[x,x,y] 与 B=[] 求 A−B 输出仅 [x,y]——已发货单号重复的场景行数从 3 变 2 且无任何"已去重"提示，名单核对工具出这种错最伤信任
2. 【可用性】结果区钉 300px：.result max-height:300px overflow:auto（TextSetOps.vue:83），并集几百行时同屏只见约 15 行，且无全屏/展开开关（审计底稿共性-根因 2 明确点名本组件）
3. 【功能】无对称差集：A△B（只在一边有的行）是名单异动核对的核心算子，现需 A−B 与 B−A 各跑一次手动合并
4. 【可用性】无重复行统计：lineCounts 只报去重前后？不——它报的是过滤空行后的行数（textExt.ts:117-121，同不去重），与结果行数（去重后）口径不一致，两处数字对不上时用户无从排查
5. 【功能】无"来自哪边"标注：差集结果纯行列表，无法区分同值行在 A 出现几次（对照 diffchecker.com 行级左右标注）
6. 【交互】无导出：结果只能复制（:36-39），无 TXT/CSV 下载；名单核对完要归档的用户只能再粘一步
7. 【灵魂】死代码：swap ref（TextSetOps.vue:15）定义后从未写入，:18-19 的 left/right 分支恒走 false 路径，实际交换靠 :32-34 直接对调 a/b——留着的半成品逻辑是维护陷阱
8. 【交互】无输入历史/无自动记忆：比对过的名单刷新即丢（无 localStorage）；忽略大小写选择不记忆

## 行业对标与差距

- **diffchecker.com**：行级左右对照、差异高亮、单行"仅在左/仅在右"标注、导出与分享。差距：**结果可读性**——对方把"谁和谁不一样"讲清楚，本工具只给一列冷结果。
- **Excel COUNTIF/Power Query**（用户现有替代方案）：保留重复计数、透视汇总。差距：本工具在"去重语义"上比 Excel 更激进，反而丢了名单核对的保真度。
- 借鉴优先级：**差集保留重复选项（第一优先）> 对称差集 > 结果区弹性高度 > 来源标注 > 导出**。

## 可拓展性

- 短期（1 周）：去重行为开关（默认保留重复，差集按多重集语义输出）；删除 swap 死代码；结果区加"全屏展开"
- 中期（1 月）：对称差集按钮；三分类结果视图（共有/仅 A/仅 B 三个 Tab，对照 diffchecker）；TXT 导出；重复行计数行显示
- 远期：与 text-diff 合并"文本比对工作台"（行集合运算+行级 diff 两档粒度）；比对历史快照（localStorage 存最近 10 组）

## 优化处方（验收标准）

1. **差集保真**：默认多重集语义——A−B 逐行扣减 B 的计数而非整体去重。→ **验收：A=[x,x,y]、B=[x] 时 A−B 输出 [x,y] 两行；开启"结果去重"选项才恢复现行为**
2. **结果区弹性**：.result 改默认 `calc(100vh - 420px)`、下限 360px、带全屏切换。→ **验收：1366×768 下 200 行并集同屏可见 ≥25 行**
3. **计数口径统一**：行计数旁显示"去重后 N 行"，与结果行数同源。→ **验收：A 含 5 行含 2 重复时显示"5 行（去重后 3）"且交集结果行数与之自洽**
4. **对称差集**：运算组加"A△B（仅一边有）"。→ **验收：A=[x,y]、B=[y,z] 时输出 [x,z]**
5. **来源标注**：差集结果每行尾缀"(A)"或"(B)"计数徽标。→ **验收：A−B 中来自 A 的行显示其在 A 中出现次数**
