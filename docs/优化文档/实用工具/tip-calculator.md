## 结论与优先级

**需拓展 + 交互优化** · P2（工具轻量，改造成本小、收益中等）

判据：相比 Calculator.net Tip 缺快捷档位/取整/币种三大标配（子功能缺失）；空态零值与无 note 属交互优化。

## 扣分点明细

1. 【口径-场景错位】货币硬编码 ¥：小费是欧美出行场景，四行结果全部 `¥` 前缀（registry.ts:621-624）——目标用户在纽约需要 $，本工具却以人民币计价；而国内场景本就不给小费，"15% 默认"也是美式惯例，工具没交代自己为谁服务
2. 【功能】无快捷比例档位：10/15/18/20% 一键切换是所有小费计算器 App 的标配，本工具每次改比例要清格重输（registry.ts:612 number 输入）
3. 【功能】无取整策略：每人应付 33.33 元无法"凑整 35 付现金"，Calculator.net 有 per-person round-up 与总额取整选项；小费基数（税前/税后账单）口径也未说明
4. 【可用性】空态零值误导：账单留空时四行结果全显示 ¥0.00（registry.ts:615-625 无守卫，Number('')=0 直接运算；CalcTool.vue:25 只拦 NaN）——与 mortgage/compound 同家族病
5. 【交互】people 静默纠错：填 0 或负数被 Math.max(1,…) 悄悄按 1 人算（registry.ts:619），无任何提示
6. 【家族共性】无输入记忆、结果不可单值复制（CalcTool.vue:55-66）；无 note（规约口径要求未达标，registry.ts:609-628 无 note 字段）
7. 【可用性】比例无范围校验：填 -10% 得负小费、填 500% 照算（registry.ts:612,617 无拦截；CalcFieldInput.vue:44-46 的 min/max 未配置），负数结果无提示直接展示
8. 【交互】进入页面输入框无 autoFocus、无 Enter 联动（CalcFieldInput.vue:39-48 原生输入无聚焦管理），先点一下才能开始填账单

## 行业对标与差距

- **Calculator.net Tip Calculator**：比例快捷按钮组、每人/总额取整开关、小费基数说明、共享拆分带人数调节。差距：**决策辅助三件套全缺**——对方 2 次点击完成"15% 档+凑整"，本工具全程手敲。
- **Omnicalculator**：币种选择、按人头/按账单口径切换、附"什么情况给 20%"场景文案。差距：场景教育与口径选项。
- 借鉴优先级：**快捷档位按钮组 > 币种切换（或 $ 默认）> 取整开关 > 空态守卫 > note 口径**。

## 可拓展性

- 短期（1 周）：快捷档位按钮（10/15/18/20%）；空账单守卫；补 note
- 中期（1 月）：币种下拉（$/¥/€）或"出境小费"场景定位文案；每人凑整开关（差额计入小费）
- 远期：与 discount-calculator 等"账单类"计算器共享货币/取整组件；多人按消费额分摊（不等额拆分）

## 优化处方（验收标准）

1. **快捷档位**：比例字段上方加 10/15/18/20% 按钮，点击回填比例。→ **验收：点击 20% 后小费行即时按 20% 重算且按钮高亮，无需键盘**
2. **币种切换**：结果区加币种下拉（¥/$/€），符号随选切换。→ **验收：选 $ 后四行结果货币符号全部为 $**
3. **取整开关**："每人凑整"开启后每人应付向上取整，差额归入小费。→ **验收：总额 166.65/3 人开启后每人显示 56 且小费行相应增加 0.35×3**
4. **空态守卫**：账单为空时返回引导行。→ **验收：清空账单后 300ms 内结果区显示"请填写账单金额"而非 ¥0.00**
5. **note 口径**：注明"小费按账单总额计（未区分税前税后）；默认 15% 为美式惯例"。→ **验收：页面底部可见该口径行**
