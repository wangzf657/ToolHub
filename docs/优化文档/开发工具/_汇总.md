# 开发工具分类汇总（92 项）

> 依据：`docs/优化文档/开发工具/` 92 份工具档案（全部数字来自脚本提取产物 `docs/优化文档/_scripts/dev-extract.json`）＋ `docs/优化文档/_布局审计底稿.md` ＋ `docs/优化文档/_实测锚点.md`（M-xx）。本汇总只做归并分析，不改任何业务代码。

## 一、总览

- **样本与均分**：92 份档案，**均分 59.23 / 100**，中位 58；无一项达到 70。
- **分数段**：≥60 共 41 项（44.6%）、55~59 共 43 项（46.7%）、<55 共 8 项（8.7%）——九成工具挤在 55~65 的"及格线泥潭"，失分模式高度一致（见§三）。
- **头部 5 名**：number-base-converter 67、color-contrast-checker 67、bcrypt-hash 66、hash-generator 66、keycode-lookup 66。共同点：computed 实时计算零按钮、报错指名道姓、结果单屏收纳——**没有硬伤就能上 65**。

- **优先级分布**：P0 4 项、P1 68 项、P2 20 项——P1 占 74%，说明分类整体处于"明显交互摩擦"层，尚未大面积失守。
- **布局模式分布**：D（grid-2+ResultBox）32 项为第一大族群、C（文件流）22、B（表单）19、A（TextTool）18（code-playground 档案未标模式）。模式 D 即布局审计的"结果窗口太小主案发现场"。

## 三、七维共性病灶 Top5

1. **灵魂度 39%（7.88/20，全维度最低）**：无空态示例填充（全分类仅 slugify 一项带示例 chips）、无键盘快捷键（TextTool 全家族无 Ctrl+Enter/Ctrl+Shift+C）、无失败纠偏引导（base64 报"包含无效的 Base64 字符"后用户不知该换什么变体，textEngine.ts:215）、报错用浏览器英文原文（url-encoder）。整改范式：空态示例一键填充＋错误中文化＋"疑似 XX，请切换"提示——number-base-converter（67 分）的报错文案与预填 255 即是分类内已有金标准。
2. **可用性 54%（10.79/20）**：`ResultBox.vue:69` `height:minHeight` 双重钉高（模式 D 普遍 320px / TextTool 180px / 预览 520px），且 1920×1080 大屏零增益（M-02）；P0 四项全部触此红线——json-to-excel"盲盒下载"是变体（结果区根本不存在）、text-diff 结果区视口外。判据统一为"结果区没法看 = 可用性硬伤"。
3. **交互便捷性 68%（10.23/15）**：粘贴后需手动点击执行（CodeFormatter/SqlFormatter 系，对照 TextTool 家族 watch 自动执行是加分项）、无"粘贴即处理"开关、家族内互跳为零（json-visualizer→jsonpath、cron explainer→builder、number-base→bitwise 互不知晓）、watch 自动执行无防抖（code-minifier 每键触发完整 terser，TextTool.vue:47-48）。
4. **功能完善性 54%（10.79/20）**：失分主因不是引擎缺失而是**能力未透出**（sql 方言 3/12+、位宽仅 32 位一档、prettier 配置面为零、chmodFromSymbol 闲置）——详见§四清单，多为低成本补齐。
5. **移动端 6.12/10 + 环境干扰**：`.grid-2` 到 ≤560px 才堆叠（base.css:329-335），768px 平板双栏各约 250px 近乎不可读；Cookie 横幅首访遮挡底部结果条（M-01 截图）；断点碎片化（520/560/760/860/900/960/1100 七种并存）致工具间切换时机不一。

## 五、P0 清单（4 项，全部触发"结果区没法看"硬伤红线）

1. **json-formatter（58）**：输出 ResultBox 钉死 320px，158 行 JSON 同屏仅约 17 行、需滚 10.8 屏（M-01）；1920 大屏依旧 320px（M-02）。全站模式 D 整改样板。处方：弹性高度→粘贴即处理→错误行内跳转→折叠树 Tab→同步滚动，五条均带验收标准。
2. **json-to-excel（57）**：盲盒下载——run() 校验后直接 saveBlob 自动下载（JsonToExcel.vue:78-91），无表格预览、无下载前确认，拍平列名/列顺序/null 填充全部下载后才能发现。处方：先渲染表格预览再人工点下载。
3. **cookie-parser（57）**：textDef 180px 钉高最重受害者——多行 Set-Cookie 输出缩进 JSON 动辄 30+ 行，窗内滚 3 屏起步（M-06 家族锚点）。判据同 textDef 家族样板 pinyin-converter.md。
4. **text-diff（54，本分类最低 P0）**：双输入各钉 170px（主功能区过小）且 diff 结果区在面板下方视口外（M-05）——"对比"工具看不见对比结果。处方含输入区弹性高度＋结果区上移。

**P1 候补预警**：P0 计 4 项是按"硬伤红线"从严认定的结果，68 项 P1 中判据含"钉高/小窗/结果不可见"的占多数（CodeFormatter 四口、TextTool 系 cookie/escape、jsonpath 等）——若第一周的钉高整改不落地，P0 将实质性扩散；反之钉高修复会让 P1 批量降级为 P2。另注意 55 分以下的 8 项（graphql-formatter、html-minifier、json-to-xml、json-schema-generator、svg-optimizer、css-formatter、text-diff、xml-to-json）里 7 项为 P1，整改优先级应按分数而非优先级字段排序。

## 六、疑似功能缺陷清单（读码/实测疑似，只记录不修复，交用户决定）

1. **url-encoder**：解码（组件档）先 `replace(/\+/g,' ')` 再 decode（textEngine.ts:263）——字面 `+` 被静默改写为空格；RFC 3986 组件内 `+` 是合法字面字符，API 签名串/含 + token 场景直接翻车，且无开关可关。
2. **sql-formatter**：catch 把一切异常（含语法错误）静默降级 lightFormat（SqlFormatter.vue:56-59）——错误 SQL 也提示"已格式化"，无校验无定位。
3. **base64-encoder**：`atob` 遇 URL-safe 的 `-_` 直接抛错（textEngine.ts:213）且无变体选项（JWT payload 段正是 URL-safe）；注册表宣称"也可编码文件"而 TextTool 壳无文件入口（承诺与实现不符）。
4. **svg-optimizer**：数字精度正则 `/-?\d+\.\d+/g` 作用于全文（jsEngine.ts:878-881）——`<text>` 内的"3.14"、`stroke-width="1.5"` 都被取整，precision=0 时 1.5px 描边变 2px，视觉静默损坏。
5. **docker-run-to-compose**：compose→run 反向生成 docker 不存在的 `--depends-on` flag（devExt.ts:297-299）——生成的命令被 docker 直接拒绝"unknown flag"，应转注释或省略并警告。
6. **curl-to-fetch**：`-u/--user/-o` 等带独立参数的 flag 落入"未知裸 flag"分支后，其参数在下一轮被当 URL 抢占（jsEngine.ts:683-688）——`curl -u user:pass URL` 解析出 url=user:pass 且真 URL 丢失，解析器结构性错误而非单纯缺功能。
7. **markdown-formatter**：bullet 正则 `/^(\s*)\*\s/gm` 无字符串保护（MarkdownFormatter.vue:30）——行首形如 `* 强调` 的强调语法被误转列表符号；`+` 列表完全不在册。
8. **markdown-preview**：desc 承诺"输入 Markdown 实时渲染预览"（registry.ts:158），实际 render() 仅挂载/勾选框/按钮触发（MarkdownPreview.vue:35,:60,:64）——粘贴长文后预览仍是旧内容，与文案直接矛盾。
9. **html-minifier**：`replace(/\n\s*/g,'')` 无 pre/textarea 保护（jsEngine.ts:332）——压缩含 pre 内容的页面会改变渲染结果，产物不可直接部署。
10. **xml-to-json / json-to-xml**：`@` 前缀属性口径不对称（json-to-xml 52 分结论项），往返转换属性字段名不一致，建议两案并修。
11. **javascript-formatter**：prettier 语法错误信息含行列号与代码帧，仅 toast 展示且 `slice(0,120)` 截断（CodeFormatter.vue:50-52）——toast 瞬逝后用户无从复查，属错误呈现通道选错。
12. **number-base-converter**：前缀剔除无条件执行（NumberBase.vue:21）——10 进制下输入 `0x1F` 被剔成 `1F` 再按十进制报错，报错文案与用户预期错位（67 分工具的少数瑕疵，处方为"检测到 0x 前缀是否按 16 进制重解"按钮）。
13. **markdown-to-slides**：逐页预览仅在挂载（MarkdownToSlides.vue:48）与导出（:51）时刷新，而页数提示是实时 computed（:96）——"页数变了、内容没变"，用户无法信任预览；与 §六-8 同属 mdEngine 联动缺席一族，一处接线两案同修。

## 七、阉割与合并建议

1. **html-minifier → 并入 html-formatter（阉割判例，51 分）**：二者为同一 CodeFormatter 组件重复注册（registry.ts:186-187），唯一差异是文案，独立存在理由为零。建议合并为单入口（压缩为按钮/Tab），slug 301 保留；若用户选择保留独立入口，则必须升级真压缩引擎（html-minifier npm 浏览构建或自研三档开关）以兑现 slug 承诺。
2. **压缩三套收敛**：以 code-minifier 的真 terser+csso 为唯一压缩引擎；javascript-formatter 的正则假压缩与 html-minifier 的正则三连降级为"去注释去空白"轻档并明示口径（jsEngine notice 的诚实文案 CodeFormatter.vue:90-92 推广即可）；code-minifier 自身需补防抖（逐键 terser）与 Worker 化后再承接收敛后的全部流量。
3. **JSON 工作台（远期，模式 E）**：json-formatter（格式化）+ json-visualizer（可视化宿主）+ jsonpath-tester（查询命中树上高亮）+ json-diff 合并为单页多 Tab；前置条件是统一路径格式为 `$..a.b[0].c`（现 visualizer 的点路径无法无缝衔接 jsonpath）。
4. **正则工作台**：tester+visualizer 互通输入（互跳传参）；tester 补逐 token 解释/铁路图时直接复用 visualizer 的图数据，避免两套解析器。**不做裁撤**——两工具互补不重复（regex-visualizer.md 结论明示）。
5. **Cron 工作台**：explainer+builder 双向互跳（解读↔构建），explainer 补"下次执行时间"实时解读（crontab.guru 口径），builder 补月历打点。
6. **位级工作台（低成本新机会）**：number-base-converter 67 分自提远期项——与 bitwise-calculator 组互跳入口（进制转换/位运算/补码视图三 Tab），两工具现互不知晓。
7. **不建议合并**：正则双工具、cron 双工具；CSS 三兄弟保留独立工具但共用拖拽控件；格式化九项保留（sql/graphql/xml/markdown 引擎各异），仅 CodeFormatter 四口做信息架构复核。
