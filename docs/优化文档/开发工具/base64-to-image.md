## 扣分点明细

1. 【可用性-疑似功能问题】URL-safe Base64 触发未捕获异常：纯 base64 判定正则允许 `-`/`_`（`Base64ToImage.vue:21`）但 `atob` 不接受 URL-safe 字符且该行**无 try/catch**（:22）——粘贴含 `-_` 的输入直接抛 InvalidCharacterError，错误提示条完全不出现，用户以为工具坏了
2. 【功能】URL 编码型 data URI（`data:image/svg+xml,%3Csvg…`）被强制改写为 `;base64,`（:18-19 分支不区分 base64 标记语义），SVG 明文被当 base64 解码后报"不是有效的图片数据"，提示误导排查方向
3. 【交互】一切靠手点"加载预览"（:90）：无 paste 事件监听，与姊妹工具 image-to-base64 的"拖入即编码"形成双向体验不对称
4. 【功能】复制只有原始 Data URI 一种形态（:77-81）：姊妹工具有 dataURI/img 标签/CSS background 三模板 Tab（ImageToBase64.vue:75-79）——闭环不对称，反向用户拿到 URI 后最常见的用途恰恰是贴进代码
5. 【可用性-轻】预览 img max-height 320px（:122-126）且不可点击放大：800×2000 长图只能看顶部一条
6. 【性能】MB 级字符串 fetch(dataURI) 下载内存翻倍（:67-73），超长输入无任何提示或截断策略
7. 【灵魂】无 1×1 像素示例 data URI 一键填充（成本为零的空态引导）；错误两段式文案（:37/:53）本就是灵魂分却没被空态利用
8. 【家族】与 image-to-base64（64 分）零互链：双向工具互相找不到对方，用户只能靠站内搜索猜 slug

## 行业对标与差距

- **base64-image.de**：粘贴即预览、编码/解码双向同页切换、img/HTML/CSS 多模板复制。差距：**触发即时性与模板对称性**——对方零按钮，本工具多一步点击。
- **姊妹工具 image-to-base64（站内 64 分）**：体积膨胀三徽章＋"值不值得内联"决策辅助；本工具有预览有元信息而对方无——两工具各有一块对方缺的能力，合体即是站内最佳。
- 借鉴优先级：**修复 URL-safe 异常 > 粘贴即解码 > img/CSS 模板对称 > 预览点击放大 > 双向互链**。

## 可拓展性

- 短期（1 周）：normalize 内 atob 包 try/catch（先 `-`→`+`、`_`→`/` 归一再嗅探）；paste 事件 200ms 自动解码；结果区挂"反向：图片转 Base64"互链
- 中期（1 月）：img 标签/CSS background 复制形态（与姊妹工具共用模板定义）；预览 lightbox 全尺寸查看；SVG data URI 直通分支（base64 标记缺省时不改写）
- 远期：批量队列（多段 base64 逐个出文件）；与 image-to-base64 合并为"Base64 ⇄ 图片"双 Tab 工具，一页双向

## 优化处方（验收标准）

1. **修复 URL-safe 崩溃**：atob 前归一化 URL-safe 字符并包 try/catch，失败回落"无法识别"错误条。→ **验收：粘贴含 `-_` 的 base64 不再无响应，出现明确错误条或正常预览**
2. **粘贴即解码**：textarea paste 事件 200ms 后自动调用 preview()。→ **验收：粘贴合法 data URI 后不点按钮即出现预览与四元信息**
3. **模板对称**：预览下方加"复制 img 标签 / 复制 CSS background"两按钮。→ **验收：点击后剪贴板分别为 `<img src="…">` 与 `background-image:url(…)`**
4. **预览点击放大**：点击图片切 max-height:80vh 全尺寸，再点还原。→ **验收：2000px 高长图点击后可滚看底部**
5. **双向互链**：空态与结果区各挂"图片转 Base64"链接。→ **验收：点击跳转 /t/image-to-base64**
