## 结论与优先级

**交互优化** · P1

判据：判定口径正确、首屏闭环完整，无硬伤；与 WebAIM 的差距集中在"为什么"的解释陈述（大字号阈值、UI 组件 3:1）与建议色的可用性上，属单点改造。

## 扣分点明细

1. 【可用性-疑似缺陷】非法色值静默变黑：`hexToRgb` 对非十六进制输入 `parseInt` 得 NaN 后返回 [0,0,0]（`ContrastChecker.vue:14-15`），输入 "#zzz" 比值照常出数，无错误提示——WebAIM 会明确报错
2. 【功能】缺 WCAG 1.4.11 非文本对比判定：图标/输入框边框/UI 组件 3:1 是设计走查高频项，WebAIM 页面同页给出，本工具只有文字四档
3. 【功能】缺 APCA（APG 新版感知对比度）：对深色主题低透明度文字，WCAG 2.x 判定已知失真；至少应标注"WCAG 2.x 口径"
4. 【灵魂】建议色只给 #1a1a2e/#ffffff 两个极端（:57），把品牌色 #6366f1 直接换成黑/白——正确做法是在原色相上二分调整亮度直到达标（保持色相）
5. 【可用性】大字号判定行无阈值注释：AA 大字号 ≥3.0 的适用条件（≥18pt/24px 或 ≥14pt bold/18.66px）未陈述，预览卡仅标注"18pt+"（:95），初学者无法对号入座
6. 【交互】无 URL 快照（?fg=&bg=），把检查结果发给同事只能靠复制文本
7. 【功能】无批量模式：整组设计 token（10 对 fg/bg）需一对对手工换
8. 【灵魂】无历史记录：上一轮检查过的色对无法回看对比（localStorage 存最近 10 对即够）

## 行业对标与差距

- **WebAIM Contrast Checker**：比值+四级判定之外，核心是**原因陈述**——"Large-scale text (at least 18pt or 14pt bold)"括号写明阈值，未通过时直接给出建议色并附新比值；另有 Normal Text / Large Text / UI Components 分节。差距：本工具"给结论不给原因"，教学价值缺位。
- **coolors contrast checker**：滑杆微调任一颜色实时看比值越线瞬间、深浅色预设。差距：微调手感。
- 借鉴优先级：**非法输入提示 > UI 组件 3:1 判定 > 大字号阈值注释 > 同色相建议色 > URL 快照**。

## 可拓展性

- 短期（1 周）：非法色值行内报错并置灰结果；判定行补像素阈值副文案；建议色改为同色相二分搜索
- 中期（1 月）：UI 组件 3:1 判定行；URL 快照；批量 Tab（粘贴多对色值出全表）
- 远期：引入 APCA 口径并列显示（标注与 WCAG 差异）；与 color-converter 互链（转换结果一键送检）

## 优化处方（验收标准）

1. **非法输入提示**：解析失败时输入框红框+提示"无法识别的颜色"，比值卡置灰显示"—"。→ **验收：输入 #zzz 后出现错误态且不显示任何比值数字**
2. **UI 组件判定行**：判定列表加第五行"UI 组件/图形（≥3.0）"。→ **验收：#949494 on #ffffff 时该行"通过"而 AA 普通字号行"未通过"**
3. **大字号阈值注释**：AA/AAA 大字号行下加副文案"≥24px，或 ≥18.66px 粗体"。→ **验收：判定列表可直接看出 14px 粗体应按哪一档判定**
4. **同色相建议色**：建议色在原色 HSL 色相不变的前提下二分调整亮度至恰好达标，显示调整后新比值。→ **验收：#6366f1 on #ffffff 的建议色仍为紫色系且新比值 ≥4.5，而非白色**
5. **URL 快照**：fg/bg 写入查询参数，加载时还原。→ **验收：带 ?fg=%236366f1&bg=%23ffffff 打开页面后双色与比值完全还原**
