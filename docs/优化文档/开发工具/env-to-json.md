## 结论与优先级

**交互优化** · P1

判据：解析质量合格、无硬伤级钉死之外的个性问题；主要摩擦是"方向要人选 + 脏数据静默丢失"，小改可显著提分。

## 扣分点明细

1. 【可用性】非法 key 静默 continue（`EnvToJson.vue:21`），含空格/中划线键名的行直接消失，toast 只报总数（:54）——应列出"第 N 行已跳过及原因"（对照 dotenv-linter 的逐条诊断）
2. 【可用性-家族共性】ResultBox height=minHeight 钉死 280px（`ResultBox.vue:69`、`EnvToJson.vue:82`），大配置输出在小窗内滚，无弹性高度
3. 【功能】按 `\n` 硬切（:14）不支持 dotenv 引号内跨行值——私钥/证书类多行配置（如 BEGIN CERTIFICATE）会被截断，属真实高频边界
4. 【功能】无 ${VAR} 变量插值展开与多文件级联能力
5. 【交互】JSON→.env 时嵌套对象被 JSON.stringify 塞成单行（:42），输出不可读且无"点路径展平"（a.b.c=d 是 12-factor 惯例）
6. 【灵魂】无语法速查、无示例填充按钮、无"自动判定方向"（首字符 `=`→env、`{`→JSON 可启发式判定）
7. 【交互】两窗无同步滚动，长配置对照检查困难（同 json-formatter 扣分 2 同构）

## 行业对标与差距

- **codebeautify.org**（ENV to JSON）：上传/粘贴双通道、键值表格视图、错误行提示。差距：错误可见性与文件通道。
- **dotenv-linter**：重复键/键序/无值等逐条 lint 规则。差距：本工具对脏 .env 只静默清洗不诊断，用户不知道输入质量如何。
- 借鉴优先级：跳过行清单 > 自动方向识别 > 跨行值 > 点路径展平。

## 可拓展性

- 短期（1 周）：跳过行 warning 清单；自动方向识别高亮对应按钮
- 中期（1 月）：跨行引号值解析；点路径展平开关；与 yaml/toml 转换统一为"配置转换"家族页（共享语法速查与示例）
- 远期：并入"JSON 工作台"（愿景见金标准 `docs/优化文档/开发工具/json-formatter.md` 远期档）作配置分支入口

## 优化处方（验收标准）

1. **跳过行可见**：解析后如有被跳过行，输出区顶部黄条列出"第 N 行 xxx（原因）"。→ **验收：输入一行 `BAD KEY=v`，生成后可见该行被点名并可定位到输入位置**
2. **自动方向**：粘贴后按首字符特征自动判定并主色高亮对应按钮，可手动覆盖。→ **验收：粘贴 `A=1` 时".env → JSON"呈主色；粘贴 `{}` 时"JSON → .env"呈主色**
3. **跨行值**：引号未闭合时继续吞行至闭合。→ **验收：三行 `PK="-----BEGIN` / `ABC` / `END-----"` 解析为一个含换行的单值**
4. **点路径展平**：JSON→.env 增加"嵌套展平"开关，`{"a":{"b":1}}` → `A_B=1`。→ **验收：两层嵌套对象开启开关后输出 1 行键值且键为 A_B**
