## 结论与优先级

**交互优化 + 需拓展** · P1

判据：开关触发全量重算与大文件无进度是明显交互摩擦（交互 9/15）；SM3 国密与 HMAC 入口缺失对 emn178 功能面有代差，属拓展项。

## 扣分点明细

1. 【交互】大写/无连字符开关 `@change="reformat"`（`HashGenerator.vue:110-111`）而 reformat 直接重跑 run()（:81-83）——formatOne（:76-79）本是后处理，却缓存了原始值不用，1GB 文件切开关=六次全量重读重算，纯浪费
2. 【性能-硬伤边缘】MD5/SHA 走 `file.arrayBuffer()` 一次载入（`hashEngine.ts:27-29`）：2GB 文件直接占 2GB 内存且 UI 冻结，六算法串行各读一遍（:59-67），无分块/Worker/进度百分比——对照任务红线"安全类注意大文件性能"
3. 【功能】无 SM3 国密算法：中文场景（政务/信创对接）常用，emn178/online-tools 已验证支持（js-sm3 系列库可懒加载，符合站内懒加载纪律）
4. 【功能】与 hmac-generator（`registry.ts:155`）零互跳：算完哈希想签名要回搜索；emn178 在哈希页直接带 HMAC 开关
5. 【可用性】大文件期间唯一反馈是按钮 disabled+微文案（:113），无进度条/耗时预估/取消——对照站内 FfBase 进度带百分比是全站最完善反馈（`FfBase.vue:189-197`），此处连简版都没有
6. 【交互】拖入文件不自动开始计算（:20-26 仅登记），多一次必点；文本粘贴后亦无自动（哈希可实时算，输入即出六行是 emn178 的即时体验）
7. 【功能】不支持 SHA-3/Keccak、RIPEMD-160（emn178 全有）；算法徽章固定 6 行不可增减排序
8. 【灵魂】比对通过后无"复制校验通过报告"类产出（发公告/存档场景），✓ 判定只活在当前页面

## 行业对标与差距

- **emn178/online-tools**：MD2~SHA-3/Keccak/RIPEMD/SM3/CRC 全家、每个算法页自带 HMAC 开关、文本即时计算、文件分块读取。差距：**算法矩阵（尤其 SM3/SHA-3）与"输入即算"的即时感**。
- **CyberChef**：Hash 配方可串联（extract→hash→compare），Generate all hashes 一_recipe 多算法。差距：管道不必追；其"分块大文件"路径值得抄。
- 借鉴优先级：**开关免重算（缓存原值）> 文件计算进度条 > SM3 > 拖入即算 > HMAC 互跳**。

## 可拓展性

- 短期（1 周）：reformat 改为对缓存原始值重新 formatOne（不再重跑哈希）；文件计算加进度条（CRC32 已有分块骨架可复用，:43-49）
- 中期（1 月）：SM3（懒加载 js-sm3 类库）；SHA 文件路径改分块增量或 Web Worker；拖入/粘贴即算开关
- 远期：与 hmac-generator、bcrypt-hash 组成"哈希工作台"（算法页内嵌 HMAC 开关）；多文件批量校验清单（对照发布包核对场景）

## 优化处方（验收标准）

1. **开关免重算**：upper/compact 切换仅对已缓存原始哈希重排版。→ **验收：1GB 文件计算完成后切换"大写输出"，结果 100ms 内翻转且不触发任何再读取（Performance 面板无新 file 读取）**
2. **文件计算进度**：按算法×字节双维度显示进度条与百分比，完成后显示总耗时。→ **验收：500MB 文件计算中进度条持续推进、UI 不冻结、可点"取消"中止**
3. **SM3 国密**：算法列表增加 SM3（懒加载引擎），输出与国标测试向量一致。→ **验收：对 "abc" 输出 `66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0`（GB/T 32905-2016 标准向量）**
4. **拖入即算**：FileDrop 收到文件后自动开始计算（提供"自动计算"开关默认开）。→ **验收：拖入文件松手即见进度条启动，无需点击按钮**
5. **HMAC 互跳**：结果区尾部加"需要签名？生成 HMAC →"链接直达 hmac-generator 并透传文本。→ **验收：点击跳转后 hmac-generator 消息框预填源文本**
