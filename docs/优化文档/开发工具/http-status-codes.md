## 结论与优先级

**需拓展（补全状态码库）＋ 交互优化** · P1（desc 与实际库不符按疑似功能问题登记）

判据：交互层无硬伤，但数据覆盖 29/63 属功能面硬缺口——速查工具的立身之本是"查得到"，desc 承诺"全部"而库缺一半以上。

## 扣分点明细

1. 【功能-疑似缺陷】状态码库覆盖不足且 desc 名实不符：`HTTP_STATUS` 仅 29 条（`jsEngine.ts:777-807`），缺 RFC 常见码 34 个——300 Multiple Choices、402、406、407、411、412、414、416、418、421、423、425、426、428、431、451、505、507、511、102、103、203、205、207 等；registry.ts:208 desc 写"1xx–5xx 全部状态码"与实际不符，用户搜"418""451"返回零结果且无"未收录"说明
2. 【功能】无处置层：每个码只有一句定义（如 502"网关收到上游无效响应"），没有"常见触发方（nginx upstream/网关）、排查动作（看上游日志）、伴随头（Retry-After）"——排障用户拿到 502 的真实问题是"我该怎么办"
3. 【交互】无锚点直达：无 `?code=404` 或 `/t/http-status-codes#404` 承载，聊天里发"看这个工具"对方还得自己再搜一遍 404；httpstatuses.io 每码独立 URL 是分享刚需
4. 【交互】单行不可复制：状态码行无复制钮（:83-89），写文档贴"429 Too Many Requests"要手动划选
5. 【灵魂】无场景化入口：登录失败用 401 还是 403、限流返回 429 要带什么头，这类"按问题找码"的反向路径缺席——速查表的灵魂是回答真实排障问题而非罗列
6. 【功能-轻】搜索仅匹配 code/name/desc 三字段（:24-28），搜"teapot""payment"无果（库内本无）；搜索无防抖亦无延迟问题，但空结果态无"试试这些词"引导
7. 【UI-轻】搜索高亮用 `<mark>` 的 v-html 注入：先 escapeHtml 再 wrap（:9-11,33）实现安全✓，但分组头计数在过滤后显示"0 条"的分组仍占一整行折叠头（:80,90），扫视时噪音偏大

## 行业对标与差距

- **httpstatuses.io**：63 码全收录、每码独立 URL、一码一屏大字排版、来源 RFC 标注。差距：**覆盖度代差**——纯数据补齐即可追平，零架构障碍。
- **MDN HTTP Status**：每码带完整语义（何时返回/默认无响应体否/安全性与缓存语义/示例）。差距：处置层缺席。
- **restapitutorial.com**：按"成功/重定向/客户端错误"场景组织 + 每码配一句"什么时候你会见到它"。差距：场景化叙事视角。
- 借鉴优先级：**补全状态码库 > 每码锚点直达 > 单行复制 > 场景化反查（401 vs 403）> RFC 出处**。

## 可拓展性

- 短期（1 周）：HTTP_STATUS 补齐至 RFC 9110/9111/6585/7538 全集 60+ 条（纯数据工作）；每行加复制钮；空搜索结果加"库内暂无此码"诚实文案
- 中期（1 月）：URL query `?code=` 打开定位对应分组并滚动高亮；每码加"常见触发场景/排查建议"两行折叠；场景化快捷标签（认证/限流/缓存/重定向）点击即过滤
- 远期：与站内 reqbin 类工具（若有）互链"试发请求看响应码"；HTTP 头速查（Retry-After/Location/Allow）姊妹工具；版本演进标注（308/425/451 属 RFC 新增）

## 优化处方（验收标准）

1. **补全状态码库**：HTTP_STATUS 扩至 RFC 全集 ≥60 条。→ **验收：搜索"418"返回 I'm a teapot，搜索"451"返回 Unavailable For Legal Reasons，总库计数显示 ≥60**
2. **desc 对齐**：registry.ts:208 desc 改为"常用状态码速查"或补全后保留"全部"。→ **验收：工具页 H1 下描述与库条数一致，不再夸大**
3. **锚点直达**：支持 `?code=404` 自动展开 4xx 组并滚动至该行高亮。→ **验收：带参打开页面后 404 行在首屏内且背景高亮 2s**
4. **单行复制**：行尾 hover 出复制钮。→ **验收：点击后剪贴板为 `429 Too Many Requests — 请求过多：触发了速率限制`**
5. **场景化标签**：搜索框下加"认证｜限流｜缓存｜重定向｜服务端故障"5 个 chip。→ **验收：点击"认证"后列表过滤为 401/403/407/428 四行并附一句选型口诀**
