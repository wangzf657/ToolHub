## 结论与优先级

**交互优化 + 需拓展** · P1（结果可读性硬伤在长数组场景，与 jsondiff.com 有代差）

判据：可用性 10/20 接近硬伤线；数组对比策略缺失属"子功能缺失悬殊"。

## 扣分点明细

1. 【可用性】左右输入 textarea 各钉 170px（`JsonDiff.vue:75,79`；M-05 同构，共性-根因 2）——长 JSON 粘贴后窗口只显示十几行，且对比后焦点回到列表、输入区被挤压
2. 【功能·策略】数组对比按路径索引逐项（deepDiff 对 Array 的处理未做按键/值匹配），`[1,2,3]`→`[1,2,3,4]` 可识别新增，但 `[3,2,1]`→`[1,2,3]` 会报 3 处修改——**顺序无关数组的语义对比缺失**，jsondiff.com 按键匹配（id 字段）可正确识别
3. 【功能】无"只看差异"过滤视图：千项对象找 3 处差异靠肉眼滚列表
4. 【交互】无路径点击定位：`data.items[5].name` 只是文本，无法展开树形上下文
5. 【可用性】差异列表无固定高度/虚拟滚动，500 处差异时页面无限拉长
6. 【灵魂】无示例（改 3 个字段的两个版本 JSON）一键填入；与 text-diff（文本 diff）零互链指引（"结构对比 vs 文本对比"的选择指引）

## 行业对标与差距

- **jsondiff.com**：树形可视化（折叠展开+三色着色）、数组按键匹配（`~id` 语法）、图片/URL 直传。差距：**结果可读性代差**——对方"看树找差异"，本工具"读列表找差异"。
- **diffchecker**：行内并排高亮+行号+语法着色。差距：语法着色双栏视图。
- 借鉴优先级：**树形结果视图 > 数组按键匹配 > 只看差异过滤 > 输入区弹性高度**。

## 可拓展性

- 短期：输入区改弹性高度（min(300px, calc(100vh - 480px))）；差异列表 max-height + 计数徽章
- 中期：树形结果组件（可复用 json-visualizer 的折叠树）；"只看差异"开关；忽略键（正则）选项
- 远期：数组按键匹配策略（检测对象数组的共同 id 键）；与 text-diff 合并"对比工作台"

## 优化处方（验收标准）

1. **输入区弹性高度**：左右 textarea 改 `min(300px, calc(100vh - 500px))`。→ **验收：1366×768 下粘贴 100 行 JSON 同屏可见 ≥20 行，无需滚页面**
2. **差异列表约束**：列表容器 max-height 50vh + overflow auto + 顶部三类计数徽章常驻。→ **验收：500 处差异时页面总高 ≤ 2 屏**
3. **只看差异**：新增过滤开关，隐藏无差异路径段。→ **验收：千项对象 3 处差异时列表仅 3 条**
4. **数组匹配披露**：输出顶部注明"数组按索引对比"；检测到对象数组含共同键（id）时提示可用按键匹配。→ **验收：`[{id:1}]`→`[{id:1},{id:2}]` 出现"检测到 id 键，可按 id 匹配"提示**
