## 结论与优先级

**交互优化 + 需拓展** · P1（产出正确性缺陷应与 xml-to-json 的 @ 前缀对称性一起解决）

判据：可用性 9/20 家族硬伤 + 扣分点 1 属产出级正确性问题（非法标签名静默输出）。

## 扣分点明细

1. 【灵魂-产出缺陷】JSON key 直接用作 XML 标签名且不校验合法性（`build(val,k)` 直接拼 `<${name}>`，`jsEngine.ts:432,436`）——`{"2F 空间":"x"}` 产出 `<2F 空间>x</2F 空间>` **非法 XML**（标签不得数字开头/含空格），下游解析器报错时用户无从得知源头在此
2. 【功能】数组转换语义不对称：`{"items":[1,2]}` 产出 `<items>1</items>\n<items>2</items>`（数组键名重复，`jsEngine.ts:429`）而非 `<items><item>…</item></items>`——与 xml-to-json 的 @ 属性前缀（registry.ts:110-113 desc 承诺）往返不对称，A→B→A 不可还原
3. 【功能】对象属性无 `@attr` 映射策略（xml-to-json 产出 `@id` 键，本工具反向时把 `@id` 原样转成 `<@id>` 同样非法）
4. 【可用性-家族】180px 钉高 + pending 不渲染（M-06；共性-根因 2，引用 pinyin-converter.md 处方 1-2）
5. 【灵魂】JSON 语法错误只有浏览器原生 message（"Unexpected token"），未翻译未定位

## 行业对标与差距

- **Code Beautify**：属性前缀选项（@/#text）、数组包裹元素名自定义、非法标签名自动清洗（前缀 `_`）。差距：**产出合法性保障**。
- **convertcsv.com**：XML→JSON→XML 往返一致性说明文档。差距：本工具与姊妹 xml-to-json 零互链零口径说明。
- 借鉴优先级：**标签名合法性校验+清洗 > 数组包裹元素选项 > 往返对称说明**。

## 可拓展性

- 短期：家族整改获得 pending+弹性高度；标签名非法时行内警告（不阻断转换）
- 中期：属性映射策略选项（对象含 @ 开头键→转属性）；数组包裹元素名选项（默认 item）
- 远期：与 xml-to-json 组成 XML 工作台双向页（含往返一致性自检按钮）

## 优化处方（验收标准）

1. **标签名合法性守卫**：build 前校验 key 匹配 `/^[A-Za-z_][\w.-]*$/`，不合法时自动清洗（`_` 前缀+空格转 `_`）并在输出顶部提示"N 个键名已清洗"。→ **验收：输入 `{"2F":"x"}` 产出 `<_2F>x</_2F>` 且提示 1 处清洗**
2. **数组包裹选项**：新增"数组项元素名"选项（默认沿用键名，可改 item）。→ **验收：选 item 后 `{"items":[1,2]}` 产出 `<items><item>1</item><item>2</item></items>`**
3. **往返自检**：输出区加"↔ 回转校验"按钮，本结果喂给 xmlToJson 比对结构差异。→ **验收：简单对象往返后 JSON 深度相等显示绿色对勾**
4. **家族整改**：引用 pinyin-converter.md 处方 1-2
