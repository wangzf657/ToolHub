## 结论与优先级

**交互优化** · P1

判据：功能与交互为 JSON 家族内最佳（63 分家族最高），唯一硬伤级扣分是 480px 树区钉死——这与"可视化"工具的核心产出直接冲突。

## 扣分点明细

1. 【可用性-硬伤倾向】树区 `max-height:480px` 钉死（`JsonVisualizer.vue:155`，共性-根因 2 在案点名），全屏工作流（对照浏览大响应体）无法放大——可视化工具的结果区就是产品本体
2. 【可用性】搜索命中无计数反馈（`JsonVisualizer.vue:89-96` 只做展开，无"命中 N 处"），大 JSON 里用户不知道搜没搜全
3. 【功能】无图谱视图（Graph 模式）——JSON Crack 的招牌能力，复杂引用关系（环形引用、跨层跳转）只有树一种表达
4. 【功能】复制路径为 JS 点路径格式 `a.b[0].c`（JsonTreeNode copyPath），非 JSONPath `$..a.b[0].c`——与 jsonpath-tester 无法无缝衔接（工作台断链点）
5. 【功能】无 URL 分享/快照：JSON Crack 可把当前数据+展开状态编码进链接，协作场景本工具为零
6. 【交互】输入窗 110px（:119）改完 JSON 需重新粘贴才能"回到根视图"，无"重新解析"按钮
7. 【功能】无原文对照视图（jsonformatter.org 的 Text/Tree 双 Tab），找"第几行"场景要切去 json-formatter

## 行业对标与差距

- **JSON Crack**：树/图谱双视图、节点搜索+替换、JSONPath 即取即复制、URL 分享快照、Code 模式行号对照。差距：**单视图 vs 双视图的代差**（金标准 json-formatter.md 已确认结构可读性代差，本工具已补齐"树"这一半，缺"图"）。
- **jsonhero.io**：属性面板式浏览（点选节点看类型/大小/预览）、多视图（Inception/JSON/Schema）。差距：节点级元信息（类型/字节数）展示。
- 借鉴优先级：树区弹性高度 > JSONPath 格式复制 > 搜索命中计数 > 图谱视图（中期）。

## 可拓展性

- 短期（1 周）：树区弹性高度 + 全屏切换（金标准处方 1 同口径）；搜索命中计数徽章
- 中期（1 月）：路径复制格式切换（JS 点路径/JSONPath 双模式）；Text/Tree 双 Tab 行号对照；节点类型/大小元信息悬浮
- 远期：图谱视图（D3/dagre 懒加载）；URL hash 分享；作为"JSON 工作台"（金标准 `docs/优化文档/开发工具/json-formatter.md` 远期档）的可视化宿主——jsonpath-tester 查询结果直接在本树上高亮

## 优化处方（验收标准）

1. **树区弹性高度**：`.tree` 改 `height: calc(100vh - 380px)` 下限 480px，工具栏加全屏按钮（fixed 覆盖层）。→ **验收：1366×768 下树区 ≥330px 且全屏后覆盖含侧栏整页**
2. **搜索命中计数**：搜索框右侧显示"命中 N 处"，N 为 matchSelf+子树命中节点数。→ **验收：默认示例搜"球状闪电"显示命中 1 处**
3. **JSONPath 复制**：键名右键或长按菜单提供"复制 JSONPath（$ 格式）"，与 jsonpath-tester 表达式直接互通。→ **验收：复制 `store.book[0].title` 的 $ 版本粘贴进 jsonpath-tester 直接命中**
4. **重新解析按钮**：输入窗旁加"重新解析"，点击回到根视图并保留输入。→ **验收：展开深层后修改输入再点击，树回到默认两层展开态**
