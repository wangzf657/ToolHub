## 结论与优先级

**交互优化** · P1

判据：数据加载提示质量（BUG-20 修复）与协议解释性是全站上乘；扣分集中在结果不可搬运（复制/导出）与 2MB 首载的进度反馈缺失。

## 扣分点明细

1. 【交互】结果零搬运：单查卡的厂商/OUI/EUI-64/链路本地地址均无复制钮（:157-169 全文未引 copyText），批量表无"导出 CSV/复制表格"（:172-187）——盘点场景的终点就是表格进文档
2. 【可用性-轻】2MB 首载无进度：loading 文案只有 spinner＋"约 2MB"（:137），慢网下无百分比/已加载量，用户无法判断是卡死还是在走；fetch 可接 ReadableStream 计算进度（content-length 已知）
3. 【可用性-轻】2MB 解析主线程阻塞：`await res.json()`（:41）＋3 万条 Map 构建同线程，低配设备首查点击后有约半秒到一秒冻结，无"解析中"阶段拆分（可 setTimeout 分块或 Web Worker）
4. 【功能】无厂商反查：输入"华为"或"Huawei"列不出其全部 OUI 前缀——MAC-Vendors 支持双向，设备采购核对与安全分析（识别伪造厂商字段）都依赖反查
5. 【功能】批量无 CSV 导出与统计摘要：1000 行批量后无"全局/本地地址占比""未收录数"汇总（:118-129 只逐行），网管盘点要自己数
6. 【灵魂-轻】会话内缓存仅内存（:35-36 `loaded` 标志），刷新页面重新拉 2MB——Cache API/IndexedDB 可存一次管一个月，IEEE OUI 月级更新频率完全允许
7. 【交互-轻】批量中非法行混排：错误行 vendor 列写错误文案（:121），但表格无按"合法/非法"过滤或高亮过滤钮，混在 1000 行里难挑出
8. 【UI-轻】单查与批量结果互斥清空（:105-106,124），切模式即丢上一次结果，无"保留上次结果"记忆

## 行业对标与差距

- **MAC-Vendors（macvendors.com）**：MAC→厂商与厂商→前缀双向查询、API、批量导出。差距：**双向查询与导出代差**（反查是前端 Map 反转即得，零架构障碍）。
- **Wireshark OUI 页**：官方权威数据源标注与更新时间。差距：本工具未标注数据快照日期（oui.json 生成时间），用户无法判断库新鲜度。
- 借鉴优先级：**结果复制与 CSV 导出 > 厂商反查 > 加载进度百分比 > Cache API 持久缓存 > 数据快照日期标注**。

## 可拓展性

- 短期（1 周）：结果卡各行复制钮；批量表加"复制 TSV/下载 CSV"；库加载后标题旁显示"快照日期 2025-xx"（构建时写入 oui.json 元数据）
- 中期（1 月）：fetch ReadableStream 进度条（百分比）；Cache API 持久化（首次 2MB，之后 0ms）；厂商名模糊搜索 Tab（反转 Map＋前缀匹配）；批量统计摘要行
- 远期：与 subnet-calculator 组成"网络工具族"互链；IEEE MA-L/MA-M/MA-S 三级前缀区分标注；ARP 表粘贴解析（IP↔MAC 联查）

## 优化处方（验收标准）

1. **结果搬运**：单查卡加"复制结果"钮（厂商＋MAC＋EUI-64 四行文本），批量表加"下载 CSV"。→ **验收：批量 3 行查询后下载 CSV，用 Excel 打开得到 5 列 3 行数据**
2. **加载进度条**：fetch 用 reader 读取按 content-length 更新百分比。→ **验收：2MB 慢速加载时显示"已加载 45%"递增文案，完成后消失**
3. **厂商反查**：加"按厂商搜前缀"模式，输入"Huawei"列出其全部前缀卡。→ **验收：搜索 Huawei 返回 ≥20 个 OUI 前缀且点击任一前缀回填单查框**
4. **持久缓存**：Cache API 存储 oui.json，二次访问直接命中。→ **验收：第二次打开工具点击查询，Network 面板无 /data/oui.json 请求且结果 <100ms 出现**
5. **批量统计摘要**：批量结果表头上方显示"共 N 行：全局 X／本地 Y／未收录 Z"。→ **验收：粘贴 10 行含 3 个随机 MAC，摘要显示本地 3**
