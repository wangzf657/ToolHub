## 结论与优先级

**交互优化** · P1

判据：算法正确性与口径说明达到国民工具水准无硬伤；摩擦集中在结果不可复制与批量展示形态，属 CalcTool 壳层单点改造。

## 扣分点明细

1. 【交互】结果零复制：600 个坐标值无任何复制入口（registry.ts compute 未接 copyText，CalcTool.vue 无结果行复制机制）——转完的坐标最终目的就是贴进代码/Excel，现在只能手动划选 6 位小数
2. 【可用性】批量结果无表格形态：200 行输入产生 600 条结果行平铺（CalcTool.vue:44-52 逐行 div），无分组表头、无折叠、无"只看第 2 行"能力——coordinator.info 是输入输出左右对照表
3. 【交互】经纬度顺序不宽容：严格要求「经度,纬度」（registry.ts:332），用户从 Google Earth（lat,lon 习惯）或部分 GPS 工具粘贴 `39.9,116.4` 会得到纬度 116.4 报"格式不合法"，而中国经度 73-135、纬度 0.8-55.8 的取值域足以自动判别并提示
4. 【功能】无 DMS 度分秒输入：GPS 设备与测绘资料常给 `116°23′29″E`，需自行转十进制才能用
5. 【功能】无地图预览：转换对不对肉眼难辨（偏移约 500m），coordinator.info 在地图上打点前后对比是最有说服力的验证——纯前端可用无需 key 的瓦片（OSM）渲染，属可追差距
6. 【交互】200 行上限静默截断（registry.ts:328 slice(0,200)），超限无提示，用户不知道第 201 行起被丢弃
7. 【灵魂】无偏移量显示：GCJ02 与 WGS84 差值（约几百米）本身是排查"偏了多少"的答案，输出只有终值没有 Δ
8. 【交互-轻】默认坐标系 wgs84 固定（registry.ts:322），无记忆——高德开发者每次来都要手动切 GCJ02

## 行业对标与差距

- **coordinator.info**：输入输出对照表、地图打点前后对比、单点/批量双模式、一键复制任意系结果。差距：**验证闭环与结果可搬运性代差**（对照表＋复制是纯前端可及项）。
- **高德开放平台坐标转换 API 文档**：官方口径给出三系定义与适用边界（本工具 note :354 已对齐其表述）。差距：官方样本坐标系对比示例表可借鉴。
- 借鉴优先级：**结果复制（单行＋整批文本块）> 输入输出对照表 > 经纬度顺序智能判别 > 偏移量 Δ 显示 > 地图预览（远期）**。

## 可拓展性

- 短期（1 周）：结果行 hover 复制＋"复制全部结果"按钮（`经度,纬度` 原格式逐行）；超 200 行显式提示；坐标顺序智能判别（lat>55.8 且 lon≤55.8 时警告"疑似纬度在经度位"）
- 中期（1 月）：批量结果改 table 形态（输入|WGS84|GCJ02|BD09 四列对照，复用 .table-wrap）；DMS 解析；最后使用的坐标系 localStorage 记忆
- 远期：OSM 瓦片小地图打点验证（免 key）；GPX/KML 文件导入导出（文件级批量）；与站内单位换算家族的"口径说明"规范对齐补充精度边界（城市级 ±1m 与郊野 ±5m 分档）

## 优化处方（验收标准）

1. **结果可复制**：结果区尾加"复制全部结果"按钮，输出 `原始值→三系值` 逐行文本。→ **验收：输入 3 行坐标点击复制后，剪贴板为 3 行×3 系文本，直接可贴 Excel 且列对齐**
2. **顺序智能判别**：解析时若首值 ∈(0.8,55.8] 且次值 ∈[73,135.8] 触发警告"疑似纬度、经度顺序颠倒，已按输入原样计算"。→ **验收：输入 `39.9,116.404` 出现该警告且结果照常**
3. **对照表格**：≥5 行输入时结果切换为四列对照表。→ **验收：粘贴 10 行后出现表头「输入/WGS84/GCJ02/BD09」的表格，10 行对应 10 个 tr**
4. **偏移量显示**：GCJ02 与 WGS84 结果行尾附 `(Δ 约 537m)`。→ **验收：天安门坐标两行差值以米数显示且误差 <10%**
5. **截断提示**：超 200 行时提示行"已处理前 200 行（共 N 行），请分批"。→ **验收：粘贴 250 行后提示出现且结果恰 600 条**
