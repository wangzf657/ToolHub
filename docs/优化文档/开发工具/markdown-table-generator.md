## 结论与优先级

**交互优化 + 需拓展** · P1

判据：生成引擎（转义＋等宽对齐）质量高于同类无硬伤，但"只能尾部增删＋全局对齐"把编辑能力压到玩具级，导入侧空白需拓展。

## 与 csv-to-markdown 的关系：引擎应下沉共享，两页互为出入口

csv-to-markdown（56 分，textDef 朴素 split，registry.ts:161-178）吃"已有 CSV"的流量，本工具吃"手动建表"的流量——方向互补却互不引用。本工具的输出引擎（esc＋padEnd 等宽对齐，:28-31）正是 csv-to-markdown 缺的输出质量（对方产物不对齐）；csv-to-markdown 的 CSV 解析入口正是本工具缺的导入。建议：对齐引擎下沉到共享 lib（含 papaparse 接入）供两侧复用＋顶部互链传数据。

## 扣分点明细

1. 【功能】行列操作只有尾部 push/pop（`MarkdownTable.vue:15-22`）：中间插行、删除指定行/指定列全部缺失——第 3 行填错只能逐格清空，10 行表格场景直接劝退
2. 【功能】对齐仅全局单选（:12,:54-58）：GFM 本支持逐列对齐（`| :--- | ---: |`），"左列文字＋右列数字"的常见表格无法表达
3. 【功能】无任何导入：粘贴 CSV/HTML 表格一键进网格没有——tableconvert.com 支持 CSV/Excel/HTML/JSON/MD 多态互转
4. 【交互】无渲染预览：输出只有源码 pre（:82），效果要另开 markdown-preview 或 GitHub 验证
5. 【可用性-轻】输出 pre 无 max-height 无行号（:116-126），行多时页面失控拉长，与全站"钉死过矮"形成另一个极端
6. 【交互-轻】增删行列/切对齐无键盘路径，批量编辑全靠鼠标逐格
7. 【灵魂】无粘贴侦测：用户把 3 行 CSV 贴进某格时无"检测到 CSV，一键导入"提示，主动智能缺席

## 行业对标与差距

- **tableconvert.com**：CSV/HTML/Excel/Markdown/SQL 多格式互转＋网格编辑＋源码/渲染双视图＋逐列对齐。差距：**编辑粒度与导入格式面**——对方是表格工作台，本工具是单格记事本。
- **csv-to-markdown（站内）**：见上节，引擎共享与互链是零成本的双赢。
- 借鉴优先级：**指定行/列增删 > 逐列对齐 > CSV 粘贴导入 > 渲染预览 Tab > 两页互链**。

## 可拓展性

- 短期（1 周）：每行左侧 hover 出"在此后插入/删除本行"按钮，表头每列同理；对齐改每列一个下拉
- 中期（1 月）：粘贴 CSV 自动识别导入（复用 src/lib/csvEngine papaparse，注意懒加载纪律）；输出区加"源码|预览"双 Tab（复用 markdown-preview 渲染链）；与 csv-to-markdown 互链传数据
- 远期：与 csv-to-markdown、json-to-csv、csv-to-json 合并为"表格工作台"（模式 E）：CSV/JSON/HTML/MD 四态互转＋网格编辑一个入口

## 优化处方（验收标准）

1. **行列粒度操作**：每行左侧 hover 出"下插一行/删除本行"，表头每列右侧出"下插一列/删除本列"。→ **验收：3 行表删第 2 行后剩 2 行且首行数据完好**
2. **逐列对齐**：对齐改为每列独立下拉（默认左）。→ **验收：3 列选"左|中|右"输出分隔行 `\| :--- \| :---: \| ---: \|`**
3. **CSV 粘贴导入**：侦测输入含 ≥2 个逗号的行时 toast 提示"检测到 CSV，一键导入网格"。→ **验收：粘贴 3 行 CSV 点击后网格出现 3×N 单元格且引号字段正确拆分**
4. **渲染预览 Tab**：输出区加"源码|预览"切换。→ **验收：预览渲染出带边框表格，样式接近 GitHub 渲染**
5. **输出区滚动上限**：输出 pre 加 max-height:420px＋内部滚动（与全站 table-wrap 口径一致）。→ **验收：30 行表格输出不再撑长页面，pre 内可滚**
6. **两页互链**：顶部挂"从 CSV 导入→csv-to-markdown"，对侧挂反向入口。→ **验收：互跳后表格数据保留（query 或 localStorage 传递）**
