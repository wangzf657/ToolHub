## 结论与优先级

**交互优化** · P1

判据：预览时效/主题脱节（:48,:51,:115）破坏"编辑-预览-导出"闭环，预览不可信；与 Marp 的实时分页预览有代际差，但"零依赖单文件导出"是差异化亮点应保留。

## 扣分点明细

1. 【可用性-硬伤】逐页预览不随输入更新：previews ref 仅在挂载（`MarkdownToSlides.vue:48` void render()）与导出（:51）时刷新，编辑中预览是过期内容，而页数提示（:96）是实时 computed——页数变了、内容没变，用户无法信任预览
2. 【可用性-硬伤】预览配色与导出主题脱节：slide-card 标题色固定 var(--accent-text)（:115），THEMES 三套配色（:13-17）仅导出生效——切"暖橙"主题预览毫无变化，所见非所得
3. 【可用性】编辑区 rows=10（:98）≈240px 全家族最小；逐页预览堆叠下方，第 10 页预览需滚 2 屏（共性-根因 1/2 叠加）
4. 【功能】非 reveal.js/Marp：无演讲者备注、无 fragment 逐点显示、无纵向子页、无 PDF 导出（reveal ?print-pdf / Marp CLI 均支持）——正式演示场景功能悬殊
5. 【功能】分页语法单一：不支持 Marp 指令（bg/color/paging）与 reveal 属性块，图片页/章节页需手写 HTML
6. 【灵魂】无页码跳转/缩略图侧栏（第 N 页直达）；导出前无全屏试演（站内预览只能滚卡片）
7. 【性能】每次导出全量重渲染所有页（exportHtml 内 await render，:51），无增量/缓存
8. 【美观】≤560px 堆叠（共性-根因 5）

## 行业对标与差距

- **Marp**：编辑器实时分页预览、指令系统（分页/背景/尺寸/页码）、Marp for VS Code、PDF/PPTX 导出。差距：实时预览与指令系统是代差；我们的差异化是零依赖单文件（Marp 需 CLI/其 Web 编辑器）。
- **reveal.js**：fragment 逐点动画、演讲者视图（备注+计时）、纵向子页、主题市场、?print-pdf。差距：正式演示能力整体缺席。
- 借鉴优先级：输入防抖实时分页预览 > 预览随主题配色 > 备注语法 > PDF 导出 > 页码跳转。

## 可拓展性

- 短期（1 周）：watch(input) 400ms 防抖重渲 previews；slide-card 按 THEMES[theme] 动态配色
- 中期（1 月）：`<!-- note -->` 备注语法与导出折叠；当前页高亮+页码输入跳转；@media print 每页一节导 PDF
- 远期：并入 Markdown 工作台"演示"Tab；导出模板可选 reveal.js 单文件 bundle（懒加载纪律内）

## 优化处方（验收标准）

1. **实时分页预览**：watch(input) 400ms 防抖调 render。→ **验收：输入 1s 内页面预览与页数同步更新，编辑第二页文字后预览立即可见变化**
2. **预览随主题**：slide-card 注入 THEMES[theme] 配色（背景/标题/正文色与导出一致）。→ **验收：切"暖橙"后预览标题/背景即时变色，且与导出 HTML 同屏对比无色差**
3. **备注支持**：`<!-- note -->` 收集为导出 HTML 折叠备注区。→ **验收：备注不出现在幻灯片正文，打开导出文件可展开查看对应页备注**
4. **编辑区弹性高度**：min-height `calc(100vh - 420px)`。→ **验收：1366×768 下 20 页 deck 编辑无需在编辑区内滚超过 2 屏**
5. **PDF 导出**：@media print 每页一节强制分页。→ **验收：浏览器打印预览中每页独立分页、无跨页截断**
