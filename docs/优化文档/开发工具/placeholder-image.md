## 结论与优先级

**交互优化 + 需拓展** · P1

判据：单链路体验顺畅无硬伤；格式矩阵与"复制即用"出口（SVG/data-URI）是对照 placehold.co 的功能面代差，URL 直链属架构边界应诚实标注并给出前端可及替代。

## 扣分点明细

1. 【功能】仅 PNG 单格式：`toBlob(..., 'image/png')` 写死（`PlaceholderImage.vue:56`），SVG（矢量占位、体积极小、文本可编辑）与 JPEG/WebP 一行代码可加却缺席——placehold.co 四格式是标配
2. 【功能】无"复制即用"出口：对标站的灵魂是拿到一段 `<img src>` 或 `background-image: url(...)` 直接贴进代码；本工具唯一出口是下载文件，前端用户还要自己转 base64——SVG data-URI 复制是纯前端可及的补偿方案
3. 【交互】无尺寸预设：OG 图 1200×630、公众号头图 900×383、favicon 512×512、App Store 截图等高频尺寸要手敲两个输入框
4. 【交互】非法尺寸静默钳制：输入 0 或负数直接按 1 绘制（:18-19），无"最小 1px"提示，用户不知道自己输入没生效
5. 【可用性-轻】预览与实际导出无对比信息：360px 预览不显示导出文件体积（PNG 尺寸差异巨大），"导出多大"只能下载后才知道
6. 【灵魂】无图案/照片占位变体：placehold.co 的斜纹/网格/灰度人像（picsum.photos 随机照片）是排版稿里区分"图文区"的关键，本工具只有单一对角线款（:26-35）
7. 【交互-轻】无宽高互换钮：竖版改横版要手动交换两个数；下载行"清空文字"（:97）与参数区距离远，操作分组松散

## 行业对标与差距

- **placehold.co**：`600x300` 即 URL 的直链模式、SVG/PNG/JPEG/WebP 四格式、字体/圆角/文字位置参数、格式即扩展名切换。差距：**直链属云端架构不可追**，格式矩阵与代码出口纯前端可追。
- **picsum.photos**：随机真实照片占位（灰度/模糊/指定 ID），排版演示质感远超色块。差距：照片库需 CDN，纯前端可用 canvas 程序化纹理（噪点/网格/渐变）替代。
- **dummyimage.com**：老牌 URL 参数制占位图（尺寸×配色×格式单串直链）。差距：同属直链架构不可追，但其"参数串"形式提示本工具可支持 query 预填。
- 借鉴优先级：**SVG 格式＋复制 data-URI/SVG 代码 > 尺寸预设 chip > 图案变体（斜纹/网格/渐变）> 体积预估 > 宽高互换**。

## 可拓展性

- 短期（1 周）：加 SVG 生成（文本尺寸即 SVG 元素，纯字符串拼接）与"复制 SVG 代码 / 复制 data URI"两钮；尺寸预设 chip 6 个（OG/favicon/公众号/全高清/竖屏/自定义记忆）
- 中期（1 月）：格式 Tab（PNG/SVG/JPEG/WebP）；斜纹与网格图案选项；导出体积实时预估（toBlob 后回填到下载行）；宽高互换钮
- 远期：程序化照片感占位（渐变＋噪点＋形状模板）；与 qr-code-generator、favicon-generator 组成"生成器家族"统一"参数行＋预览＋多格式导出"壳；URL query 承载参数（`?600x300` 生成分享链接，静态站可做的"准直链"）

## 优化处方（验收标准）

1. **SVG 出口**：新增"复制 SVG 代码"与"复制 data URI"按钮。→ **验收：点击后贴入 HTML 文件，`<img src="data:image/svg+xml,...">` 渲染出与预览一致的 600×300 占位图**
2. **尺寸预设 chip**：参数行下 6 个 chip 一键填充。→ **验收：点击"OG 1200×630"后宽高输入框变为 1200/630 且画布即时重绘**
3. **格式选择**：下载行加 PNG/SVG/JPEG 三选。→ **验收：选 JPEG 下载得到 `.jpg` 文件且体积小于同尺寸 PNG**
4. **导出体积预估**：下载行显示"导出约 N KB"（300ms 防抖 toBlob 测算）。→ **验收：改尺寸后 N 随之变化，误差 ≤20%**
5. **非法输入提示**：宽高 <1 时输入框红框＋"最小 1px"提示。→ **验收：输入 0 后出现提示且画布保持上次合法值**
