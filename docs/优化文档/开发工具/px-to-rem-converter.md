## 结论与优先级

**交互优化** · P1（含一处疑似功能缺陷需修复确认）

判据：单值换算闭环可用无硬伤；但 root 不联动是承诺与行为不符的缺陷，批量转换缺席使其停留在"玩具级"功能面。

## 扣分点明细

1. 【交互-疑似缺陷】改根字号后换算结果不更新：`onPx/onRem` 仅挂在两个输入框的 `@input`（`PxRemConverter.vue:49,:57`），无 `watch(root)` 重算——输入 32px 得 2rem 后把根字号改成 8，结果仍显示 2rem（应为 4rem），而对照表因依赖 `rootNum` computed（:78-79）即时更新，页面自相矛盾；且 :87 文案明确承诺"表格与换算实时更新"
2. 【功能】无批量转换：不能粘贴多行 px 值或整段 CSS 一次性替换为 rem（nekocalc 的核心用法），真实迁移场景效率低
3. 【功能】em 列无信息量：与 rem 列逐格相同（:78-79 按"1em=根字号"估算），em 实际随父元素字号变化，表格未给出任何额外参考或干脆移除
4. 【交互】对照表行不可复制：常用值表 6 行只有"复制对照表"整表按钮（:25-29），无法单行点击复制
5. 【灵魂】root 值不持久化（localStorage），每次进入都要重新设置非 16px 项目的根字号
6. 【功能】无双向"锁定输入焦点"模式：两个方向各占一卡，同屏同时维护两份输入值，反向输入会覆盖正向结果（共用 pxInput/remInput 两个状态，:9-10），用户可能被静默覆盖感到困惑
7. 【交互】换算结果无一键复制：结果在 readonly input 里，没有复制按钮也没有回车复制（:51,:59），每次都要手动选中文本
8. 【功能】无反向链换算（px→rem→px 完整闭环展示）：卡内只显示一步结果，无"12px = 0.75rem = 12px"自检行帮助确认根字号设置正确

## 行业对标与差距

- **nekocalc.com px-to-rem**：单值+批量 Tab、支持表格粘贴（多列多行）、整段 CSS 直接替换输出。差距：批量能力整体缺席。
- **convertlive / unitconversion.io**：双向即时+换算链（px→rem→em→%同屏并列）。差距：只有 rem/em 两列且同值。
- 借鉴优先级：**watch(root) 联动修复 > 批量 CSS 替换 > 单行复制 > root 持久化 > em 列改造**。

## 可拓展性

- 短期（1 周）：`watch(root)` 重算两卡结果；对照表行 hover 显复制按钮；root 值 localStorage 持久化
- 中期（1 月）：批量 Tab——textarea 粘贴 CSS/多值，正则替换 `(\d+)px` → rem 输出全文；em 列改为"父字号可调的 em 参考"或移除
- 远期：与 css-formatter 联动（格式化结果一键送入批量转换）；支持 ch/vw 等其他相对单位换算

## 优化处方（验收标准）

1. **root 联动重算**：加 `watch(rootNum)` 触发双向重算（保持最近编辑方向语义）。→ **验收：输入 32px=2rem 后改根字号 8，两卡即时显示 4rem/256px，与表格一致**
2. **批量转换 Tab**：加"单个|批量"，批量模式粘贴任意 CSS 文本，输出所有 `Npx`→`Nrem`（保留原格式）全文+一键复制。→ **验收：粘贴含 10 处 px 的样式块，输出全文 10 处替换正确、小数 ≤4 位、其余文本原样**
3. **对照表单行复制**：每行尾加复制图标，点击复制 rem 值。→ **验收：点击 24px 行后剪贴板为 `1.5rem` 且 toast 提示**
4. **root 持久化**：根字号存 localStorage（key 前缀 toolhub）。→ **验收：设为 14 后刷新页面仍为 14**
5. **em 列改造**：表格提供"父字号"输入（默认=根字号），em 列按父字号计算并标注口径。→ **验收：父字号改 20 后 em 列与 rem 列数值不同且随父字号联动**
6. **结果一键复制**：结果 input 尾加复制图标按钮，点击复制计算值。→ **验收：点击后剪贴板为 `1.5rem` 且 toast 提示，无需手动选中文本**
