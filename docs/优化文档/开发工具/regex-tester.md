## 结论与优先级

**交互优化 + 需拓展** · P1（预设首屏外 147px 接近硬伤；主流程输入→高亮首屏闭环可达故不判 P0）

判据：可用性 10/20 达硬伤边缘；与 regex101 的"逐 token 解释"存在功能性代差。

## 扣分点明细

1. 【可用性】常用预设按钮组（邮箱/URL/手机号…）位于 DOM 最底部（`RegexTester.vue:110-117`），实测 top=915、首屏外需滚 147px（M-04）——预设是该工具最便捷的入口，却藏在最深处
2. 【可用性】测试文本 textarea `min-height:120px`（:87）、高亮区 `.hl max-height:220px`（:144）双钉高（共性-根因 2），长文本只能在两个小窗内分别滚动，且文本窗与高亮窗滚动不同步
3. 【可用性】正则输入是单行 `<input type="text">`（:72），复杂正则（如 IPv4 那条 55 字符）在窄面板里被截断，无法通览全貌——regex101 支持多行编辑
4. 【功能】无替换（replace/substitute）模式：regex101 底部的替换预演是调正则的第二 half，本工具只能测匹配
5. 【功能】捕获组只在文本下方列表展示"第一个匹配的组值"（:98），正文高亮不区分组（regex101 每组独立着色、hover 高亮对应组）
6. 【功能】无逐 token 解释——regex101 的灵魂：鼠标放任一段自动讲"这里是负向断言/量词贪婪"。本工具对复杂正则零解释能力
7. 【交互】匹配列表仅"位置 {{ m.index }}"裸数字（:105），无行:列定位，无法回原文定位第几行
8. 【灵魂】报错只有浏览器原生 message（:95"正则有误：…"），未翻译成人话（如"缺少右括号"）

## 行业对标与差距

- **regex101**：右侧面板实时逐 token 解释、每匹配组独立着色、替换预演 Tab、调试器（step 匹配过程）、匹配计数与优化提示（如"可改为非贪婪"）、社区正则库。差距：**"解释与调试"代差**——对方教用户写正则，本工具只让用户看结果。
- **Regulex / debuggex**：正则→铁路图可视化，复杂嵌套一眼看清。差距：结构可视化完全缺位（纯前端可实现，属真差距）。
- 借鉴优先级：**替换预演 > 预设按钮前置 > 逐 token 解释（可先做分段悬停提示）> 分组着色 > 铁路图**。

## 可拓展性

- 短期（1 周）：预设按钮组上移到正则输入框正下方；测试文本与高亮区改弹性高度；正则输入改 auto-grow textarea
- 中期（1 月）：替换模式 Tab（String.replace 预演）；匹配列表加行:列并点击回跳；分组独立着色高亮
- 远期：接入或自研轻量正则解析器做逐 token 解释/铁路图（对标 Regulex），注意懒加载纪律；与文本类工具组成"正则工作台"

## 优化处方（验收标准）

1. **预设前置**：将"常用正则速查"按钮组移至 flags 行之后、测试文本之前。→ **验收：1366×768 下 6 个预设 chip 全部 top<650，无需滚动即可点击**
2. **双区弹性高度**：测试文本与高亮区默认 `min(280px, calc(100vh - 480px))`，提供"扩展"切换。→ **验收：粘贴 200 行日志，同屏可见 ≥15 行高亮结果，无需页面滚动**
3. **替换预演**：加"匹配 | 替换"Tab，替换预演实时显示替换后全文（差异高亮）。→ **验收：输入 `\d+` 替换为 `X`，预览区 300ms 内显示全部数字变 X**
4. **匹配列表行:列 + 回跳**：每条匹配显示"行 3 列 12"，点击后高亮区滚动到该位置并闪烁标记。→ **验收：构造 50 行文本，点击第 40 行的匹配，高亮区自动滚至可见**
5. **报错人话化**：捕获 SyntaxError 消息映射为中文提示（缺少括号/量词前无内容/转义错误三类先行）。→ **验收：输入 `[a-` 显示"字符类未闭合"而非原生英文异常**
