## 与 regex-tester 的关系：补位而非重复

regex-tester.md 已明确记载其"铁路图完全缺位（纯前端可实现，属真差距）"且远期规划含可视化——本工具正是该差距的**补位实现**，两者分工：tester 管"匹配对不对"（执行侧），visualizer 管"正则长什么样"（结构侧），**不构成重复建设**。但两点割裂：① 输入不互通——同一正则要在两页重复粘贴，无互链传参；② 本工具同样缺 regex101 式"解释能力"（无逐节点 hover 讲解），与 tester 的核心短板同病，说明站内正则家族的整体天花板都在"解释/教学"层。结论：保留本工具（不做阉割），中期与 tester 组成"正则工作台"互通输入。

## 结论与优先级

**交互优化** · P1（导出保真缺陷应尽快修复）

判据：图引擎自研质量合格无硬伤；实时渲染缺失与导出 CSS 变量失效是两处明确单点改造。

## 扣分点明细

1. 【功能-疑似缺陷】下载的 SVG 独立打开失效：全部 rect/text/path 用 `fill="var(--panel-solid)"`、`stroke="var(--accent)"` 等页面级 CSS 变量（`regexDiagram.ts:39-40,:69-70,:107-110,:125`），saveText 存出后变量无定义——fill 回退 black、stroke 回退 none，**独立打开是一坨黑块**，与 :56"下载的 SVG 可直接贴进文档"的承诺相悖
2. 【交互】非实时渲染：Regulex 输入即画，本工具改一个字符都要点按钮/回车（`RegexVisualizer.vue:16-35`），迭代调正则时摩擦明显
3. 【功能】无匹配模拟动画：debuggex 的样例文本沿铁路图逐节点点亮是"理解执行过程"的独特能力，纯前端可实现
4. 【功能】无逐节点解释：hover 量词盒应讲"贪婪，尽可能多吃"，现仅有静态标签；与 regex-tester 缺"逐 token 解释"同病（见上节）
5. 【灵魂】size（宽×高）已计算但模板从未展示（`RegexVisualizer.vue:12,:26`）——贴文档前想知道图多大做不到（死数据）
6. 【可用性】图区无缩放：宽度 >1200px 的长正则只能横滚（svg max-width 截顶 regexDiagram.ts:234），无"适应宽度/原始尺寸"切换
7. 【性能】极端嵌套正则无复杂度上限保护，递归布局可能长阻塞

## 行业对标与差距

- **Regulex**：输入实时渲染铁路图、拖拽平移、错误即时标注。差距：实时性（本工具按钮触发）。
- **debuggex**：样例文本匹配动画（沿图逐段前进+文本同步高亮）、步进/播放控制。差距：模拟能力整体缺席。
- **regex101**（tester 家族共同标杆）：逐 token 解释。差距：解释层缺席——建议与 regex-tester 共建而非各自补齐。
- 借鉴优先级：**导出内联色值（修缺陷）> 实时渲染 > 节点 hover 解释 > 匹配动画 > 与 tester 互链**。

## 优化处方（验收标准）

1. **导出保真**：下载前把 `var(--x)` 替换为解析后的实际色值（getComputedStyle 读 tokens）。→ **验收：下载的 SVG 双击独立打开，线条呈主题色、文字可见、无黑块**
2. **实时渲染**：watch(input+flags) 300ms 防抖调用 regexDiagramSvg，按钮保留。→ **验收：连续输入 `^(a|b)+$` 过程中图 0.5s 内跟随更新，解析失败时显示上次成功图+错误条**
3. **节点解释**：term/group 盒加 `<title>` 中文说明（如"\b 词边界：零宽断言，不消耗字符"）。→ **验收：hover 任意盒出现 tooltip 且下载版不含 tooltip（title 仅交互版保留）**
4. **尺寸展示**：工具行显示"宽 486 × 高 132 px"。→ **验收：生成后数字与 svg viewBox 一致**
5. **与 regex-tester 互链**：两页顶部互挂跳转按钮，query 传正则与 flags。→ **验收：visualizer 输入 `^\d{4}$` 点"去测试"后 tester 页正则框回显该表达式**
