## 结论与优先级

**需拓展 + 交互优化** · P1（引擎真实度是根本短板）

判据：定位是"优化器"但引擎是正则清洗，与 SVGOMG（SVGO）的压缩能力存在代差；预览手动刷新与文本节点误伤是直接可用性问题。

## 扣分点明细

1. 【功能】引擎非 SVGO：`optimizeSvg` 仅正则去注释/metadata/属性+取整+压空白（`jsEngine.ts:866-884`），SVGO 的 path 数据优化（相对坐标/弧转曲线）、mergePaths、collapseGroups、cleanupIDs、removeUselessDefs 全部缺席——设计稿导出 SVG 通常只能省 20% 左右，SVGO 可达 50%+
2. 【功能-疑似缺陷】数字精度正则误伤非几何内容：`/-?\d+\.\d+/g` 作用于全文（`jsEngine.ts:878-881`），`<text>` 内的数字文本、`stroke-width="1.5"`、`opacity="0.45"` 都会被取整——precision=0 时 1.5px 描边变 2px、图内"3.14"文字变"3"，视觉静默损坏
3. 【交互】预览需手动刷新：优化完成后不自动渲染（`SvgOptimizer.vue:50-53`），要点"刷新预览"（:98）才更新 img——SVGOMG 是参数一动预览即动
4. 【可用性】预览区 max-height 300px 钉死（:149-152）：600px 高的插画预览被压缩，确认画质需下载文件（对比滑块/原优并排也没有）
5. 【功能】开关仅 2 个：精度+移除元数据（:67-70），SVGOMG 每个插件可独立勾选/试错
6. 【可用性】双窗 200px（:78,:80）：中型 SVG（几百行）两侧都要内滚，原始代码窗还是裸 textarea 无行号无错误定位
7. 【功能】单文件限制：`:multiple="false"`（:64），无批量优化+打包下载
8. 【灵魂】压缩率条形图只有"优化前/后"绝对宽度，无 SVGO 同场景参考线，用户无法判断 30% 是好是坏（SVGOMG 会显示优化细节分类统计）

## 行业对标与差距

- **SVGOMG**：SVGO 全插件实时开关（勾选即重渲染）、原/优对比滑块（叠加比较像素差异）、压缩率与耗时展示、复制/下载。差距：**引擎代差 + 预览时效代差**双杀。
- **vecta.io/nano 或 compressed svg 工具**：批量目录处理。差距：单文件限制。
- 借鉴优先级：**引擎升级（svgo-browser 懒加载）> 精度白名单（防误伤）> 预览实时化 > 对比滑块 > 逐项开关**。

## 可拓展性

- 短期（1 周）：精度取整改为几何属性白名单（d/points/x/y/cx/cy/r/width/height/transform）；优化完成自动刷新预览
- 中期（1 月）：引入 svgo-browser（或自研 mergePaths/cleanupIDs 两组核心插件）懒加载；逐项开关面板 ≥6 项；原/优对比滑块
- 远期：批量多文件（FileDrop multiple 已支持，补打包 zip 下载）；与 svg-viewer 类工具组成"SVG 工作台"

## 优化处方（验收标准）

1. **精度白名单**：小数取整只作用于几何属性（d/points/x/y/cx/cy/r/rx/ry/x1/y1/x2/y2/width/height/transform 值内）。→ **验收：含 `<text>3.14159</text>` 与 `stroke-width="1.5"` 的 SVG 优化后两者原样保留，path d 内坐标已取整**
2. **预览实时化**：优化成功后自动刷新 previewDoc；精度/开关变更防抖 400ms 自动重跑。→ **验收：拖入文件后预览 1s 内自动出现，调精度无需点任何按钮**
3. **引擎升级**：引入 svgo-browser（懒加载，遵守依赖纪律）作为后端，正则清洗保留为"轻量模式"选项。→ **验收：Figma 导出的测试 SVG 轻量模式省 20~30% 时，SVGO 模式省 ≥45%，且优化前后 DOM 渲染一致**
4. **对比滑块**：预览区加原/优叠加滑块（左拖右拖比较细节）。→ **验收：拖到中间可见左右两版本拼接，无像素错位**
5. **逐项开关**：至少 6 项（注释/metadata/id/class/路径合并/精度），关闭项不生效。→ **验收：关闭"移除 id"后输出保留全部 id 属性**
