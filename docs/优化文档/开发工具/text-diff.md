## 结论与优先级

**交互优化 + 需拓展** · P0（结果区视口外 = 可用性硬伤；输入区 170px 主功能区过小）

判据：可用性 9/20 触发硬伤红线（M-05 实测结果区在折叠线以下 + 双窗各 170px）。

## 扣分点明细

1. 【可用性-硬伤】对比前面板仅 308px 高、结果区出现在视口外（M-05）；对比后面板增长但结果区顶部仍在 570px 左右，1366×768 下首屏只见增删徽章、见不了正文几行
2. 【可用性】双输入 textarea 各钉 170px（`TextDiff.vue:56`、`:60`，比全局 180px 还低，共性-根因 2），对比前连"看全要贴的两段话"都做不到
3. 【可用性】结果区 `.diff-view max-height:420px` 钉死（:92），500 行 diff 需在 420px 窗口滚 10+ 屏，无"只看差异"过滤
4. 【功能】无并排（side-by-side）视图——diffchecker 默认双栏对照，适合逐行核对；本工具仅 unified 单列
5. 【功能】无行内词级高亮：一行改了两个词，本工具整行标红/绿，用户自己找差异（jsdiff 有 diffChars/diffWords 能力未用，:24-25 仅用了 diffLines）
6. 【功能】无行号列、无未变行折叠（GitHub 式"…跳过 N 行"），长 diff 上下文淹没变更
7. 【交互】输入变化后不自动重算也不提示"内容已修改，请重新对比"（:20-48 run 仅按钮触发），用户极易对着旧结果看新文本
8. 【交互】结果不可导出：无复制 diff 文本、无下载 .diff/.html，闭环断裂
9. 【美观】无行号列（:77-81 仅 +/- 标记列），反馈与协作场景（"第 12 行删了这句"）无法落地

## 行业对标与差距

- **diffchecker.com**：并排/统一双视图切换、行号、行内词级高亮、同步滚动、文本/图片/PDF 多类型、直接粘贴或上传文件、分享链接。差距：**视图与定位代差**——对方让差异"可指认"，本工具让差异"可滚动"。
- **Text-Compare 类工具**：行内高亮改动词（实色底纹）、字符级对比模式、一键交换。差距：改动定位精度。
- 借鉴优先级：**并排视图 > 行内词级高亮 > 行号 > 自动重算 > 未变行折叠 > 导出**。

## 可拓展性

- 短期（1 周）：输入区弹性高度（calc(100vh - 420px)、下限 240px）；输入变化后自动重算（可加 300ms 防抖）；A/B 一键交换按钮
- 中期（1 月）：并排视图 Tab（复用 jsdiff，注意懒加载纪律）；行号列；行内词级高亮（diffWords）；"只看差异"开关折叠未变行
- 远期：diff 结果导出 .patch/.html；与 json-diff 等结构化对比工具整合为"对比工作台"（模式 E）

## 优化处方（验收标准）

1. **输入区弹性高度**：双 textarea 默认 `min(260px, calc(100vh - 460px))` 且可拖拽。→ **验收：1366×768 下粘贴 50 行文本无需内部滚动即可通览 ≥30 行**
2. **结果区进入首屏**：对比后自动 scrollIntoView 结果区，且结果区默认高度 `calc(100vh - 360px)`。→ **验收：点击"开始对比"后 300ms 内结果区顶部进入视口，同屏可见 ≥25 行 diff 正文**
3. **自动重算**：watch 双输入 + 500ms 防抖自动执行，保留手动按钮；结果区显示"内容已更新"时间戳。→ **验收：修改任一侧文本后 1s 内统计徽章数字变化，无需点击**
4. **行内词级高亮**：变更行内被改词加实色底纹。→ **验收：A"苹果香蕉"→B"苹果樱桃"，仅"樱桃"与"香蕉"两词带高亮底纹而非整行**
5. **并排视图**：增"统一 | 并排"切换，并排模式左右行号对齐 + 同步滚动。→ **验收：滚动左栏时右栏按行号比例跟随**
