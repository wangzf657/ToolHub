## 结论与优先级

**交互优化 + 需拓展** · P1

判据：单账户体验优秀（可用性 12/20），但 totp.app 的核心价值"多账户并存管理"缺失，属对标主功能代差。

## 扣分点明细

1. 【功能-代差】无多账户管理：真实用户存 5–20 个服务的密钥，本页一次只能算一把（totp.app 为多账户卡片流+命名+本地持久化）
2. 【功能-疑似问题】HOTP 链接误接受：parseUri 正则接受 `otpauth://hotp/`（:56）但 counter 参数被忽略、仍按时间口径出码——HOTP 密钥会得到看似合法实则错误的口令
3. 【功能】issuer 丢失：`issuer=xxx` 参数未回填（:68-72 仅从 label 提取含":"的账号），口令卡下账户语境不全
4. 【可用性】首用 otpauth 动态加载（:45）期间口令卡空白占位无"引擎加载中"提示（对照 PgpTool.vue:146 有加载提示，站内不一致）
5. 【交互】无下一码预览：30 秒末尾复制常在传输途中过期，2fa.live 当前/下一码并排
6. 【交互】无 otpauth 迁移二维码扫描入口（Google Authenticator 导出场景断链）；也无粘贴板一键读取
7. 【灵魂】与 base32-converter（`registry.ts:134-143`）无互链：手动模式下"密钥从哪来/Base32 是什么"无跳转指引
8. 【美观】剩余 <5 秒时秒数与进度条无红色紧迫态，"复制到一半就过期"的挫败无预警

## 行业对标与差距

- **totp.app**：多账户卡片管理、账户名/issuer 编辑、本地持久化、逐账户倒计时。差距：**账户管理代差**——对方是"轻量验证器替代品"，本工具是"单次计算器"。
- **2fa.live**：当前码+下一码并排、自动复制选项、otpauth 批量解析。差距：下一码与自动复制两个小而高频的点。
- 借鉴优先级：**多账户列表（localStorage 持久化）> 下一码预览 > issuer 回填 > HOTP 拒绝或正确支持 > base32 互链**。

## 可拓展性

- 短期（1 周）：HOTP 链接行内警示"计数器型本工具不可用"；issuer 解析回填；首用加载文案
- 中期（1 月）：多账户卡片流（localStorage 持久化、逐卡倒计时+复制）；下一码预览；剩余 5 秒红色紧迫态
- 远期：otpauth 迁移二维码解析（jsqr 已在依赖树 `package.json` jsqr ^1.4.0）；密钥导出回 otpauth:// 链接

## 优化处方（验收标准）

1. **HOTP 纠偏**：检测到 `otpauth://hotp/` 时不出码并警示"该密钥为 HOTP 计数器型，本工具按时间计算的口令不可用"。→ **验收：粘贴 HOTP 链接后口令卡不出现数字且警示可见**
2. **issuer 回填**：解析 `issuer=` 参数与 label 前缀两种来源，口令卡下显示"服务 · 账号"。→ **验收：粘贴含 issuer=GitHub 的链接后显示 "GitHub · 账号名"**
3. **下一码预览**：口令卡右侧小字显示下一时段口令。→ **验收：与 2fa.live 同密钥同参数的 next code 数值一致**
4. **多账户**：支持添加多张密钥卡（名称+密钥），刷新后保留。→ **验收：添加 3 个账户后刷新完整恢复，且口令与手机验证器当前值一致**
5. **紧迫态**：remaining ≤5 秒时秒数与进度条转 var(--err) 红色。→ **验收：30 秒周期最后 5 秒颜色变化可见并恢复**
