## 结论与优先级

**交互优化** · P1（家族处方覆盖 + 口径披露补齐）

判据：可用性 9/20 家族硬伤；个性问题集中在口径透明度而非正确性。

## 扣分点明细

1. 【可用性-家族】180px 钉高 + pending 不渲染（M-06；共性-根因 2，引用 pinyin-converter.md 处方 1-2）
2. 【功能·口径】同名重复子标签→JSON 数组的合并规则 UI 零披露——用户拿到 `["a","b"]` 数组无法预期，混合 text 节点时（`<p>hi<b>x</b></p>`）的 #text 键约定同样无说明
3. 【功能】命名空间（`<ns:tag xmlns:ns="…">`）处理策略未说明：前缀保留还是剥离，转换结果直接取决于实现
4. 【灵魂】与 json-to-xml 往返不对称（本工具产 `@id`，对方把 `@id` 转非法标签 `<@id>`）——互链与提示双缺
5. 【灵魂】无 SOAP/配置文件示例空态；CDATA 内容转换行为未验证未披露

## 行业对标与差距

- **Code Beautify**：属性前缀可选（@/无前缀）、文本键名可选（#text/value）、强制数组开关（单元素也包数组）。差距：**口径可控性**。
- **freeformatter**：命名空间处理三选一（保留/剥离/映射）。差距：命名空间策略。
- 借鉴优先级：**口径选项（属性前缀/文本键名）> 强制数组开关 > 往返互链**。

## 可拓展性

- 短期：家族整改；输出顶部加口径摘要 chip（"属性 @ 前缀｜同名合并数组｜文本 #text"）
- 中期：口径选项面板（与 json-to-xml 共用策略对象）；SOAP 示例空态
- 远期：XML 工作台双向页 + 往返自检（引用 json-to-xml.md 处方 3）

## 优化处方（验收标准）

1. **口径摘要**：输出非空时显示"属性已保留为 @key｜重复子节点已合并为数组"chip 行。→ **验收：转换含属性与重复标签的 XML，chip 内容与实际输出一致**
2. **强制数组选项**：新增"单元素也输出数组"开关（默认关）。→ **验收：开关开启时 `<a>1</a>` 转出 `{"a":[1]}`**
3. **家族整改**：引用 pinyin-converter.md 处方 1-2（pending 渲染+弹性高度）
4. **往返互链**：结果区加"转回 XML"按钮直达 json-to-xml 并预填。→ **验收：点击后跳转且输入区已填入当前 JSON**
