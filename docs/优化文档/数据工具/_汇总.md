# 数据工具分类汇总（18 项）

> 依据：`docs/优化文档/数据工具/` 18 份工具档案（全部数字来自脚本提取产物 `docs/优化文档/_scripts/data-extract.json`，可复算）＋ `docs/优化文档/_布局审计底稿.md`（共性-根因 1~5）＋ `docs/优化文档/_实测锚点.md`（M-16）。只做归并分析，不改任何业务代码。
> 口径备注：query-csv-with-sql 档案标题行写"60/100"，但其七维表加权合计为 **63**（13+10+13+12+7+8），本汇总以表内加合计为准（标题行笔误，建议档案侧勘误）。

## 一、总览

- **样本与均分**：18 份档案，**均分 58.39 / 100**，中位 58.5；最高 query-csv-with-sql **63**（分类最高）、最低 epub-reader **53**——全带宽仅 10 分，是全站最"平"的分类：没有压舱旗舰，也没有崩塌项。
- **分数段**：≥60 共 4 项（22.2%）、55~59 共 12 项（66.7%）、<55 共 2 项（11.1%）——三分之二挤在 55~59"差一口气"带，失分模式高度一致（见§三）。
- **头部**：query-csv-with-sql 63（alasql 真 SQL 引擎 + 中文标识符自动补 `[]`）、data-analysis-tool / excel-viewer 62（工作台聚合 / 分页诚实）。共同点：引擎真实 + 能力边界诚实披露。
- **尾部**：epub-reader 53（阅读器五件套只配齐一件半）、chart-from-csv 54（列映射缺失、标签列钉死第一列）、parquet-to-csv 56（导出仅前 500 行且措辞易误读全量）。共同点：核心能力对标杆有代差，或对用户有隐瞒。
- **优先级分布**：P0 1 项（csv-viewer）、P1 9 项、P2 8 项。另有两处档案自评"硬伤级"却定 P1（query-csv 编辑区 96/140px、merge-csv 全量渲染冻结），整改时应按"分数 + 硬伤"双排序。
- **布局模式分布**：模式 C 15 项 + C 变体 2 项 + E 变体 1 项——**全分类几乎清一色"文件流"模式 C**（FileDrop→选项→按钮→结果表），共性-根因 2（钉高）与根因 4（按钮流底）以全站最大浓度存在。
- **七维均分**（得分/满分，得分率）：

| 维度 | 均分 | 得分率 | 一句话判读 |
|---|---|---|---|
| 功能完善性 | 11.72/20 | 59% | 引擎面是真短板：SQL 无窗口函数、透视单字段、图表无列映射 |
| 可用性 | 10.67/20 | 53% | 结果区钉高 + 首屏外是家族病，P0 与两处硬伤级 P1 全落此维 |
| 实用价值 | 12.67/15 | **85%** | 全分类最强项——选题全部命中真实数据工作流 |
| 交互便捷性 | 10.39/15 | 69% | computed 实时重算是亮点（dedupe/pivot/excel-to-csv 零按钮）；multiple select 需 Ctrl+点击三处（compare/dedupe），触屏不可用 |
| UI 美观性 | 6.94/10 | 69% | 家族风格统一；epub-reader 白底亮块刺眼暗色模式、长键撑破透视表 |
| 灵魂度 | 6.00/20 | **30%** | **全站已评估分类最低**——无示例数据、无统计卡、静默改数据不披露 |
| 附加：大文件性能 | 5.44/10 | — | 主线程解析/加密/全量渲染三宗罪，全家族几乎无一处进度条 |
| 附加：移动端 | 5.72/10 | — | multiple select 触屏不可用、宽表/小窗在窄屏更挤 |

- **结构性结论：实用价值率 85% ≫ 可用性率 53% ≫ 灵魂度率 30%**——"会算、看不见、不敢信"：失分不在算错，而在算完钉在小窗里（钉高）、看不全（截断无披露）、不敢信（静默归 0/口径不符）。

## 二、表格高度谱系与弹性化方案（一处 table-wrap 改造惠及全家族）

- **同族多值谱系（审计底稿 §一-2 点名 data 分类行 + 全局值）**：SqlQuery 错误区 **96px**（SqlQuery.vue:303）｜ParquetViewer schema **160px**（:132）｜CsvToExcel 预览 **260px**（:100）｜CsvDedupe 结果 **300px**（:78）｜SqliteViewer 表列表 **380px**（:220）｜ExcelViewer 表格 **460px**（:122）｜全局 `.table-wrap` **520px**（base.css:362-367，csv-viewer/excel-to-csv/compare/DataStudio 数据表共享）——**同是"数据表格"这一种东西，一个分类内 7 种钉值**；计入档案另载的 SqlQuery 编辑框 140、ZipPassword 列表 320、SqlPreviewTable 340、DataStudio ChartPanel 400、EmlViewer 正文 480、EpubReader 阅读 600，数据工具内共出现 **13 种钉高取值**（96~600px），无一致性可言（共性-根因 2 最重灾区）。实测后果见 M-16：csv-viewer 表格 top=648 首屏外、520px 窗内 41 行数据同屏仅 ~13 行。
- **两层弹性化方案**：
  1. **全局一层（一处改动惠及 4+ 工具）**：`.table-wrap` 改弹性——`max-height: calc(100vh - 340px)` + `min-height: 480px`，csv-viewer、excel-to-csv、compare-csv-files、DataStudio DataTablePanel 四处共享该类的钉高同时解套，M-16 场景验收"41 行同屏 ≥25 行"。
  2. **本地一层（六处套同一公式）**：本地钉值统一替换为各档案处方已给定的 `min(420~480px, calc(100vh - Npx))` 模式（SqlQuery 编辑框 `min(280px,…)`、schema/错误等辅助区 240~320px 弹性）——公式一致后，新工具不再发明第 14 种取值。
- **连带收益**：表格预览家族均分 58.5、转换家族 57.8、分析家族 59.4 中所有触"钉高"扣分项的档案，可用性得分率（现 53%）预计一次性抬升；query-csv 与 merge-csv 两处硬伤级 P1 的"小窗"部分同步解套（merge 的全量渲染冻结另需护栏，见§五）。

## 三、七维共性病灶 Top3

1. **灵魂度 30%（6.00/20，全站最低）——"静默与隐瞒"是数据工具特有病灶**：①静默改数据：excel-pivot 与 chart-from-csv 非数值 parseFloat 失败按 0 计（PivotTable.vue:97-98 / ChartFromCsv.vue:64-66）、remove-duplicates "忽略首尾空格"实做连续空白归一（csvEngine.ts:151）、compare-csv 重复键 Map 静默合并（csvEngine.ts:249-250）——脚本"静默/无披露"关键词命中 8/18 份档案；②截断不告知：compare 三类差异表 slice(0,200) 零披露（:142,155,168）、CsvDedupe 50 行、csv-to-excel 无"已显示 N/全部"；③空态无示例数据（pivot/data-analysis/zip 均无，chart-from-csv 反而有"载入示例"）。对照家族内已有金标准：excel-to-csv"仅预览前 50 行，导出包含全部 N 行"（:109-111）、parquet-to-csv 能力声明 notice（:109-112）——补披露是抄自家兄弟，不是新能力。
2. **可用性 53%（10.67/20）——钉高 + 首屏外 + 输入区挤压三件套**：结果区钉高谱系见§二；M-16 实测表格首屏外；输入侧同样挤压——SqlQuery 编辑框 140px+错误区 96px（20 行 JOIN 只见 5~6 行）、SqliteViewer SQL 是单行 `<input>`（:164，多行查询粘贴即压平）、ChartFromCsv 输入 150px。叠加共性-根因 4：excel-to-csv 下载按钮在流内底部（:114-119）。
3. **大文件性能 5.44/10——全家族主线程同步 + 零进度**：PapaParse 主线程解析（csvEngine.ts:61-63）、xlsx 全量读入（officeEngine）、zip 加密 `useWebWorkers:false`（ZipPassword.vue:28）、merge"显示全部"全量进 DOM（:55）、pivot 每格重算聚合 O(n²)（:106-126）。唯一进度亮点是 epub-converter 逐章进度（:66）。而 PapaParse 原生支持 `worker:true`、zip.js 支持路径配置——多数是"接了就有"。

## 五、P0 与疑似缺陷清单（只记录不修复，交用户决定）

**P0（1 项）**

1. **csv-viewer（58）**：表格 top=648 首屏外 + table-wrap 520px 钉死，同屏仅 ~13 行（M-16）——"查看器看不见查看结果"。处方 8 条齐备（解析后 scrollIntoView、弹性高度、输入区折叠、列统计、搜索高亮、原始行号…）。

**硬伤级 P1（档案自评"硬伤级"，整改建议按 P0 对待）**

2. **query-csv-with-sql（63）**：SQL 编辑框 140px + 错误区 96px（SqlQuery.vue:224,303）——分类最高分工具的核心编辑区反而是全分类最小窗，与"写 SQL"定位直接冲突。
3. **merge-csv-files（58）**："显示全部 N 行"全量进 DOM（:55），10 万行确定性冻结；再次拖放整体替换（:48），补第 3 个文件必须全部重来。

**疑似缺陷 / 口径问题**

4. **data-analysis-tool Parquet 失信**：registry desc 承诺"打开 Parquet"（registry.ts:12），但 FileDrop accept 无 .parquet（DataStudio.vue:103）且装载函数无分支（dataShared.ts:12-42）——拖入即按文本解析报错；同款承诺在编辑器区 data-studio 双注册（editors/registry.ts:8）需两处同修。修 desc 或补 hyparquet 装载二选一（后者路径已由 parquet-to-csv 验证可行）。
5. **parquet-to-csv needModel 矛盾**：registry 标 `needModel: true`（registry.ts:16），组件 notice 却写"纯 JS 无需下载任何模型"（:111）——UI 可能出现多余下载提示，属注册口径问题。
6. **compare-csv-files 截断零披露 + 重复键静默合并**：三类差异表 slice(0,200) 无提示（:142,155,168），徽章"新增 300"表里只有 200；主键不唯一时 Map 合并使对比结果不可信（csvEngine.ts:249-250）。
7. **非数值静默按 0 计两处**：excel-pivot-table-online（PivotTable.vue:97-98）、chart-from-csv（:64-66）——缺失数据与真 0 混同，均值/求和被污染且无提示。
8. **remove-duplicates trim 口径不符**：开关标签"忽略首尾空格"，引擎实做"所有连续空白归一"（csvEngine.ts:151），"A␣␣B"与"A␣B"被判重且口径未披露。
9. **epub-converter 反向双雷**：GBK 编码 TXT（中文网文最大存量）以 UTF-8 直读即乱码（file.text()，:111）；章节正则不认英文"Chapter 1"（fileExt.ts:382），英文书整本变单章且无阈值预警。
10. **zip-password 安全弱化**：密码下限仅 4 位无强度警示（:45-47）——对 AES-256 形同虚设；解压错误"密码错误或文件已损坏"二合一文案（:125,152）。
11. **chart-from-csv desc 滞后**：注册 desc 只写"柱状、折线或饼图"（registry.ts:8），实现另有环形第四种（:29）——搜索命中面缩水。
12. **sqlite-viewer 单行 SQL input**（:164）：粘贴含换行的多行查询被压平，连 140px textarea 的 SqlQuery 都不如。

## 六、阉割与合并建议

1. **数据预览工作台（核心愿景）**：csv-viewer / excel-viewer / sqlite-viewer / parquet-to-csv 的"表格呈现 + 分页 + 搜索 + 单元格复制 + 导出"应共享一个 DataTable 组件——excel-viewer 的"加载更多 + 点击复制"（:108,:98）与 SqlPreviewTable 的 NULL/BLOB 格式化已是雏形，以 excel-viewer 路径为基座；各格式只保留装载器（Papa / SheetJS / sql.js / hyparquet）。收益：弹性高度、列统计、搜索、导出一处实现四处受益，§二全局弹性方案顺势落地。
2. **分析入口收敛**：透视双实现收敛为单实现（以 excel-pivot-table-online 的 PivotTable.vue:56-134 为基座，DataStudio.PivotPanel 改为引用，避免复制粘贴漂移）；SQL 双入口共享表结构面板与导出链路（SqlQuery 全功能档 ↔ SqlPanel 简版分档明示）；远期 query-csv / pivot / chart 并入 data-analysis-tool 成唯一分析入口——前置欠账是 Tab 状态保持（v-show）与"结果即新数据集"。
3. **zip-password IA 分流**：解压半边与 archive-extractor（实用工具 57 分，多格式 + 支持密码包）重叠且两工具零互链（registry 互检确认）——建议本工具聚焦"加密打包"、解压需求引导跳转 /t/archive-extractor（或反向分流，交用户决策）。
4. **对称缺口互链闭环（不裁撤）**：csv-to-excel ↔ excel-to-csv 呈精确对称缺口（对方缺分隔符选择、本方缺编码选择），两档案处方合并即闭环，各补一个 select + 底部互链；split ↔ merge、merge ↔ compare 同理互链组"CSV 拆合比对工作台"。
5. **电子书工作台**：epub-converter ↔ epub-reader 互链（转完即读）；epub-reader 先补进度记忆/键盘翻页/夜间主题三件接线题再谈合并。
6. **不建议合并**：sqlite-viewer 与 query-csv（sql.js 与 alasql 引擎不同，只共享表格组件）；eml-viewer（取证场景独立价值）；parquet-to-csv（稀缺能力，保留独立入口）。

## 八、分类优化路线图

- **第一周（还债：钉高与失信）**：①全局 `.table-wrap` 弹性化（§二方案，一处 CSS 解四工具）+ csv-viewer 解析后 scrollIntoView/输入区折叠 → P0 解套；②三处"承诺与实现不符"修正二选一（data-analysis Parquet 补 hyparquet 装载或删 desc、parquet-to-csv needModel 复核、chart desc 补环形图）；③对称缺口两个 select（分隔符/编码）。验收：M-16 场景复测 41 行同屏 ≥25 行。
- **第一个月（销号：接线与披露）**：§四倒挂清单逐项接线（chart 列映射移植 ChartPanel 现成实现、sqlite 导出复用 rowsToCsv 路径、eml 原始头折叠面板、FileDrop 管理接入 merge、epub-reader relocated/键盘/主题）；§五疑似缺陷清单交用户裁决后修复并回归；chip 选键三处（compare/dedupe）；弱密码警示；PapaParse worker:true 与 zip.js worker 开启。
- **一季度（收敛：信息架构）**：数据预览工作台共享 DataTable 组件（§六-1）；透视收敛单实现；六处互链补全（csv↔excel、split↔merge、merge↔compare、zip↔archive、epub↔reader、dedupe↔text 去重跨分类）；SQL/pivot 双入口分档披露。
- **半年（工作台化）**：data-analysis-tool 补 Tab 状态保持、结果即数据集、清洗 Tab、示例数据后升为唯一分析入口；DuckDB WASM 双引擎分档评估（懒加载约 5MB，严守懒加载纪律）；epub 书内搜索。
- **不做清单（防过度工程）**：不追云端协作与实时共享（Google Sheets 级）；不做桌面级百万行虚拟滚动；不做图形化 ETL；样式统一走 tokens.css/base.css 既有体系，不新增第 14 种钉高取值。
- **量化目标**：分类均分 58.39 → 67+，P0 清零、<55 分项清零、55~59 带清空过半，灵魂度得分率 30% → 45%+，附加性能维 5.44 → 7+。
- **复算口径**：全部计数（均分/分数段/优先级/家族均分/关键词命中）可由 `docs/优化文档/_scripts/data-extract.json` 复算（query-csv-with-sql 按 63 计入）；单工具证据以各档案 file:line 与实测锚点 M-16 为准，共性判定以 `_布局审计底稿.md` 五条根因为准。
