## 扣分点明细

1. 【功能】无原始邮件头视图（postal-mime 已返回 header 列表却未展示，Message-ID/Received-SPF 是取证关键信息）——eml.tools 类工具的标配
2. 【可用性】HTML 正文 iframe 480px（`EmlViewer.vue:179-183`）+ 纯文本 pre 480px（:193 max-height）双钉高（共性-根因 2）；无"新窗口打开/全屏"出口，长 newsletter 只能小窗滚
3. 【交互】日期字段直接渲染 Date.toString()（:97）——"Mon Nov 11 2025 14:30:00 GMT+0800"英文长串，未本地化格式化（对比头部其他字段均为人工可读中文语境）
4. 【功能】附件无大小显示（postal-mime attachment.size 可用而未用，按钮只有文件名 :101-103）、无"全部下载"（多附件邮件要逐个点）、下载失败 toast 无具体附件名
5. 【可用性】解析超大邮件（50MB 附件级）无进度与预警（:86 仅 spinner 文案）；.msg 拒载发生在解析前✓但拖错文件后 FileDrop 状态不回显失败原因（只 toast 一闪）
6. 【灵魂】无邮件正文关键字搜索；无"查看纯文本/HTML 切换"（两种呈现互斥，:108-112 有 HTML 即不显示 text——文本版更适合复制引用）
7. 【美观】暗色模式下 iframe 白底与外框生硬相接；头部卡片无发件人头像/首字母占位
8. 【功能】无打印/另存 PDF 出口——取证留档的自然终点是"原样存一份"，当前只能截图

## 行业对标与差距

- **eml.tools / mailbody 类**：原始头折叠面板、HTML/纯文本双视图切换、附件批量下载、打印/另存 PDF。差距：**取证视图与批量操作**。
- **Outlook Web 阅读窗**：附件卡片带类型图标+大小、日期相对化（今天 14:30）。差距：附件呈现与日期本地化。
- 借鉴优先级：**原始头面板 > 日期本地化 > 附件大小+全部下载 > 文本/HTML 切换**。

## 可拓展性

- 短期（1 周）：日期格式化（Intl.DateTimeFormat zh-CN）；附件按钮附大小；"下载全部附件"
- 中期（1 月）：原始头折叠面板（postal-mime headers 全量渲染，等宽字体）；文本/HTML Tab 切换；正文区高度 `min(64vh, 640px)` + 新窗口打开
- 远期：多封 .eml 批量导入列表化浏览；另存 PDF（正文截图式渲染，复用站内 html-to-image 能力）

## 优化处方（验收标准）

1. **日期本地化**：日期字段用 `YYYY-MM-DD HH:mm` 中文格式。→ **验收：头部显示"2025-11-11 14:30"而非英文长串**
2. **原始头面板**：头部卡片底部"展开原始头"折叠区渲染全部 header。→ **验收：展开后可见 Message-ID 与 Received 行，等宽字体可复制**
3. **附件增强**：按钮显示"文件名 (128 KB)"，标题行加"全部下载"。→ **验收：3 附件邮件一键得到 3 个文件**
4. **正文弹性**：iframe 高度 `min(64vh, 640px)` 并提供"新窗口打开"链接。→ **验收：1366×768 下正文区 ≥490px 且新窗口可滚动阅读全文**
5. **文本视图**：HTML/纯文本 Tab 切换。→ **验收：有 HTML 的邮件也能切到 text 视图并选中复制**
6. **打印留档**：头部+正文区加"打印/另存 PDF"按钮（window.print 局部样式）。→ **验收：打印预览仅含邮件卡片不含站头侧栏**
