## 结论与优先级

**交互优化 + 需拓展** · P1（补多字段/筛选/热力是标杆级缺口；静默归 0 是正确性问题）

判据：单行键×单列键的模型上限明显（Excel 透视表最基础的多层行标签即缺），标"需拓展"；非数值归 0 无披露属可用性。

## 扣分点明细

1. 【功能-代差】行/列/值三区各只支持 1 个字段（`PivotTable.vue:15-18`）——Excel/PivotTable.js 的"多层行标签""多值字段并排"全缺，复合维度分析做不了
2. 【数据正确性】值列 parseFloat 失败静默归 0（:97-98）——把"缺失数据"与"真 0"混为一谈，平均值/求和被污染且无提示
3. 【功能】无筛选：不能先过滤"仅 2024 年数据"再透视；无维度值排序（rowKeys 按出现序 :83-100）， alphabetical/数值排序都不可选
4. 【可用性】行键/列基数无护栏：类别列 1000+ 取值时生成千行×千列表格卡死浏览器，无预警无截断
5. 【交互】无拖拽——PivotTable.js 的核心交互即拖字段入区，select 下拉在字段多时效率低（可接受但需以"字段 chip 分区"补偿）
6. 【灵魂】无示例数据（空态只有"载入数据后开始配置透视表" :241-245）；热力着色/条件格式（Excel 色阶）缺失，结果可读性靠裸数字
7. 【美观】长键值无 ellipsis/换行策略（:224-233），一个长类目即把整列撑爆

## 行业对标与差距

- **PivotTable.js demo**：字段拖拽分区、多行/列/值字段、多聚合器并排、热力图渲染器、CSV/T SV 导出。差距：**多字段模型与渲染器选择**。
- **Excel 数据透视表**：值"显示方式"（占比/差异/累计）、切片器、分组。差距：占比类衍生指标（求和占比是运营周报刚需）。
- 借鉴优先级：**多字段行/列 > 值占比显示方式 > 基数护栏 > 热力着色**。

## 可拓展性

- 短期（1 周）：非数值披露（toast/notice"N 个非数值按 0 计"）；行键数超 200 时截断+提示；示例数据按钮
- 中期（1 月）：行/列多选字段（嵌套键）；值排序 select；求和占比显示方式
- 远期：并入 data-analysis-tool 透视 Tab 的强化版（两处透视逻辑为复制粘贴维护，`PivotPanel.vue:22-81` 与本组件 :56-134 几乎同码）——收敛单一实现
- 注意：与 DataStudio.PivotPanel 代码重复，收敛时应以本组件为基座

## 优化处方（验收标准）

1. **非数值披露**：载入后检测值列非数值率，>0 时显示"N 个非数值项按 0 计入"notice。→ **验收：含空值的列透视后 notice 出现且数字准确**
2. **基数护栏**：行/列键超 200 截断并提示"仅显示前 200 个组合（共 N）"。→ **验收：1000 类目列只渲染 200 行且表格流畅**
3. **多行字段**：行字段支持多选（嵌套缩进）。→ **验收：省+市两字段透视出两级行标签，合计逐级正确**
4. **占比显示**：聚合方式新增"求和占比（行/列/总计）"。→ **验收：每单元格显示百分比且列合计=100%**
5. **热力着色**：开关"色阶"后单元格按值深浅着色。→ **验收：开关即时生效且导出 xlsx 不含底色（或披露仅网页生效）**
