## 结论与优先级

**交互优化** · P1（"导出只是前 500 行"必须让用户无法误读；schema 区弹性化）

判据：转换类工具的输出范围歧义属可用性问题（用户以为转了整个文件）；160px schema 钉高（共性-根因 2 家族点名）加重误读。

## 扣分点明细

1. 【可用性-歧义】"表格仅预览前 100 行，导出包含全部 {{ rows.length }} 行"（`ParquetViewer.vue:147`）——rows.length≤500，**导出永远不是完整文件**但措辞让用户以为全量；徽章"最多预览 500"（:123）未与导出按钮关联说明
2. 【可用性】schema 区 `max-height:160px`（:132，审计底稿点名）——几十列 schema 要在 160px 窗口里滚屏
3. 【功能】无文件总行数/行组数展示（footer metadata 可算总行数却未读出，hyparquet parquetMetadataAsync 已在用 :50）——"这个 parquet 有多大"是打开文件第一问
4. 【功能】无列选择：宽表（100+ 列）只想看 5 列做不到，导出也只能全列
5. 【功能】编码支持窄且无扩展路径：gzip/brotli 压缩块直接失败（:74-76 只能报错），spark 写出的默认 gzip parquet 无法打开
6. 【交互】解析无进度/耗时；500 行截断无法换页看后续行（无 offset 跳读）
7. 【注册口径】registry.ts:16 标 `needModel: true`，但 hyparquet 纯 JS 免下载——与组件 notice"无需下载任何模型"（:111）自相矛盾，UI 可能出现多余下载提示（疑似注册口径问题，交用户决定）
8. 【功能】单文件入口：parquet 数据集普遍分片存储（part-0001/0002…），只能逐个拖入逐个导出，无多文件批量合并导出

## 行业对标与差距

- **DuckDB WASM shell**：完整 Parquet 读取（全编码）、SQL 过滤投影下推、总行数即时统计。差距：**读数能力代差**（架构性，hyparquet 上限；诚实标注后可先补总行数）。
- **parquet-viewer 类在线工具**：schema 树可折叠、列显隐。差距：schema 呈现与列控制。
- 借鉴优先级：**总行数披露 > 导出范围明示 > schema 弹性 > 列选择**。

## 可拓展性

- 短期（1 周）：导出按钮旁明示"仅前 500 行"；schema pre 高度改 `min(320px, calc(100vh - 560px))`；从 metadata 读总行数显示
- 中期（1 月）：offset 分页读取（rowStart/rowEnd 翻页）；列选择（parquetRead 支持 column 下推则用，否则读后过滤）；needModel 注册项复核
- 远期：gzip/brotli 解码路径（DecompressionStream 原生 API 可试）；与 DuckDB WASM 分档双引擎（5MB 懒加载，注意懒加载纪律）

## 优化处方（验收标准）

1. **导出范围明示**：导出按钮组上方固定显示"本工具仅读取前 500 行，导出即这 500 行"。→ **验收：文案常驻且在导出按钮视线范围内**
2. **总行数**：读取 metadata 显示"文件共 N 行（已载入前 500）"。→ **验收：构造 5000 行文件显示共 5000 行**
3. **schema 弹性**：pre 高度 `min(320px, calc(100vh - 560px))`。→ **验收：1366×768 下 30 列 schema 同屏可见 ≥15 列**
4. **分页读取**：表格上方"载入后续 500 行"按钮（offset 累进）。→ **验收：5000 行文件可连续读到第 1500 行**
5. **注册口径**：needModel 复核为 false 或提示文案与 hyparquet 实际一致。→ **验收：工具页不再出现"需下载模型"类提示**
6. **批量入口**：FileDrop 开 multiple，多分片合并导出为一个 CSV。→ **验收：拖入 3 个同 schema 分片后导出单文件含全部行**
