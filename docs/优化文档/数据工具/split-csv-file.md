## 结论与优先级

**交互优化** · P2（预览先行是分类亮点，补表头开关与统计卡）

判据：无硬伤；表头处理是数据正确性风险点，优先补齐。

## 扣分点明细

1. 【功能·数据正确性】按行数拆分时每片是否带表头行无开关无披露（`splitCsv` 引擎行为 UI 不说明）——下游拼回时表头混入数据
2. 【功能】无按目标体积拆分（邮件 25MB 限制场景）——站内 PDF 家族 split-pdf-by-size.md 已示范"逐页实测+贪心打包"的严谨做法，CSV 侧空缺
3. 【灵魂】无统计卡：拆分前看不到"将生成 N 片/每片约 X 行/预计总体积"
4. 【交互】大文件解析（parseCsvAsync）无进度百分比；拆分+zip 无进度（100 万行秒级冻结）
5. 【灵魂】与 merge-csv-files 零互链（拆分↔合并是同一工作流的两半）；输出文件名规则（原名_001？）未披露

## 行业对标与差距

- **csvsplit.net**：按行/按大小/按列三模式 + 表头开关。差距：**体积模式与表头开关**。
- **站内 split-pdf-by-size**（65 分）：逐单元实测体积+贪心打包+确定性达标。差距：同款严谨度未移植到 CSV。
- 借鉴优先级：**表头开关 > 按体积拆分（移植 PDF 家族算法）> 统计卡 > 进度条**。

## 可拓展性

- 短期：加"每片包含表头"开关（默认开）并在结果列表注明；文件名规则披露
- 中期：按体积拆分（移植 split-pdf-by-size 的实测+贪心思路：抽样估算每行均重）；统计卡
- 远期：与 merge-csv-files 组"CSV 拆合工作台"；worker 化拆分（懒加载纪律）

## 优化处方（验收标准）

1. **表头开关**：新增"每片包含表头行"checkbox（默认开）。→ **验收：关掉后第 2 片起首行是数据行；开启后每片首行与原表头一致**
2. **统计卡**：选择模式后实时显示"将生成 N 片 · 每片 ≤ X 行"。→ **验收：10001 行设 5000 行/片显示 3 片**
3. **按体积拆分**：新增"按大小"模式（目标 MB），抽样估算行重贪心分组。→ **验收：50MB CSV 按 10MB 拆出 5~6 片且各片 ≤ 11MB**
4. **进度条**：解析与打包阶段显示百分比进度条（复用 FileDrop/6px 进度家族样式升级版）。→ **验收：100 万行拆分全程有进度反馈不冻结提示**
