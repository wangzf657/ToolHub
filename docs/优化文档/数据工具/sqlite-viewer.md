## 结论与优先级

**交互优化 + 需拓展** · P1（导出是能力缺口标拓展；SQL 输入与高度钉死标交互）

判据：查看器"只能看不能取"（无导出）与标杆 sqlime 的 schema+导出组合有明显能力差距；单行 input 直接限制复杂查询可用性。

## 扣分点明细

1. 【功能-缺口】查询结果与表数据均无导出（`SqlPreviewTable.vue` 全文无下载逻辑）——"打开 db 抽张表出来"这一主场景断在最后一步；站内 query-csv-with-sql（63 分档案）同分类已有 CSV 导出，能力倒挂
2. 【可用性】SQL 输入是单行 `<input>`（`SqliteViewer.vue:164`）——粘贴含换行的多行查询被压平，JOIN/子查询书写体验受限；对照 SqlQuery 用 textarea（140px）尚且被档案点名
3. 【可用性】表列表 380px 钉高（:220，审计底稿点名）+ 结构表 180px（:177）+ 数据表 340px 三窗叠放，1366×768 下主数据区折叠线以下
4. 【功能】侧栏无行数/无视图与索引：sqlite_master 只筛 table（:62），VIEW 不显示；点表前不知道行数（要 SELECT count 自查）
5. 【功能】无分页：每表固定前 200 行（:92）、查询固定 500 行（:129），第 201 行起"不存在"，且 LIMIT 上限在结果区无披露（仅 chip"前 N 行" :172）
6. 【交互】无查询历史（localStorage）；错误信息原始 sqlite 消息直出，无中文翻译层
7. 【灵魂】无 schema 关系图/外键标注（PRAGMA foreign_key_list 未用）；打开后无"库大小/引擎版本"元信息卡
8. 【功能】结构表只有列名/类型/非空/主键四列（:97-103），缺默认值与外键列（PRAGMA 返回里 dflt_value 已有未取），排查约束仍需手写 SQL

## 行业对标与差距

- **sqliteviewer.app**：表结构树+行分页浏览。差距：分页与结构呈现方式（对方 schema 折叠树更省空间）。
- **sqlime.org**：schema 面板+查询历史+结果导出 CSV/JSON+自动补全。差距：**导出与历史**。
- 借鉴优先级：**结果导出 CSV > 多行 SQL textarea > 行数披露 > 分页 > 查询历史**。

## 可拓展性

- 短期（1 周）：结果区加"下载 CSV"（复用 SqlQuery 的 rowsToCsv 路径）；input 换 textarea（3 行起可拖高）；表 chip 显示行数（点表时 count(*)）
- 中期（1 月）：SELECT 分页（OFFSET 续读）；侧栏加视图与行数徽标；查询历史 chips（最近 10 条）
- 远期：外键关系面板（foreign_key_list 可视化）；大库 OPFS/流式方案评估（sql.js 内存上限的架构性绕行）

## 优化处方（验收标准）

1. **结果导出**：数据预览区标题行加"下载 CSV"。→ **验收：任意表前 200 行可导出为带 BOM 的 CSV，Excel 打开中文正常**
2. **多行 SQL**：input 改 textarea（min 2 行，可拖拽）。→ **验收：粘贴 5 行 JOIN 语句结构完整不被压平，回车改为 Ctrl+Enter 执行**
3. **行数披露**：点表后 chip 显示"共 N 行（预览前 200）"。→ **验收：1000 行表显示共 1000 行**
4. **高度重排**：结构表默认折叠（点击展开），数据表高度 `min(420px, calc(100vh - 480px))`。→ **验收：1366×768 下点开表后数据区首屏完整可见 ≥12 行**
5. **视图支持**：侧栏列出 VIEW 并标注类型。→ **验收：含视图的库侧栏出现视图名，点击可查询**
6. **结构增强**：结构表补默认值列。→ **验收：含 DEFAULT 值的表结构显示该默认值**
