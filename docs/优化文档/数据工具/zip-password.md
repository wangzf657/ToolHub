## 扣分点明细

1. 【可用性-安全弱化】密码策略仅"至少 4 位"（`ZipPassword.vue:45-47`）无强度反馈——4 位纯数字密码对 AES-256 加密形同虚设，工具应警示"弱密码使加密失去意义"（加密工具的安全提示义务）
2. 【站内重复】解压模式与 archive-extractor 重叠（对方 desc 明确"支持密码加密包"且多格式 7z/rar）——两工具零互链（registry 互检确认），用户从"加密打包"完成后的自然下一步"对方怎么解"无引导
3. 【可用性】打包侧无文件明细：只有计数 chip（:187），看不到每个文件名/大小/总体积，误拖大文件无预警；打包完成 zip 命名规则（首文件名 :64）未披露
4. 【性能】主线程加密（:28 useWebWorkers:false），GB 级文件无进度条 UI 冻结——zip.js 支持 worker（配置路径即可），当前为规避路径问题牺牲了体验
5. 【功能】无压缩等级选择（zip.js 支持 level），加密包默认是否压缩无披露——"加密后还有多大"用户不可控
6. 【交互】解压错误二合一文案（:125,152）——密码错与文件损坏区分开是排查第一步（zip.js 可按异常类型判断）
7. 【可用性】条目列表 320px 钉高（:243）+ 平铺无目录层级——深层目录包丢失结构感（filename 全路径平铺展示）
8. 【可用性】无目标体积预警：加密打包常为邮件附件服务，打包完成才发现超 25MB 限制；文件选完即显示总体积可提前分流

## 行业对标与差距

- **7-Zip / WinRAR**：密码强度无警示但压缩等级/加密算法（AES-256/ZipCrypto）可选、文件树平铺可切换、进度与取消。差距：**过程可控性**。
- **站内 archive-extractor**（57 分）：解压侧多格式+列表预览按需下载——同款交互本工具已复制，差异仅在加密支持；分流合并可减一个工具的维护面。
- 借鉴优先级：**密码强度警示 > 打包明细卡 > 进度条（开 worker）> 与 archive-extractor 互链/分流**。

## 可拓展性

- 短期（1 周）：密码框旁强度条（长度+字符种类三档）；打包前显示文件明细与总体积；与 archive-extractor 底部互链
- 中期（1 月）：开启 zip.js worker（locateFile 路径配置）+ 进度条（writer.add onprogress）；压缩等级 select；错误分流文案
- 远期：与 archive-extractor IA 整合（加密打包专属 + 通用解压归位）；AES-256 文件名加密选项（zip.js 支持 filename 加密元数据隐藏）

## 优化处方（验收标准）

1. **密码强度警示**：输入 4~6 位纯数字时显示红色"弱密码：建议 ≥8 位并混合字母"。→ **验收：输入 1234 出现警示，输入 12 个混合字符显示绿色**
2. **打包明细**：选文件后列出名称+大小+合计。→ **验收：3 文件打包前可见每项大小与总体积**
3. **进度反馈**：开启 worker 后打包/解压显示百分比进度条。→ **验收：500MB 打包期间进度条推进且输入框不冻结**
4. **错误分流**：解压失败区分"密码错误（可重试）"与"文件损坏/不支持的加密"。→ **验收：错密码提示重试、非 zip 文件提示格式不支持**
5. **互链**：解压模式空态加"无密码的压缩包？试试「在线解压」"链接。→ **验收：点击跳转 /t/archive-extractor**
6. **体积预警**：打包明细显示总体积，超 25MB 时提示"可能超过邮件附件限制"。→ **验收：拖入 30MB 文件后出现黄色提示**
