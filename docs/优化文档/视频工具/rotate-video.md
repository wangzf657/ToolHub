## 结论与优先级

## 扣分点明细

1. 【灵魂-口径硬伤】desc 与实现相反：desc"90/180/270° 旋转**写入元数据**，全设备正常播放"（registry.ts:14），实现是 transpose 滤镜+libx264 全量像素重编码（FfmpegRotate.vue:25-27）——用户带着"秒转无损"预期进来，面对的是 wasm 慢速重编码；页内 note（:52-55）诚实承认重编码，但入口文案的虚假承诺已先行伤害预期
2. 【功能-个性】元数据快路径缺位：旋转 90° 的专业做法是改 display matrix（秒级、零质量损失、不重编码），组件自己承认此路径存在（:53"只想改播放方向标记……可使用视频编辑器"）却不在本页提供开关——用户必须跳工具；需验证 wasm 构建是否支持 `-display_rotation`（ffmpeg 6.0+），不支持则可用纯 JS remux 改 rotation box
3. 【功能】音频无谓重编码：`-c:a aac -b:a 128k`（:27）——旋转与音轨无关，却每次解码再编码 AAC（音质损失+耗时），`-c:a copy` 应为默认
4. 【功能】质量/速度档缺位：crf23+veryfast 固定（:26），家族 compress-video 至少有三档质量；旋转素材若要二次剪辑，高码率档无处可寻
5. 【功能-疑似缺陷】竖拍源方向存疑：手机竖拍 MP4 带旋转标记，ffmpeg 输入端 autorotate（wasm 构建是否启用）决定 transpose 后是"转正"还是"叠加旋转"出 270° 结果——需用带旋转标记的夹具实测定性
6. 【灵魂-个性】无耗时预期：重编码耗时与 mute-video 的秒转差三个量级，页内却无任何"旋转需重新编码，耗时与视频时长相关"文案（对比 FfmpegMute.vue:20 的诚实示范）
7. 【可用性】无旋转后预览与方向预演：onDone 直接下载（FfBase.vue:135-138）；90 与 270 认知错位高发（"顺时针 270°=逆时针 90°"的文案自救，:12），选错只能下载后播放发现再重来
8. 【可用性-家族】执行按钮流内底部（FfBase.vue:199-206，M-14，共性-根因 4）；25MB 无下载进度、无 beforeunload（compress-video.md 扣分 4/5）

## loadVideo 门禁影响评估

源侧低风险：MP4/MOV（旋转工具的典型源）浏览器稳定解析，基本不挡门；带旋转标记的竖拍 MP4 元数据可正常读取（仅 autorotate 行为需实测，见扣分 5）。AVI/WMV 挡门但场景占比极小。输出侧无容器兼容性问题（重编码产物 H.264+AAC MP4 标准兼容）。

## 行业对标与差距

- **Clideo**（云）：Rotate 一键 + 在线预览旋转效果 + 输出格式可选。差距：**预览联动**（选角度即看效果）纯前端完全可做（canvas transform 预演）。
- **ezgif**：rotate 提供 90/180/270/flip 且"transpose（无损快速）"与重编码路径区分标注。差距：路径透明度——它告诉你哪个快哪个慢，我们入口承诺快实际慢。
- **FFmpeg 命令行**（同源参照）：`-display_rotation`（6.0+）秒转元数据；`-c:a copy` 常规操作。差距：我们没把同源引擎的专业选项暴露出来。
- 借鉴优先级：**desc 口径修正 > 元数据快路径 > 音频 copy > 预览联动 > 质量档**。

1. **desc 口径修正**：registry.ts:14 与落地页首屏不再出现"写入元数据"表述，或改为"元数据旋转（快速）+重编码旋转（兼容）"双选项文案。→ **验收：desc 描述与实际执行路径一致**
2. **元数据旋转选项**：新增"快速旋转（仅改方向标记，推荐）"默认项，命令含 display rotation 或 remux 改标记。→ **验收：90° 快速档 10 秒内完成且画质比特级一致；播放器显示方向正确**
3. **音频 copy**：命令串 `-c:a aac -b:a 128k` 改 `-c:a copy`（元数据档天然不动音轨）。→ **验收：产物音轨编码与源一致，处理时长下降**
4. **方向预演**：选择变换时预览区实时以 CSS transform 显示效果。→ **验收：点"顺时针 90°"后预览画面立即横竖切换，无需执行**
5. **竖拍夹具实测**：用带 rotation 标记的竖拍 MP4 实测 transpose 结果方向。→ **验收：重编码档产物在各播放器中方向正确，若出现叠加旋转则在命令串补偿（如 autorotate 关闭或反向 transpose）**
6. **家族处方 1-2**：按钮置顶＋耗时预期文案（compress-video.md 处方 1/2）
