## 结论与优先级

**交互优化 + 需拓展** · P1

判据：59 分；转换质量与自动执行是加分面，但"字幕格式转换"不认 ASS 等于缺席专业格式（Subtitle Edit 支持 200+ 字幕格式），且 180px 小窗处理长字幕违背可用性基线。

## 扣分点明细

1. 【功能-个性】无 ASS：desc 主打"SRT/WebVTT/SBV 互转"（registry.ts:37）未撒谎，但站内唯一免下载的转换器缺 ASS 互转，Aegisub 调轴→烧录的专业链路断头；stripCueStyling 已会剥 {\...} ASS 标签（subtitles.ts:133），说明引擎考虑过 ASS 却未实现解析/序列化
2. 【可用性】输出 ResultBox 钉死 180px（ResultBox.vue:69，调用方未传高），输入 textarea 全局 180px（base.css:164-168）——90 分钟电影字幕约 1500 条/100KB，同屏只见十几条
3. 【可用性-个性】解析失败静默：catch 后 cues=[]（:23-30），输出空白、下载灰掉，用户分不清格式坏了还是操作错了
4. 【功能-个性】平移钳制静默产生退化字幕：shiftCues 把 start 钳到 0、end 钳到 0.1（subtitles.ts:115-116）——整体前移超出片头的条目全挤在 0:00 附近互相重叠，无警告无剔除
5. 【功能-个性】拆分按字符硬切（subtitles.ts:171 plain.slice）会把英文单词切断；合并给中文行间插空格（subtitles.ts:144）——中文两条合并出"你好 世界"式空格
6. 【交互】无拖放：仅 label 包 input 的点击上传（:66-69），与站内文件工具 FileDrop 范式不一致
7. 【交互】帧率选项钉死五档（:112-129），无 60fps、无自定义输入；25↔23.976 这类真实修轴只能近似选档
8. 【功能】无逐条编辑：转换前想顺手改一条错字/时轴必须回 Aegisub，"转换"与"校对"割裂
9. 【灵魂】去样式默认勾选（doStrip=true :18）：SRT→SRT 原样往返也悄悄丢 <i> 斜体，默认值替用户做了主张且无提示

## 行业对标与差距

- **Subtitle Edit（在线版）**：200+ 格式互转、逐条列表编辑、错误检查（时间重叠/字幕过速）、字幕 OCR。差距：格式覆盖数量级差距；重叠/过速健康检查纯前端完全可做。
- **Aegisub**：音波对轴+全量 ASS 样式。差距：专业校对天花板，站内无需复刻但应打通 ASS 进出口。
- 借鉴优先级：**ASS 进出 > 解析失败报错 > 健康检查（重叠/速率）> 逐条编辑 > 拖放**。

## 优化处方（验收标准）

1. **输出区弹性高度**：ResultBox 传 320px 起并支持展开模式（json-formatter.md 处方 1 同款）。→ **验收：1366×768 下 1000 条 SRT 输出同屏可见 ≥25 条**
2. **解析报错+格式回显**：失败 toast 定位行号；成功后显示"识别为 VTT · 312 条"。→ **验收：粘 WEBVTT 显示识别结果；粘乱码显示报错**
3. **ASS 互转**：新增 ass 进/出，样式行按 doStrip 决定去留。→ **验收：Aegisub 导出的 ASS 转 SRT 再转回，时间轴无损（±1ms）**
4. **钳制警告**：shift 导致 N 条 start 被钳到 0 时提示"N 条字幕被挤到片头"。→ **验收：字幕整体 -400s 时出现警告**
5. **中文合并无空格**：mergeCues 相邻为 CJK 时直接拼接。→ **验收：两条中文合并后中间无空格**
