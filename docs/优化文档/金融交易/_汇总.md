# 金融交易分类汇总（20 项）

> 依据：`金融交易/` 20 份工具档案（结构化字段经 `_scripts/finance-extract.mjs` 提取核对）＋ `_布局审计底稿.md` ＋ `_实测锚点.md`。只评估、只开处方，不改任何业务代码；疑似缺陷交用户决定。

## 一、总览

- **形态**：14 项 calcDef（模式 B，`CalcTool.vue` 117 行共用壳）＋ 6 项自定义变体（OptionsPayoff 268 行 / PortfolioRebalance 202 / StockAverage 195 / DividendCalculator 177 / SharpeRatio 166 / IrrNpvCalculator 153）。全分类零执行按钮（watch 自动重算是家族公约数，也是可用性基本盘）。
- **分数**：均分 **61.8 / 100**（区间 54~67）。Top3：installment-rate **67**、options-payoff **66**、black-scholes **65**；垫底：forex-pip **54**、bond-ytm 58、cagr 58。定级 **P1×19、P2×1**（cagr），**正式 P0=0**，但疑似功能缺陷 **5 例**（第五节）建议按 P0 优先处置。
- **维度失分率**（加权五维）：灵魂度 9.3/20（**46.5%，全分类最差维**）＜ 功能 11.3/20（56.5%）＜ 可用性 12.6/20（63%）＜ 交互 9.9/15（66%）＜ UI 7.2/10（72%）＜ 实用 11.7/15（78%）；附加维移动端 6.6/10 同为全站低位。**"算得对"普遍及格、"懂用户"普遍缺席**：引擎层扎实（finance.ts 牛顿+二分、IRR/MIRR 双算法），败在空态引导、图表缺位、术语教育与互链断裂。
- **家族共性病**：无输入记忆（20 项仅 StockAverage.vue:42-64 有 localStorage 实践）、结果不可单值复制（CalcTool.vue:55-66 仅展示）、20 项仅 2 项有图、同参工具零互链（entry/stop 手动抄）。四项病根都在 calcDef 壳层，修一次全家族受益。

## 三、口径纪律专项（note 违规 2 例 vs 正面样板 3 例）

- **违规 2 例**（AGENTS.md"金融工具需附计算口径"硬要求，registry.ts 实测 14 个 calcDef 仅 12 个带 note）：**crypto-profit**（双边费口径只能靠 hint 侧写，registry.ts:22-57 无 note）、**risk-reward**（保本胜率/EV 两条决策口径未披露，registry.ts:241-270 无 note）。两份档案均已备好可直接粘贴的 note 文案与验收标准。
- **正面样板 3 例对照**：① **installment-rate 67（全站样板）**：note 四要素齐——计费方式（全额计收）＋摊还结构（本金等额摊还）＋折算方法（IRR 年化）＋免责边界（以账单为准，registry.ts:363），配 hint"每期手续费 ¥X（**不随本金递减**）"（:357）点破认知差；② **fire 63**：假设来源披露"4% 提取率源自三一学院研究，并非保证"（:175）＋80 年兜底行动建议（:170-171）；③ **black-scholes 65**：模型假设披露完整（:230），仅缺"仅适用欧式"边界一句。
- **installment IRR 口径拆解**（可作全站金融 note 模板）：installmentIrr（finance.ts:247-264）复用 irr 牛顿+二分双保险（:192-225），现金流=期初 −本金、每期 −(本金/期数＋手续费)，解出月 IRR×12 即真实年化；note 把"月费率 0.6%×12≈名义 7.2%、真实年化≈13%"的认知差直写给用户。**四要素句式（怎么收/怎么还/怎么折/以什么为准）应反哺**：违规 2 例＋简化未披露 4 例（position-size 未提佣金滑点、renovation 未提分批放款、bond-ytm 未提净价/全价、balloon 近似未给误差量级）。

## 四、空态失守清单（NaN 守卫不拦 0 的四类错误财务结论）

`CalcTool.vue:25-28` 守卫只拦结果字符串含 NaN/Infinity，**拦不住 0 值路径与越界值**——四类"数学合法、财务荒谬"的输出正占据首屏：

| 类型 | 工具 | 触发路径 | 错误结论 |
|---|---|---|---|
| 零值型 | sip 59 | monthly 空 → Number('')=0 | 到期总值/本金/收益三行 ¥0.00 |
| 零值型 | crypto-profit 60 | buy/qty 空 | 持币 0.000000、保本卖出价 ¥0.00 照常展示 |
| 零值型 | cagr 58 | begin=0 → 引擎返回 0（finance.ts:117） | CAGR 0.00%，"无法计算"混为"没增长" |
| 零值型 | options-payoff 66 | qty 手输 0（HTML min=1 可绕过） | 图表平线、最大盈亏 $0.00 无提示 |
| 0 年型 | fire 63 | 三字段空 → target=0、while 不进入 | 「预计达成时间 **0 年后**」＋¥0.00 目标 primary |
| 100% 型 | risk-reward 61 | 四字段空 → risk=0、rr=0 | 盈亏比 1:0.00、**保本胜率 100.0%**（"零风险"方向性误导） |
| 无界型（Infinity 跑道） | kelly 61 | 胜率填 120；ratio 填 0 被 `\|\|1` 静默改写 | **下注比例 108.33% 照常展示**，守卫与语义边界双双缺位 |
| 无界型 | position-size 63 | 止损极近 → 股数剧增 | 占账户比例 >100% 无"需杠杆"预警 |

- **对照样板（black-scholes 65）**：守卫点名具体字段——"请填写标的现价、行权价、期限、无风险利率与波动率"（registry.ts:215-217），档案评为家族最佳空态。
- **统一处方**：8 个失守工具的档案均已给出"请填写 X"守卫文案＋预填示例（sip 2000 / kelly 55·1.5 / risk-reward 25.5·24·30·55 / crypto 30000·33000·0.5·0.1% / bond-ytm 950·1000·3.5·5），照单实施即可，零设计成本。

## 六、家族整合愿景（从散装计算器到三个工作台）

- **现状**：20 份档案合计出现"互链"36 处，**全部是处方而非现状**——同参工具靠用户手动抄数。
- **贷款六兄弟**（utility loan:42 / mortgage:66 / amortization:1189 ＋ 金融 auto:372 / renovation:413 / balloon:453）：loan/mortgage/amortization 三处分裂（单模式/房贷/明细表）；auto（双模式）/renovation（手续费 IRR）/balloon（尾付结构）各有真差异、非 SEO 克隆，但六者零互链。互链图：**场景入口（auto/renovation/balloon）→ 通用引擎（amortize finance.ts:283-338 ＋ installmentIrr :247-264）→ 明细表 amortization-calculator（已有 chartEngine 曲线）**；三份档案的处方末条均为"跳明细页并透传金额/利率/期限"。
- **风控双件套**（position-size 63 ＋ risk-reward 61）：entry/stop 完全同参却零互链；处方互指——risk-reward"按 1% 风险算这笔仓位 →"、position-size"计算这笔交易的盈亏比 →"，再加 kelly 61 即成**交易风控工作台**（三价位→盈亏比→期望值→凯利比例→仓位金额）。
- **期权三件套**（black-scholes 65 / options-payoff 66 / kelly 61）：定价→损益断链；black-scholes 处方"以当前参数构建到期损益 →"透传 spot/strike 即可接通；impliedVol 引擎（finance.ts:63-84）建而未用，可作 payoff 的 IV/POP 补件。
- **跨分类引擎互认先例**：utility 的 income-tax/social-insurance（utility/registry.ts:197/242）共认 `src/lib/chinaPayroll.ts`（registry.ts:10 import）——贷款六兄弟应效仿此模式：同一 finance.ts 引擎跨金融/实用两分类互链互认，任一入口进来都能看见其余五兄弟。
