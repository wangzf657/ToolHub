## 结论与优先级

**需拓展 + 交互优化** · P1

判据：桌面无硬伤（清单首屏闭环）；与 portfoliovisualizer 的差距在策略纵深（带宽/费用/回测），移动端表格可用性差记缺陷交用户。

## 扣分点明细

1. 【交互】无输入记忆：holdings 无 localStorage 持久化（`PortfolioRebalance.vue:16-23` 仅初始值），季度再平衡场景每次重录全部持仓；同目录 StockAverage.vue:42-64 已有成熟实践未复用
2. 【功能】无交易费用与取整：清单给"买入 3000 元"精确到元（:61 fmt 取整到 0 位），未计申购/佣金费，也不支持按 100 份整数份额折算——ETF/股票按手交易时清单需二次换算
3. 【功能】无带宽策略：只要偏差超总市值 0.1% 即给动作（:48），与业界常用的"目标±5% 才触发"带宽再平衡不符——频繁小额调仓的建议对普通用户是噪音，也无"惰性区间"开关
4. 【可用性】偏差无图形化：当前占比 vs 目标配比只有数字列（:123-124），无对比条形/环形图；"股 58%→50% 差 8 个点"的幅度感靠读表
5. 【功能】无现金/新注资输入：加仓再平衡（新增资金买入低配资产、免卖出）是税务更优路径，工具不区分"用新钱补"与"卖高买低"
6. 【家族共性】无预设模板：60/40、股债现金 5/3/2 等经典配比无一键填充（示例 :16-20 已是 50/30/20 但无"换个模板"入口）
7. 【移动端-缺陷】7 列清单表 ≤640px 仅列宽 90px 收窄（`PortfolioRebalance.vue:167-169`），横向溢出，手机上无法舒适读取执行清单——疑似需卡片化重排，交用户决定
8. 【灵魂】报告无"调整前后对比"段：TSV 报告（:63-74）只有当前态+动作，无再平衡后占比确认行（执行完怎么核对）

## 行业对标与差距

- **portfoliovisualizer**：再平衡策略可选（固定周期/带宽阈值）、计入费用后的回测对比、免税/应税账户差异化建议。差距：**策略纵深与费用意识**——对方回答"哪种再平衡更划算"，本工具回答"现在该买什么卖什么"（后者恰是纯前端可做的核心一步，先做深）。
- **东方财富组合宝**：关联实时行情自动算偏离（架构天花板：无行情源，可保留手填并诚实标注）、组合诊断评分。差距：数据自动性（标注"手填模式"边界即可）。
- 借鉴优先级：**localStorage 记忆 > 当前/目标占比图 > 带宽阈值开关 > 新注资模式 > 预设模板**。

## 可拓展性

- 短期（1 周）：holdings 记忆（复用 StockAverage 模式）；报告追加"再平衡后占比"段；当前/目标双条形图（纯 CSS 即可）
- 中期（1 月）：带宽阈值输入（默认 0.1% 可改 5%）；现金输入与新注资分配模式；申购费率字段与含费清单
- 远期：与 fire/sip 合并"资产配置工作台"；按手取整模式（ETF）；组合收益跟踪（手动录入净值快照）

## 优化处方（验收标准）

1. **输入记忆**：holdings 持久化 localStorage（key 前缀 toolhub）。→ **验收：改持仓后刷新页面数据保留，清空浏览器数据后恢复默认示例**
2. **占比对比图**：每行加双条形（当前 vs 目标）或表格上方汇总环图。→ **验收：股 52000/50% 场景可见当前 52% 与目标 50% 的长度差**
3. **带宽阈值**：新增"触发阈值%"字段默认 0.1%，改 5% 后偏差 2% 的资产行显示"保持"。→ **验收：阈值 5% 时偏差 <总市值 5% 的行 action=保持（hold 样式）**
4. **新注资模式**：顶部加"投入新资金 ¥X"输入，清单优先用新资金补低配、不足才卖出。→ **验收：注资等于低配差额时清单无卖出动作**
5. **移动端卡片化**：≤640px 清单表改为持仓卡片（名称+当前/目标+动作行内展示）。→ **验收：390×844 下清单无横向滚动、动作 chip 完整可读**
