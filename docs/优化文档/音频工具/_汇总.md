## 三、编码路径诚实度矩阵

三条真实路径（`AudioConvert.vue:43-47`：`srcNeedsFf` 源正则 wma/opus/amr/ac3/ape/mka/aif/aiff/wv/tta；`targetNeedsFf` 目标 m4a/flac/ogg/aac/opus）：

- **A 快路径**（decodeAudio 平台解码 + lamejs/encodeWav，零下载）：wav-to-mp3、mp3-to-wav、flac-to-mp3、flac-to-wav、m4a-to-mp3、m4a-to-wav、ogg-to-mp3、aac-to-mp3 及 convert-audio 快组合；效果家族全部亦为纯 WebAudio 快路径。
- **B ffmpeg.wasm 兜底**（25MB）：目标系 3（mp3-to-m4a/wav-to-m4a/wav-to-flac，均为 FFmpeg 原生 aac/flac 编码器，实现真实）+ 源系 2（wma-to-mp3/opus-to-mp3 强制）。
- **C 原生能力**（零依赖）：audioSynth 合成/分析 5 项、Web Speech 3 项、MediaRecorder（voice-recorder）、soundtouchjs（pitch-shift）、music-metadata+browser-id3-writer（tag-editor）。

**needModel 标注准确性审计**（registry.ts 共 14 项 true，对照实现逐项核对）：

| 判定 | 项 | 证据 |
|---|---|---|
| **失信 1** | audio-transcribe | 承诺"端侧语音识别模型"，组件仅 transformers.js TODO（`AudioTranscribe.vue:14-19`），ToolPage 却渲染模型下载提示 |
| **误标 7** | flac-to-mp3、flac-to-wav、m4a-to-mp3、m4a-to-wav、ogg-to-mp3、aac-to-mp3、compress-audio | 前六者原生解码+快路径不命中 `srcNeedsFf`，永不下 25MB；compress-audio 全文无任何 ffmpeg 路径 |
| 准确 5 | wma-to-mp3、opus-to-mp3、mp3-to-m4a、wav-to-m4a、wav-to-flac | 确需 ffmpeg |
| 合理 1 | convert-audio | 母工具确有 ffmpeg 组合 |

## 四、疑似功能缺陷清单（档案登记，均需实测复核后定性）

> 以下 12 条全部为档案扣分点中带"疑似"标记的实现级问题，每条已在档案中给出 file:line 与复现/验证方法；本汇总按严重度排序，**测试纪律禁止在此阶段顺手修复**——先实测定性（证实/证伪登记回档案），再交用户决定修复批次。

1. **changeSpeed 颗粒算法与注释不符**（`audioEngine.ts:169-177`）：注释称"线性插值+5ms 交叉淡化"，实际逐块直赋——慢速档疑似周期性静音洞、快速档颗粒重叠覆写；"变速不变调"承诺存疑，**证实则升 P0**（change-audio-speed 52 分）。
2. **mergeBuffers 重采样是抽样保持非插值**（`audioEngine.ts:293-294` `dst[di] += src[i]`）：48k 并入 44.1k 幅度倍增失真、反向留 0 毛刺，notice 却称"自动对齐"（merge-audio）。
3. **opus-to-mp3 微信 SILK 风险**：微信 .opus 多为 SILK v3 封装，@ffmpeg/core 0.12.10 无 SILK 解码器——desc 主打场景大概率不可用；另真 Opus 本可 decodeAudioData 快路径却被强制 25MB（证实则升 P0 复核）。
4. **flac-to-wav 静默降位深**：encodeWav 写死 16bit（`audioEngine.ts:54`）+解码采样率随设备 AudioContext（`:17`）——Hi-Res"逐样本一致"承诺实际不成立且无警示；m4a-to-wav/mp3-to-wav 同源。
5. **reverse-audio 连点叠播**：preview 无 src 引用无防抖，点 3 次=3 层倒放混响。
6. **compress-audio 两条自相矛盾文案**：mono"体积再降一半"与自家估算公式（CBR 体积与声道无关）打脸；目标不可达时静默夹值到 32kbps，估算条仍显示"按目标估算"。
7. **normalize-audio RMS 削波无防护**（`audioEngine.ts:192-201`）+ audio-equalizer 增益拉满静默削波（encodeWav 逐样本 clamp 无警示）。
8. **text-to-speech 注册表承诺"选中文本试听"未实现**（`registry.ts:5` vs 组件无 getSelection）；长文本单 utterance 有 Chrome 中途截断风险。
9. **instrument-tuner 命中判定跨八度误亮**（`InstrumentTuner.vue:104` 只比音名不比八度），初学者被误导。
10. **fade-audio "指数"曲线实为 t³**（`FadeAudio.vue:31` 注释自认）名实不符；convert-audio 码率 step=32 产生 288kbps 非标准档，ffmpeg `-b:a 288k` 预期报错。
11. **speech-to-text 断网静默失败循环**：network 错误后 onend 无退避重启，离线用户卡"正在聆听"永不出字。
12. **denoise 逆变换丢相位**（`ifftFromMag` 把幅度谱当实谱，`audioEngine.ts:411-423`，注释自称"取原相位"与实现不符）——"水声"伪影比常规谱减更重。

## 六、阉割与合并建议

- **audio-transcribe → speech-to-text**（或补真 whisper）：两工具共用同一识别引擎，transcribe 仅多"文件播放"一环且该环不可用（外放收听）；档案结论明确"若放弃模型路线则建议阉割并入"。留一个诚实入口即可，SEO 上 301 到 speech-to-text。
- **13 个 X-to-Y 转换 slug 收敛评估**：14 个转换入口共用 `AudioConvert.vue`，组件差异仅初始 target。**不建议物理删 slug**（X-to-Y 是搜索流量入口，且站规 slug 一经发布不更改）；建议"母工具+路由参数"软收敛：全部 slug 保留、挂载时按 slug 预设目标/码率（即 P0 修复本身），长期把 6 个 ffmpeg 页共享的"重格式工作台"（wma-to-mp3 档案远期建议）作为底座整合点。compress-audio 可并回 convert-audio 成"转换+压到指定 MB"双模式（convert-audio 档案远期）。
- **能力互通类合并**（远期，档案均有登记）：audio-trimmer+merge-audio → 多段标记合并工作台；change-audio-speed+audio-pitch-shift → 变速/变调双 Tab（pitch-shift 已是 soundtouchjs 双引擎）；remove-noise+vocal-remover → "语音修复"工作台；audio-transcribe+speech-to-text → "转写工作台"。
- 站内互链补课：remove-noise 与视频分类 remove-background-noise-from-video 零互链（两算法路线无分流）；reverse/trimmer/merge 的选区能力互不联通。
