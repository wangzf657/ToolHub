## 结论与优先级

**交互优化** · P1

判据：60 分无硬伤——"目标体积反推码率"模式与实时估算条是本批最接近"懂用户"的设计；扣分集中在估算不预警、mono 文案错误、needModel 失真三点，属可快速修复的诚实度问题。

## 扣分点明细

1. 【交互-疑似事实性错误】"转为单声道（体积可再降约一半）"（`AudioCompress.vue:76`）与自家估算公式矛盾：`:84` 预计体积=kbps×时长÷8，与声道数无关——CBR MP3 下 mono 不省体积（收益是音质集中）；同页 size 档文案（:69"信息量减半，同码率更清晰"）反而是对的，两档文案口径不一
2. 【可用性】目标不可达静默夹值：`:35` 把估算码率夹在 32~320——1 小时录音压到 1MB 需约 2.3kbps，实际按 32kbps 输出约 13.7MB，估算条仍显示"按目标 1MB 估算码率 32kbps"误导用户，点完才发现目标落空
3. 【交互】needModel: true 失真（`registry.ts:28`）：组件全文仅 AudioToolBase+encodeMp3（无任何 ffmpeg 路径），页面却挂"需下载引擎"预期——本工具永远不会加载 ffmpeg
4. 【功能】不可解码源无兜底：WMA 等想压缩的用户被"浏览器无法直接解码…"挡回（`audioEngine.ts:22`），而"压不动的老格式"恰是转 MP3 的衍生刚需；desc 未说明仅支持浏览器可解格式
5. 【功能】缺采样率降档：语音类 44.1kHz→22.05kHz/16kHz 是单声道之外的另一大压缩杠杆（12kHz 人声 64kbps mono 可再省近半），竞品 123apps 高级选项里有采样率/声道双控制
6. 【可用性】结果不闭环：完成后仅"压缩完成：处理后体积 X"（`:87`）——不显示压缩率百分比、不显示是否达到目标、无试听（128kbps 听感可否接受要下载后自己判断）
7. 【可用性】编码无进度：`:46` 未传 onProgress（引擎 `audioEngine.ts:70` 支持，接线即得；家族共性，见 audio-trimmer.md 扣分点3）
8. 【交互】targetMB 手输无快捷档：邮件附件 10/25/50MB、微信文件 25MB 等常用限制值没有 chip；五档质量码率（:21）不记忆
9. 【家族共性】波形纯静态（`AudioToolBase.vue:70-81`，见 audio-trimmer.md 扣分点1）；执行按钮流内底部（M-15；共性-根因 4）

## 行业对标与差距

- **123apps online-audio-converter.com**：质量档+高级选项（采样率/声道/码率三联动）+转换前后体积对比。差距：采样率杠杆与闭环回显。
- **CloudConvert**：压缩预设组+输出预估。差距：目标体积反推模式反而是本工具领先点——对标的短板补齐即可拉平。
- 借鉴优先级：**夹值预警 > 采样率降档 > 结果闭环（压缩率+达标+试听） > 快捷目标档 > mono 文案更正**。

## 可拓展性

- 短期（1 周）：夹值触发时显示"该时长最低可压至 X MB"并建议开启 mono/降采样；mono 文案统一更正；needModel 改 false
- 中期（1 月）：采样率降档选项（22.05k/16k/12k）；结果卡显示压缩率+达标状态+试听；快捷目标 chip（10/25/50MB）
- 远期：VBR 档（lamejs 支持 VBR 参数）进一步压体积；与 wav-to-mp3/convert-audio 打通"转码即压缩"动线

## 优化处方（验收标准）

1. **夹值预警**：估算码率触底 32kbps 时估算条变黄色警告"32kbps 为下限，该时长最低约 X MB，无法达到 Y MB"。→ **验收：目标 1MB/1 小时音频时警告出现，X 计算正确（≈13.7MB），导出按钮不禁用但目标状态明示**
2. **mono 文案更正**：质量档文案改"同码率音质更集中（体积不变）"。→ **验收：文案不再出现"体积可再降约一半"**
3. **needModel 修正**：注册项改 false。→ **验收：页面无 25MB 下载提示**
4. **结果闭环**：完成后显示"55.6MB → 4.8MB（-91%）· 达到目标 5MB ✓"并可试听输出。→ **验收：压缩率百分比正确、达标状态与 targetMB 比对一致、试听可播放**
5. **采样率降档**：新增"降采样"下拉（保持/22.05k/16k/12k）并联动估算。→ **验收：选 16k 后估算体积下降且输出时长不变、可播放**
6. **快捷目标档**：目标输入框旁加 10/25/50MB chip。→ **验收：点击 chip 后 targetMB 同步、估算刷新**
