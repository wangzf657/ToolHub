## 扣分点明细

1. 【功能-个性】字段面仅 4+1：流派（TCON）/音轨号（TRCK）/碟号（TPOS）/作曲（TCOM）/注释/歌词全缺——音乐库整理中流派与音轨是仅次于标题/艺术家的常用帧；music-metadata 已能读出全量 common（:44-45），只差表单与 setFrame
2. 【功能-个性】整标签重建丢帧：browser-id3-writer addTag 全量重建（:110），除 5 帧外原有帧（歌词/流派/自定义 TXXX）静默清除——黄字预警（:160）是诚实的好实践，但"解析后逐帧回写以保留未知帧"技术上可行（桌面 MP3Tag 均默认保留）
3. 【功能】无批量：一拖一存 N 次是整库整理最大摩擦（FileDrop multiple=false :125-131）；Picard/MP3Tag 的核心场景恰是整库批量
4. 【功能】无文件名↔标签互转："01 - 周杰伦 - 晴天.mp3"→自动填字段与反向按模板重命名，是标签工具的半壁江山，全缺
5. 【灵魂】无在线元数据查询：填对歌名即从 MusicBrainz/iTunes 公开 API 带出专辑/年份/封面是第一效率杠杆，纯浏览器可直连，架构无障碍
6. 【可用性】写回结果无验证环节：保存后仅 toast（:112），无"已写入帧清单"或播放确认——写丢封面要靠用户开播放器发现
7. 【交互-疑似】年份写 TYER（ID3v2.3 :107）：v2.4 源用 TDRC 且可能带"1998-03"多段值，读侧截断行为未验证（建议实测）；写侧无 TDRC 选项
8. 【家族共性/工程】未用 AudioToolBase（标签工具不需波形，但缺文件确认锚点）；大封面内嵌无体积预警；参数不记忆

## 行业对标与差距

- **MP3Tag（桌面，能力参照）**：全字段表格编辑、批量整库、filename↔tag 转换、Discogs/MusicBrainz 在线源、未知帧保留。差距：**字段面与批量是代差**；两者纯前端均可做。
- **MusicBrainz Picard（开源标杆）**：声纹匹配识别无名文件+一键写全元数据。差距：声纹匹配成本高（fpcalc wasm 化），"按歌名查询"轻量版可先行。
- 借鉴优先级：**字段面补齐 > 批量 > 在线查询 > filename↔tag > 未知帧保留**。

## 可拓展性

- 短期（1 周）：补流派/音轨/作曲三字段（读写）；保存后行内显示"已写入帧清单"；加播放确认条
- 中期（1 月）：批量队列（多文件列表+逐行编辑+统一写回）；filename→tag 解析模板；MusicBrainz 按歌名查询带出专辑/封面
- 远期：未知帧保留（解析→改帧→重组而非重建）；tag→filename 重命名模板；FLAC/M4A 写回（Vorbis Comment/iTunes tags）

## 优化处方（验收标准）

1. **字段面补齐**：新增流派/音轨号/作曲三输入框，读侧回填、写侧 setFrame('TCON'/'TRCK'/'TCOM')。→ **验收：带全字段的 MP3 载入后三框回填正确；写回用 MP3Tag 桌面版验证三帧生效**
2. **结果验证条**：保存成功后显示帧清单（"已写入：标题/艺术家/封面(120KB)"）与原/副本体积对比。→ **验收：清单与所填字段一致，副本体积=原文件+标签增量**
3. **批量模式**：FileDrop multiple 开启，文件列表+上一首/下一首导航。→ **验收：连续处理 5 个文件无需重新拖拽，每个写回独立 -tagged 副本**
4. **filename→tag**："艺术家 - 标题"格式一键解析回填（分隔符可选）。→ **验收：对"周杰伦 - 晴天.mp3"点击解析后艺术家/标题两框自动填入**
5. **在线查询**：标题+艺术家输入后提供"查询 MusicBrainz"按钮，命中带出专辑/年份/封面（确认后才写入）。→ **验收：查询知名歌曲后三字段自动回填，未命中给出明确提示且不误写**
