## 结论与优先级

**交互优化** · P1

判据：无可用性硬伤（结果区可用可编辑），但断网死循环与草稿不保存是听写场景的真实风险；对标 Speechnotes 的命令/留存体系差距明确且均可纯前端落地。

## 扣分点明细

1. 【兼容-硬伤边缘】SpeechRecognition 仅 Chromium 系完整支持（Firefox 不支持、Safari 14.1+ 部分支持且中文不稳），且 Chrome/Edge 云端识别**必须联网**——notice 有诚实披露（:103-106）但缺常态化"当前浏览器是否可用"徽标，用户点了麦克风才知道
2. 【交互-疑似功能问题】断网进入静默失败循环：network 错误 toast 一次（:40）后 onend 无退避自动重启（:44-48），无终态提示——离线用户看到"正在聆听"永远不出字
3. 【交互】聆听中切换语言 chips 无效：lang 仅 start() 读取（:22），切换后 UI 无任何"需停止重开"提示
4. 【功能】无标点与语音命令：中文标点靠识别引擎随机加注，无"换行/逗号"口令、无自动分段——Speechnotes 有完整命令词典
5. 【灵魂】无麦克风电平反馈（说太远不知道是否收到）、无置信度显示、无听写统计（时长/字数）
6. 【可用性】ResultBox 默认 180px 钉死（`ResultBox.vue:69`；家族共性-根因 2）——听写场景结果区就是主视区，长篇需要频繁小窗滚动
7. 【灵魂-疑似功能问题】无草稿自动保存：finalText 仅存内存（:16），听写 30 分钟误关页面全部丢失
8. 【家族共性】面板 top≈250px 装饰税（共性-根因 1）；本工具 CTA 置顶、核心控件首屏可达，属于布局做对了的

## 行业对标与差距

- **Speechnotes**：语音命令词典（new paragraph 等）、自动标点/大小写、草稿自动保存、一键导出 Drive/邮件、听写计时统计。差距：命令体系+留存闭环。
- **dictation.io**：100+ 语言、逐段编辑、免键鼠操作引导。差距：语言覆盖（本工具 3 chips 属务实取舍，中文站可接受，但粤语 chip 在部分版本 Chrome 上效果不稳未披露）。
- 与站内 audio-transcribe 边界：本工具胜在实时+可编辑；对方的"文件转写"承诺未兑现（见 audio-transcribe.md），若该工具阉割，本工具是家族唯一 STT 入口。
- 借鉴优先级：**草稿自动保存 > 网络错误终态 > 聆听中切语言即时生效 > 电平反馈 > 语音命令**。

## 可拓展性

- 短期（1 周）：草稿 localStorage 自动保存+恢复+清空入口；network 连续失败 3 次停止重启显示终态横幅；可用性徽标
- 中期（1 月）：聆听中切语言自动 restart+toast；getUserMedia 独立流做 3 柱迷你电平；听写统计（时长/字数）
- 远期：语音命令词典（中文"另起一段"等）；结果区弹性高度改造（随家族 ResultBox 统一整改）

## 优化处方（验收标准）

1. **可用性徽标**：支持的浏览器显示"✓ 当前浏览器可用（需联网）"状态条。→ **验收：Chrome 打开即见绿色可用提示；Firefox 见替代路径警示**
2. **网络错误终态**：连续 3 次 network 错误停止自动重启，显示"网络不可用，语音识别需联网"横幅。→ **验收：断网开始识别约 5s 内出现横幅，而非无限"正在聆听"**
3. **草稿自动保存**：每次最终结果变更写 localStorage，重进自动恢复并提供"清空"。→ **验收：听写 5 段后刷新，文本完整恢复；清空后不残留**
4. **切语言即时生效**：聆听中点语言 chip 自动 restart 并 toast"已切换"。→ **验收：聆听中点 English 后下一句按英语识别**
5. **电平反馈**：CTA 旁迷你电平条，静默 10s 提示"没听到声音，请靠近麦克风"。→ **验收：说话时电平跳动；静默超时提示出现一次而非循环**
