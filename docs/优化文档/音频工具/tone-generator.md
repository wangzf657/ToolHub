## 结论与优先级

**交互优化** · P1

判据：无可用性硬伤，但"播放中波形/音量不可调"是信号发生器的核心交互（对比谐波、边听边调），与 szynalski 的差距集中在活参数与声道分置两处，均为节点级小改。

整改优先序：setWave/setGain 活通道（P1）→ 声道分置 → URL 分享 → 扫频 ramp 化（P2）。

## 扣分点明细

1. 【交互-硬伤边缘】播放中波形与音量是死控件：kind/volume 仅 start() 时读取（`ToneGenerator.vue:29`），音量滑条连事件绑定都没有（:94 无 @change/@input）——正弦切方波无声无息无效、拖音量零响应；频率的 setFreq 活通道（:44-46）证明句柄模式已在，缺 setWave/setGain 两个方法
2. 【功能】无双声道独立测试：startTone 直连 destination 双声道（audioSynth.ts:179），无 L/R 声道分置——耳机左右校验/单边损坏检测做不了；szynalski 标配；亦无双振荡器拍频（听力测试经典手段）
3. 【技术-可改进】扫频用 setInterval 50ms 步进+setTargetAtTime(0.01)（:57-64）而非 exponentialRampToValueAtTime 采样级连续斜坡，细听有微台阶；对数扫频公式正确（:60）值得肯定
4. 【功能】无幅度参考：音量 0~1 无 dB 标注，"听力自测"（desc 卖点，`registry.ts:37`）无法与任何基准横向比较，预设"15kHz 高频极限"也无年龄解读
5. 【交互】扫频与定频互斥切换突兀：startSweep 先 stopAll（:49）再起振，无淡入淡出过渡；扫频中频率数字实时跟随（:62）是亮点
6. 【灵魂】参数（频率/波形/音量）不记忆，刷新归位 440Hz；无 URL 参数分享（szynalski 支持 ?f=440&w=sine 直达状态）
7. 【家族共性】面板 top≈250px 装饰税（共性-根因 1）；单面板无结果区，共性-根因 2 不适用

## 行业对标与差距

- **Online Tone Generator（szynalski.com）**：播放中波形/音量即时切换、L/R 声道分置、扫频方向可逆、URL 参数分享、音量 Sone 换算。差距：**活参数与声道分置**。
- **audiocheck.net**：专业测试信号体系（扫频/粉噪/THD/摆频/听阈测试带年龄参考表）。差距：测试信号库与科普深度——本工具已有四波形的骨架，补"测试场景"分组即成体系。
- 借鉴优先级：**setWave/setGain 活通道 > L/R 声道分置 > URL 参数分享 > 扫频 ramp 化 > 双振荡器拍频**。

## 可拓展性

- 短期（1 周）：startTone 返回 setWave/setGain；波形 radio 与音量滑条 @input 直通；参数 localStorage 记忆
- 中期（1 月）：StereoPannerNode 声道分置 chips（左/右/双）；扫频改 exponentialRampToValueAtTime；URL query 携带参数分享
- 远期：双振荡器拍频模式（Δf 可调）；测试场景分组（验机/调音/听力自测）与 15kHz 年龄参考表；AM/FM 调制

## 优化处方（验收标准）

1. **活参数**：startTone 增加 setWave/setGain，波形切换与音量拖动播放中即时生效不重启。→ **验收：播放正弦中点方波立即变音色、拖音量立即变化，全程无断音重启**
2. **声道分置**：加"左/右/双声道"chips 路由到指定声道。→ **验收：选"左"时仅左耳机出声，右声道静默**
3. **URL 分享**：频率/波形/音量同步到 query 参数，载入恢复。→ **验收：调至 1kHz 方波复制 URL，新标签打开即同状态**
4. **扫频 ramp 化**：exponentialRampToValueAtTime 替代 50ms 步进。→ **验收：扫频过程频谱分析连续，无可闻台阶（与改造前对比）**
5. **dB 标注**：音量旁显示相对 dB 值并提示"听力自测需固定系统音量再横向比较"。→ **验收：拖动音量时 dB 数值联动更新，提示文案可见**
