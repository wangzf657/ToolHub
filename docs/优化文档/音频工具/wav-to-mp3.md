## 结论与优先级

**交互优化 + 需拓展** · P1

判据：62 分无硬伤（默认目标正确是全家族最顺的入口之一），但压缩类工具的核心卖点"省了多少空间"完全没有量化反馈，与 123apps 的体积预估存在明确差距。

## 扣分点明细

1. 【可用性】编码无进度：`AudioConvert.vue:79` 调 `encodeMp3(src, kbps.value)` 未传第三参，而引擎签名 `encodeMp3(buffer, kbps, onProgress?)`（`audioEngine.ts:70`）明明支持——接线即可得百分比（家族共性，见 audio-trimmer.md 扣分点3）
2. 【功能】体积卖点零兑现：desc 承诺"体积小 10 倍"（`registry.ts:11`），但 UI 无任何"转换后约 X MB"预估——数据已齐（AudioToolBase meta.duration + kbps，一行算式），压缩工具不给压缩预期是失职
3. 【可用性】结果无预览无 A/B：点击即下载（`AudioConvert.vue:146`、`DownloadButton.vue:21-31`），192kbps 是否可接受要下载后自己听
4. 【功能】WAV INFO 块元数据丢失：解码重编码路径不透传（`audioEngine.ts:70-89` 无 tag 写入）
5. 【功能】无批量：FileDrop `multiple=false`（`AudioToolBase.vue:101`），一摞 WAV 录音逐个转是最大摩擦
6. 【交互-疑似功能问题】码率滑条 step=32（`:142`）产生 288kbps 非标准 MP3 档位（MPEG-1 L3 码率表无 288），lamejs 行为未验证，建议实测
7. 【灵魂】码率/单声道不记忆；输出名不可自定义（`:85`）
8. 【家族共性】波形纯静态装饰（`AudioToolBase.vue:70-81` 无 pointer 事件，见 audio-trimmer.md 扣分点1）；空态无引导、按钮流内底部（M-15；共性-根因 1/4）

## 行业对标与差距

- **123apps online-audio-converter**：批量、逐文件码率、转换前预估输出体积。差距：量化反馈与批量。
- **CloudConvert**：WAV→MP3 预设组（ archival/standard/podcast）+ 高级参数（采样率/声道）。差距：预设引导——小白不知道 128/192/320 该选哪个。
- 借鉴优先级：**体积预估 > 编码进度 > 码率预设文案 > 批量 > 元数据**。

## 可拓展性

- 短期（1 周）：加载完成后在码率滑条下显示"预计输出 ≈ 时长×码率"实时计算；onProgress 接线
- 中期（1 月）：批量队列+zip；码率三预设按钮（128 存储省空间/192 通用/320 高保真）
- 远期：与 compress-audio 打通"压缩到目标体积"模式（反推码率）

## 优化处方（验收标准）

1. **体积预估**：文件加载后码率滑条旁显示"5:30 音频 @192kbps ≈ 7.9MB（原 55.6MB，-86%）"，随码率实时刷新。→ **验收：拖入 5 分钟 WAV 后预估文案出现且误差 <10%，拖动滑条数字联动**
2. **编码进度**：忙条变百分比。→ **验收：3 分钟 WAV 转 MP3 期间进度 0→100% 递增**
3. **结果对比卡**：完成后显示实际输出体积与压缩率 + 试听输出按钮。→ **验收：试听可播放输出文件；显示"38.0MB → 4.1MB"**
4. **码率预设**：滑条上方加三枚预设 chip。→ **验收：点"192 通用"滑条跳 192 且文案同步**
5. **批量**（中期）：多文件+统一设置+zip 下载。→ **验收：5 个 WAV 一次转完整包下载**
